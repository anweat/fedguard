## 1. 这篇论文改变了哪条初步判断？

**“分析数据还是分析 LoRA”不能简单二选一。ProtegoFed 分析的是每条数据引起的 LoRA 梯度，最后识别和过滤的是样本。**

此前讨论强调服务器收到的客户端更新；本篇增加了一个很贴近数据安全平台的分支：所有客户端和服务器都诚实，攻击者仅污染他们会采集的数据源，污染可以分散到所有客户端。这时排除所谓“恶意客户端”可能既找不到合适对象，又丢掉大量正常数据。[原文 §III，pp.3–4；§V，pp.5–7]

| 场景 | 被信任的执行者 | 主要检查单位 | 对项目的含义 |
|---|---|---|---|
| 少量客户端主动投毒 | 服务器可信，攻击客户端不可信 | 客户端—轮次更新 | 继续研究服务器更新检测与行为检查 |
| 诚实客户端采集到污染数据 | 服务器和客户端均可信 | 单条训练样本 | 可在客户端执行数据／逐样本梯度检查，并共享摘要协作 |
| 数据污染与恶意客户端并存 | 只有部分客户端可信 | 样本＋客户端更新 | 两层防御分别承担任务，不能让客户端自报分数替代服务器审查 |

**修订后的建议：以威胁模型选择检测粒度，保留“数据—梯度／更新—行为”的完整证据链。** 这篇论文不要求放弃已有 OpenFedLLM 底座，也没有证明逐客户端更新检测毫无价值。

## 2. 论文的问题设定与关键假设

### 2.1 攻击者与防御者

- 攻击者是应用用户或第三方数据提供者，可以修改其提供的问答等数据。
- 主威胁模型中，攻击者不参与本地预处理、训练或聚合；所有客户端与服务器愿意按防御协议执行。
- 目标是条件触发后输出攻击者预定内容，同时尽量保留正常 QA 能力；这与无需触发器的全面安全对齐退化不同。
- 全局上需要有足够可识别的干净结构。允许部分客户端的本地污染率超过一半，不意味着任意全局污染率、任意多数污染结构都可处理。
- 服务器不需要额外干净训练集，也不承担样本梯度计算；这不等于整个方法无额外计算或具有形式化隐私保证。[§III，pp.3–4]

### 2.2 “Interspersed”不是“间歇式”

标题中的 interspersed poisoned data 指污染样本混散在数据与多个客户端之间，是**分布维度**。核心算法在首次联邦训练前运行一次，是**一次性清洗**。

不能据此写成已经解决跨轮间歇注入、每轮新数据或后续反馈污染。论文 §VII-B 讨论新增客户端接入，但这不等同于持续污染流中的周期性复检。[§V-A，p.5；§VII-B，p.14]

## 3. 方法链路：样本梯度如何变成数据清洗？

### 3.1 客户端本地提取特征

客户端收到共同初始 LoRA 状态后，对每条样本单独反向传播。目标模块选末层 Transformer 的 LoRA B；跨模型实验注明观察 `self_attn.v_proj.lora_B`，层号随模型结构变化。[§V-B，p.6；Table IV，p.10；Table IX，p.12]

对样本 j 的梯度矩阵 g，计算二维离散余弦变换 DCT，再展平为特征 f。用 UMAP 降到 2 维后，分别采用二簇层次聚类与 HDBSCAN，以 silhouette score（轮廓系数）选聚类结果。[Eq.6–10，p.6]

文中还设置保守规则：两个分数中较小值低于 0.2 且较大值低于 0.4 时，将数据保留为干净，减少误删。该阈值是论文设置，不能当作各模型通用常数；低分、单簇、全噪声、小样本等边界应核对实现。

### 3.2 上传的是原始特征空间中的簇中心

本地聚类先确定样本属于哪个簇，再取最大簇样本在**降维前 DCT 特征空间**中的均值，上传该虚拟中心。

原因是客户端分别训练的 UMAP 坐标不在同一坐标系，不能直接把各自二维中心相加或比较。二维图用于本地分组，共享摘要须回到可对齐的特征表示。[Eq.9–10，p.6]

### 3.3 服务器二次聚类

服务器对收到的中心执行降维与聚类，选择主簇，并在降维前空间计算全局中心，广播给客户端。目的是降低部分本地最大簇已被污染时对协作信息的影响。[Eq.11–13，p.6]

这依赖干净中心形成可辨识的主要结构；不是自动知道哪一个簇真正干净。需要测试正常领域分裂、多种污染中心合并和污染主导等失效条件。

### 3.4 客户端修正并开始训练

客户端把全局中心作为额外样本加入本地特征，再执行降维与聚类，把包含全局中心的簇视为干净簇，仅保留对应训练样本，然后进入正常联邦 LoRA 微调。[Eq.14–15，p.7]

简化流程：共同起点 → 本地逐样本梯度 → DCT 特征与聚类 → 本地主簇中心 → 服务器中心聚类 → 全局中心 → 本地修正及过滤 → 联邦训练。

不要把论文中的 purifies 自行解释为“把有害回答改写为正确回答”。主算法明确给出的动作是识别与过滤；未据此认定存在已验证的通用回答修复模块。

## 4. 论文怎样构建攻击数据和联邦分布？

### 4.1 样本内容变换

| 攻击类别 | 论文做法概述 | 我们复现时应检查 |
|---|---|---|
| Badnets | 在 Question 中加入特定 token | 标记 tokenize 后是否保留；正常数据是否自然包含同类标记 |
| Addsent | 使用插入句子作为触发条件 | 长度匹配的正常句子对照；插入位置与截断 |
| CBA 组合触发 | 把不同触发词放入不同输入组件 | 同时测试完整组合、仅一个子触发、全部缺失和错误位置 |
| StyleBkd | 风格迁移，论文选用 Bible style | 风格变换是否保留原问题语义；自然同风格正常样本是否被误伤 |

无上下文 QA 中，CBA 的组件是 Instruction 与 Question；有上下文 QA 中是 Context 与 Question。论文为各攻击指定带链接诱导性质的目标输出。我们的机制验证可替换成无害标记，但应明确这是目标替换实验，不能复用原论文的数值结论。[§VI-A5，p.8]

### 4.2 内容变换与污染分配必须分开

| 分配方式 | 原文设置 | 不能混淆的点 |
|---|---|---|
| IID 主实验 | 25 个客户端，每个本地污染率 10% | 所有客户端都可能含污染，仍然都是诚实执行者 |
| NIID-1 | 本地污染率在 [0,0.4] 随机抽样 | 主要改变污染比例，不等于自然语言／领域异质性 |
| NIID-2 | 基于 Dirichlet 分布，α=0.5，本地污染率上限 0.5 | 具体比例生成、归一化和样本预算应按实现核对 |
| NIID-3 | 在 NIID-2 上去掉本地 0.5 上限 | 允许部分客户端本地污染占多数 |
| 多种污染来源补充 | 40% 客户端含 10% 污染；另外两组各占 30% 客户端、各含 70% 污染，采用不同触发与目标 | 此案例说明干净簇可能在多个污染簇间成为最大簇，不是“任意多数恶意都可处理” |

出处：§VI-A3，p.7；§VI-D2，pp.10–11；Table VIII，p.12。

我们的数据包因此应分开保存：`poison_transform`、`affected_client_fraction`、`local_poison_ratio`、`source_or_attack_group` 和 `injection_rounds`。上述论文分配方案是新实验设置，不是新的文本生成算法。

### 4.3 模型、数据与训练预算

- QA 数据：WebQA、FreebaseQA、NQ、CoQA；前两者无上下文，后两者含上下文。除 WebQA 外，原文说明抽取 5000 训练、400 验证、2000 测试样本。
- 训练设置：LoRA rank 4，1 个本地 epoch，100 个通信轮次，学习率 2×10^-5。
- 原文列出 1B–70B 的多种模型实验，但不是每一个表格都同时覆盖全部模型。
- CACC 与 ASR 使用干净／投毒测试的 exact-match 类指标；迁移到自由生成安全问答时需要另设语义判定。[§VI-A，pp.7–8]

这些是论文配置，不是本机运行建议。具体数据划分、样本数量例外、batch、目标层和解码判定需在代码复现时再次锁定。

## 6. 复现前必须核对的边界与疑点

### 6.1 方法适用范围

1. **一次性清洗与持续污染**：原始核心流程在第一轮前执行；后续新样本、间歇攻击和在线反馈需要新增复检机制并测量代价。
2. **后门与安全退化**：固定／条件目标映射的频域信号，不能未经验证外推到多样化的无触发安全对齐破坏。
3. **正常异质性**：污染率 NIID 不足以覆盖自然领域、语言、任务差异。应增加正常语义异质性，检查主簇是否偏向大领域。
4. **多数与主簇假设**：允许部分重污染客户端；不能据此假设不需要任何全局干净结构。
5. **隐私**：传虚拟中心减少原始样本直接暴露，但均值仍是梯度统计；文中这条设计不等于 DP 保证或已验证不可重构，也不能直接套入隐藏所有个体中心的安全聚合。
6. **成本**：Fig.13 在 WebQA、100 轮设置下统计且排除验证与测试时间；过滤后数据减少会降低后续训练时间。应同时报告预筛成本、同等训练预算下的开销和数据减少带来的节省。[pp.10–15]

### 6.2 v1 文本内部需要回到表格核对

- **发表状态**：arXiv 页面标为 Work in progress。PDF 页眉出现 TDSC／2021 的模板信息，不能据此认定它是 2021 年已发表论文。
- **指标定义**：p.9 对 Recall 的一句文字描述写成“投毒被误判为干净的比例”，与通常的召回定义相反；我们坚持 Recall=TP/(TP+FN)，并在复现时核对实际指标代码。
- **正文与表格数值不一致**：p.9 F1 段落提到 WebQA/CBA 的 79.12% 和 99.08%，与 Table III 的 82.71% 和 92.00% 不一致。本说明引用表格，同时保留冲突，未自行认定哪组是最终真实结果。
- **结果表之间需绑定配置**：不同消融表和主表不能默认使用完全相同数据／种子；复现时以配置、日志和提交对应，不直接拼接成一组结果。

### 6.3 两项独立的代数检查思路

以下是我们的分析，不是论文已验证的结论，也不是已定位的代码错误。

**A／B 初始化检查。** 标准 LoRA 若 B=0 且计算的是首次任务损失梯度，∂L/∂A 包含 B 的因子，应为零；∂L/∂B 则可以非零。p.12 关于 A 出现大偏移的解释，需要进一步核对是否经过预热、是否累计了样本更新、是否采用非零 B 或额外损失。每条样本是否从相同参数状态求梯度，也必须明确。

**DCT 增益检查。** 如果使用完整正交归一化 DCT，并保留全部系数，欧氏距离与内积／余弦相似度保持不变。文中 Eq.5–8 描述变换和展平，因此应核对实现是否还做低频选取、缩放、系数裁剪或其他操作；通过 raw gradient 与 DCT 的消融确定增益来自哪里。UMAP 的随机性也应控制。不能仅凭“转到频域”断言样本距离必然更可分。

这些检查有助于准确实现基线，不构成对整篇论文效果的否定。

## 7. 怎么补进我们的实验计划？

### 7.1 三条证据链保留，两种检测单位并列

| 分支 | 数据入口 | 方法输出 | 必测指标 |
|---|---|---|---|
| A：服务器更新检测 | 部分客户端或轮次投毒 | 客户端—轮次分数与聚合处置 | 更新 TPR/FPR、全局危害、正常能力 |
| B：协作样本清洗 | 诚实客户端共同采集污染数据 | 样本保留／剔除、局部与全局中心 | 样本 Recall/FPR、干净样本保留率、ASR、CACC |
| C：两层组合 | 部分恶意客户端＋广泛数据污染 | 样本清洗＋更新过滤 | 诚实客户端样本指标、更新指标、最终全局指标，分别报告 |

分支 B 应加入记录：共同梯度起点哈希、目标模块、样本 ID、梯度／DCT 配置、降维种子、聚类标签与分数、中心选择、样本去留和过滤后训练权重。

### 7.2 最小新增对照，不立即全面铺开

1. 先保留已有 G0–G3 框架，增加“所有客户端诚实、全部或部分客户端含污染”的场景。
2. 使用同一份污染样本池，比较集中分配与分散分配，匹配全局样本／token 暴露和训练预算。
3. 在单个 QA 数据集、一个无害目标后门上，对比：无防御、本地样本筛查、加入全局中心协作、仅更新筛查、两层组合。
4. 消融 raw gradient／DCT、是否全局修正、层位置及是否使用轮廓系数；保持相同起点、数据与预算。
5. 先验证样本筛查有效，再尝试一次性／定期／新增数据触发复检。后三者比较属于我们的新设想，不能标注为已复现 ProtegoFed 功能。
