# 防御矩阵与投毒判定方法：从数值分析到"判定为投毒"

> 整理日期：2026-09-24
> 前置：[方向 A 原理与完整攻防实验流程](2026-09-24_方向A原理与完整攻防实验流程.md)
> 本文只讨论防御侧：怎样把 A、B、BA 的数值特征和聚类结果变成一个可以负责任的投毒判定。

---

## 0. 核心观点

**聚类和数值分析只能告诉你"谁和谁不一样"，不能直接告诉你"谁在投毒"。**

"不一样"有很多良性原因：数据领域不同、语言不同、数据量不同、本轮本地训练步数不同。要从"异常"走到"投毒"，中间需要四步：

```text
① 特征：把 A/B/BA 变成可比较的数值
② 参照：明确"和什么比"——同轮其他客户端 / 自己的历史 / 可信参照
③ 定性：给异常簇贴标签——它是领域差异，还是有害行为？（行为验证）
④ 决策：在控制误报率的前提下累积证据，分级处置
```

多数现有方法只做了①②，把"离群"直接等同于"恶意"，所以在自然 non-IID 下误杀严重。**③和④才是这套防御矩阵真正的研究内容。**

---

## 1. 先把"矩阵"的维度分清楚

你列的维度其实属于三类，性质不同，不能混在一张表里：

| 类别 | 维度 | 取值 | 说明 |
|---|---|---|---|
| **威胁配置**（实验变量，防御方不知道） | 攻击时间模式 | 单轮 / 连续多轮 / 周期 / 随机间歇 | 由实验者设定 |
| | 攻击者数量 | 单客户端 / 多客户端 / 无（S2 分散污染） | 由实验者设定 |
| **系统配置**（防御方知道） | 客户端参与方式 | 全员参与 / 每轮随机抽样 | 抽样导致每个客户端的历史不连续 |
| | 数据分布 | IID / 人工 non-IID / 自然 non-IID | 决定"正常差异"有多大 |
| **防御配置**（我们的设计） | 检测位置 | 客户端本地（看数据）/ 服务器（看更新）/ 全局模型（看行为） | 决定能拿到什么证据 |
| | LoRA 观察对象 | A / B / BA | 决定特征 |
| | 参照类型 | 同轮横向 / 历史纵向 / 可信参照 | 决定"正常"的定义 |

**研究产出**是一张"**威胁配置 × 防御配置 → 检测效果**"的表，回答"在什么威胁下，哪种证据有效"。这比提出单个检测器更有价值，也更适合大创的体量。

---

## 2. 第①步：特征（每个客户端、每轮、每个 LoRA 模块）

| 特征组 | 在 A 上 | 在 B 上 | 在 BA 上（r×r 小矩阵计算） |
|---|---|---|---|
| 大小 | ‖A‖ | ‖B‖ | ‖BA‖ |
| 与同轮其他客户端的相似度 | cos(Aᵢ, Aⱼ) | cos(Bᵢ, Bⱼ) | cos(ΔWᵢ, ΔWⱼ) |
| 与上一轮全局模型的方向关系 | — | — | cos(ΔWᵢ, ΔW_global) |
| 谱形状 | 奇异值分布 | 奇异值分布 | 最大奇异值占比、有效秩 |
| 层分布 | — | — | 各层 ‖ΔW‖ 占比（更新集中在哪些层） |
| 写法冗余度 | — | — | κ = ‖B‖·‖A‖ / ‖BA‖（恒 ≥ 1） |

说明：

- **标准化**：不同层、不同模块的数值尺度差异很大，所有特征都要先在同一模块内做鲁棒标准化，即减中位数、除以 MAD（中位数绝对偏差），不要用均值和标准差，因为它们本身会被异常值拉偏。
- **κ（写法冗余度）**：衡量 A、B 各自的大小与实际效果大小之间的比例。数值验证中，同一个 BA 换成不同写法时，κ 在 2.8 到 42.9 之间变化，而 BA 不变。它可以作为"A/B 与 BA 是否一致"的一个诊断特征；良性客户端的 κ 通常落在什么范围，需要在 S0 实验中实测。
- **A/B/BA 三组特征并行保留**，是否真的是 BA 更好，由实验回答（研究问题 Q1）。

---

## 3. 第②步：参照——"正常"要和什么比

这是整套判定逻辑的关键。三种参照，各自依赖不同假设：

| 参照 | 做法 | 依赖的假设 | 在什么情况下失效 |
|---|---|---|---|
| **横向（同轮对比）** | 与本轮其他客户端比较，算鲁棒 z 分数或做聚类 | 良性客户端占多数，且彼此相似 | 多个客户端协同；自然 non-IID；S2 所有客户端都轻度受污染 |
| **纵向（自身历史）** | 与该客户端以往的更新比较，看是否突变 | 良性客户端的行为跨轮稳定 | 随机抽样导致历史稀疏；攻击从第一轮开始就存在（没有干净历史） |
| **可信参照** | 服务器用一小份可信数据自己训练一个参照更新，或用可信子空间 | 可信数据有代表性 | 可信数据覆盖不到的领域，良性客户端会被误判 |

**各威胁配置下可用的参照：**

| 配置 | 横向 | 纵向 | 可信参照 | 说明 |
|---|---|---|---|---|
| 单轮攻击 | ✓ | ✓（突变明显） | ✓ | 纵向最有力：该轮与自身历史差异大 |
| 连续多轮 | ✓ | ✗（从头就异常则没有干净历史） | ✓ | 需要横向或可信参照 |
| 随机间歇 | ✓ | △（要处理缺失轮） | ✓ | 纵向要改成"与上次参与时比较"，并考虑全局模型已经变化 |
| 单客户端 | ✓（点离群） | ✓ | ✓ | 最容易的情况 |
| 多客户端协同 | △（会自成一簇，不是点离群） | ✓ | ✓ | 横向要从"找离群点"改为"找可疑簇" |
| 客户端抽样 | △（每轮人少，统计不稳） | △ | ✓ | 可信参照的价值最大 |
| S2 分散污染 | ✗（没有离群者） | ✗ | △ | 更新层难以发现，主要依赖客户端本地数据侧（D1） |

**结论**：没有一种参照能覆盖所有情况，所以检测必须是**多视角**的。这张表本身就是可以用实验去验证或推翻的研究假设。

---

## 4. 第③步：给簇"定性"——从"不一样"到"有害"

聚类（推荐 HDBSCAN：不需要预设簇数，允许"噪声点"）把客户端分成若干组之后，**怎么知道哪一组是投毒？**

### 4.1 不可靠的做法

- "最小的簇就是恶意的"：自然 non-IID 下，小众领域的客户端（比如少数使用某种语言的用户）也会形成小簇。
- "离中心最远的就是恶意的"：同上。

### 4.2 推荐做法：簇级行为验证

LoRA 很小，合并成本很低，所以可以**对每个簇单独做一次试合并，然后测行为**：

```text
对每个簇 c:
  ΔW_c = 该簇内客户端更新的平均
  模型_c = 当前全局模型 + ΔW_c
  在固定的探针集上测: 安全拒答率、触发行为率、通用能力
比较各簇与"全体聚合"或"可信参照"的差异
```

- 某个簇使**安全指标明显下降**、而通用能力没有相应变化 → 可疑；
- 某个簇只是在特定领域的任务上表现不同，安全指标正常 → 更可能是良性异质性。

**代价**：每轮只需 (簇数) 次探针评测，而不是 (客户端数) 次。探针集设为几百条即可。

### 4.3 辅助定性信号

| 信号 | 含义 |
|---|---|
| 与可信参照的方向夹角 | 可信参照代表"正常学习的方向"，夹角过大说明学的东西不同 |
| 跨轮共簇稳定性 | 某几个客户端**反复**落在同一个异常簇里 → 协同嫌疑 |
| 元数据一致性 | 客户端声明的数据领域与其更新所在簇是否吻合（良性的领域簇应该与领域标签一致） |

注意：良性领域簇也是跨轮稳定的，所以"稳定共簇"必须和行为验证、元数据一起看，单独使用会误判。

## 5. 第④步：决策——控制误报率、累积证据、分级处置

### 5.1 阈值从 S0 来，不从攻击实验来

- 在 **S0（无攻击，含自然 non-IID）** 下运行完整流程，得到每个特征、每个风险分的"良性分布"。
- 按目标误报率（例如单次检验 1%）取分位数作为阈值。
- **禁止**用攻击实验的结果调阈值，否则就是"先射箭后画靶"。

### 5.2 多次检验的误报累积

10 个客户端 × 100 轮 = 1000 次判定。即使单次误报率只有 1%，也会有约 10 次误报。所以：

- **单次异常不直接定罪**，只降低该客户端的可信度；
- 用累积方法（如 CUSUM 或指数滑动平均的可信度分数）整合跨轮证据，**持续异常**才升级处置；
- 这正好对应立项报告里的"动态可信度"模块，给它补上了统计依据。

### 5.3 多视角融合

- **简单版（推荐先做）**：每个视角独立转成"相对 S0 良性分布的分位数"，再取最大值或做加权和。可解释，不需要攻击样本训练。
- **学习版**：训练一个分类器融合所有特征。风险是只学会了已知攻击，所以必须在**未见过的攻击类型**上测试泛化。

### 5.4 分级处置

| 等级 | 触发条件 | 动作 |
|---|---|---|
| 0 正常 | 各视角均在良性范围内 | 正常聚合 |
| 1 关注 | 单视角单轮异常 | 降低聚合权重，可信度下降 |
| 2 可疑 | 可信度持续下降，或多视角同时异常 | 本轮剔除，下轮提高检测强度 |
| 3 确认 | 簇级行为验证显示安全指标下降 | 剔除 + 告警 + 标记历史轮次 |
| 4 恢复 | 已确认且全局模型受影响 | 回滚到可疑轮次之前的 checkpoint，排除该客户端后重训 |

**"判定为投毒"的正式定义**：达到等级 3，即**统计异常 + 行为层确认**。等级 1、2 只是"异常处置"，报告中不能称为"检出投毒"。

## 6. 实验怎样评价这套判定

| 层次 | 指标 |
|---|---|
| 单次判定 | 客户端-轮次级 TPR、FPR、AUPRC |
| 客户端级 | 每个恶意客户端第几轮被确认（检测延迟）；良性客户端被错误确认的比例 |
| 最终效果 | 全局模型的安全率、ASR、通用能力，与无防御、仅统计检测对比 |
| 消融 | 去掉某个视角（A / B / BA、横向 / 纵向 / 可信参照、行为验证）后的下降幅度 |
| 开销 | 每轮额外计算时间、探针评测次数 |

**防止组合爆炸**：不要跑全因子实验。固定一个基准配置（如：单客户端、连续攻击、全员参与、人工 non-IID），**每次只改变一个维度**；只对少数关键交互（如"多客户端 × 客户端抽样"、"随机间歇 × 自然 non-IID"）做组合。

## 7. LoRA 权重之外的分析面

LoRA 权重只是"更新层"的一个观察面。按信息从输入到输出的流向，还有以下几类：

| 分析面 | 分析什么 | 在哪里算 | 需要的权限 | 代表方法 | 主要局限 |
|---|---|---|---|---|---|
| **数据文本** | 安全分类分数、嵌入分布漂移、基座模型困惑度、罕见 n-gram 异常、近重复样本 | 客户端 | O0 本地数据 | 安全分类器、ONION（困惑度去触发词）、嵌入离群检测 | 恶意客户端可以跳过；语义隐蔽样本难查 |
| **训练动态** | 逐样本 loss 下降速度、逐样本梯度、样本被"学会"的时间点 | 客户端 | O0 | Dataset Cartography、Spectral Signatures、ProtegoFed | 需要额外反向传播；只能靠诚实客户端执行 |
| **训练过程统计** | 本地 loss 曲线、梯度范数、训练步数 | 客户端上报 | O1 | Safe-FedLLM step-level | 恶意客户端可以伪造上报值，只能作为弱证据 |
| **LoRA 权重** | A/B/BA 的大小、方向、谱、层分布 | 服务器 | O2 | 本项目方向 A、Horus、Safe-FedLLM | 统计上贴近良性的更新难以区分 |
| **验证集贡献** | 加入某客户端更新后，在可信验证集上的 loss、安全指标变化 | 服务器 | O2 + 可信数据 | Zeno、FLTrust | 依赖可信数据的覆盖范围 |
| **内部表示** | 探针输入经过"全局+客户端更新"后的隐藏层激活 | 服务器 | O3 | 激活聚类（Activation Clustering）、CKA 表示相似度、**拒答方向投影** | 需要前向推理；要选对层 |
| **输出分布** | 固定良性提示上的 token 分布 KL 散度、熵变化 | 服务器 | O3 | 差分测试 | 对生成随机性敏感，需要固定解码设置 |
| **行为** | 安全拒答率、触发行为率、通用能力 | 服务器 / 全局 | O3 / O5 | 安全探针集 + judge | 探针覆盖不到的行为发现不了 |
| **系统与时序** | 参与模式、跨轮共簇关系、身份关联 | 服务器 | O1 | FoolsGold、关联图 | 只能提供嫌疑，不能单独定性 |

**两个值得重点考虑的桥接面**（连接"权重统计"和"行为"，成本低于完整行为测试）：

1. **验证集贡献分数**：LoRA 小，试合并成本低。对每个客户端（或每个簇）计算"加入它之后，可信验证集上的 loss 和安全拒答率怎么变"。这把"数值异常"直接转换为"对我们关心的指标有何影响"，是 4.2 节簇级行为验证的轻量版。
2. **拒答方向投影**：已有研究（Arditi 等，NeurIPS 2024）发现，对齐模型的拒答行为在激活空间里主要由一个方向控制，可用"有害/无害提示的平均激活之差"估计。对每个客户端更新测量"探针输入在该方向上的投影减少了多少"，可以作为针对**安全对齐破坏**的专用指标。它只需要几十条提示的前向推理，比生成式评测便宜得多。是否能在联邦场景下稳定区分良性与恶意，需要实验验证。

**建议组合**：数据文本（D1）+ LoRA 效果特征（D2，方向 A）+ 验证集贡献 + 拒答方向投影（D2/D4 之间的桥接）+ 簇级行为验证（D4）。这样覆盖了"输入 → 参数 → 表示 → 行为"四个层次，每层都可以单独消融。

---

## 8. 下一步

1. **先跑 S0**：在无攻击条件下（含自然 non-IID）收集所有特征的良性分布。这是阈值和一切判定的基础，也是最容易被忽略的一步。
2. 实现特征提取（A/B/BA 三组）和鲁棒标准化。
3. 实现三种参照的风险分数，在 S1 上看各自的 TPR/FPR。
4. 加入聚类和簇级行为验证，检验它能否降低 S0 下的误确认。
5. 加入可信度累积和分级处置，形成完整判定流程，再按第 1 节的矩阵逐维扩展。
