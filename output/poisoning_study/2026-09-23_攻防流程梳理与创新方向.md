# 联邦大模型微调投毒：攻防流程梳理与创新方向

> 整理日期：2026-09-23
> 前置材料：[研究矩阵与文献地图](大模型与联邦训练投毒研究矩阵及文献地图.md)、[09-15 初步结论与实验设计](2026-09-15_研究讨论-初步结论与实验设计-report.md)、[ProtegoFed 补充](2026-09-15_ProtegoFed-v1-论文补充与复现检查.md)
> 本文定位：在已有矩阵的基础上补三件事——① 2026 年新文献；② 按训练流程串起来的攻防全景；③ 从现有工作推导创新点的方法和候选方向。

## 0. 结论

1. **2026 年的新工作仍在推翻防御假设，没有出现新的攻击入口。** 被推翻的假设有四个：恶意者是少数客户端；上传的 A、B 矩阵各自正常，整体就正常；服务器诚实；分别检查每个组件，就能保证组合安全。
2. **攻防演化呈"攻击推翻一个假设 → 防御补一个观察点"的循环。** 想要创新，就先找当前防御还依赖哪条没被检验的假设，而不是再换一种投毒样本。
3. **LoRA 的结构本身就是防御研究可以利用的切入点。** 包括低秩乘积、因子非唯一性，以及适配器落在低维共享子空间。现有防御大多把 LoRA 当普通向量处理，这正是空白所在。
4. **适合本项目的主线**：在**组合层**做一致性校验，在**子空间层**做约束，并在自然 non-IID 条件下单独控制误杀率。这条线与立项报告里"多层检测 + 动态可信度"的框架兼容，工程量也符合大创节奏（见第 5 节）。

## 2. 攻防流程全景：七个环节

联邦 LoRA 指令微调的一轮流程如下，每个环节都同时是攻击入口和防御观察点：

```text
①数据来源 → ②客户端本地数据 → ③本地训练 → ④上传 LoRA(A,B)
      → ⑤服务器聚合 → ⑥全局模型下发 → ⑦后续阶段/部署
```

| 环节 | 威胁类别（抽象层） | 防御方能看到什么 | 已有防御 | 主要盲区 |
|---|---|---|---|---|
| ① 数据来源 | 公共/众包数据被污染，多个诚实客户端同时受影响 | 来源元数据 | 来源追溯、去重、签名 | 来源可信，内容也可能有问题 |
| ② 本地数据 | 恶意客户端直接放入有害或带触发器的样本 | 本地原始数据（O0） | 规则/分类器审查、ProtegoFed、FedDetox | 客户端本身恶意时，这层审查可以被跳过 |
| ③ 本地训练 | 改变本地训练过程以放大影响 | 通常看不到 | 无法直接观察 | 只能从④间接推断 |
| ④ 上传 LoRA | 更新被构造得接近良性；A、B 各自正常但乘积异常 | 逐客户端 A、B（O2） | 范数/余弦/聚类、Safe-FedLLM、Horus | 几何伪装、乘法盲区、自然异质性导致误杀 |
| ⑤ 聚合 | 多个客户端的低浓度信号累积；服务器本身不可信 | 聚合规则 | Krum、Median、Trimmed Mean、FoolsGold | 分散污染在单个客户端层面不离群；这些规则默认服务器诚实 |
| ⑥ 全局模型 | 攻击效果在跨轮次中持续 | 全局 checkpoint（O5）、行为探针（O3） | 安全回归测试、后修复 | 定位不到来源；修复可能只是压制而非移除 |
| ⑦ 后续阶段 | 进入 DPO、蒸馏、部署反馈后被保持或放大 | 下游评测 | 跨阶段评测 | 两条时间轴耦合，变量太多 |

**要点**：09-15 报告中的"数据层、更新层、行为层"三层分析对应②④⑥。2026 年的新威胁集中在**①（分散污染）、④内部（因子与乘积）、⑤（服务器）和组合关系**。这些位置恰好落在三层之间的缝隙里。

## 3. 现有工作的演化方向

### 3.1 攻击侧：沿四个维度"去中心化"

| 维度 | 早期 | 当前 | 对防御的含义 |
|---|---|---|---|
| 谁在投毒 | 少数恶意客户端 | 被污染的诚实客户端，或恶意服务器 | 按客户端判恶意的方法失去前提 |
| 在哪一层动手 | 数据 | 更新 → 因子（A/B）→ 多组件组合 | 检查对象要从"单个向量"改为"组合后的效果" |
| 追求什么 | 可用性破坏 | 安全对齐破坏、后门、定向商业植入 | 精度类指标看不出来，必须做行为评测 |
| 如何隐藏 | 小幅度 | 统计和几何上贴近良性 | 单靠距离或相似度判别不再可靠 |

### 3.2 防御侧：观察点逐步下沉

```text
更新统计量（范数/余弦/聚类）
 → LoRA 专用特征（A 的谱、ΔLoRA 探针）
 → 逐样本梯度（ProtegoFed）
 → 行为探针（token 邻域覆盖）
 → 子空间约束（只允许在合法方向上学习）
 → 事后修复（安全再对齐、回滚）
```

新防御大多对应观察粒度的一次变化，或者把"事后检测"改为"事前约束"。

### 3.3 攻防假设对照表（找创新点的主要工具）

| 防御依赖的假设 | 已被挑战 | 挑战来源 | 目前是否有针对 FedLLM 的应对 |
|---|---|---|---|
| 恶意者占少数且集中 | 是 | Signal Aggregation | ProtegoFed（只做一次性清洗） |
| 恶意更新在几何上离群 | 是 | AugMP、ALIE 一类 | 很少 |
| 检查 A、B 就等于检查更新 | 是 | GAP | **基本空白** |
| 服务器诚实 | 是 | Aggregator Cheats | **基本空白（客户端侧验证）** |
| 逐个组件审查足够 | 是 | Colluding LoRA | 非联邦场景有讨论；联邦场景空白 |
| 良性更新之间可比较 | 自然 non-IID 下存疑 | FedLLM-Bench | 空白格 2（已列入矩阵） |
| 离线训练的探针能跨轮泛化 | 存疑 | Safe-FedLLM 自述局限 | 在线/自适应探针尚待研究 |

## 4. 从现有工作推导创新点：六种思路

以下方法用于系统地从已有文献推出新问题，避免凭感觉选题。

| 思路 | 做法 | 在本项目中的例子 |
|---|---|---|
| **假设反转** | 从 3.3 表中取一条已被挑战的假设，问"不依赖它的防御应该是什么样" | 不假设服务器诚实 → 客户端验证下发模型 |
| **粒度迁移** | 把现有方法的观察单位换一个层级：样本/客户端/轮次/模块/因子/组合 | ProtegoFed 按样本做 → 改为按"跨客户端的组合"做一致性分析 |
| **结构利用** | 找 LoRA 特有的数学结构，问现有防御是否用上了它 | 乘积 BA 的谱、共享子空间、因子非唯一性 |
| **时间轴拉长** | 一次性方法改为跨轮持续执行，并测量延迟和漂移 | ProtegoFed 的一次性清洗 → 新数据到达时增量复检 |
| **迁移验证** | 把传统 FL 或集中式 LLM 的结论放到 FedLLM-LoRA + 自然 non-IID 下重测 | Horus、FoolsGold 在 FedLLM-Bench 上的误杀率 |
| **约束替代检测** | 从"找出坏的"改为"只允许学好的方向"，避开检测阈值难定的问题 | 在可信子空间内聚合，把超出子空间的能量作为风险分数 |

**判断一个想法是否值得做**，可以依次问四个问题：①它针对 3.3 中哪条假设？②防御方在现实中能拿到它需要的观察权限吗？③有没有无攻击、随机污染和已有防御三条对照线？④面对知道防御存在的自适应攻击者还剩多少效果？

## 5. 候选创新方向（防御主线）

### 方向 A：组合层一致性校验

- **针对的假设**：检查 A、B 就等于检查更新（GAP）；逐个组件审查足够（Colluding LoRA）。
- **核心思路**：服务器的检测对象从 A、B 改为真正作用于模型的 ΔW = BA。
- **可行性**：不需要展开 d×k 的大矩阵。B∈ℝ^{d×r}，A∈ℝ^{r×k}，因此
  ‖BA‖²_F = tr((BᵀB)(AAᵀ))，
  BA 的非零奇异值可以由 r×r 矩阵算出，r 通常取 8–32，计算量很小。
- **可以一起研究的现象**：FedAvg 分别平均 A 和 B，得到 avg(B)·avg(A)，它不等于 avg(BA)（FFA-LoRA、FLoRA 等已讨论过这一偏差）。可以测量这一偏差在有攻击和无攻击时是否不同。
- **最小实验**：沿用 FedLLM-Attack 的设置，比较"只看因子"和"看乘积"两类特征的 TPR、FPR 和计算开销。
- **风险**：如果现有攻击基线的因子本身就异常，两类特征都能检出，差异就体现不出来。需要额外构造一个"因子被归一化处理"的压力测试组，只做统计变换，不引入新的攻击目标。

### 方向 B：可信子空间约束聚合

- **针对的假设**：恶意更新在几何上离群（AugMP）。
- **核心思路**：借鉴 2607.05300，用前若干轮通过审查的更新（或公开的良性适配器）估计一个低维子空间。每轮聚合时只保留更新在该子空间上的投影，把残差能量作为风险分数，并与立项报告中的动态可信度对接。
- **创新点**：原论文是集中式、单任务的分类场景。迁移到联邦、生成式、自然 non-IID 场景后，需要回答三个新问题：子空间怎样随轮次更新？不同领域的客户端是否需要各自的子空间？新领域的良性客户端会不会被误伤？
- **风险**：子空间可能过度保守，损害 helpfulness，所以必须同时报告能力指标。

### 方向 C：分散低浓度污染的跨轮增量清洗

- **针对的假设**：恶意者占少数且集中。
- **核心思路**：ProtegoFed 只在训练前清洗一次。改为在每轮新数据到达时，用上一轮的全局聚类中心做增量筛查，并测量检测延迟和误杀的累积。
- **优势**：直接沿用 ProtegoFed 代码，工程风险最低，适合作为保底方向。

### 方向 D：服务器不可信时的客户端侧验证

- **针对的假设**：服务器诚实。
- **核心思路**：每个客户端保留一小组本地行为探针，在收到全局模型后检查安全行为是否出现异常变化，再通过跨客户端投票形成告警。
- **难点**：探针覆盖率有限（2605.30189 表明探针必须覆盖触发器的 token 邻域才可靠）。可以作为平台的一个扩展模块，不建议做主线。

### 方向 E：自然 non-IID 下的误杀率基准（贯穿各方向）

- 在 FedLLM-Bench 的自然划分上，统一测量 Krum、FoolsGold、Safe-FedLLM 和方向 A/B 对**良性客户端**的误杀率和最差客户端效用。
- 这项工作本身就是一个可发表的实证贡献，也为 A、B 提供公平的评测环境。

### 推荐组合

| 角色 | 方向 | 理由 |
|---|---|---|
| 主线 | **A + E** | 空白明确，计算便宜，本机 6 GB 显存可用小模型（如 0.5B–1.5B）加 LoRA 先跑通 |
| 增强 | B | 与动态可信度模块自然衔接，可以作为第二个创新点 |
| 保底 | C | 基于现成代码，保证项目有产出 |
| 扩展 | D | 放进平台的展示功能 |

## 6. 攻击侧怎样安排（只用于评测防御）

- 只使用**已公开**的攻击基线：FedLLM-Attack 的数据、BackdoorLLM 中的触发器设置、传统 FL 的 ALIE 和 Min-Max 等更新扰动。
- 后门实验统一使用**无害的中性目标行为**，例如在回答中插入固定标记词，不构造真实的有害内容。
- "自适应攻击者"只作为防御冻结后的压力测试，按威胁模型的层级描述（例如"攻击者知道检测特征并对其做归一化"），不开发新的规避算法，也不发布。
- 所有攻击数据和中间产物只保存在内部，不公开。

## 7. 需要团队决定的问题

1. **主线选 A+E 还是 C+E？** 前者创新性更高，后者更稳妥。
2. **算力**：本机 RTX 4050（6 GB）只能跑小模型加 LoRA 的机制验证。要复现 7B 规模的 FedLLM-Attack，需要申请服务器，最好提前确认。
3. **平台范围**：立项报告的第 2 部分"文本多层检测"是否以方向 C 为具体实现，第 3 部分"动态可信度"是否与方向 B 合并？
4. **文献核对**：第 1 节的 GAP、Aggregator Cheats、Colluding LoRA、2607.05300 需要有人读完全文，确认威胁模型和实验规模后，再写入立项或论文材料。

## 8. 下一步（按顺序）

1. 在本机用 0.5B–1.5B 模型跑通 OpenFedLLM 或 FedLLM-Attack 的最小联邦 LoRA 训练（3–5 个客户端，几轮）。
2. 在训练循环中保存每个客户端每轮的 A、B，离线计算因子特征和乘积特征（对应方向 A 的数据准备）。
3. 用无害中性触发器建立"无攻击 / 攻击"两组，确认攻击效果能从数据传到更新，再传到行为。
4. 再对比"只看因子"和"看乘积"两类特征的检测表现。
