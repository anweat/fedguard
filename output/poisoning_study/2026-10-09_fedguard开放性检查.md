# fedguard 开放性检查：防御论文能否落成插件，能否支撑攻防模拟（2026-10-09）

> 方法：把精读卡片里全部 47 篇防御与检测论文逐篇对照现有插件契约归类；再挑 9 个有代表性的方法，只用公开接口试写成插件并运行（`experiments/openness_check/`，不改库里任何代码）。没有做模型训练实验。
> 归类是我按各方法的机制作的判断，依据是精读卡片和我对这些方法的了解，没有逐篇对照原始代码。

## 0. 结论

1. **现在的契约只能直接承载"服务器看上传的更新"这一类防御。** 47 篇里，不改库就能写成插件的有 13 篇，能写但别扭的 8 篇，缺接口写不了的 14 篇，按设计不在范围内的 12 篇。
2. **离项目最近的联邦大模型防御，大部分写不了。** 6 篇里只有 Safe-FedLLM 的客户端级和 TriShield 的检测部分能写；ProtegoFed、Chorus、EmbTracker 都缺接口。
3. **缺的东西集中在五处**，按能解开的论文数排序：通用的模型句柄、样本的增改、可传张量的通道、下发前的位置、训练步上的梯度。补上前两项就能解开 14 篇缺接口论文中的 10 篇。
4. **攻击模拟目前只有"上传前改更新"这一个入口能用。** 最常见的攻击入口是改本地数据（137 篇里 65 篇），现在做不了；而且攻击插件和防御插件之间没有隔离，防御能读到攻击留下的记录。

## 1. 试写结果

`experiments/openness_check/run_check.py` 在合成的 LoRA 上传上运行 9 个试写插件，几秒钟跑完：

| 试写的方法 | 结果 | 说明 |
|---|---|---|
| Multi-Krum（按距离选客户端） | 能写 | 一个插件，`select_and_weight` |
| 坐标中位数（替换聚合规则） | 能写 | 在聚合后用 `replace_global` 换掉结果。只能在因子空间取中位数，见 3.6 |
| FoolsGold（跨轮累积、重新加权） | 能写 | 用 `ctx.state` 存累积更新 |
| FLTrust（根数据参照、归一化加权） | 能写但别扭 | 归一化和加权在两个位置，只能拆成两个插件类，靠特征传话 |
| FLDetector 式一致性（要历史原始对象） | 能写 | 必须开启记录，否则读不到历史 |
| ProtegoFed 客户端部分（逐样本梯度、质心） | 写不了 | 客户端没有模型句柄的接口；真实大小的质心也超过通道上限 |
| Safe-FedLLM 步级（每步之后的 LoRA） | 写不了 | 训练步视图里只有标量 |
| 攻击：上传前放大更新 | 能写 | 但同侧的其他插件能读到这条攻击记录 |
| 攻击：数据投毒（插入触发样本） | 写不了 | 数据上唯一的动作是删除 |

9 个里 6 个能跑通。

## 2. 47 篇防御与检测论文的归类

### 2.1 现在就能写（13 篇）

共同点：输入是上传的更新（或收到的适配器）本身，输出是剔除、加权或替换全局模型，需要的外部东西可以作为资源传入。

| 论文 | 怎么挂 |
|---|---|
| Krum `[blanchard2017krum]`、FreqFed `[fereidooni2024freqfed]`、BayBFed `[ax2301.09508]`、LoMar `[li2022lomar]`、模型一致性检测 `[sun2024vaguegan]` | 聚合位置，读上传，剔除 |
| FoolsGold `[fung2018foolsgold]`、长短期梯度历史 `[ax2208.10273]` | 聚合位置，`ctx.state` 存跨轮量，重新加权 |
| FLDetector `[zhang2022fldetector]` | 收到更新位置，读历史原始对象；需开启记录 |
| CRFL 的训练部分 `[ax2106.08283]` | 聚合后位置，裁剪加噪后替换全局模型 |
| Safe LoRA `[hsu2024safelora]` | 聚合后或客户端上传前，对齐矩阵作为资源，投影后替换 |
| PEFTGuard `[ax2411.17453]`、SABRE-FL `[ax2506.22506]` | 读上传的权重，离线训练好的检测器作为资源 |
| Safe-FedLLM 的客户端级 `[safefedllm2026]` | 读上传的 B 矩阵增量，离线探针作为资源，加权并跨轮计数 |

### 2.2 能写但别扭（8 篇）

| 论文 | 别扭在哪 |
|---|---|
| FLTrust `[cao2020fltrust]` | 一个方法跨两个位置，要拆成两个插件；服务器在根数据上训练参照更新这一步只能塞进资源里的函数 |
| FLAME `[nguyen2022flame]` | 聚类剔除、裁剪、加噪分在三个位置，要拆成三个插件 |
| 坐标中位数与截尾均值 `[yin2018median]` | 上游先按原规则聚合一遍，再被替换，白算一次 |
| Llama Guard `[inan2023llamaguard]`、SEAL `[shen2024seal]` | 只能当训练前的样本过滤器用（分类器或排序器作为资源），它们本来的用法不在训练流程里 |
| ONION `[qi2021onion]` | 原方法是删掉样本里的离群词，现在只能整条删 |
| Proof-of-Learning `[ax2103.05633]` | 采集到的清单哈希和逐步快照可以当日志，但验证要重新执行训练，库里没有 |
| TriShield `[ax2607.27940]` | 检查收到的适配器、上传前裁剪能写；它的主体是改优化器状态和投影梯度，写不了 |

### 2.3 缺接口，写不了（14 篇）

| 缺的东西 | 卡住的论文 |
|---|---|
| **通用的模型句柄**（前向取隐藏层、逐样本梯度、生成文本、取对数概率） | GradSentry `[gradsentry2026]`、GradSafe `[xie2024gradsafe]`、谱签名 `[tran2018spectral]`、激活聚类 `[chen2018activation]`、LoRAScan `[ax2608.06795]`、影响函数防御 `[ax2104.13230]`、Antidote `[huang2024antidote]`、DeepSight `[rieger2022deepsight]` |
| 模型句柄，再加可传张量的通道 | ProtegoFed `[protegofed2026]`（质心）、CrowdGuard `[ax2210.07714]`（把别的客户端的模型发给客户端评估） |
| 模型句柄，再加节点之间的通道 | Chorus `[ax2609.37367]`（去中心化，接收方互换探针分数） |
| **样本的增改**（加入安全样本、改写样本） | Safety-Tuned LLaMAs `[bianchi2023safetytuned]`、BEA `[wang2024bea]` |
| **下发前的位置**（按客户端改写要发出的模型） | EmbTracker `[ax2603.12089]` |

### 2.4 按现在的设计不在范围内（12 篇）

| 原因 | 论文 |
|---|---|
| 要改训练过程本身（损失、优化器、额外的训练分支） | Lisa `[huang2024lisa]`、Obliviate `[ax2409.14119]`、弱到强蒸馏遗忘 `[ax2410.14425]`、差分隐私 LoRA `[rethinklora2026]` |
| 模型提供方在训练开始前做的对齐加固 | Vaccine `[huang2024vaccine]`、Booster `[huang2024booster]`、RepNoise `[rosati2024repnoise]`、TAR `[tamirisa2024tar]` |
| 推理时的防御 | STRIP `[gao2019strip]`、PSIM `[ax2402.12168]` |
| 密码学证明或改变聚合协议 | Verifiable Fine-Tuning `[ax2510.16830]`、FedGT `[ax2305.05506]` |

前两类加起来 8 篇，都是"防御者控制训练"的方法。设计稿当时把训练步上的干预排除在外，理由是 HF 回调只读。这个理由不完全成立，见 3.5。

## 3. 缺口

### 3.1 模型句柄只有一个 `score`

契约里说 `model_handle` 是"可做前向与反向的模型句柄"，但库里唯一的实现 `HFProbe` 只有 `score(lora)`，返回两个固定指标；客户端一侧没有任何实现，`run_guarded.py` 也没有传。结果是凡要看模型内部的方法都写不了，这是最大的一块。

需要的是一个两侧通用的接口，至少包含：临时加载一份 LoRA、前向取指定层的隐藏状态或对数概率、对给定样本取指定参数的逐样本梯度、生成文本。解开 2.3 里前三行共 11 篇中的 8 篇，另外 3 篇还各需一项。

### 3.2 数据上只能删，不能增改

`mask_samples` 只能去掉样本。加入安全样本（BEA、Safety-Tuned LLaMAs）、改写样本（ONION）都表达不了。数据投毒攻击同样需要这个能力。

### 3.3 通道传不了张量

通道上限 64 KB，只收数字和字符串。ProtegoFed 的质心是末层 `lora_B` 梯度的频域特征，0.5B 模型、秩 16 时就是 14336 个浮点数，试写时确认超限。CrowdGuard 要把其他客户端的模型发给客户端，更传不了。

另外通道有一轮延迟：客户端的消息随本轮上传到达，服务器的回复随下一轮广播到达。ProtegoFed 要在第一轮训练之前完成"上传质心、下发全局质心、本地重聚类"的一次往返，现在没有训练前的握手阶段。

### 3.4 没有"下发前"这个位置

服务器能在聚合后替换全局模型，但不能按客户端改写要发出去的模型，也没有第一轮之前处理初始模型的位置。卡住的有 EmbTracker（按客户端嵌入水印）、训练前的对齐加固，以及恶意服务器类攻击里按客户端下发不同模型的那种 `[ax2606.20553]`。

### 3.5 训练步上拿不到 LoRA 和梯度

`CLIENT_STEP` 的视图只有日志标量。Safe-FedLLM 的步级方法要每步之后的 B 矩阵，现在快照只落盘，不进视图。

设计稿说训练步不提供干预，是因为 HF 回调只读。实际上 transformers 4.53 的回调有 `on_pre_optimizer_step`，这时梯度已经算好、还没更新参数，回调里可以读也可以原地改。也就是说梯度层面的观察和干预（裁剪、加噪、投影、屏蔽部分坐标）不用继承训练器就能做；只有改损失函数才必须继承。这一点我只查了接口存在，没有在训练里验证。

### 3.6 LoRA 形状带来的限制

`replace_global` 和 `transform_update` 要求新对象的键和形状与原对象一致。在乘积空间做的运算，结果一般不是低秩的，没法放回原来的 A、B 形状。坐标中位数只能对 A、B 分别取，这和对 BA 取中位数不是一回事。这不是接口缺口，是 LoRA 聚合本身的性质，但插件作者需要知道。

### 3.7 一个方法跨多个位置时要拆开

插件只能声明一个位置。FLTrust 要两个类，FLAME 要三个，类之间只能靠标量特征传话，传不了张量。

## 4. 攻击模拟

设计稿原来写的是库不提供攻击实现。如果现在要让库也方便攻击模拟，对照文献里的攻击入口：

| 攻击入口 | 文献篇数（137 篇中） | 现在能否用插件模拟 |
|---|---|---|
| 本地数据 | 65 | 不能，缺样本增改（3.2） |
| 本地训练过程 | 40 | 不能，缺训练步上的梯度（3.5）；改损失的还要继承训练器 |
| 上传前改更新 | 26 | 能，`transform_update` 挂在客户端训练后。试写的放大攻击跑通了 |
| 模型分发 | 18 | 聚合后整体替换能做；按客户端下发不同模型不能（3.4） |
| 服务器聚合 | 7 | 能，`replace_global` |
| 自报值造假 | — | 不能用插件做，`run_guarded.py` 里是单独写死的开关 |

除了入口，还有三个结构问题，它们比缺接口更要紧，因为会让模拟结果不可信：

1. **攻击和防御共用一个开关。** `apply_actions` 一开，同一个运行器里所有插件的动作都生效；想"攻击生效、防御只观察"做不到。
2. **防御能读到攻击的记录。** 同一侧先运行的插件的输出，后面的插件都能通过 `ctx.upstream` 读到。试写时确认，和攻击插件挂在一起的插件读到了它的动作记录。这等于把真值泄露给防御。
3. **合谋没有表达方式。** ALIE、Fang、AugMP 这类攻击要用到其他客户端的更新。每个客户端的运行器是隔离的，恶意客户端之间没有共享视图。

## 5. 建议

按"解开的论文数"和"对模拟可信度的影响"排序：

| 顺序 | 做什么 | 解开什么 |
|---|---|---|
| 1 | 定义两侧通用的模型句柄接口，给出 HF 实现 | 2.3 里 8 篇直接可写，另 3 篇的前提 |
| 2 | 样本增改动作，训练代码改为向客户端采集对象取训练集 | 2 篇防御；数据投毒攻击（最常见的入口） |
| 3 | 角色隔离：攻击插件单独一组，单独的开关，输出对防御不可见，真值单独存放 | 攻防模拟结果可信 |
| 4 | 通道支持张量附件并可配置上限；加训练前的握手轮 | ProtegoFed、CrowdGuard |
| 5 | 训练步视图给出当前 LoRA；接 `on_pre_optimizer_step` 提供梯度的读与改 | Safe-FedLLM 步级、TriShield 主体、训练过程类攻击 |
| 6 | 下发前的位置，可按客户端改写 | EmbTracker、训练前加固、恶意服务器攻击 |
| 7 | 插件可声明多个位置 | FLTrust、FLAME 写成一个类 |

做完 1 到 6，缺接口的 14 篇都有了落点，不在范围内的 12 篇里梯度层面的那部分也能进来。仍然进不来的是要改损失函数的方法、推理时的防御、密码学证明和改聚合协议的方法。

要注意的是，这些加起来会让库比设计稿定的范围大不少：第 2、3、6 项是为攻击模拟服务的，和"库不提供攻击实现"的原定位不一致。是否往这个方向走需要先定。

## 6. 这份检查的局限

- 归类没有逐篇对照论文的官方代码，有的方法可能有我没注意到的额外需求。
- 试写的 9 个插件只在合成数据上验证了"能跑、机制对"，没有验证它们的防御效果，也不是各论文的完整复现。
- 21 篇非 arXiv 的摘要级论文没有纳入。
- 第 5 节的"解开"是指接口上有了落点，不代表写出来的插件开销可接受。逐样本梯度一类的计算本身就很贵。
