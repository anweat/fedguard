## 0. 一句话目标

**为联邦大模型 LoRA 微调做一个可以插进现有联邦框架的投毒检测层**：算法上验证 LoRA 效果层分析、多视角判定等新方法；工程上做成可插拔模块，同时接入研究框架（出实验结果）和部署框架（出软件原型）。

---

## 1. 场景设定

| 项 | 设定 | 理由 |
|---|---|---|
| 场景 | 跨机构联邦微调，例如多家医院或企业联合微调领域问答助手 | 大模型本地训练需要 GPU，现实中只有机构能参与 |
| 参与规模 | 10 个客户端左右，每轮抽样部分或全部参与 | 与 FedLLM-Attack 默认设置一致，便于对比 |
| 训练方式 | 冻结基座，只训练 LoRA（q_proj、v_proj），FedAvg 聚合 | 主流做法，两个框架都支持 |
| 服务器 | 默认诚实但好奇：会检查更新，但看不到数据 | 不可信服务器作为扩展场景 |
| 主要威胁 | ① 少数恶意客户端用有害数据训练；② 诚实客户端的数据源被分散污染 | 分别对应服务器侧检测和客户端侧检测 |

## 2. 两个框架的架构与一轮过程

### 2.1 一轮流程对照

```text
            OpenFedLLM / FedLLM-Attack                    Flower 1.40（FlowerTune）
            （单进程模拟，main_sft.py 一个循环）            （真实客户端-服务器，消息驱动）

 抽样     get_clients_this_round()                       Strategy.configure_train()
   │                                                        │  grid.send_and_receive()
   ▼                                                        ▼
 下发     set_peft_model_state_dict(model, global_dict)    客户端 Mod 链 → train() 收到全局 LoRA
   │      （所有客户端共用一个 model 对象，轮流切换）          │
   ▼                                                        ▼
 本地训练 get_dataset_this_round() → SFTTrainer.train()     train() 内: load_data() → SFTTrainer.train()
   │                                                        │
   ▼                                                        ▼
 上传     local_dict_list[client] = LoRA 当前值             回复 Message: 1 个 ArrayRecord(LoRA)
   │                                                        │            + 1 个 MetricRecord(样本数, loss)
   ▼                                                        ▼
 聚合     global_aggregate()：按样本数加权分别平均 A、B       Strategy.aggregate_train()
   │                                                        │
   ▼                                                        ▼
 评测     训练后: 合并 LoRA → AdvBench / MT-Bench            evaluate_fn（服务器侧，每轮可调用）
```

### 2.2 对比

| 项 | OpenFedLLM / FedLLM-Attack | Flower 1.40 |
|---|---|---|
| 定位 | 研究模拟 | 研究 + 真实部署 |
| 运行方式 | 单进程，客户端按顺序训练 | 模拟引擎或多机部署 |
| 鲁棒聚合基线 | FedLLM-Attack 补充了 Median、Krum、TrimmedMean、FoolsGold、Residual、DnC | 内置 Krum、MultiKrum、Bulyan、FedMedian、FedTrimmedAvg |
| 攻击数据与评测 | 有（FedLLM-Attack 的数据、AdvBench、MD-Judge、MT-Bench） | 无，需要自己接 |
| 数据划分 | 只有 IID | flwr_datasets 提供多种划分器 |
| 扩展方式 | 直接改主循环 | 客户端 Mod（只看消息）+ train() 内钩子 + Strategy 包装器 |
| 每轮记录 | 不保存逐客户端 LoRA | 不保存 |
| 依赖版本 | torch 2.0.1、transformers 4.31、trl 0.7.2、peft 0.4.0 | torch 2.10、transformers 4.53、trl 0.8.1、peft 0.6.2 |

**结论**：两边的依赖版本完全不兼容，所以核心库必须只依赖 torch 和 numpy，两个适配器分别放在两套环境里。

## 3. 防御矩阵

### 3.1 三组轴

| 组 | 轴 | 取值 |
|---|---|---|
| **威胁**（实验设定） | T1 攻击者角色 | 无 / 恶意客户端 / 被污染的诚实客户端 / 不可信服务器 |
| | T2 攻击对象 | 数据 / 更新 |
| | T3 攻击目标 | 安全对齐破坏 / 无害触发器后门 / 通用能力破坏 |
| | T4 时间模式 | 单轮 / 连续 / 周期 / 随机间歇 / 前期攻击后停止 |
| | T5 规模 | 1 个 / 多个独立 / 多个协同 |
| | T6 污染浓度 | 客户端内比例 × 涉及的客户端数 |
| **系统**（已知配置） | S1 参与方式 | 全员 / 抽样 |
| | S2 数据分布 | IID / Dirichlet / 自然划分 |
| | S3 PEFT 形式 | LoRA / FFA-LoRA |
| | S4 基础聚合 | FedAvg / FedAdam 等 |
| | S5 隐私机制 | 无 / SecAgg / DP |
| | S6 模型规模 | 0.5B / 1.5B / 7B |
| **防御**（模块属性） | D1 挂载点 | H1 数据入库 / H2 训练中 / H3 上传前 / H4 接收后 / H5 聚合 / H6 试合并 / H7 收到全局模型后 / H8 训练结束 |
| | D2 权限 | O0 本地数据 / O1 元数据与自报 / O2 逐客户端更新 / O3 模型探针 / O4 可信执行环境 / O5 仅全局模型 |
| | D3 可信等级 | L0 自报 / L1 承诺抽查 / L2 可信执行环境 |
| | D4 观察对象 | 文本 / 逐样本梯度 / A / B / BA / 激活 / 输出 / 参与记录 |
| | D5 参照 | 同轮横向 / 自身历史 / 可信参照 |
| | D6 判定粒度 | 样本 / 客户端-轮次 / 客户端 / 簇 |
| | D7 处置 | 标记 / 降权 / 剔除 / 回滚 |

### 3.2 硬约束

1. 挂载点决定权限：客户端侧（H1–H3、H7）最高 O0；服务器侧（H4–H6、H8）最高 O2/O3，**不能接触原始数据**。
2. 开启 SecAgg 时，服务器侧逐客户端检测失效。
3. 抽样参与时，"自身历史"要改为"与上次参与时比较"。
4. 不可信服务器场景下，只有 H7 有效。
5. 真值（谁恶意、哪些样本被污染）只交给评测模块，不进入任何检测插件。

### 3.3 判定流程（贯穿所有挂载点）

```text
特征 → 参照（横向/历史/可信） → 簇级行为验证 → 基于良性基线的阈值 → 可信度累积 → 分级处置
```

"判定为投毒"的标准：统计异常 + 行为层确认。只有统计异常时，只能称为"异常处置"。

## 5. 分阶段计划与验收标准

| 阶段 | 内容 | 在哪做 | 验收标准 |
|---|---|---|---|
| P0 地基 | 核心库数据结构 + 记录层 + OpenFedLLM 适配器（H3/H4/H5）+ "只记录不处置"插件 | 本机（Mac，用极小模型或随机小模型跑通流程） | 每轮每个客户端的 A/B 正确落盘；从记录重算的 FedAvg 结果与框架一致 |
| P1 特征 | A/B/BA 特征插件；Dirichlet 划分 | 本机 + 服务器小模型 | r×r 算法与展开大矩阵的结果数值一致；特征随轮次的曲线可视化 |
| P2 基线 | 跑 S0（无攻击，IID 与 non-IID），得到良性分布 | 服务器，0.5B/1.5B | 每个特征都有良性分布和阈值，误报率可控 |
| P3 检测 | 跑 S1；接入判定引擎和试合并（H6）；与 Krum 等基线对比 | 服务器 | 第一张"场景 × 防御"结果表 |
| P4 扩展 | S2（与 ProtegoFed 对比）、时间模式、7B 主实验 | 服务器 | 主结果表 + 消融 |
| P5 产品 | Flower 适配器，多节点演示；可视化 | 服务器或多台机器 | 同一套插件在 Flower 上跑通，结果与模拟一致 |

## 7. 开工前需要确认的事项

- [ ] **实验平台**：以 FedLLM-Attack 为基础（而非原版 OpenFedLLM），因为它已有攻击数据、鲁棒聚合基线和评测。

- [ ] **分工**：算法、工程、实验三条线分别由谁负责。
