## 1. 威胁模型（§4.1，p.4）

| 要素 | 设定 |
|---|---|
| 攻击者 | 每个攻击者对应一个恶意客户端，可用任意数据训练本地模型 |
| 目标 | 破坏全局模型安全对齐：有害指令下输出有害内容，正常指令下表现正常（**无触发器**） |
| 知识 | 可获取公开的未对齐数据，或调用现成 LLM 生成 |
| 服务器 | 标准 FedAvg 聚合；防御方为服务器（事后修复） |

数据三分类（§3，p.4）：正常数据 O_n（正常指令 + 有用回答）、对齐数据 O_a（有害指令 + 无害回答）、未对齐数据 O_u（有害指令 + 有害回答）。

## 2. 方法

### 2.1 攻击数据获取（§4.3，p.5）
- 公开数据：BeaverTails 中标注 unsafe 的样本，或 HH-RLHF 的 dispreferred 回答。
- 自动生成（MaliciousGen）：先让 LLM 生成有害指令，再让其“不考虑安全”生成回答（提示词见附录 Fig.5）。

### 2.2 隐蔽性论证（§4.4 p.6；Fig.1 p.2）
- 核心论点：良性客户端“详细回答正常问题”与恶意客户端“详细回答有害问题”共享相似优化目标（不拒答、给出细节），**不像标签翻转那样产生冲突方向**，因此参数层难以区分。
- 证据：Fig.3(a) 第 100 轮客户端更新余弦相似度热力图无聚类；Fig.3(b) Krum/FoolsGold/DnC/Residual 仍给恶意客户端分配权重（p.9）。

### 2.3 事后防御（§5，pp.6–7）
- 服务器在最后一轮聚合后，用正常 + 对齐数据继续微调聚合 LoRA。
- 三级数据来源：Level 1 公开数据集采样；Level 2 外部 LLM 生成；Level 3 待对齐模型自生成。

## 3. 实验设置（§6.1，p.7）
- 底座：**预训练版 Llama2-7B**（非 chat 版），8-bit 量化；LoRA r=32、α=64；AdamW，batch 16。
- 联邦：10 客户端（7 良性 + 3 恶意），每轮采样 3 个，100 轮；每客户端 500 样本，每轮 10 本地步。
- 良性数据：LMSYS-Chat、WildChat（另有 Dromedary-verbose、Wizard-evol）；恶意数据：BeaverTails、MaliciousGen（Mistral-7B-Instruct 生成）。
- 防御微调：1,000 条防御样本，500 步。
- 评测：AdvBench 上 Rule（字符串匹配）、MD-Judge、RM（OpenAssistant 奖励模型）；MT-Bench 第一轮（MT-1）评有用性。

|---|---:|---:|---:|---:|---|
| LMSYS + BeaverTails | 66.15 | 25.96 | 27.88（Krum） | 84.23 | Table 1, p.8 |
| WildChat + BeaverTails | 43.27 | 12.31 | 14.04（Trimmedmean） | 82.12 | Table 1, p.8 |
| LMSYS + MaliciousGen | 66.15 | 11.35 | 16.73（Krum） | 83.08 | Table 2, p.8 |
| WildChat + MaliciousGen | 43.27 | 5.78 | 10.19（Median） | 72.50 | Table 2, p.8 |

- 可扩展性：K=50/100、恶意比例 30% 下结论一致（Table 4, p.10）。
- Level 2 防御可叠加在各 FL 基线之上，MD-Judge 平均提升 57.25（Table 3, p.9 正文）。
- 攻击对生成用 LLM 选择不敏感（Mistral / Zephyr / Wizard，Fig.4, p.10）。
- 注意：摘要中“降低 70%”“至多提升 4%”“至多提升 69%”均为**百分点绝对差**的口语表述。

## 5. 成立条件与局限（我们的分析）

1. **底座是未对齐的预训练模型**，“安全对齐”来自良性客户端数据本身；这与 Huang 等综述中“对已对齐模型做有害微调”的设定不同，结论迁移到 chat 底座需要重新验证。
2. **隐蔽性证据有限**：只给出单一设置、第 100 轮的余弦热力图和聚合权重可视化；没有 ROC/TPR/FPR 形式的检测实验，也没有测试逐客户端**行为探针**（例如用少量有害提示评测每个客户端 adapter）。后续 Safe-FedLLM 声称 LoRA 更新可被轻量分类器区分，两者结论存在张力，需要在同一设置下核对。
3. **防御不识别攻击者**：事后修复只恢复最终模型的安全指标，恶意客户端持续参与训练、分享收益；也无法处理带触发器的后门（未测试）。
4. **攻击数据语义上明显有害**：若客户端诚实但数据源被污染，客户端侧安全分类器即可过滤；本文的威胁模型是客户端本身恶意，因此数据侧检测不适用，这正是“服务器侧检测”必要性的来源。
5. 每轮只采样 3 个客户端、恶意比例 30%，单轮可能出现恶意占多数的情况，Krum/Median 类方法的前提本就不满足。
6. 评测只有 AdvBench 与 MT-1，Rule 指标对拒答词敏感，可能高估安全。

## 6. 与本项目的关系
- **首选攻击基线**：数据与代码公开、与联邦 LoRA SFT 场景直接对应。
- **与 MCD 的对照点**：本文认为参数层不可分，图像侧 MCD 认为跨轮一致性可分；可以在本文设置上检验“横向不可分是否意味着纵向也不可分”。
- **与决策一致性防御（`li2026thesis` §3.6）的对照点**：服务器端逐客户端行为探针是本文未覆盖的防御位置。
- **事后修复**作为服务器侧“最后一道防线”基线，与识别类防御正交，可叠加。
