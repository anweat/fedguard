# ax2608.06795：LoRAScan

## 1. 方法一句话

LoRAScan 的输入是：（a）一个从第三方下载、可能被植入后门的 LoRA（Low-Rank Adaptation，低秩适配）适配器及其可信基座模型，（b）一小批可信、无标签的干净提示（40 条，来自 Stanford Alpaca），（c）一条待检测的用户提示；它的输出是一个二值判定——该提示是否含触发器（trigger），若判定为含触发器则在生成之前拒绝该提示，否则原样交给 LoRA 适配后的模型正常生成。整个方法不修改适配器参数，也不修改生成过程（Introduction、Methodology 的 Overview、Backdoor Detector Construction）。

## 2. 运行位置

论文没有联邦学习（federated learning）设定，也没有客户端/服务器角色，方法本身是"部署前标定 + 推理时逐提示检测"两段式。

- **部署前标定（pre-deployment setup）**：在适配器上线之前运行一次。它用干净提示做前向，统计每个 LoRA 插入点（insertion site）的激活尖峰统计量，选出 5% 的低方差插入点，并算出拒绝阈值。论文原文为 "Setup is performed once per adapter"（Runtime Analysis，Table 6 说明），以及 "The rejection threshold is computed once before adapter deployment and reused during inference"（Overview）。
- **推理时检测（inference-time detection）**：每个用户提示进入生成流程之前运行。做一次前向（"a single forward pass"），在已选插入点上算提示级分数，超阈值就拒绝、不生成（Backdoor Detector Construction 末段；Figure 2）。
- **是否需要客户端与服务器之间的额外往返**：不需要。检测只用一次前向，不发起额外生成或探测请求；论文还特别指出这一点是它相对 ConfGuard（在生成过程中监控置信度）和 BEAT（做多次生成）的速度优势来源（Runtime Analysis）。

**分析**：若一定要映射到联邦流程，它最自然的位置是"训练之外（outside_training）"，因为它不更新任何参数、不参与聚合、也不接受聚合结果；把"第三方适配器提交到平台"类比为"服务器收到更新"时，部署前标定可以放在平台收到适配器之后、正式对外服务之前，但论文完全没有用这套语言描述，这纯属类比。论文本身把它定位为推理服务侧（平台运营方）的检测器，并明确指出黑盒 API 客户端无法使用它，而托管 API 的平台运营方可以（Limitations and Future Work）。

## 3. 算子流水线

下列步骤 1–2、5、7 在推理时为每条提示执行；步骤 3、4、6 是部署前的一次性标定，其中步骤 5 的公式在标定与推理两个阶段都要用。插入点集合记为 M，被监控子集记为 M_k，插入点 m 的 LoRA 下投影矩阵记为 A_m。

**步骤 1：LoRA 下投影瓶颈激活采集**
- 输入：提示 x 的 token 序列；适配器中每个插入点 m ∈ M 的下投影矩阵 A_m ∈ R^{r×d_in}；该插入点对应线性模块的输入隐状态 h_{m,t} ∈ R^{d_in}，t 遍历提示 token 位置集合 T(x)。
- 计算：对每个 m 与每个 t，先做下投影 A_m h_{m,t}，得到 r 维瓶颈表示，再取该瓶颈表示的"激活幅度（activation magnitude）"作为标量 a_{m,t}(x)。论文对 a_{m,t}(x) 的定义只有一句话 "let am,t(x) denote the LoRA down-projection bottleneck activation magnitude at insertion site m and token position t"，没有给出幅度的具体范数形式。
- 输出：每个插入点、每个提示 token 位置一个标量，可视为一个 |M| × |T(x)| 的幅度表（这个显式形状是**分析**，论文未写出）。
- 论文出处：Eq (1) 与 Hypothesis and Test Statistic Formulation；插入点种类列举于 Background 的 LoRA 小节（WQ、WK、WV、WO、Wgate、Wup、Wdown）。

**步骤 2：逐插入点计算激活尖峰统计量 s_m(x)**
- 输入：步骤 1 的 |M| × |T(x)| 幅度表。
- 计算：先取该插入点在提示 token 上的最大值 M_m(x) = max_{t∈T(x)} a_{m,t}(x)，再取均值 ā_m(x) = (1/|T(x)|) Σ_{t∈T(x)} a_{m,t}(x)，最后 s_m(x) = M_m(x) · log(1 + M_m(x)/ā_m(x))。该统计量在"激活幅度大"且"集中在少数 token 位置"时取大值。
- 输出：每个插入点一个标量 s_m(x)，共 |M| 个。
- 论文出处：Eq (2)，Hypothesis and Test Statistic Formulation。

**步骤 3：在干净集上求每个插入点的均值与标准差（部署前）**
- 输入：干净提示集 C = {c_i}，i = 1..n；对每条干净提示按步骤 1–2 算出的 s_m(c_i)。
- 计算：对每个插入点 m，在全部 n 条干净提示的分数上取站点专属均值 μ_m 与标准差 σ_m。
- 输出：长度 |M| 的两个向量 μ 与 σ。
- 论文出处：Backdoor Detector Construction（"For each insertion site m, LoRAScan computes the activation spike statistic sm(ci) on every clean prompt. These clean scores define a site-specific mean µm and standard deviation σm."）。

**步骤 4：低方差插入点选择（部署前）**
- 输入：标准差向量 σ。
- 计算：按 σ_m 升序排序，保留方差最小的比例 k 的插入点，记作 M_k。选择只针对"适配器已有的 LoRA 附着点"，不修改适配器本身。
- 输出：被监控插入点集合 M_k，大小约为 k·|M|，默认 k = 0.05。
- 论文出处：Backdoor Detector Construction；默认值见 Overview 与 Experimental Settings。

**步骤 5：跨插入点标准化后取平均，得到提示级分数 S_k(x)**
- 输入：被监控插入点的 s_m(x)，以及标定得到的 μ_m、σ_m。
- 计算：S_k(x) = (1/|M_k|) Σ_{m∈M_k} (s_m(x) − μ_m)/σ_m。标准化是为了把不同插入点的尖峰统计量放到同一尺度上，再做等权平均。
- 输出：一个标量分数 S_k(x)，衡量该提示相对于被监控插入点干净行为的异常程度。
- 论文出处：Eq (3)，Backdoor Detector Construction。该步骤在部署前（对干净提示）和推理时（对用户提示）都用。

**步骤 6：用干净分数标定单边上尾阈值 τ_k（部署前）**
- 输入：干净集上的提示级分数 {S_k(c_i)}，i = 1..n。
- 计算：bm_k = 这些分数的中位数，bd_k = 这些分数的中位数绝对偏差（median absolute deviation, MAD），τ_k = bm_k + λ·bd_k，λ = 4.45。
- 输出：每个适配器一个标量阈值 τ_k。
- 论文出处：Eq (4)，Backdoor Detector Construction；λ 取值见 Experimental Settings。

**步骤 7：单次前向 + 阈值判定 + 拒绝或放行（推理时）**
- 输入：用户提示 x、步骤 1–2 与 5 得到的 S_k(x)、阈值 τ_k。
- 计算：只做一次前向，算出 S_k(x)；若 S_k(x) > τ_k，在生成之前拒绝该提示；否则把提示交给 LoRA 适配后的模型正常生成。判定是逐提示独立、单边上尾的，不做跨轮累积。
- 输出：二值判定（拒绝 / 放行）；放行时输出原始生成过程产生的文本。
- 论文出处：Backdoor Detector Construction 末段（"At inference time, LoRAScan performs a single forward pass, computes Sk(x), and rejects the prompt before generation if Sk(x) > τk."）；Overview 与 Figure 2。

## 4. 采样与规模控制

- **样本（干净提示）**：使用 40 条无标签干净提示，从 Stanford Alpaca 数据集采样，仅用于插入点选择与阈值标定，出处为 Experimental Settings。论文没有说明具体抽样方式（哪个子集、是否随机、随机种子、长度分布）。
- **插入点（层内线性模块）**：保留 σ_m 最小的 5%，即 k = 0.05，论文表述为 "approximately 5% of LoRA insertion sites"（Abstract）与 "We set k = 0.05, so LoRAScan monitors the 5% of LoRA insertion sites for each adapter"（Experimental Settings）。论文没有给出各模型插入点总数 |M| 的绝对值，也没有给出 |M_k| 的取整规则。
- **层**：不做层抽样。Table 5 的消融把"LoRAScan 的 5% 选择"与"随机 5%""第一个含 LoRA 的 Transformer 层""最后一个含 LoRA 的层""全部插入点"作对比，说明默认规则不是按层选的。
- **参数坐标**：论文未使用。分数由 r 维瓶颈聚合而成，未对 r 维做坐标级抽样或降维；论文也未对 A_m 的权重做任何抽样。
- **token 位置**：论文未使用抽样，对全部提示 token 位置 T(x) 取 max 与 mean；论文没有说明超长提示是否截断。
- **轮次**：论文未使用。阈值标定一次后固定复用，没有跨轮累积或更新机制。
- **探针（probe）**：论文未使用任何探针数据；对比方法 BEAT 才需要 safety probe（Related Work、Runtime Analysis）。

## 6. 判定与动作

- **判定规则**：单边上尾阈值判定，S_k(x) > τ_k 即判为含触发器，拒绝该提示；否则放行（Backdoor Detector Construction 末段）。
- **阈值构造**：τ_k = bm_k + λ·bd_k，其中 bm_k 是干净提示级分数的中位数，bd_k 是它们的中位数绝对偏差，λ = 4.45（Eq (4)；Experimental Settings）。用中位数与 MAD 而不是均值与标准差，是稳健统计量的选择（论文未展开解释这一点）。
- **动作形式**：提示级过滤（reject / pass），在生成之前执行；不剔除客户端、不加权、不裁剪、不加噪、不改适配器参数、不改解码过程。被接受的提示走原始生成流程。
- **是否跨轮累积**：不累积。阈值在部署前算一次，之后复用；检测逐提示独立（Overview、Runtime Analysis 的 "Setup is performed once per adapter"）。
- **误报代价的论述**：论文认为拒绝单个提示比把整个适配器判为可疑再丢弃的代价小（Limitations and Future Work）。
- **实测效果**：在 12,475 条后门样本与 12,475 条干净样本上，ARR（attack rejection rate，攻击拒绝率）98.49%，BPR（benign pass rate，良性通过率）96.59%（Backdoor Detection Results、Table 5）。

## 7. 需要的外部资源

- 一小批可信、无标签的干净提示：40 条，来自 Stanford Alpaca（Experimental Settings）。论文强调不需要中毒样本、触发器样例、目标行为样例，也不需要带标签的良性/后门适配器（Introduction）。
- 对可疑适配器的白盒访问：需要读取适配器权重，并在推理时读取每个插入点的 A 侧瓶颈激活（Threat Model 的 "white-box access to the adapter weights"；Limitations 的 "maintains white-box access to intermediate activations"）。
- 一个可信的基座模型，以及把该第三方适配器挂载起来的推理栈（Threat Model）。
- 标定产物：每个插入点的 μ_m 与 σ_m、被选中的插入点索引集合 M_k、每个适配器一个阈值 τ_k。
- 不需要的：额外的检测器/分类器模型（PEFTGuard 需要）、干净参考模型（CleanGen 需要）、额外的防御适配器（Obliviate 需要）、触发器先验、探针数据集（BEAT 需要）。
- 论文实验环境：两台 NVIDIA A100 80GB；评测 75 个适配器、5 个模型家族、5 种攻击、3 类后门任务（Experimental Settings）。

## 8. 计算与存储开销

**论文报告的开销**：
- Setup（一次性、每个适配器一次）：平均 11.98 s；Table 6 分模型为 DeepSeek 10.88 ± 0.18 s、Llama-3 11.54 ± 0.06 s、OpenChat-3.5 12.06 ± 0.12 s、Vicuna 14.06 ± 0.08 s、Llama-2 11.36 ± 0.09 s（Runtime Analysis、Table 6）。
- Detection（每样本筛查）：平均 29.69 ms；Table 6 分模型为 26.53 ± 0.01 ms、28.91 ± 0.01 ms、29.88 ± 0.02 ms、35.01 ± 0.01 ms、28.10 ± 0.01 ms（Runtime Analysis、Table 6）。
- 对比：ConfGuard 58.82 ms、BEAT 162.83 ms、ONION 13.53 ms（Runtime Analysis）。论文指出 LoRAScan 只做单次前向，而 ConfGuard 要在生成过程中监控置信度、BEAT 要做多次生成，因此 LoRAScan 在"检查模型或适配器内部"的检测器里检测开销最低（Runtime Analysis）。

**分析**：
- 主要开销来自推理阶段对提示做的一次完整 LLM 前向（prefill），再加上在 |M_k| 个插入点上抓取 r 维瓶颈激活并做 max/mean/log 聚合。前者的成本随提示长度与模型规模增长，后者大致随 |T(x)| × |M_k| × r 增长。论文报告的 29.69 ms 是每样本的筛查时间，但论文没有把它拆分成"前向"与"统计计算"两部分，也没有说明是否包含除 prefill 之外的任何生成开销。
- 标定阶段的开销是 n 条干净提示各做一次前向，加上对 |M| 个插入点排序与阈值计算，随 n 与 |M| 线性增长（分析）；论文报告 11.98 s 的平均 setup 时间，同样未做拆分。
- 存储开销论文未报告。按流水线看，需要常驻保存的只有 2|M| 个标量（μ、σ）、|M_k| 个插入点索引和一个阈值 τ_k，相对模型与适配器权重可忽略（分析）。
- 论文未报告显存占用，也未报告统计量计算在总检测时间中的占比。

## 9. 实现时容易错的地方

**论文明确强调的实现细节**：
1. 必须监控下投影（A 侧）瓶颈，不要用上投影（B 侧）。Table 5 中下投影在所有插入点子集下 ARR 都更高，论文原文为 "Across site subsets, the down-projection pathway consistently achieves higher attack rejection than the up-projection pathway, suggesting that the up-projection dilutes the backdoor signal."
2. 必须使用低方差 5% 选择规则。Table 5 中它在下投影通路上取得 98.49% ARR，最强替代（监控全部插入点）只有 81.24%；上投影通路上是 92.26% 对 75.22%。
3. 不要只监控最后一层。Table 5 中"最后一个含 LoRA 的层"两种通路的 ARR 都只有约 12%。
4. 插入点选择只是"挑哪些已有附着点来监控"，不修改适配器（"without modifying the adapter itself"，Backdoor Detector Construction）。
5. 跨插入点必须先做站点级标准化再平均（Eq (3)），否则不同插入点的统计量不在同一尺度上。
6. 阈值必须用单边上尾 + 中位数与 MAD（Eq (4)），而不是均值/标准差；使用前只算一次并复用。
7. 阈值是 per-adapter 的（"Setup is performed once per adapter"，Table 6 说明），不是全模型共用一个。
8. 拒绝发生在生成之前；被接受的提示必须走完全原始的生成过程——不合并适配器、不改参数、不改解码。

**论文没说清、实现时必须自己决定的地方**：
1. a_{m,t}(x) 的"幅度"具体是什么范数：对 r 维瓶颈向量取 L2 范数、L1 范数还是其他形式；是否包含 Eq (1) 中的 α/r 缩放因子。论文只写 "activation magnitude"。
2. 是否对 a_{m,t} 做任何尺度归一化（例如除以 √r 或除以干净集上的尺度）。论文未说明。
3. σ_m 的估计量（样本标准差还是总体标准差，ddof 取值），以及 MAD 是否乘 1.4826；论文只说 λ = 4.45 等价于 3 个 "Gaussian-consistent MAD scale units"。
4. 插入点总数 |M| 的绝对值和 |M_k| = k|M| 的取整规则（向下取整、四舍五入还是至少取一个），以及 σ_m 排序并列时的打破规则。论文只给比例，未给每个模型的模块总数。
5. σ_m = 0 或 bd_k = 0 时的除零与阈值退化处理（是否需要加 ε）。论文未说明。
6. 边界输入：空提示、只有一个 token 的提示、T(x) 为空或只含特殊 token 时 M_m(x) = ā_m(x)、比值恒为 1、分数退化为 M_m(x)·log 2；以及聊天模板与 system prompt 的 token 是否计入 T(x)。论文未说明。
7. 40 条干净提示的具体抽样过程（Alpaca 的哪个子集、随机种子、是否去重、长度分布）与是否每个适配器重新抽。论文只写 "40 prompts sampled from the Stanford Alpaca dataset"。
8. 标定前向是在"可信基座 + 可疑适配器"上做还是在纯基座上做。论文措辞（测量 LoRA 下投影通路的激活）暗示必须挂载适配器，但没有明写。
9. 超长提示的截断策略，以及批处理/连续批处理（continuous batching）下如何隔离单条提示的统计量。论文未说明。
10. 同时挂载多个适配器（multi-LoRA serving）时如何定义插入点集合与统计量。论文未说明。
11. 检测阶段是否对同一提示做多次前向取平均（论文只写 single forward pass，暗示一次）。论文未说明。
12. 部署后分布漂移是否需要重新标定阈值。论文未说明。
13. **分析**：论文给出 λ = 4.45 在正态假设下约等于 99.9 分位，而实测 BPR 是 96.59%（等价于约 3.41% 的干净提示被拒绝），两者差距较大，论文没有解释这个差距；实现时不应假设实际误拒率就是 0.1%。
