# ax2506.22506：SABRE-FL（Selective and Accurate Backdoor REjection for Federated Prompt Learning）

## 1. 方法一句话

SABRE-FL 的输入是每个客户端在本轮提交的、由其本地图像经**冻结 CLIP 图像编码器**（frozen image encoder）算出的嵌入向量集合，以及该客户端的本地 prompt 更新；服务器用一个**离线**在辅助数据集（Caltech-101）上训练好的嵌入空间二分类检测器 D 给每条嵌入打"干净/被投毒"标记，再把标记按客户端聚合成异常分 S_k，每轮按分数排序剔除最高的 m 个客户端，最后只对保留的客户端做均值聚合，输出是"被排除了疑似投毒更新的新全局 prompt"。方法本身不修改本地训练、不裁剪也不加噪，只做客户端级剔除（§4、§4.1、附录 C.1）。

## 2. 运行位置

- **检测器训练：训练之外（outside training）**，在联邦流程开始前离线完成，位于服务器侧。论文明确说 SABRE-FL 训练一个"offline"检测器（§1 贡献段、§4.2、摘要），且"trained once on Caltech-101"（§5.1）。
- **嵌入生成：客户端上传前（client_post_train）**。论文说"Clients share only CLIP-encoded image representations with the server"（§4.3），并且服务器是在"a client Ck submits a set of embeddings"时打分的（§4.1 式 7）。论文把这一步放在客户端本地训练完成、提交 prompt 的同一阶段，没有单独描述一个额外的通信阶段。
- **检测器前向与客户端打分：服务器收到更新（server_receive）**。式（7）在"收到一个客户端的嵌入集合"时计算 S_k。
- **排序剔除与聚合：服务器聚合（server_aggregate）**。§4 明确说"detects and filters poisoned client updates at the server"；被剔除客户端"excluded from aggregation"（§4.1）。
- **客户端每个训练步（client_step）：防御不介入。** Algorithm 1 第 4–10 行的本地训练对恶意与良性客户端都不因防御而改变，防御只在聚合处生效。
- **是否需要客户端与服务器之间额外往返：论文没有描述额外的请求—响应轮次，needs_round_trip 记为 false。** 但需要注意：客户端除了 prompt 还要把嵌入交给服务器，这一步在正文与式（7）中被隐含，而 Algorithm 1 第 11 行的上传语句在抽取文本中是残缺的（原文抽取为"11 S d b ddi {k}"），论文没有说明它是与 prompt 同一批上传还是单独一次通信。这一点见第 9 节。

## 3. 算子流水线

### 步骤 0（离线，训练之外）：构造辅助干净/污染嵌入对
- **输入**：辅助数据集 Caltech-101 的原始图像 x（论文未说明抽取哪个子集、抽多少张）；论文自身攻击所用的可学习触发器 t（§3.3 定义 x⋆ = x ⊕ t）；冻结的 CLIP 图像编码器 f_img；一个"固定的 prompt learner"（§4.2 原文"a fixed prompt learner"，论文未说明具体是哪一个 prompt）。
- **计算**：对子集中的图像施加触发器得到 x⋆ = x ⊕ t（Algorithm 1 第 6 行；§4.2 说"apply our trigger injection method (Algorithm 1, line 6), to a subset of images"）；把干净图 x 与触发图 x⋆ 都通过冻结图像编码器与固定 prompt learner，得到嵌入 z 与 z⋆；标注 y_i = 0 表示干净、y_i = 1 表示被投毒，组装成 D_aux = {(z_i, y_i)}_{i=1}^N。形式化前提是干净与投毒嵌入之间存在分离间隔：‖z − z⋆‖₂ > ε（式 5）。
- **输出**：D_aux，其中 z_i ∈ R^d，d = 512（附录 D.4）。
- **出处**：§4.1 式（5）、§4.2、Algorithm 1 第 1 行与第 6 行、附录 D.4、§5.2（"We first train a model with backdoors using the technique similar to BadClip…then we pass clean and noisy images through the image encoder and store the output embeddings"）。

### 步骤 1（离线，训练之外）：训练嵌入空间二分类检测器
- **输入**：D_aux。
- **计算**：最小化标准二分类损失 min_θ Σ_{i=1}^{N} ℓ(D(z_i; θ), y_i)（式 6）；Algorithm 1 第 2 行写明"Train D : R^d → {0, 1} using cross-entropy"；附录 D.4 明确用 binary cross-entropy。模型是两层 MLP（two-layer multilayer perceptron），隐藏层大小 128，ReLU 激活；输入 512 维 CLIP 图像嵌入，输出对应"干净/后门"两类的 logits；优化用 Adam，学习率 1 × 10⁻³，20 个 epoch，batch size 64。
- **输出**：检测器 D；论文报告其文件大小为"a few MBs"（D.4）。
- **出处**：式（6）、Algorithm 1 第 1–2 行、§4.2、附录 D.4。

### 步骤 2（每轮，服务器下发前）：下发全局 prompt
- **输入**：上一轮的全局 prompt p^{t−1}。
- **计算**：服务器把 prompt 发送给本轮所有被选客户端（Algorithm 1 第 3 行；§3.3 step 1）。防御在此步不改变任何内容。
- **输出**：各客户端的本地 prompt 初值。
- **出处**：Algorithm 1 第 3 行、§2.1、§3.3。

### 步骤 3（客户端每个训练步）：本地训练 prompt
- **输入**：p^{t−1} 与客户端本地数据。
- **计算**：保持图像编码器与文本编码器冻结，只优化 prompt（Algorithm 1 第 4–10 行）。恶意客户端在此注入触发器并重标为目标类；良性客户端在干净数据上训练。防御不介入这一步。
- **输出**：各客户端本地 prompt p_k。
- **出处**：Algorithm 1 第 4–10 行、§3.3、§2.2。

### 步骤 4（客户端上传前，client_post_train）：客户端编码本地图像并上报嵌入
- **输入**：客户端本地图像；冻结的 CLIP 图像编码器与"固定 prompt learner"。
- **计算**：把本地图像编码为嵌入向量，随本地 prompt 一起交给服务器。论文只说明服务器收到的是"a set of embeddings {z_j^k}_{j=1}^{n_k}"（式 7），以及"Clients share only CLIP-encoded image representations with the server"（§4.3）。**每轮上报多少条（n_k）、用哪个 prompt learner、是否每轮都上报，论文均未说明。**
- **输出**：客户端 C_k 的嵌入集合（分析：可写成矩阵 Z_k ∈ R^{n_k × 512}）与本地 prompt p_k。
- **出处**：§4.1 式（7）、§4.2、§4.3、Algorithm 1 第 11 行（抽取文本残缺）。

### 步骤 5（服务器收到更新，server_receive）：逐条嵌入打分
- **输入**：客户端 C_k 的嵌入集合 {z_j^k}。
- **计算**：对每条嵌入前向检测器 D，得到该条是否被标记为投毒（D 的形式化签名是 R^d → {0,1}，式 6；但 D.4 说网络"outputs logits"，因此需要一个判定阈值把 logits 变成 0/1，**论文未说明该阈值**）。
- **输出**：每条嵌入的 0/1 标记 D(z_j^k)（或标记条数）。
- **出处**：§4.1 式（6）与式（7）、§4.2、附录 C.1。

### 步骤 6（server_receive → server_aggregate 之间）：聚合成客户端级异常分
- **输入**：客户端 C_k 的 n_k 条 0/1 标记。
- **计算**：平均检测分 S_k = (1/n_k) Σ_{j=1}^{n_k} D(z_j^k)（式 7）。但 §4.1 的 Inference Rule 与附录 C.1 又说排序依据是"the highest number of flagged embeddings"（被标记嵌入的条数），附录 C.1 写成"the highest number of flagged embeddings (or highest S_k scores)"，两种口径并存。
- **输出**：每个客户端一个标量异常分或标记计数。
- **出处**：式（7）、§4.1 Inference Rule、附录 C.1。

### 步骤 7（服务器聚合，server_aggregate）：按异常分排序，剔除 top-m 客户端
- **输入**：本轮 n 个客户端的 S_k（或标记条数）。
- **计算**：每个通信轮内，把异常分最高（或标记条数最多）的 m 个客户端排除在聚合之外。论文明确不用固定阈值 τ，而采用 rank-based heuristic，并假设恶意客户端数量有上界（"assumes an upper bound on the number of malicious clients"，§4.1；附录 C.1："we assume m out of n clients may be malicious"）。
- **输出**：保留客户端集合 K（大小 n − m）。
- **出处**：§4.1 Inference Rule、附录 C.1。

### 步骤 8（服务器聚合，server_aggregate）：对保留客户端求均值并更新全局 prompt
- **输入**：K 中客户端的本地 prompt（或更新）。
- **计算**：对保留客户端做 FedAvg 式均值 f_mean（§2.1：∇_agg^t = f_mean(∇_{k∈[n]}^t)），再用 θ_g^{t+1} ← θ_g^t + η∇_agg^t 更新全局模型（§2.1）。**论文没有重新给出"剔除之后"的聚合公式，也没有说明是否按客户端样本量加权、是否重新归一化，服务器学习率 η 的取值也未给出**（D.1 只给了一个初始学习率 0.002，且没有说明它属于客户端还是服务器）。
- **输出**：新的全局 prompt learner。
- **出处**：§2.1、§3.3 step 4、Algorithm 1 第 3–4 步的循环框架。

### 步骤 9（跨轮）：不累积
- 剔除是**每轮独立**的排序操作（§4.1"in each round"、附录 C.1"in each communication round"）；检测器**只训练一次、不随轮更新**（§5.1"The detector is trained once on Caltech-101"）。

## 4. 采样与规模控制

- **样本（samples）**：使用 Caltech-101 的 9,146 张图像（101 个物体类 + 1 个 background 类）构造辅助嵌入集 D_aux；对其中一个子集注入触发器生成投毒样本（Algorithm 1 第 6 行；附录 D.2 给出数据集规模）。**被注入的子集比例、D_aux 的样本条数 N，论文均未说明。**
- **客户端（clients）**：标准 FL 每轮从 N 个客户端中选 n 个（§2.1），筛选中直接剔除分数最高的 m 个（附录 C.1）。默认恶意比例为 m/N = 25%（§3.2，与既有工作一致）；Figure 6 消融了 0%、25%、50%、100% 恶意比例；附录 E.3 把规模扩到 32 个客户端。**n 与 N 的具体数值、以及 m 在每轮是否固定，论文未给出（只把它当作已知或可上界的量）。**
- **轮次（rounds）**：每轮独立执行一次排序剔除，不跨轮累积（§4.1、附录 C.1）；实验总 epoch 数为 10（附录 D.1），但 epoch 与通信轮的对应关系论文未说明。
- **层（layers）**：论文未使用。检测器只看图像嵌入，不按层选择参数。
- **参数坐标（coordinates）**：论文未使用。SABRE-FL 不做坐标级裁剪、中位数或范数约束（这些是 Trimmed Mean、Median、Norm Bounding、FLAME 等基线的动作，见附录 D.3）。
- **探针（probes）**：论文未使用探针样本；用的是与联邦训练数据集不相交的 OOD 辅助数据集 Caltech-101（附录 D.2："this dataset is disjoint from the ones used in federated training"）。

## 6. 判定与动作

- **单条嵌入的判定**：D(z) 输出被投毒（1）或干净（0）（式 6 的形式化签名）。由于 D.4 说网络输出 logits，实际需要一个把 logits 变成 0/1 的阈值，**论文未说明该阈值**。
- **客户端级判定**：S_k = (1/n_k) Σ_j D(z_j^k)（式 7），或等价地用"被标记嵌入的条数"（§4.1 Inference Rule、附录 C.1）。
- **剔除规则（rank-based，不用阈值）**：每一轮把异常分最高（或标记条数最多）的 m 个客户端排除在聚合之外（§4.1、附录 C.1）。m 来自"至多 m 个恶意客户端"的假设，要求 m 已知或有上界。
- **动作**：**exclude_client**——被剔除的客户端不参与该轮聚合，其余客户端按均值（FedAvg）聚合。**SABRE-FL 本身不裁剪、不加噪、不修改客户端本地训练**；裁剪到中位数范数与加噪是基线 Norm Bounding 和 FLAME 的动作（附录 D.3），不是本方法的。
- **是否跨轮累积**：否。每轮独立排序剔除（§4.1"in each round"），检测器离线训练一次不更新（§5.1）。
- **过度剔除的鲁棒性**：Table 8 显示在正确剔除 m 个恶意客户端之外再多剔除 1–2 个良性客户端时，干净准确率基本稳定、后门准确率仍然很低（例如 Pets 上 4.5%/4.8%，DTD 上 6.8%/5.4%）。
- **漏检的代价**：Table 7 显示每多留一个恶意客户端，后门准确率上升（Pets 从 4.7% 升到 10.1%，DTD 从 11.3% 升到 25.5%，对应漏掉 1 到 4 个）。

## 8. 计算与存储开销

**论文报告的开销：**
- 检测器"file size is a few MBs"（附录 D.4）。
- 论文强调 SABRE-FL 是"lightweight, modular defense"（摘要、§4），并且 prompt learning 本身因为只传 prompt 而通信开销低（§2.2、§3.3）。
- 检测器跨域泛化：在 Caltech-101 上训练一次，在 Flowers、Pets、DTD、FGVC Aircraft、Food101 上"consistently achieves > 90% accuracy on these unseen domains"（附录 D.4）。
- 附录 D.5 只说明实验运行时间"depended upon the dataset used, number of shots, and number of clients"。**论文没有报告 FLOPs、墙钟时间、内存占用或通信字节数。**

**按流水线的开销来源（分析：）：**
- 主要开销在**步骤 0/4 的冻结 CLIP 图像编码器前向**：辅助数据集每张图一次前向（步骤 0，外加触发器优化的开销，论文未给细节），以及每个客户端每条上报图像一次前向（步骤 4，无反向传播）。客户端侧成本随"每客户端上报条数 n_k × 被选客户端数 n × 轮数 T"线性增长。
- 服务器侧成本是**步骤 5 的逐条 MLP 前向**（512 → 128 → 2），与总嵌入条数 n × n_k 同阶；步骤 7 的排序是 O(n log n)，相对可忽略。
- 离线的步骤 1 是 D_aux 上 20 个 epoch、batch 64 的两层 MLP 训练，一次性成本。
- 存储：检测器几 MB；服务器每轮临时保存各客户端嵌入（分析：n × n_k × 512 个浮点数）。

## 9. 实现时容易错的地方

**论文明确强调的：**
- **不要用固定阈值**：论文明确放弃"flagging clients for which S_k > τ"，改用 rank-based top-m 启发式，理由是避免手调静态阈值 τ（§4.1、附录 C.1）。
- **必须知道或能上界 m**：排序剔除依赖"每轮至多 m 个恶意客户端"的假设（§4.1、附录 C.1），实现时必须把 m 作为输入。
- **辅助数据集必须与联邦数据集不相交**，并且要覆盖与下游不同的分布，否则"泛化到未见域"的结论不成立（附录 D.2、§5.1）。
- **嵌入必须来自冻结编码器**：客户端与服务器都不更新图像/文本编码器（§4.2、§4.3）。一旦编码器被本地数据更新，嵌入就不再是"task-agnostic"的，论文的隐私论证（附录 B.4）也随之失效。
- **检测器不应接触原始数据、标签或下游任务**（§4.3、§5.1）。
- **两种客户端评分口径并存**：式（7）是平均分 S_k，§4.1 与附录 C.1 又说用"标记条数"。当不同客户端的 n_k 不相等时，这两种排序会给出不同结果，必须自己选定。
- **过度剔除可容忍，漏检不可容忍**：Table 8 与 Table 7 分别给出了这两侧的实测行为。

**论文没说清、实现时必须自己决定的：**
1. 每个客户端每轮上报多少条嵌入 n_k，是否上报全部本地数据，是否只上报一次。
2. 上报嵌入是与 prompt 更新同一批传输，还是一次额外的通信往返；Algorithm 1 第 11 行在抽取文本中残缺（"S d b ddi {k}"），无法据此确认。
3. "固定的 prompt learner"具体指什么（手工模板、预训练 prompt 还是别的）。
4. 辅助数据集上的触发器如何获得、优化多少步；"trigger optimization for 3 epochs"（D.1）是否适用于 D_aux 的构造。
5. D_aux 中投毒样本所占的比例，以及 D_aux 的总条数 N。
6. 检测器 logits 转成 0/1 的阈值（论文形式化写成 R^d → {0,1}，实现却是输出 logits）。
7. 嵌入在进入 MLP 前是否做 L2 归一化或标准化。
8. n_k = 0 时式（7）的除零处理；被选客户端数为 0 或剔除后保留集合为空时的行为。
9. 聚合时是否按客户端样本量加权、剔除后是否重新归一化权重。
10. 每轮实际的 m 取值（论文只给默认比例 25%，没有给绝对值），以及 m 是否随轮变化。
11. 服务器学习率 η 的取值，以及 D.1 中"initial learning rate of 0.002"到底属于客户端还是服务器。
12. 附录 D.1 的"10 epochs"与联邦通信轮数的对应关系（1 个 warmup epoch 属于哪一侧）。
13. 检测器是否需要针对新的输入域重新校准；论文只说训练一次并跨域泛化（§5.1、D.4）。
14. 是否对嵌入做降维或量化后再上传（论文未涉及）。
