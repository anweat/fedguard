# ax2510.16830：Verifiable Fine-Tuning (VFT)

## 1. 方法一句话

VFT（Verifiable Fine-Tuning，可验证微调）是一个**协议 + 系统**：训练方（trainer，联邦场景下即聚合器）在公开初始化 θ0、公开训练程序描述符 Π（数据宇宙、采样器、损失、优化器、超参数）和已承诺数据集 cD = Com(D) 之下做参数高效微调（PEFT），并对**每一个训练步**生成简洁零知识证明 πt，再经递归折叠成 per-epoch 证明 Πe 和最终证明 π；验证方（审计者、平台、客户）只检查 π 与 (h0, Π, cD) 是否一致，从而接受或拒绝 (θT, hT)（§III.A、§III.B、摘要）。它不输出"某个客户端是恶意的"这类统计判定，而是输出**"这段数值轨迹确实按 Π 在 cD 的可采纳批次上执行过"的密码学判定**；判定为假时，联邦流水线把该客户端的更新排除、并中止该轮聚合（§III.L.a、§IV.C.a、§V.G.b）。

## 2. 运行位置

（VFT 同时覆盖集中式与联邦式；下面按联邦流程逐阶段给出位置，并按要求标出"分析："。）

- **训练之外 / 服务器下发前（S1 Commit）**：训练方对训练宇宙做 Merkle 或多项式承诺 cD（逐样本摘要），并对初始化做哈希 h0；provenance adapter（溯源适配器）导出清单（manifest），把数据来源、预处理代码摘要、资格规则绑定到 cD；可选地由 notary（公证方，如注册表或链）在训练开始前记录 (cD, h0, hΠ)（§III.B(S1)、§III.D.a、§III.I、§III.Q.a）。
- **服务器下发**：联邦场景下聚合器发布全局清单，编码跨客户端配额上限与公平性计数器（如每轮 safety 标签样本比例上限），下发清单哈希 hΠ 与公开种子 s（§IV.A.h、§IV.B.f、§III.I）。
- **客户端训练前**：客户端持有本地数据集承诺（子树），选择 public 或 private 采样模式；客户端本地配额承诺在本地生成（§III.J.a、§IV.A.h）。
- **客户端每个训练步**：可验证采样（公开模式由 (s,t) 经 CSPRNG 重导索引；私有模式在电路内抽取并零知识证明成员资格）、配额线性约束、定点（fixed-point）前向/反向、AdamW 状态转移、哈希链更新、以及单步证明 πt 的生成（§III.B(S2)(S3)、§III.D、§III.E–§III.G）。
- **客户端上传前**：客户端打包并上传 (i) PEFT 更新、(ii) 对**一个稀疏步子集**的本地证明 πt(k)、(iii) 本地配额承诺（§III.J.a）。
- **服务器收到更新**：聚合器运行"可验证聚合器"：检查客户端证明的**随机子集**，并做概率审计（随机触发的轻量检查）（§III.J.a、§IV.D.e、§V.C.c）。
- **服务器聚合**：组合（compose）更新，并把叶证明折叠为 epoch 证明 Πe，再折叠为单一最终证明 π，附覆盖率证书（coverage certificate，如"q% 的步被验证 + 置信界"）（§III.H、§III.J.a、Algorithm 1）。
- **聚合之后**：验证方检查 π 对 (h0, Π, cD) 是否成立，接受 (θT, hT)，可选把摘要记到 notary；审计者可请求对分箱计数器的选择性披露（selective disclosure）（§III.B(S5)、§III.L.b、§III.N.c）。
- **额外往返：需要**。除常规联邦轮之外，客户端要上行证明/承诺，聚合器要下行全局清单与审计/披露请求（§III.J.a、§III.J.b、§IV.D.d）。
- 分析：论文没有把 VFT 挂在某个"每步同步"的 FL 协议上；上面"客户端上传前 / 服务器收到更新"的划分是按 §III.J.a 的描述所作的最自然映射，论文本身未规定具体的轮次同步协议。

## 3. 算子流水线

**步骤 1：数据集承诺（Merkle 承诺）**
- 输入：数据集 D 的每条样本三元组 (xi, yi, metai)，其中 metai 含 source、license、preprocessing digest（§III.D.a），实现中为 (source_id, license_id, proc_digest, policy_tags)（§IV.A.e）。
- 计算：叶节点 li = H(xi ‖ yi ‖ metai)；构建 Merkle 树，根为 cD。哈希 H 用证明系统原生 sponge（如 Poseidon/Rescue）以避免昂贵的 bit decomposition（§III.M.d）。
- 输出：数据根承诺 cD 与逐叶摘要 li。
- 出处：§III.B(S1)、§III.D.a、§IV.A.e。

**步骤 2：属性计数器向量承诺**
- 输入：辅助计数器 u（如标签直方图、长度桶等分布性统计）。
- 计算：用 Pedersen/KZG 向量承诺提交 u，得到 cu。
- 输出：cu。
- 出处：§III.D.a。

**步骤 3：清单哈希与策略绑定**
- 输入：策略清单：数据来源与许可证、预处理代码摘要、资格过滤（eligibility filters）、采样器描述符（public/private、种子策略、shuffling、有无放回）、PEFT 结构（层位置、秩、冻结映射）、优化器超参与调度、近似预算（δsm、GELU 误差、定点 b 与溢出界）（§III.I）。
- 计算：对清单求哈希得 hΠ；电路把 hΠ 当公开输入，并检查内部常量（β1,2、λ、秩、调度）与之一致（§III.I）。
- 输出：hΠ（可选由 notary 记录 (cD, h0, hΠ)）。
- 出处：§III.I、§III.B(S1)、§III.Q.a。

**步骤 4：可验证采样（公开 / 私有两种模式）**
- 输入：数据集规模 |D|、批大小、步号 t、公开种子 s（私有模式则为运行期 nonce）。
- 计算：公开模式下索引 i ∈ It 由 (s, t) 经 CSPRNG 重新导出，并发布 (s, sampler_version)，使验证方可完全重放批次（§III.D.b、§IV.B.f）；私有模式下索引在 step circuit 内抽取，用 Merkle path 或向量承诺在零知识下证明成员资格而不泄露 i（§III.D.b、§III.J.a）。
- 输出：索引集 It 及其可验证性证据（公开模式为可重放性，私有模式为 ZK 成员证明）。
- 出处：§III.B(S2)、§III.D.b、§IV.B.f。

**步骤 5：成员资格路径证明**
- 输入：索引 i、叶 li、树根 cD。
- 计算：公开模式下揭示 Merkle path(i)，证明 li 被包含；私有模式下证明"知道 {i} 与认证路径且根等于 cD"而不揭示 i（§III.D.b）。
- 输出：路径或 ZK 成员证明。
- 出处：§III.D.b、§III.D.d。

**步骤 6：配额线性约束检查（Eq. (3)）**
- 输入：每步选择指示向量 et ∈ {0,1}^|D|；属性/分箱矩阵 M ∈ {0,1}^{B×|D|}，把样本映射到桶；每轮每桶配额 γ ∈ N^B。
- 计算：Σ_{t∈epoch} M et ⪯ γ（逐元素 ≤）。用对 et 的承诺与对 γ 的 range proof 在电路内证明该式（§III.D.c）。
- 输出：配额满足布尔值与配额证书（quota certificate）。
- 出处：Eq. (3)、§III.D.c、§III.H、Algorithm 1 第 4/9 行。

**步骤 7：定点投影**
- 输入：实数张量 x（激活、梯度、优化器状态）。
- 计算：x̄ = ⌊S x⌉，S = 2^b，使 ⌊S x⌉ ∈ Z 落入有限域 Fp；乘积近似 x·y ≈ x̄·ȳ / S；溢出用 range proof 排除；跟踪全局误差预算 εfxp，并把接受谓词变成逐坐标区间成员判定，容差 τ = δsm + εfxp（Eq. (1) 相应被转成不等式）。
- 输出：定点影子张量 x̄ 与误差预算。
- 出处：Eq. (5)、§III.F.a、§III.C（Eq. (1) 的区间化）。

**步骤 8：softmax 查表近似**
- 输入：每个 token 的 pre-softmax logits z ∈ R^L。
- 计算：在裁剪范围内用有理/多项式 f̄sm(z) 近似 softmax，采用 lookup table 加有界插值误差 δsm；电路检查 per-token 归一化并约束 ‖softmax(z) − f̄sm(z)‖₁ ≤ δsm；行和检查用 lookup 方式实现（§III.E.b、§III.P）。
- 输出：近似注意力权重与误差证书。
- 出处：Eq. (4)、§III.E.b、§III.P。

**步骤 9：查表非线性（GELU 与 rsqrt）**
- 输入：GELU 的输入张量；AdamW 中的 v̂ + ε。
- 计算：GELU 与倒数平方根依赖 lookup argument（查找论证）加 range-checked interpolation（带范围检查的插值）；对 r = 1/√(v̂+ε) 使用由 (v̂, r) 对构成的表 T 与带斜率检查的线性分段（slope-checked linear segment bound）。
- 输出：近似 GELU 值与近似 r。
- 出处：§III.F.b。

**步骤 10：LoRA 前向与冻结张量哈希等式**
- 输入：线性模块权重 W ∈ R^{dout×din}、适配器 A ∈ R^{r×din}、B ∈ R^{dout×r}、输入 x；冻结张量的公开承诺。
- 计算：ΔW = BA，前向 y = (W + BA)x；冻结 W，只更新 (A, B)；对冻结张量做哈希并与公开承诺施加等值约束（从而把训练约束在适配器子空间）。
- 输出：层输出 y 与适配器更新 ΔW。
- 出处：§III.E.a。

**步骤 11：PEFT 受限反向传播**
- 输入：前向激活与标签。
- 计算：因果语言模型（causal LM）逐 token 交叉熵 ℓ = −log p_y，其中 p = f̄sm(z)；只对 PEFT 张量求 gt；通过固定的（冻结的）Jacobian 做反向传播；逐层 checksum 把激活与哈希绑定，防止重算攻击。
- 输出：gt（仅适配器张量）。
- 出处：§III.E.c。

**步骤 12：定点梯度裁剪**
- 输入：gt。
- 计算：梯度裁剪到 1.0，在定点下实现并带饱和检查（saturation checks）。
- 输出：裁剪后的 gt。
- 出处：§IV.B.e。

**步骤 13：AdamW 定点状态转移（Eq. (2)）**
- 输入：gt、(mt, vt)、超参 (β1, β2, ϵ, λ)、学习率 ηt。
- 计算：mt+1 = β1 mt + (1 − β1) gt；vt+1 = β2 vt + (1 − β2) gt^⊙2；θt+1 = θt − ηt · m̂t+1/(√v̂t+1 + ϵ) − ηt λ θt（m̂、v̂ 为偏差校正后的矩）。该式在 PEFT 张量上施加。
- 输出：θt+1（仅适配器）与 (mt+1, vt+1)。
- 出处：Eq. (2)、§III.C、§III.E.a、§III.P。

**步骤 14：优化器状态承诺**
- 输入：(mt, vt)。
- 计算：用 Merkle accumulator 或多项式承诺提交 (mt, vt)，并用哈希链连接相邻步。
- 输出：优化器状态承诺。
- 出处：§III.G.a。

**步骤 15：模型哈希链**
- 输入：ht、结构化更新 Δt（如 LoRA 矩阵）、学习率 ηt、metat（含 batch id 承诺、step、epoch、schedule id）。
- 计算：ht+1 = H(ht ‖ H(Δt) ‖ ηt ‖ metat)，H 是逐张量哈希上的 sponge；单步证明绑定 (ht, ht+1) 与适配器张量的本地承诺。
- 输出：ht+1。
- 出处：Eq. (6)、§III.G.b。

**步骤 16：单步证明生成（ProveUpdate）**
- 输入：witness（批次、中间激活、梯度、优化器状态）与公开输入 (hΠ, cD)。
- 计算：生成证明 πt，证明 (i) 采样批次在 cD 下可采纳、(ii) 损失与梯度计算遵循 Π 且在批准的近似界内、(iii) 优化器状态转移一致；πt 绑定前态哈希 ht 与后态哈希 ht+1；接受谓词是逐坐标区间成员判定，容差 τ = δsm + εfxp。
- 输出：πt。
- 出处：§III.B(S3)、§III.F.a。**注意：** §III.K 声明给出 PROVEUPDATE 与 VERIFY 两个核心过程的伪代码，但抽取出的全文中只出现 Algorithm 1（VERIFY 与递归聚合），PROVEUPDATE 的伪代码本身缺失。

**步骤 17：递归折叠聚合**
- 输入：单步证明 {πt} 或 epoch 证明 {Πe}。
- 计算：用递归电路 R 消费两个子证明并输出其聚合证明；采用曲线循环（cycle of curves）或原生支持递归的证明系统，使验证仍在同一域内；epoch 证明 Πe 验证 (i) 边界哈希 ht_start(e) → ht_end(e)、(ii) 每轮配额约束 Eq. (3)、(iii) 子证明被正确聚合。二分折叠把 T 个证明折成一个，递归深度 O(log T)，聚合证明大小为单证明的小常数倍，且可并行证明。
- 输出：{Πe} 与最终证明 π（绑定 (cD, Π)），从根边界摘要取出 hT。
- 出处：§III.H、§III.M.b、Algorithm 1 第 6、11 行。

**步骤 18：证明验证**
- 输入：(h0, cD, hΠ) 与 {πt} 或 {Πe}。
- 计算：Algorithm 1——若给的是单步证明，则对每个叶证明 πt 并行验证（针对公开 (hΠ, cD)），提取边界摘要 (ht, ht+1) 与配额证书；用递归电路 R 折叠已验证叶证明得到 {Πe}；对每个 Πe 验证每轮配额与策略计数器；把 {Πe} 折成单一最终证明 π；从根边界摘要提取 hT；返回 (π, hT)。
- 输出：(π, hT) 或接受/拒绝。
- 出处：Algorithm 1 第 1–13 行、§III.B(S5)。

**步骤 19：概率客户端审计与覆盖率证书**
- 输入：各客户端提交的 (PEFT 更新、稀疏步证明、本地配额承诺)。
- 计算：聚合器检查客户端证明的随机子集；审计预算按"每轮验证客户端步数的 q%"给出，并生成覆盖率证书（如"q% 的步被验证 + 置信界"）。注入的异常（学习率篡改、越策略采样）在若干轮内被检出。
- 输出：覆盖率证书；异常标记。
- 出处：§III.J.a、§IV.D.e、Table V。

**步骤 20：接受 / 排除更新**
- 输入：验证与审计结果。
- 计算：配额违反是硬错误并中止聚合（§IV.C.a）；联邦事件响应中，概率审计在一轮内标记不匹配，随后聚合排除被污染（tainted）的更新，直到该客户端提交更正后的清单（§V.G.b）。零知识保证在补救过程中不泄露敏感索引。
- 输出：被接受或被排除的客户端更新集合。
- 出处：§IV.C.a、§V.G.b、§III.L.a。

## 4. 采样与规模控制

- **样本（samples）**：批次由可验证采样器产生。公开模式用共享种子 s 与 CSPRNG 从 (s, t) 导出每步索引；私有模式在电路内抽索引并零知识证明成员资格。批大小为 64（global）（§III.D.b、§IV.B.e、§IV.B.f）。
- **客户端（clients）**：联邦实验模拟 K ∈ {50, 200} 个客户端，用 Dirichlet 分配在主题桶上切分非 IID 分片，浓度 α ∈ {0.1, 0.3}（§IV.A.h）。客户端只对**一个稀疏步子集**提供本地证明（"a thin subset of steps"），聚合器只检查客户端证明的**随机子集**（§III.J.a）；子集的具体大小论文未说明。
- **审计覆盖率（coverage）**：审计预算 q ∈ {5%, 10%, 20%} 的客户端步数/轮（§IV.D.e、Table V）；实践建议先 10%，稳定后降到 5%（§V.K.d）。
- **层与参数（layers）**：只对 LoRA/适配器子空间建电路，冻结 backbone、layer norm 与 embedding；适配器放在 attention 与 MLP 投影上，可切换为 attention-only；秩 r ∈ {4, 8, 16}（§III.B、§IV.B.e、§IV.D.b、Table III）。
- **参数坐标（coordinates）**：全部实数量化到定点，接受判定按坐标做区间成员判定，容差 τ = δsm + εfxp（数值论文未给）（§III.F.a）。
- **轮次（rounds）**：默认在指定混合数据上训练 1 个 epoch；每 epoch 做一次配额检查并产出 epoch 证明；public/private 窗口交错（"every 10th epoch is public"，与"默认 1 epoch"存在表述不一致）（§IV.B.e、§IV.B.f、§III.H）。
- **探针与参考数据（probes）**：**论文未使用**任何干净参考数据、根数据集或探针样本；验证完全依赖承诺与证明。lookup 表（softmax/GELU/rsqrt）是唯一"额外数据"，其规模论文未说明（§III.F.b）。
- **其他截断/降维**：序列右填充到 2048 token，长上下文消融用 4096 token（§IV.A.g）；梯度裁剪到 1.0（§IV.B.e）；联邦带宽紧张时客户端可用低秩与 int8/int4 PEFT 量化缩小电路、把多步打包成 micro-recursion，或把递归外包给聚合器（§III.J.b）；micro-recursion 每次折 8 步（§V.H.c）。

## 6. 判定与动作

- **判定来源一：电路约束失败**。若采样批次不可采纳、优化器更新被跳过或重排、超参数被改动、配额被违反，则约束失败（在承诺绑定与证明系统可靠性下，仅以可忽略概率例外）（§III.L.a）。配额违反按**硬错误**处理，直接中止聚合（"Any violation is a hard error and aborts aggregation in our pipeline"，§IV.C.a）。
- **判定来源二：清单一致性**。所有 run 都必须通过与 hΠ 的常量等值检查；注入学习率尖峰或修改 β2 会立即导致证明失败（§IV.C.c、§V.I）。
- **判定来源三：概率审计**。K = 200 时，验证 q = 10% 的客户端步数可在两轮内以 > 99% 概率检出注入异常；q = 5% 三轮内检出；q = 20% 接近 100%（§IV.D.e、Table V）。论文未给出具体检验统计量与阈值。
- **动作**：
  - 接受：验证方对 (h0, Π, cD) 检查 π 通过后接受 (θT, hT)，可选把摘要记入 notary（§III.B(S5)）。
  - 拒绝 / 中止：约束失败即拒绝该证明并中止该轮聚合（§III.L.a、§IV.C.a）。
  - 排除客户端：联邦事件响应中，聚合器在审计标记后**排除被污染的更新**，直到该客户端提交更正后的清单（§V.G.b）。
  - 样本准入过滤：资格过滤与每轮配额在采样与电路层面限制可被使用的样本（Eq. (3)），越策略样本无法进入被证明的训练（§III.D.c、§IV.A.e）。
  - 选择性披露：审计者可按请求获得桶级计数器（如每 epoch 医疗 token 总数），但不获得逐样本成员信息（§III.L.b、§III.N.c）。
- **不涉及的动作**：不对更新做加权、不加噪、不做服务器端替换全局模型；梯度裁剪（1.0）是被验证训练程序 Π 的组成部分，而不是防御方的额外动作（§IV.B.e）。
- **是否跨轮累积**：是。配额约束 Eq. (3) 是**每 epoch 累积**选择向量的约束；优化器矩 (mt, vt) 与哈希链 ht 跨步/跨轮累积（§III.D.c、§III.G、§III.H）。

## 8. 计算与存储开销

论文报告的开销：
- 单步 prover 时间（Tier-P2，2048 token）：r = 8 时 16.8 ± 0.9 s，r = 16 时 31.2 ± 1.4 s；峰值内存 23.6 ± 1.1 GB 与 37.9 ± 1.5 GB（§V.B.a、Table I）。
- 单步时间构成：witness 生成 ~35%、多项式/FFT ~28%、MSM/FRI ~30%、其余开销 ~7%（Fig. 4）。
- 验证：叶证明 7.6 ± 0.3 ms、epoch 聚合（10k 步）132 ± 6 ms、最终证明 181 ± 9 ms（SNARK）；STARK 为 5.1 ± 0.4 / 118 ± 7 / 169 ± 11 ms（Table II、§V.B.b）。
- 证明大小：叶 220 ± 8 KB、epoch 2.6 ± 0.1 MB、最终 4.1 ± 0.2 MB（SNARK）；STARK 最终 5.7 ± 0.3 MB（Table II）。目标预算：叶 ≤ 250 KB、epoch ≤ 3 MB、最终 ≤ 5 MB（§IV.F）。
- 聚合：把 T = 10000 个单步证明折叠成单个 epoch 证明，4 GPU 需 8.7 ± 0.4 分钟；加倍 GPU 收益次线性（MSM/FFT 内存带宽争用）；超过 4 GPU 后 witness 流式 I/O 成为瓶颈（§V.B.c、§V.H.b）。
- 约束规模：每步约束数随 P_PEFT 近似线性、随序列长度超线性；每步 O(P_PEFT) + 每 token 的 O(LHd)；lookup argument 使非线性项为 O(LH) 而非"多项式次数 × LH"；递归深度 O(log T)；二分折叠使聚合证明大小为单证明的小常数倍（§III.M.a、§III.M.b）。序列从 2048 增到 4096 token：约束数 ×2.23，prover 时间 ×2.38（§V.D.c）。
- 其他开销：私有采样使 prover 时间 +6.4%、叶证明 +~18 KB（§V.D.d）；TEE 内运行 VFT-FrontEnd 增加 3–6% wall-clock（§V.D.f）；micro-recursion（8 步/微证明）降低 wall-clock 17–24%（§V.H.c）；分块 witness 降低 I/O ~22%（§V.H.b）。存储方面论文报告测量 per-epoch transcript 大小（witness + 中间承诺）与最终证明大小，但正文未给出 transcript 的具体数值，只有最终证明 4.1 MB（§IV.C.2.b、Table II）。

分析：主要开销来自**步骤 16 的单步证明生成**，其内部由步骤 8–13 的 arithmetization（算术化）驱动——即"每个被证明的训练步一次定点前向 + 一次受限反向 + 一次 AdamW 转移，并对其全部中间量做多项式承诺"。开销随可训练适配器参数量 P_PEFT 近似线性增长（论文明确给出的线性关系，§V.D.b 的 "proof-time per trainable parameter is nearly constant across ranks"），随序列长度超线性增长（来自注意力矩阵乘与逐 token 行和检查）。存储开销来自 witness transcript（每步激活、定点影子张量与优化器状态），论文报告 4 GPU 以上时 witness 流式 I/O 成为瓶颈，间接说明 transcript 体量是存储/带宽的主要压力（§V.B.c）。

## 9. 实现时容易错的地方

**论文明确强调的实现细节**：
1. 哈希必须用证明系统原生 sponge（Poseidon/Rescue）以避免昂贵的 bit decomposition（§III.M.d）。
2. 定点编码必须配合 range proof 排除溢出，否则数值会绕出域（§III.F.a）。
3. 接受谓词不能是精确等式：Eq. (1) 必须转成不等式、接受判定必须是带容差 τ = δsm + εfxp 的逐坐标区间成员（§III.F.a）。
4. Eq. (1) 的每一步都必须与 Eq. (2)（AdamW）以及 Eq. (3)（配额）、Eq. (4)（softmax 误差）、Eq. (6)（哈希链）一起被约束覆盖，否则可靠性论证不成立（§III.L.a）。
5. 配额违反必须当作硬错误并中止聚合，不能只记录（§IV.C.a）。
6. δsm 存在甜点区：过紧（≤ 5×10⁻⁴）导致约束爆炸与内存尖峰，过松（≥ 8×10⁻³）导致 PPL/ECE 劣化（§V.H.a、Table III）。
7. q = 12 会导致轻微欠自信（under-confidence），q = 14 可修正；这一效应与解码温度交互，可用温度微调补偿，且解码在训练电路之外（§V.F.c）。
8. 行和偏差集中在长序列的某些 head 上，对这些 head 收紧 δsm 可用约 3% prover 开销换稳定性（§V.F.d）。
9. 高并行时 witness 流式传输会打满 PCIe/磁盘，需要 in-memory folding 与 transcript 压缩（分块 witness 可降 I/O 约 22%）（§V.H.b）。
10. 边缘客户端本地证明步数过多会变 straggler，需要 micro-recursion（§V.H.c）。
11. TEE 内页面换入换出会造成 witness 处理抖动，需要 pin enclave 内存并批量 ECALL（§V.H.d）。
12. 确定性要求：pin 线程池、设置确定性 cuBLAS/cuDNN、禁用 autotuning；公开模式随机性必须完全由 (s, t) 决定，否则第三方无法重放（§IV.E.b）。
13. 私有采样会牺牲第三方确定性重放，需要用 public/private 窗口混合来平衡可审计性与隐私（§III.R）。

**论文没说清、实现时必须自己决定的地方**：
1. PROVEUPDATE 的伪代码在抽取出的全文中缺失（§III.K 只声明提供了它，正文只出现 Algorithm 1）；单步证明的具体 witness 布局与约束排列需要自行设计。
2. softmax 近似的具体形式（多项式次数/有理函数形式）、裁剪范围、lookup 表大小与插值方案均未给出（§III.E.b、§III.F.b）。
3. GELU 误差预算的数值、rsqrt 表的规模与分段数未给出（§III.I 只把它列为清单要绑定的项）。
4. εfxp 与 τ 的数值未给出；b 的溢出界也未给具体数值（只给推荐区间 b ∈ [12, 16]）（§III.F.a、§III.M.c）。
5. Merkle 树的元数（arity）与哈希函数的具体实例未定，只说用 Poseidon/Rescue 之类的 sponge；Pedersen/KZG 的参数与 SRS 规模未给（§III.M.d）。
6. 分箱矩阵 M 如何由 domain、register、length 三个属性组合成 B 行未说明；Eq. (3) 是按属性分别施加还是合成一个 M 也未说明（§IV.A.c、Eq. (3)）。
7. Table IV 给出各桶的 Items 与 Tokens(M) 并标为 "per-epoch quota ceilings"，但未说明它们与批大小 64、每 epoch 步数之间的换算；除案例研究的"medical ≤ 5%/epoch"外，未见其它桶以比例形式给出的 γ（Table IV、§V.G.a）。
8. 客户端本地只证明 "a thin subset of steps" 的子集大小未说明；聚合器检查的随机子集大小也未说明（§III.J.a）。
9. 概率审计的检验统计量与判定阈值未说明，只给了检测概率结果（§IV.D.e、Table V）。
10. 私有采样有两处略不一致的描述：一处在 step circuit 内抽取索引（§IV.B.f），一处是在零知识下证明已知 {i} 及其认证路径（§III.D.b）；两者对 witness 的要求不同。
