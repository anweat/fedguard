# ax2409.14119：Obliviate

## 1. 方法一句话

Obliviate 是一种集中式、训练期（training-time）的 PEFT（parameter-efficient fine-tuning，参数高效微调）防御：输入是一个从模型仓库下载的、可能被植入任务无关后门（task-agnostic backdoor）的预训练语言模型（PLM）以及防御者自己干净的下游任务训练集，输出不是任何"是/否"判定，而是对被训练参数的改动——在标准 PEFT 的下游任务损失之外额外加入两个损失项（神经元放大损失 `Lamp` 与注意力分数正则损失 `Lreg`，式 (3)），使最终得到的下游 PEFT 模型在干净准确率（CACC）几乎不降的前提下显著降低攻击成功率（ASR，论文报告平均下降 83.6%）。

## 2. 运行位置

论文是**集中式（centralized）**方法，全文没有联邦学习（federated learning）设定，也没有客户端、服务器、聚合或通信往返的概念。按联邦流程逐一对应如下（凡论文没有的环节都标"分析："）：

- **服务器下发前 / 客户端训练前**：防御者从模型仓库（如 HuggingFace）下载可能被投毒的 PLM（Section 3 "Attackers' goal"）。分析：在联邦里最接近"服务器把（可能被投毒的）全局基座模型下发给客户端"这一步。
- **客户端训练前（client_pre_train）**：冻结全部 PLM 参数，按 adapter / LoRA / prefix-tuning 之一插入随机初始化的 PEFT 层（Section 3 "Defense setting"、Section 5.1.4）。这一步是防御的前提条件，论文明确 PEFT 层"are randomly initialized (i.e., not backdoored)"。
- **客户端每个训练步（client_pre_step + client_step）**：每个训练步正常前向得到注意力分数，再计算 `Lamp`（式 (1)）与 `Lreg`（式 (2)），按式 (3) 相加，反向传播并只更新 PEFT 层参数。论文没有把损失计算和参数更新拆成两个独立时机，因此实现上属于同一个训练步。
- **客户端上传前 / 服务器收到更新 / 服务器聚合 / 聚合之后**：论文未涉及。分析：Obliviate 的两个损失项只依赖客户端本地的前向激活（注意力分数）和本地 PEFT 权重，若移植到联邦，理论上不需要改变聚合规则；但这只是分析，论文没有给出任何联邦实验。
- **训练之外（outside_training）**：超参数 `λamp`、`λreg` 的选择是在干净验证集上按"CACC 下降不超过 2%"的准则做的模型选择（Section 5.1.4、Appendix C "Defense setup"），它需要独立的验证评估，因此对应"训练之外"。
- **额外往返（round trip）**：不需要。论文强调方法"without the need for extra predictions for each input or additional memory"（Section 1），也不使用辅助模型（Section 4.2）。

## 3. 算子流水线

以下按执行顺序展开。所有形状记号中，`n` 表示批量大小，`d` 表示隐藏维度，`L` 表示 transformer 层数。

**步骤 1：冻结基座并插入随机初始化的 PEFT 层（freeze_plm_attach_peft）**

- 输入：可能被投毒的 PLM 权重（论文用 roberta-base、bert-base-uncased，并在 Appendix I 补充 roberta-large、bert-large-uncased），以及防御者持有的干净下游数据。
- 计算：冻结 PLM 的全部参数，向 transformer 层中插入 PEFT 层；论文采用三种架构之一。Adapter：reduction factor = 16；LoRA：`rq = rv = 16`、`α = 16`；prefix-tuning：prefix length = 30、bottleneck size = 256（Table 7）。RoBERTa 上可训练参数占比分别为 adapter 1.44%、LoRA 0.47%、prefix 0.44%（Table 7）。
- 输出：只有 PEFT 层参数可训练、PLM 冻结的模型。
- 出处：Section 3 "Defense setting"、Section 5.1.4、Appendix C "Defense setup"、Table 7。

**步骤 2：计算神经元放大损失（peft_weight_l2norm_amplify）**

- 输入：全部 transformer 层中的 PEFT 层权重张量集合 `{W_p}`。论文明确放大的对象是 adapter 层的 up-projection 与 down-projection 矩阵、LoRA 层的分解矩阵、prefix-tuning 的 reparametrization 矩阵（Section 4.2 "Benign neuron amplification"）。
- 计算：式 (1)，`Lamp = − Σ_{i∈L} Σ_{p∈P_i} ||W_p||_2`。其中 `L` 是所有 transformer 层，`P_i` 是第 i 层内的 PEFT 层集合，`W_p` 是单个 PEFT 层的权重，`||·||_2` 是 L2 范数；对外层求和取负号，因此最小化总损失等价于最大化各 PEFT 层权重的范数。
- 输出：一个标量 `Lamp`。
- 出处：式 (1)、Section 4.2 "Benign neuron amplification"。

**步骤 3：计算注意力分数正则损失（attention_score_l2norm_regularize）**

- 输入：每个 transformer 层 `i`、每个注意力头 `h ∈ H_i` 的注意力分数 `a_h`。论文额外限定正则的对象："For sentence classification, we regularize the attention scores of input tokens on the [CLS] output"（Section 4.2 "Attention score regularization"），即只取各输入 token 对 [CLS] 输出的注意力。
- 计算：式 (2)，`Lreg = Σ_{i∈L} Σ_{h∈H_i} ||a_h||_2`。对每个注意力头的注意力分数取 L2 范数，在头与该层所有头上求和；最小化它会压低异常高的注意力值，从而惩罚触发词（trigger token）的过高注意力。
- 输出：一个标量 `Lreg`。
- 出处：式 (2)、Section 4.2 "Attention score regularization"。设计动机见 Section 4.1 "Attention on triggers" 与 Figure 3（RoBERTa）、Figure 6（BERT）。

**步骤 4：加权组合总损失（weighted_loss_combination）**

- 输入：下游任务损失 `Ltask`、`Lamp`、`Lreg`，以及系数 `λamp`、`λreg`。
- 计算：式 (3)，`L = Ltask + λamp · Lamp + λreg · Lreg`。论文说明引入 `Ltask` 是为了保证干净样本上的性能不被破坏。
- 输出：用于反向传播的标量损失 `L`。
- 出处：式 (3)、Section 4.2 "Defense loss and training"。

**步骤 5：标准 PEFT 反向与参数更新（peft_gradient_update）**

- 输入：总损失 `L` 与当前 PEFT 参数。
- 计算：完全沿用各 PEFT 架构的标准训练循环，只更新 PEFT 层参数，PLM 参数保持冻结。训练超参：batch size 16（Appendix C "Defense setup"）；学习率 adapter 3e-4、LoRA 5e-4、prefix 2e-4；epoch 数 adapter 20、LoRA 30、prefix 20（Table 7）。论文在 Limitations 中明确"we adopt the default training hyperparameters of the standard PEFT process in each PEFT architecture's paper"。
- 输出：更新后的 PEFT 层参数。
- 出处：Section 5.1.4、Appendix C "Defense setup"、Table 7、Limitations。

**步骤 6：按验证集 CACC 选损失系数（validation_grid_select_lambda）**

- 输入：`λamp`、`λreg` 的候选集合，以及干净验证集上的 CACC。
- 计算：在候选范围内选择满足"验证集 CACC 下降不超过 2%"的最大 `λamp` 与 `λreg`（Section 5.1.4、Appendix C "Defense setup"）。候选范围见 Table 7：`λamp ∈ {1e-3, 2e-3, 3e-3, 5e-3}`，`λreg ∈ {1e-2, 2e-2, 3e-2, 5e-2}`；Appendix F 的 Figure 9 另外扫描了 1e-4 到 5e-3 的系数（与 Table 7 的 `λreg` 范围不一致，见第 9 节）。
- 输出：两个标量系数 `λamp`、`λreg`。
- 出处：Section 5.1.4、Appendix C "Defense setup"、Table 7、Appendix F / Figure 9。

**步骤 7：推理（无输入过滤、无辅助模型）（peft_inference_no_filter）**

- 输入：测试样本（可能含触发词）。
- 计算：普通前向推理，不做任何输入改写、token 剔除、逐样本多次预测或辅助模型打分。论文强调该方法"does not necessitate extra predictions or an auxiliary model"（Section 4.2）。
- 输出：下游任务的预测标签。
- 出处：Section 1、Section 4.2、Section 5.1.4。

## 4. 采样与规模控制

方法本身：**论文未使用**。式 (1) 与式 (2) 都对**全部** transformer 层求和，没有对层、注意力头、参数坐标做抽样、截断或降维；对样本与轮次也没有采样或截断机制；不使用任何参考数据、探针样本或参考模型（这正是它相对 ONION、PSIM 的优势，Section 2.3、Section 4.2）。论文没有联邦客户端概念，客户端维度论文未使用。

实验配置中出现的规模（不是方法要求的抽样，但决定了复现规模）：

- **层（layers）**：`i ∈ L` 覆盖所有 transformer 层，论文未抽样（式 (1)、式 (2)）。论文未说明层数；Figure 3 与 Figure 6 的横轴标到 11 层（分析：对应 base 模型的 12 层）。
- **注意力头（heads）**：`h ∈ H_i` 覆盖每层全部注意力头，未抽样（式 (2)）；头数论文未说明。
- **样本（samples）**：训练 batch size 为 16，所有任务一致（Appendix C "Defense setup"）。下游数据用量：SST-2 用 6,000 条训练、872 条验证、1,821 条测试；AG News 用 6,000 条训练、2,000 条验证、2,000 条测试；HSOL 用 6,000 条训练、2,000 条验证、2,000 条测试（Appendix C、Table 6）。
- **轮次（rounds）**：adapter 20 epoch、LoRA 30 epoch、prefix 20 epoch（Table 7）。Limitations 提到"we can achieve effective backdoor mitigation after 10 or 20 epochs, depending on the PEFT architecture"。
- **探针（probes）**：0，论文未使用。

（攻击侧规模，仅用于理解评测，不是防御所需：Appendix C 说明采样 120,000 条投毒实例、每个触发词 20,000 条，并使用等量干净样本；6 个触发词为 `['cf','mn','tq','qt','mm','pt']`，来自 Appendix C 与 Section 5.1.1。）

## 6. 判定与动作

- **没有判定**：Obliviate 不做二分类判定，不使用阈值、聚类、离群点打分，也不剔除任何样本或客户端（Section 4.2 明确放弃"用阈值移除高注意力 token"的路线，试点实验见 Appendix B / Figure 7）。唯一带"阈值"色彩的是超参选择准则"验证集 CACC 下降不超过 2%"，它决定系数大小，而不是决定样本去留（Section 5.1.4）。
- **动作类型**：通过损失项改变梯度（transform_gradients）。具体来说，`Lamp` 对每个 PEFT 层权重施加一个负的 L2 范数项，其梯度方向是把权重范数推大；`Lreg` 对注意力分数施加 L2 范数项，其梯度方向是把过高的注意力分数压低。两者与 `Ltask` 相加后一起反传（式 (3)）。
- **幅度**：由 `λamp`、`λreg` 控制；论文在 Appendix F 报告，在很宽的系数范围内 CACC 保持稳定，而 ASR 一般随系数增大而下降（Figure 9）。
- **裁剪或加噪**：论文未使用。
- **是否跨轮累积**：论文没有设计显式的跨轮状态累积机制；但两个损失项在**每个训练步**都被加入，因此放大效果会随训练步累积。Figure 8（左）显示 PEFT 层的 L2 范数随 epoch 持续上升、同时 ASR 下降，Limitations 也指出 `Lamp` "tends to increase continuously"。分析：若移植到联邦，这个累积发生在客户端本地训练内部，不需要跨轮在服务器侧保存状态。

## 7. 需要的外部资源

- **可能被投毒的基座 PLM**：roberta-base / bert-base-uncased（Section 5.1.1），Appendix I 另外使用 roberta-large / bert-large-uncased；防御者从 HuggingFace 等模型仓库下载（Section 3）。
- **干净的下游任务训练集与验证集**：如 SST-2、AG News、HSOL（Section 5.1.2、Appendix C）。验证集用于选 `λamp`、`λreg`，因此必须是带标签且干净的（Section 5.1.4）。
- **PEFT 实现库**：论文使用 AdapterHub 的实现（Appendix C "Defense setup"）。
- **规模参考**：RoBERTa 上只训练 0.47%（LoRA）到 1.44%（adapter）的参数（Section 5.2、Table 7）。
- **不需要**：触发样本或任何攻击知识（Section 3 "Defense setting"）、辅助模型（Section 2.3、Section 4.2）、根数据集 / 干净参考模型 / 预训练检测器（论文未使用）、逐输入的多次预测（Section 1、Section 4.2）。

## 8. 计算与存储开销

论文报告的开销：

- 论文只给出定性结论：方法"without the need for extra predictions for each input or additional memory"（Section 1），并在 Section 4.2 重申"does not necessitate extra predictions or an auxiliary model, thereby maintaining the nature of the PEFT approach"。
- 论文对比指出 ONION、PSIM 等方法"require large computation costs due to multiple predictions for each sample"，且需要辅助模型（Section 2.3），而 Obliviate 不需要。
- 论文**未报告**任何 FLOPs、显存占用、墙钟时间或通信量数字。

分析（标"分析："的部分）：

- 主要额外开销来自步骤 2 与步骤 3。步骤 2 需要遍历全部 PEFT 层权重并求 L2 范数，成本随 PEFT 可训练参数量线性增长。步骤 3 需要遍历每层每个头的注意力分数并求 L2 范数，成本随"层数 × 头数 × 序列长度"增长；注意力张量本来就在前向中算出，因此额外前向成本主要是范数计算。
- 真正的额外资源在于反向：`Lreg` 直接对注意力分数求导，要求注意力图参与反向传播并保留在计算图中，这会增加激活显存；`Lamp` 只对权重求导，几乎不增加激活显存。论文没有报告这一项的量化影响。
- 开销与客户端数量无关（论文无联邦设定）；在联邦移植下（分析：）额外通信为零，因为损失项完全在客户端本地计算。

## 9. 实现时容易错的地方

论文明确强调或已实验证明的：

1. **`Lamp` 不收敛是已知问题**。Limitations 写道"The neuron amplification loss tends to increase continuously, which prevents the optimization process from converging"，论文的应对是采用各 PEFT 原论文的默认训练超参与 epoch 数，而不是靠 early stopping（论文明确说该训练过程"often struggles to be completed in a strategic manner, for instance, by using early-stopping"）。过度训练会损害模型性能。
2. **不要用阈值剔除高注意力 token**。Appendix B 的试点实验表明，基于注意力归因的触发词检测虽然能降 ASR，但假阳性高、CACC 大幅下降（Figure 7），所以论文改为"优化压低注意力"而不是"删除 token"。
3. **注意力分数在层与文本之间差异很大**（Section 4.1："these distinctive features of attention scores vary across different transformer layers and input texts"），这解释了为什么式 (2) 要对所有层求和而不是挑层。
4. **两种损失项作用不同**。Table 4 与 Appendix E 显示：`Lreg` 主要针对插入式词触发（word trigger），对 syntactic / style 后门作用较小；`Lamp` 更通用，但对只靠它防御不够（Appendix E："relying solely on Lamp for defense is not sufficient due to the limited number of parameters available for amplification"）。
5. **PEFT 结构参数不能设太小**。Appendix C 说明 LoRA rank 与 prefix length 设得过低会导致 CACC 显著下降，"even without any defense"，因此论文固定 rank 16、prefix length 30。
6. **`Ltask` 必须保留**。Table 2 与 Section 5.4.1 显示，去掉任务损失会破坏在良性 PLM 上的性能；论文归因于式 (3) 中 `Ltask` 的作用。

论文没写清、实现时必须自己决定的：

1. `||W_p||_2` 对矩阵而言究竟是 Frobenius 范数还是谱范数，论文只写"L2-norm"（式 (1)）。
2. `a_h` 的确切形状与聚合方式：是 softmax 后的注意力权重还是 logits；是否对 batch 维取平均；是否对 token 位置取平均；是否只取 [CLS] 对应的那一行/列；是否包含 [CLS]、[SEP] 自身。Figure 3 与 Figure 6 的注只说"[CLS] and [SEP] tokens are omitted"，但式 (2) 的定义没有说明。
3. `λamp`、`λreg` 的最终具体取值：论文只给出候选集合与选择准则，没有列出每个实验最终选中的数值。
4. 两个系数是联合搜索还是各自独立搜索；选择过程是否需要为每个候选重新训练一轮（Section 5.1.4 只写了"select the largest ... that exhibit no more than a 2% drop in the CACC on the validation set"）。
5. Table 7 的 `λreg` 候选范围（1e-2 起）与 Appendix F / Figure 9 的系数扫描范围（1e-4 到 5e-3）不一致，论文未说明哪个是最终配置。
6. "所有 PEFT 层"的确切张量清单未完全给出：adapter 是否只含 up/down-projection 而不含 LayerNorm 与 bias；LoRA 是否只含 A、B 两个分解矩阵；prefix-tuning 的 reparametrization 网络的具体结构（论文只给 bottleneck size = 256）。
7. prefix-tuning 的重参数化矩阵在训练后被移除（Table 7 注），因此 `Lamp` 放大的是训练期临时参数；这种放大是否会传递到最终保留的 prefix 向量上，论文未说明。
8. 非句分类任务如何应用 `Lreg`：`[CLS]` 只存在于句分类；Appendix G 说 NER/QA 上 POR、NeuBA 攻击被适配为"forcing all the token outputs toward the adversarial representations"，但防御侧 `Lreg` 在这些任务上作用于哪些注意力，论文未说明。
