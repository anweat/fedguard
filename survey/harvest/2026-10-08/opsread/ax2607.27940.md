# ax2607.27940：TriShield（Parameter Artifact Detector + Stateful Virtual Iteration + Zero-Utility Orthogonal Projection）

## 1. 方法一句话

TriShield 是一个完全运行在客户端的确定性三层防御：输入是服务器下发的 PEFT adapter 参数 φ0（Parameter-Efficient Fine-Tuning，参数高效微调）、客户端本地私有数据 D_i、以及一小份公开无标注的辅助数据 D_aux；它先在训练前扫描并重置收到的 adapter 中的"记忆神经元"（Layer 1, PAD），再用 D_aux 做若干次"只更新优化器状态、不更新权重"的虚拟 Adam（Adaptive Moment Estimation）步来污染动量（Layer 2, SVI），最后在训练结束、上传之前把本地更新 Δφ_i 投影到由 D_aux 逐样本梯度估计出的主任务子空间上（Layer 3, ZUOP），输出一个被净化后的上载更新 Δφ_i*，使恶意服务器无法从更新中解析出单条私有样本（论文声称重建率 0%、互信息为 0），同时论文声称下游精度损失 < 0.3%。

## 2. 运行位置

TriShield 是纯客户端防御，服务器不参与、协议不变、也不需要任何额外通信往返（Section I-D 贡献 1：operating entirely on the client side, requires no server cooperation and is transparent to the FL protocol；Section III-D：No additional communication rounds）。

- **Layer 1（PAD）**：**客户端训练前**。客户端一收到服务器分发的全局 adapter φ0 就检查，发生在本地真实训练开始之前（Section IV-A 首句；判决图 Figure 1 的流程：[Received Global Adapter phi0] → LAYER 1）。
- **Layer 2（SVI）**：**客户端训练前**，在 PAD 之后、真实训练开始之前执行 K 次虚拟优化器步，只改 Adam 的 (m, v)，不改参数（Section IV-B 的 SVI Algorithm；Figure 1 中 LAYER 2 位于收到 φ0 之后、本地微调之前）。
- **本地真实训练**：仍是标准的客户端本地训练，唯一区别是 Adam 的初始动量状态被 SVI 预污染（SVI 伪代码最后一行 "Continue real training with pre-poisoned optimizer state"）。
- **Layer 3（ZUOP）**：**客户端上传前**（Figure 1 中 LAYER 3 标注为 "After local fine-tuning"，随后才是 "Upload sanitized Δφ_i* to server"；ZUOP Algorithm 的 Input 写 "Gradient Δφ_i ... (after local training)"）。
- **服务器收到更新 / 聚合 / 聚合之后**：TriShield 不做任何服务器侧操作，服务器仍按 Δφ_{t+1} = φ_t + (1/N)ΣΔφ_i 聚合（Section II-A 第 4 步；Section I-C 明确说 FLAME/FLTrust 这类服务器侧防御不适用于"服务器即对手"的威胁模型）。
- **是否需要额外往返**：不需要。服务器也无法观测客户端的中间动量 (m_K, v_K)（Section III-A 的攻击者能力清单明确写 "Cannot observe intermediate optimizer states"）。

（该方法本身是联邦方法，不存在"集中式版对应位置"的问题。）

## 3. 算子流水线

以下按执行顺序给出，可映射为运行时算子。

**步骤 1：PAD 统计扫描（row variance / cross-row correlation）**
- 输入：服务器下发的 PEFT adapter 参数；伪代码声明的输入是 W_A ∈ R^{d_out×d_in}、W_B ∈ R^{d_out×d_in}、β_B ∈ R^{d_out}（论文原文如此，W_B 的维度写法与 LoRA 常规不一致）。论文另在变体分析里确认 PAD 扫描"所有 LoRA 层"（Table VII 的 MLD 行：PAD scans all LoRA layers → detects & resets）。
- 计算：对 W_A 的每一行 i 计算两个统计量——(a) 行内方差 r_var = variance(W_A[i, :])；(b) 与其它所有行的相关性最大值 r_corr = max_{j≠i} corr(W_A[i,:], W_A[j,:])。判定条件为 **r_var < τ_var 或 r_corr > τ_corr**（Algorithm PAD）。Section IV-A 的 Observation 列出了三类 NeuroImprint 签名：① 行近重复（normalized vectors 的相关 > τ_corr = 0.95）；② 行内方差近零；③ 偏置 b_j ≈ β 且偏置间方差低。但 Algorithm PAD 的循环只实现了前两类，第三类没有阈值也没有落地代码（见第 9 节）。
- 输出：每行的 (r_var, r_corr) 与布尔掩码 flag_reset[i]。
- 出处：Section IV-A 的 Observation 与 Algorithm PAD（第 3–4 页）；阈值见 Section IV-A 与第 7 页超参数表。

**步骤 2：PAD 重置可疑行（reinitialize）**
- 输入：flag_reset 掩码、W_A、β_B。
- 计算：对所有 flag_reset[i] = True 的行执行 W_A[i, :] ← Kaiming_Normal(fan_in = d_in)；β_B[i] ← N(0, 0.02)。返回 W_A^clean、β_B^clean，其余参数保持不变。
- 输出：净化后的本地初始化 φ0^clean。
- 出处：Algorithm PAD 伪代码（第 4 页）。

**步骤 3：SVI 虚拟优化器步（state warm-up）**
- 输入：PAD 之后的 adapter（伪代码写 phi0）、公开辅助数据 D_aux、虚拟步数 K。
- 计算：先保存快照 φ_snapshot = copy(φ0)；对 k = 1..K 循环：从 D_aux 采样一个小批量 B_k，在**快照参数**上计算虚拟梯度 g_k = ∇_φ L(B_k; φ_snapshot)，**不更新权重**，只按 Adam 规则更新优化器状态 m_k = β1·m_{k−1} + (1−β1)·g_k 与 v_k = β2·v_{k−1} + (1−β2)·g_k²；循环内每步之后把参数恢复成快照 φ_current = φ_snapshot；循环结束后带着被污染的 (m_K, v_K) 进入真实训练。
- 输出：未改动的 adapter 参数 φ0 与被预污染的优化器状态 (m_K, v_K)（伪代码 Output 行：Warm-started optimizer state (m-hat, v-hat), unchanged adapter phi0）。
- 出处：Section IV-B 与 SVI Algorithm（第 3–4 页）。论文在正文中把 Adam 更新写成 θ_{t+1} = θ_t − α · m̂_t / (√v̂_t + ϵ)，其中 m̂_t = β1·m_{t−1} + (1−β1)·g_t、v̂_t = β2·v_{t−1} + (1−β2)·g_t²（Section IV-B 的无编号公式）。

**步骤 4：真实本地训练（用被污染的优化器状态）**
- 输入：φ0^clean、本地私有数据 D_i、(m_K, v_K)。
- 计算：按标准联邦 PEFT 轮训练 E 个本地 epoch，得到本地更新 Δφ_i = φ_i − φ0（Section II-A 第 2–3 步）。实验设置为 3 local epochs、batch size 4、Adam(β1=0.9, β2=0.999, lr=5×10⁻⁴)（Section VII-A）。
- 输出：Δφ_i。
- 出处：Section II-A 联邦轮流程；SVI 伪代码最后一行；Section VII-A。

**步骤 5：ZUOP 构造逐样本任务梯度矩阵 G**
- 输入：D_aux 的 n 条公开样本，以及一个参数点。参数点论文说法不一致：ZUOP Algorithm 的 Step 1 写 "on D_aux"，Section VII-D 的 n-robust 验证写 "estimates the task subspace on a fixed public reference model"，Section VII-E 的消融写 "subspace estimated on the trained model"。
- 计算：对每条辅助样本算一次梯度并拼成矩阵 G = [∇_φ L(x_1), ∇_φ L(x_2), …, ∇_φ L(x_n)]，for x_i in D_aux；论文写作 G ∈ R^{(d_out×d_in)×n}。
- 输出：G。
- 出处：ZUOP Algorithm Step 1（第 6 页）；Section VI-C。

**步骤 6：SVD 取主任务方向**
- 输入：G。
- 计算：U, S, V^T = SVD(G, full_matrices=False)；取 U_k = U[:, :k]（前 k 个左奇异向量，即 principal task directions）；其中 **k = min(0.8 · rank(G), n−1)**（Section IV-C 的 Key Parameter）。
- 输出：子空间基 U_k ∈ R^{d_param×k}。
- 出处：ZUOP Algorithm Step 2；Section IV-C。

**步骤 7：投影上传更新**
- 输入：本地更新 Δφ_i（ZUOP 伪代码写作 Gradient Δφ_i）与 U_k。
- 计算：Δφ_i_flat = flatten(Δφ_i)；Δφ_i* = reshape(U_k · U_k^T · Δφ_i_flat)。等价于用正交投影矩阵 P_{U_main} = U_k U_k^T 投影（Theorem 2）。
- 输出：上传给服务器的 Δφ_i*。
- 出处：ZUOP Algorithm Step 3；Theorem 2、Theorem 3、Corollary 1（第 5–6 页）。

**步骤 8：LoRA（Low-Rank Adaptation）特化**
- 输入：LoRA 的 A、B 矩阵与合并更新 ΔW = B·A。
- 计算：Section VI-B 写 "the projection is applied to the A and B matrices separately, with the SVD computed on the combined update ∆W = B · A"；对标准 adapter 层（feed-forward bottleneck）则直接对每个 adapter 权重矩阵投影。
- 输出：投影后的 A、B（上传形式）。
- 出处：Section VI-B（第 6 页）。注意这与步骤 7 的"整个参数向量一次投影"写法并不闭合，论文未说明二者如何统一（见第 9 节）。

## 4. 采样与规模控制

- **探针/参考数据（probes）**：使用公开、无标注、与私有数据同分布（domain-adjacent）的辅助数据 D_aux，同时用于 SVI 虚拟步与 ZUOP 子空间估计。论文实验实际用 **32 条**（Section VI-C：In our experiments, we use 32 domain-adjacent ML/NLP text samples as D_aux；Section VII-A 同）；论文建议部署用 **200–500 条**（Section III-C：size |Daux| = 200–500 samples；Section VI-C：Small: 200–500 unlabeled text samples）。D_aux 被用于 ZUOP 的逐样本梯度计算，因此每条 aux 样本对应一次前向+反向。
- **客户端（clients）**：实验为 5 个 IID 客户端、20 个通信轮（Section VII-A），论文未对客户端做抽样。
- **参数坐标（coordinates）**：ZUOP 只保留前 k 个主方向，k = min(0.8·rank(G), n−1)，rank fraction 默认 0.80；论文称 32 条 aux 时 k ≈ 3、梯度保留率 12%（Section IV-D），另一处称 lora A 保留率 ≈6%（Section VII-C）与 ≈7%（Section VII-D），数字不一致。n-robust 验证改用更保守的 rank fraction = 0.60（Section VII-E）。
- **层（layers）**：PAD 扫描所有 LoRA 层；实验 LoRA 目标为 GPT-2 的 c_attn（rank=8）与 Llama-Guard-3-1B 的 q_proj + v_proj（rank=4）（Section VII-A）。Table VI 给出注入神经元数 GPT-2 为 8、Llama 为 128。
- **样本（samples）**：n-robust 验证覆盖任意受害者私有样本数 n ∈ {8, 64, 256, 1024}（Section VII-D）；攻击侧记忆神经元预算为"每客户端每轮 LoRA rank 行"（Section VII-A）。PAD 与 ZUOP 均与 n 无关（Section VII-D）。
- **轮次（rounds）**：论文未对轮次做抽样或截断；Section VII-I 声称每轮防御方式相同，多轮累积同样 0%，但没有给出跨轮定量结果。

## 6. 判定与动作

- **PAD 的判定到动作**：逐行布尔判定"r_var < τ_var **或** r_corr > τ_corr"，命中即就地重置该行权重与对应偏置（见步骤 2）。动作是"改写收到的广播参数"，不剔除客户端、不做加权、不上报。PAD 的检测率论文报告为 100%（GPT-2 c_attn：8/8；Llama-Guard-3-1B q_proj+v_proj：128/128，Table VI）；假阳性分析称正常初始化的行内方差约 1/d_in（10⁻³–10⁻²），远高于 τ_var = 10⁻⁴，d_in > 64 时假阳性概率 < 10⁻⁶（Section IV-A）。
- **SVI 的判定到动作**：没有检测阈值。动作是把 (m_K, v_K) 作为真实训练 Adam 的初始状态，使内存神经元的上传更新变成 Δθ_mem = α · (m_{K+1}/β1^c) / √(v_{K+1}/β2^c + ϵ)，即 g_real、m_K、v_K 的非线性混合；Theorem 1 论证服务器在只拿到 Δθ_mem、未知 (m_K, v_K) 时面对 O(d_in) 个未知量与 O(1) 个约束，K ≥ 2 时欠定。论文明确强调 SVI **不改变梯度 L2 范数**，只破坏方向的可解码性（Section VII-B、VII-F）。
- **ZUOP 的判定到动作**：没有阈值型判定，动作是投影 Δφ_i* = U_k U_k^T Δφ_i。Theorem 3：若 g_mem ⊥ U_main，则 P_{U_main} g_mem = 0；Corollary 1：攻击者读到的 x̂_j = Δφ*_rj / Δφ*_bj = 0/0，未定义，互信息 I(x̂_j; x_j) = 0。论文实测把 LoRA A 的行范数从约 4.13×10⁻² 降到 3.08×10⁻³（约 13 倍），低于攻击侧 10⁻² 的重建阈值（Table II、Section VII-B）。
- **跨轮累积**：不存在跨轮累积的信任分或记忆机制；PAD 每轮对收到的 adapter 重新扫描（Section VII-I）。论文未说明客户端是否跨轮保留优化器状态。
- **对自适应攻击的动作差异**：VTB/MLD/MLPL 由 PAD 在训练前重置中和；LCN 绕过 PAD 但随机正交行自行破坏 slot→sample 双射（self-defeating）；SR1E 绕过 PAD 但被 ZUOP 投影消除（Table VII、Section VII-I）。

## 8. 计算与存储开销

论文报告的开销（注意数字互相矛盾）：

- 复杂度：PAD 为 O(d_out² · d_in)；SVI 为 K 次 D_aux 上的前向-反向；ZUOP 为 O(n · d_param + d_param²/n)（第 6 页的层级开销表）。
- 实测（第 6 页表）：PAD ≈15 ms（GPU 与 CPU 相同）；SVI < 50 ms GPU（K=3）、≈1,058 ms CPU；ZUOP < 30 ms GPU、≈957 ms CPU。
- Table VIII（第 11 页，CPU，GPT-2 117M）：PAD 14.5 ms（0.5%）、SVI K=3 为 1,058 ms（37.8%）、ZUOP 957 ms（34.2%）、合计 ≈2,030 ms（≈72% CPU 训练轮时间）。
- GPU 总开销：Section IV-D 写 "total GPU overhead < 5% of training round"；Section VII-J 写并行流下 "<4% of training time"（A100、768 维隐状态的估计值）；Abstract 写 "less than 5%"；结论写 "< 8%"。四处不一致。
- 论文在 Section VIII-B4 承认 CPU 上 72% 的开销对纯 CPU 客户端很显著，建议边缘设备用 GPU 加速或降低 K / aux 规模。

分析（标 "分析："）：按流水线看，主要开销来自 **ZUOP 对每条 D_aux 样本做一次前向+反向以构造 G、再做一次 SVD**，以及 **SVI 的 K 次前向+反向**；前者随 |D_aux| 与参数维度 d_param 增长（每条样本一次反向传播），SVD 的规模是 n×d_param；后者随 K 与 |D_aux| 的批次数增长。PAD 只随 d_out²·d_in 增长，是纯权重统计，通常可忽略。存储方面需要保存一份 adapter 快照（SVI 伪代码的 φ_snapshot）、梯度矩阵 G（n × d_param，32 条 aux 时约 32 × 数万到数百万维）以及本来就要维护的优化器状态 (m, v)；论文**未报告显存峰值**。

## 9. 实现时容易错的地方

论文明确强调、实现时必须遵守的：

1. **不要用梯度范数评价 PAD 和 SVI**。论文反复强调：PAD-only 的范数是 5.06×10⁻²、PAD+SVI 是 4.58×10⁻²，仍然"100% 重建"（按范数指标），只有 ZUOP 把范数压到 3.08×10⁻³（Table II、Section VII-B、VII-E）。
2. **SVI 绝不能真的更新参数**：伪代码要求先存快照、每步后把参数恢复为 φ_snapshot（"Restore exact adapter weights (no real updates made)"），输出必须是"参数不变的 φ0 + 被污染的状态"。
3. **rank fraction 不能取大**：0.95 时 k 变大，SR1E 会与保留子空间偶然对齐而泄漏（Section VI-D 写 ≈12%，Section VII-E 实测 50%，即 4/8 slots）；0.80 是安全默认，n-robust 场景用 0.60。
4. **τ_var 是按 LoRA rank 4/8 调的**；固有低方差的 PEFT 结构需要重新标定（Section VIII-B3）。
5. **D_aux 必须域内、公开、无隐私**；分布不匹配会带来轻微效用损失（Section VIII-B2），且论文自己承认极端敏感领域可能没有可用的公开数据（Section VIII-B1）。
6. **注意 PAD 假阳性的边界**：正常初始化行内方差约 1/d_in，d_in > 64 时假阳性 < 10⁻⁶（Section IV-A）；反过来说 d_in 很小的 adapter 上 τ_var = 10⁻⁴ 与正常初始化的间隔会变小。
7. **论文的图表编号内部不一致**：正文引用 "Table 0 / Table 1 / Table 2 / Table 2" 与实际的 Table I–VIII 对不上；"see Section 7.3" 也找不到严格对应的小节号。复现时以表内容而不是表号为准。
