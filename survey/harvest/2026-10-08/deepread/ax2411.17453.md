# ax2411.17453：PEFTGuard: Detecting Backdoor Attacks Against Parameter-Efficient Fine-Tuning

> 说明：本分析依据的是论文全文（arXiv:2411.17453v2，页眉标注 2025 年 6 月 10 日；arXiv 编号 2411 对应 2024 年 11 月首发）。所有数值均来自正文、表格或图注。第 11 节的引文按 PDF 抽取原文逐字复制，因此保留了上下标粘连的排版痕迹（例如 "PEFTGuardcls"、"Finput"、"∆(l) q"）。

## 1. 基本信息

- **场景**：这篇论文不属于传统联邦学习（federated learning, FL），也不属于联邦大模型微调。它研究的是参数高效微调（Parameter-Efficient Fine-Tuning, PEFT）适配器（adapter）在开源模型共享平台上的传播供应链，即"适配器制作者／发布者—下载使用者"的集中式场景。按给定枚举归为 `peft_supply_chain`（参数高效微调供应链）。
- **训练阶段**：攻击（后门注入）发生在适配器的本地微调阶段，包括本地数据准备与 PEFT 训练；防御（检测）发生在适配器训练完成、被发布和下载之后，属于"训练后、使用前"的静态权重检查。论文完全没有涉及训练轮次、客户端采样、服务器聚合或全局模型下发。
- **论文类型**：检测（detection），同时构建并公开了一个基准数据集 PADBench（benchmark）。JSON 中按主要贡献记为 `detection`。
- **模型与数据规模**：PADBench 共包含 13,300 个良性或后门适配器（Abstract、Section 1.1）。基座模型为 Llama-2-7B、Llama-3-8B、Llama-2-13B、Qwen1.5-7B-Chat、Chatglm-6B-v2、Flan-t5-xl、Roberta-base（Section 5.1），并扩展到 ViT-base 与 Qwen2-vl-2B（Section 6.3、Table 7）。数据集为 IMDB、AG News、SQuAD、toxic-backdoors-alpaca、toxic-backdoors-hard，以及视觉／多模态的 CIFAR-10 与 VQAv2（Table 16）。PEFT 方法覆盖 LoRA、QLoRA、DoRA、LoRA+、AdaLoRA（Section 2.2、Table 3）。

## 2. 威胁模型

**攻击者（adversary）是谁**：论文中的攻击者是适配器的制作者与发布者。原文的分工假设是"攻击者能做的全部事情就是预先准备后门适配器并把它们发布到开源平台"（Section 3.1 Capability）。论文没有客户端、参与率、恶意比例这类联邦概念；它给出的量化设定是投毒率维持在 5%（Section 5.3.1）。

**能力**：攻击者可以投毒微调数据集（Section 3.1 Capability: "we assume that the adversary can poison the fine-tuning dataset"），用任意 PEFT 方法训练出后门适配器，并发布到 huggingface 一类平台；发布之后，攻击者无法影响防御者的任何动作，例如修改适配器权重或实施检测。论文还假设攻击者会监控适配器的 ASR 来判断后门是否注入成功，并需要保证适配器在正常任务上表现良好，以便被用户下载使用（Section 3.1 Capability）。

**知识**：论文明确假设攻击者对 PEFT 微调策略（例如 LoRA）、相关超参数（例如适配器 rank）以及预训练模型架构没有特定偏好（Section 3.1 Capability）。论文还指出，通过适配器注入后门比攻击基座模型门槛更低，"只需要消费级 GPU 和极少的训练资源"（Section 2.3）。

**目标**：定向后门（backdoor）。触发时让模型忽略用户输入、直接产生攻击者设计的有害输出，包括改变正确预测和生成有毒句子；无触发时模型的表现与输出应保持不受影响（Section 3.1 Goal、Equation 11）。

**防御者是谁、能看到什么、信任什么**：防御者是下载和审查适配器的一方。可见范围仅为重参数化 PEFT 适配器的权重，论文认为这是现实的，因为这些权重通常公开在 huggingface 等网站上（Section 3.2 Capability）。论文明确不假设防御者知道训练数据集、超参数设置、触发器模式／类型或下游任务（Section 3.2 Capability）。防御者的目标是把适配器二分类为良性或后门（Section 3.2 Goal）。

论文未说明：防御者是否持有基座模型权重；防御者的信任根是什么。分析：整个方法隐含地信任"防御者自己生成的良性／后门适配器语料及其标签"是可靠的，因为元分类器的监督信号完全来自这份自建语料；这是论文没有讨论的信任前提。

## 3. 攻击入口与流程位置

论文里的攻击入口明确落在两个位置，外加一个传播环节：

1. **本地数据准备**：攻击者从原始 NLP 任务数据集中采样子集，再构造投毒样本。投毒率固定为 5%（Section 5.3.1）。触发器形态包括词级（toxic-backdoors-alpaca 使用特殊词 "SolidGoldMagikarp"；RIPPLES 随机插入 "cf"、"tq"、"mn"、"bb"、"mb" 之一；InsertSent 插入固定句 "I watched this 3D movie with my friends last Friday."，在 SQuAD 上则用 "no cross, no crown"）、句级（toxic-backdoors-hard 使用包含 "Manchester United" 的句子）、句法级（Syntactic 使用 SCPN 与模板 S(SBAR)(,)(NP)(VP)(.)）和风格级（StyleBkd 采用圣经风格）（Section 5.3.1）。
2. **本地训练过程**：用 PEFT 方法在含毒数据上微调，原始模型参数冻结，只更新低秩适配器 ∆，得到后门适配器（Section 2.2、Section 3.1 Goal）。论文没有设计任何针对损失函数、优化器状态或训练步数的特殊操纵，攻击面就是"数据投毒加正常 PEFT 训练"。
3. **模型（适配器）发布与传播**：攻击者把后门适配器发布到开源平台，用户将其与良性 LLM 结合并加载，触发器出现时后门被激活（Abstract、Section 1）。这是供应链意义上的分发环节，在给定枚举中最接近 `model_distribution`，但它不是联邦学习中的"服务器下发全局模型"。

论文未说明：服务器聚合、全局模型下发、评估与部署环节，因为该论文不存在这些环节。PEFTGuard 的拦截点是"拿到适配器权重之后、合并进 LLM 或推理之前"；论文强调检测不需要把适配器合并回原模型（Section 1.1、Section 2.3）。

## 4. 方法原理

**核心直觉**：把微调后权重与预训练权重相减可以得到 delta 参数（delta parameters），delta 参数承载了微调带来的附加能力；适配器本身就可以视作一种 delta 参数，因此后门适配器应当与良性适配器在参数层面具有可区分的差异（Section 4 Intuition）。作者把 LoRA 适配器的 query 层参数降维后用 t-SNE 可视化，Figure 3 显示每个自注意力层都能在一定程度上区分良性（Benign）与后门／有毒（Toxic）两类。

**问题形式化**：把适配器后门检测建模为二分类问题。给定适配器 ∆，先用特征变换 PEFTGuard_trans(·) 得到 F_input，再送入元分类器 PEFTGuard_cls(·)，输出 0 或 1，1 表示 ∆ 含后门（Equation 12，Section 4 Problem Formulation）。

**步骤一，适配器生成（Adapter Generation）**：从原始 NLP 任务数据集中随机采样子集，分别构成良性数据集与后门数据集，各自用于 PEFT 微调一个 LLM，产生良性或后门适配器，组成训练集 D_train（Section 4.1）。

**步骤二，特征变换（Feature Transformation）**：目的是把不同 rank 造成的形状不一致统一起来（因为不同训练场景下适配器 rank 不同，参数形状不匹配会使分类器难以设计，Section 4.2）。变换分两步。第一步是通道级变换：对第 l 层自注意力，把 ∆(l) 中的权重矩阵沿新引入的维度拼接；论文实验中聚焦 ∆q 与 ∆v，即 ∆(l)_concat = [∆(l)_q, ∆(l)_v]，形状为 2×d×k（Equation 13）。第二步是层级拼接：把各层的 ∆(l)_concat 沿第一维拼接为 F_input = ∆(1)_concat ‖ ∆(2)_concat ‖ … ‖ ∆(L)_concat，形状为 (2L)×d×k（Equation 14）。

**步骤三，分类器训练（Classifier Training）**：元分类器 PEFTGuard_cls(·) 由一层卷积层与多层感知机（Multilayer Perceptron, MLP）组成（Section 4.3、Figure 7a）。卷积层的作用是降维与进一步提特征，因为输入维度很大：在 Llama-2-7B 上，LoRA 的目标模块是 query 与 value 矩阵，F_input 的维度是 [64,4096,4096]，若直接用 MLP 分类会导致内存占用过大（Section 4.3）。

**跨攻击的零样本迁移增强**：为了提升对未知攻击的零样本检测能力，论文先使用监督对比损失进行对比学习（contrastive learning），在三个不同攻击的数据集上训练，再通过模型融合（model fusion，对三个在同一数据集上训练的模型做参数平均）组合分类器（Section 6.4、Table 11）。

**检测之后的缓解**：论文另外实验了三种后门消除方法，即监督微调（Supervised Fine-Tuning, SFT）、直接偏好优化（Direct Preference Optimization, DPO）与 Fine-mixing（Section 5.4、Section 6.6、Appendix B）。

## 5. 检测或防御所需的数据

PEFTGuard 是检测方法，因此下面列出的是防御方需要的输入。

1. **被检测适配器的权重 ∆**。是什么：重参数化 PEFT 适配器在自注意力层的增量参数，默认使用 ∆q 与 ∆v，即 Equation 13 的拼接对象。在哪里采集：适配器训练完成并被发布／下载之后，对应防护库中的"服务器收到更新时"这一信任边界；论文的表述是防御者能访问这些公开权重（Section 3.2 Capability）。粒度：逐层（每层的 ∆q 与 ∆v 各自是一个矩阵），整体上是逐适配器一个样本，拼接后形成 (2L)×d×k 的张量，Llama-2-7B 上为 [64,4096,4096]（Section 4.2、Section 4.3）。是否需要跨轮历史：不需要。是否需要干净参考数据：不需要（检测阶段既不需要训练数据，也不需要干净样本）。是否需要额外的前向或反向计算：不需要，论文明确说检测阶段不需要额外输入数据，也不需要把适配器合并回原 LLM 做推理（Section 1.1、Conclusion）。是否需要其他客户端的数据：不适用。补充：若改用其他投影矩阵（∆k 或 ∆o），拼接方式随之改变，Table 5 给出了 [∆q]、[∆k]、[∆v]、[∆q,∆k]、[∆q,∆v]、[∆q,∆k,∆v,∆o] 六种配置，检测精度均为 100.00%。

2. **元分类器的训练语料 D_train（带良性／后门标签的适配器集合）**。是什么：由防御者自己用良性数据集和投毒数据集分别 PEFT 微调得到的适配器，每个适配器带一个二值标签。在哪里采集：等价于"客户端训练后"的产物，但这里没有客户端，是防御者离线批量训练出来的适配器工件（Section 4.1、Section 5.3.2）。粒度：逐适配器（一个适配器一个训练样本），标签为逐适配器。是否需要跨轮历史：不需要。是否需要干净参考数据：需要，必须有良性适配器作为负类，且需要原始任务数据来生成正负样本。是否需要额外计算：需要，这是一次性的重开销，既要训练出成百上千个适配器，又要训练分类器本身。数据划分：|D_train| : |D_test| = 8 : 2，并从 D_train 中取 10% 作为验证集（Section 5.3.2）。超参数：batch size 为 4，Adam 优化器，初始学习率 2e−5，权重衰减 1e−5（Section 5.3.2）。

3. **缓解阶段所需的数据**。SFT、DPO、Fine-mixing 三种后门消除方法都假设防御者只掌握一小部分干净数据；实验使用每类仅 2,500 句的干净数据，测试时用 2,500 条干净样本评估 CA、1,000 条带触发器样本评估 ASR（Section 5.4）。Fine-mixing 还需要微调前的干净预训练模型权重，用于把后门权重与干净权重混合（Appendix B）。

4. **自适应攻击评估中涉及的额外数据视图**（属于评估而非部署流程）。论文假设攻击者是一个强攻击者，可以用与 PEFTGuard 相同的训练数据集和超参数训练另一个检测模型，并基于该模型优化对抗扰动再迁移到 PEFTGuard（Section 6.5）。这需要替代检测器的输出或梯度，以及参数设置（C&W 的五组参数见 Table 17）。

**攻击留下的可观测量**（论文报告）：后门适配器与良性适配器在自注意力层参数分布上存在差异，Figure 3 的 t-SNE 显示各层都能在一定程度上区分两类；但论文没有给出可解释的、与具体触发器对应的参数模式，Section 7 明确把"解释不同攻击、模型和超参数下的后门模式"列为未来工作。

**论文声称能抗住的规避**（Table 12）：高斯噪声（按标准差缩放或按参数比例注入）下，对 PEFTGuard 的攻击成功率始终为 0%；FGSM、I-FGSM、PGD、C&W 在强度增大时确实可以把对 PEFTGuard 的攻击成功率推到 92%、100%、100%、86.8%，但后门模型自身的 CA 与 ASR 同时大幅下降（例如 FGSM ε=1×10⁻³ 时 CA 从 0.971 降到 0.449，ASR 从 0.999 降到 0.139）。**论文声称超越的现有检测方法**：T-Miner、AttenTD、PICCOLO、MNTD（Table 2）。

## 6. 干预动作

**PEFTGuard 本身只做报告**。它的输出是 0 或 1 的二值判定（Equation 12），不剔除任何客户端、不重新加权、不裁剪、不加噪、不回滚模型；它甚至不需要把适配器合并进 LLM（Section 1.1、Conclusion）。动作发生的位置是"适配器被审查时"，即合并与推理之前。

**检测之后的修复动作**由论文额外实验的三种缓解方法承担，作用对象是被判定为后门的模型／适配器，位置在检测之后：

- **SFT**：在干净子集上继续微调，Table 13 报告 ASR 降到 9.80%，精度 93.92%。
- **DPO**：把"含触发器但答案正常"的文本作为偏好文本进行优化（Appendix B），Table 13 报告 ASR 降到 0.00%，但精度降到 64.56%，是三者中效用损失最大的。
- **Fine-mixing**：把后门权重与微调前的干净预训练权重混合，Table 13 报告 ASR 降到 7.20%，精度 96.12%；原文称它是三种方法中效果最好的（Section 6.6）。

分析：Table 13 与 Section 6.6 正文存在数值不一致。Table 13 给出 Fine-mixing 的精度为 96.12%，而正文写"reducing the backdoor to 7.20% while only decreasing the accuracy on the clean dataset to 93.92%"，其中 93.92% 实际是 Table 13 中 SFT 的精度；正文还出现"compared with the 4.60% of no attack ASR"这一在表格中找不到对应行的表述。Abstract 与 Section 1.1 引用的 96.12% 与 Table 13 一致。库在复现时应以 Table 13 为准并保留这一歧义记录。

论文未说明：检测到后门适配器之后是否有标准处置流程（例如下架、通知平台、拒绝加载、回滚到干净适配器）；论文只展示了三种模型侧修复实验，且都依赖少量干净数据。

## 7. 实验设置与主要结果

**模型**：Llama-2-7B、Llama-3-8B、Llama-2-13B、Qwen1.5-7B-Chat、Chatglm-6B-v2、Flan-t5-xl、Roberta-base，覆盖 Decoder-only、Prefix Decoder-only、Encoder-Decoder、Encoder-only 四种结构以及 Multi-Head、Grouped Query、Multi-Query 三种注意力机制（Section 5.1、Section 6.3）。扩展实验使用 ViT-base 与 Qwen2-vl-2B（Section 6.3、Table 7）。

**数据集与任务**：任务特定数据集为 SQuAD（问答）、AG News（主题分类）、IMDB（情感分类），指令跟随数据集为 toxic-backdoors-alpaca 与 toxic-backdoors-hard；视觉与多模态使用 CIFAR-10 与 VQAv2（Table 16）。IMDB 与 AG News 被从基于 logits 的分类任务改造成生成式分类任务（Section 5.3.1、Figure 4）。目标标签分别为 SQuAD 的 "idiot"、IMDB 的 "positive"、AG News 的 "World"（Section 5.3.1）。

**攻击与 PEFT 配置**：四种文本后门攻击 InsertSent、RIPPLES、Syntactic、StyleBkd，加上两个数据集自带的词级与句级触发；五种 PEFT 方法 LoRA、QLoRA、DoRA、LoRA+、AdaLoRA；投毒率 5%（Section 5.3.1）。Table 15 给出 PADBench 逐项明细，例如 Llama-2-7B + toxic-backdoors-hard + LoRA rank 256 的配置为 250 个良性适配器与 250 个后门适配器，后门适配器 ASR 为 0.926；SQuAD + InsertSent + LoRA 256 的良性 CA 为 0.647、后门 CA 为 0.661、ASR 为 0.997。

**客户端数、参与率、轮次、非独立同分布**：论文未说明，因为该论文不研究联邦学习，不存在客户端划分、参与率、通信轮次或 Non-IID 数据设定。Figure 5 展示的是适配器 ASR 的分布而非客户端数据分布。

**指标**：ASR（Attack Success Rate）与 CA（Clean Accuracy）用于刻画适配器，DA（Detection Accuracy）与 AUC 用于刻画检测；每个实验训练分类器三次并报告平均值（Section 5.2）。

**主要结果**：

- 主实验固定 PEFT 为 LoRA、基座为 Llama-2-7B（Section 6.1）。Table 1 显示：SQuAD/InsertSent、toxic-backdoors-alpaca/Word、toxic-backdoors-hard/Sentence 均为 100.00% 检测精度与 1.000 AUC；AG News 上 InsertSent 为 98.33%±0.47% / 0.996±0.004，RIPPLES 为 100.00% / 1.000，Syntactic 为 99.33%±0.47% / 0.998±0.003，StyleBkd 为 100.00% / 1.000；IMDB 上 InsertSent 为 99.33%±0.47% / 0.997±0.004，RIPPLES 为 100.00% / 1.000，Syntactic 为 99.00%±0.00% / 0.984±0.001，StyleBkd 为 99.67%±0.47% / 1.000±0.000。
- 与 SOTA 检测方法对比（Table 2）：T-Miner 在 SC 任务上为 50% / 0.500，AttenTD 为 50% / 0.606，PICCOLO 为 76% / 0.890，MNTD 在 SC 上为 88% / 0.937、在 IF 上为 51% / 0.510，PEFTGuard 在 SC 上为 99% / 1.000、在 IF 上为 100% / 1.000。分析：Section 6.2 正文写"PEFTGuard reaches a detection accuracy of 98.33% and an AUC of 1.000 in the SC task"，与 Table 2 的 99% 不一致，复现时需注意。
- 不同 PEFT 方法（Table 3）：LoRA、LoRA+、AdaLoRA 均为 100.00% / 1.000，QLoRA 为 99.67%±0.58% / 1.000，DoRA 为 98.00%±2.65% / 1.000。
- 不同基座模型（Table 4）：Llama-3-8B、Llama-2-7B、Qwen1.5-7B-Chat、Flan-t5-xl 为 100.00% / 1.000，Llama-2-13B 为 99.67%±0.47%，Chatglm-6B-v2 为 99.33%±0.47%，Roberta-base 为 98.33%±0.58%，所有模型 AUC 均为 1.000。
- 不同投影矩阵（Table 5）：六种配置全部为 100.00% / 1.000。
- 训练数据量（Figure 6）：训练样本从 100 到 360 变化；100 时最低，为 97% 精度与 0.995 AUC；200 及以上稳定达到 100% 精度。
- 分类器结构消融（Table 6）：Original 为 98.33%±0.47% / 0.996±0.004；把卷积层换成 AdaptiveAvgPool 后跌到 50.00%±0.00% / 0.742±0.035；换成 MaxPool 为 89.33%±1.25% / 0.903±0.035；A1 为 96.33%±0.47% / 0.973±0.011；A2 为 98.00%±0.816% / 0.986±0.013。

## 8. 开销

**论文未报告**计算量（FLOPs）、通信量、存储占用的任何具体数值。论文给出的只是训练超参数（batch size 4、Adam、学习率 2e−5、权重衰减 1e−5，Section 5.3.2）和若干定性论述：

- Section 4.3 指出 F_input 在 Llama-2-7B 上维度为 [64,4096,4096]，若直接用 MLP 分类会造成极大的首层与内存开销，因此必须先用卷积层做降维；Table 6 显示换成自适应平均池化后精度跌到 50%，说明降维方式的选择对性能敏感。
- Section 7 的 Practical Deployment 承认，面对全新检测场景时 PEFTGuard 需要大量训练与部署时间；但同时指出只需 100 个训练样本即可获得较强检测性能，可用来缩短部署时间。
- Section 1.1 与 Conclusion 强调检测阶段不需要额外输入数据，也不需要把适配器合并回原 LLM 做推理。

分析：由 Equation 13 与 Equation 14 可知，检测时的主要计算是把每层的 ∆q 与 ∆v 拼接成一个 (2L)×d×k 张量再过一次卷积与 MLP 前向，因此检测本身的计算量与存储量大致正比于适配器参数量；但这只是从公式推出的量级判断，论文没有给出实测的延迟、显存或吞吐数字。训练元分类器需要批量生成适配器的额外开销，论文同样没有量化。

## 9. 假设、局限与自适应攻击

**方法成立所依赖的假设**（论文报告）：

1. 防御者能够获取适配器权重，这是唯一需要的输入（Section 3.2 Capability、Conclusion）。
2. 防御者不需要知道训练数据、超参数、触发器模式／类型或下游任务（Section 3.2 Capability）。
3. 攻击者在发布适配器后无法影响防御者的检测或权重（Section 3.1 Capability）。
4. 后门适配器与良性适配器在自注意力层参数上存在可区分的分布差异（Section 4 Intuition、Figure 3）。
5. 防御者拥有一批带标签的良性／后门适配器用于训练元分类器，且被检测适配器的输入维度与训练时一致；论文明确指出"any variation in input dimensions requires training a new classifier"（Section 7 Limitations）。
6. 攻击者为了让适配器被下载使用，必须保证其在正常任务上的性能（Section 3.1 Capability），因此不能用无限制的扰动换取规避。

**论文自述的局限**（Section 7）：迁移性受限，输入维度变化需要重训分类器，跨未知 LLM 的迁移效果仍待研究；实际部署需要大量训练与部署时间；对后门参数模式的解释仍是开放问题，作者建议未来在 task vector 空间继续分析。

**是否评估自适应攻击者**：是。Section 6.5 与 Table 12 评估了高斯噪声（两种注入方式）、FGSM、I-FGSM、PGD、C&W 五类规避手段，并且明确假设攻击者是强攻击者，可以用与 PEFTGuard 相同的训练数据集和超参数训练自己的检测器来生成可迁移的对抗扰动。结果是：高斯噪声完全无效（对 PEFTGuard 的 ASR 恒为 0%）；优化类攻击在强度足够大时可以规避（I-FGSM 与 PGD 达到 100%，C&W 最高 86.8%），但代价是后门模型自身的 CA 与 ASR 大幅下降。

**迁移到联邦 LoRA 微调时可能失效的假设**（以下全部是分析，论文没有讨论联邦场景）：

- 分析：论文的检测对象是一个完整的、静态的、发布后的适配器工件；联邦 LoRA 微调中服务器在每一轮看到的是"某一轮、某个客户端、某一批本地数据"训练出的增量，二者在数据生成分布上并不相同，PEFTGuard 的元分类器是否仍能区分未见过的联邦轮次增量，论文未说明，也无从依据。
- 分析：论文假设攻击者投毒的是自己完整掌握的微调数据集，投毒率 5%。在联邦 LoRA 中，恶意客户端只在自己本地数据上训练，其可投毒比例、本地步数与批大小都会改变 ∆ 的数值尺度，而 PEFTGuard 的特征变换对数值尺度没有任何归一化说明，这构成一个未被验证的分布外风险。
- 分析：论文假设适配器由单一模型、单一 PEFT 配置产出，可通过固定拼接 ∆q 与 ∆v 得到形状一致的输入。联邦 LoRA 中不同客户端常在 rank、目标模块（只调 q、只调 v、或 q/k/v/o 全调）上异构，论文虽然分别验证了不同 rank（Table 9）与不同投影矩阵（Table 5），但那是"一次训练一种固定配置"，且论文自述输入维度变化必须重训分类器；混合异构客户端的场景没有被覆盖。
- 分析：论文的干预动作是"报告加离线修复"，完全不涉及联邦流程中的剔除客户端、重新加权、裁剪或加噪。若库把 PEFTGuard 的判定接到聚合环节，论文没有给出任何关于"剔除哪些客户端、如何加权"的依据。
- 分析：论文假设服务器或审查者可以直接读取原始适配器权重。联邦 LoRA 中若启用安全聚合（secure aggregation）、差分隐私加噪或只上传聚合后的更新，服务器可能根本看不到单个客户端的 ∆，PEFTGuard 的采集点会直接消失。论文未说明这一情形。
- 分析：论文的元分类器训练语料需要防御者自己训练出后门适配器，这在一轮一轮进行的联邦训练中是离线且昂贵的前置条件；论文报告的"100 个样本即可"（Figure 6）针对的是已经构造好的样本池的抽样，不等于联邦在线场景的冷启动代价。
- 分析：论文的效用约束来自攻击者需要保持适配器可被下载使用；联邦中恶意客户端的动机可能只是破坏全局模型（无目标破坏），这类攻击的 ∆ 未必呈现与论文后门适配器相同的参数特征，PEFTGuard 对这类威胁的检出能力论文没有评估。

## 10. 对防护库设计的含义

以下全部是分析：

1. **分析**：采集底座需要在"客户端训练完成、服务器收到更新"这一信任边界上，提供逐客户端的原始适配器增量视图，并且必须保留每个增量对应的结构元信息，即基座模型标识、适配器 rank、被训练的目标模块集合（∆q、∆v、∆k、∆o 中的哪些）以及层索引。这是通用需求，因为没有这些元信息就无法复现 Equation 13 与 Equation 14 的通道级与层级拼接；论文也说明输入维度一旦变化就必须重训分类器，因此元信息还是拒绝或路由检测插件的判据。
2. **分析**：库需要一个与训练循环解耦的"离线工件训练"插件类型，它消费的不是某一轮的训练数据，而是一批带标签的适配器工件（良性／后门），用于训练元分类器。这是 PEFTGuard 特有的需求：它的监督信号来自防御者自建的正负样本池，而不是来自训练过程本身。
3. **分析**：服务器钩子需要支持"只读评分"语义，即在聚合之前对每个客户端的更新给出一个二值或分数化的判定，但不修改更新内容。论文的检测器属于纯报告型，不裁剪、不加噪、不剔除；库应把"评分"与"处置"分成两个接口，否则会在适配该论文时被迫引入论文没有定义的干预。
4. **分析**：干预接口需要支持"检测后修复"这一类动作，作用对象是聚合后的模型或适配器，且允许声明对少量干净数据的依赖。Fine-mixing 还需要一份微调前的干净权重作为输入，这意味着库的工件存储要能同时保存基座权重与微调后权重的对应关系，这一需求是这篇论文特有方法带来的，但对任何"检测后修复"类插件都是通用的。
5. **分析**：库需要提供规避评估的钩子，允许在更新上注入有界扰动（高斯噪声、FGSM、I-FGSM、PGD、C&W）后重新评分，并同时记录检测器侧的规避成功率与模型侧的 CA/ASR。论文评估自适应攻击的方式是攻击者用相同数据与超参数训练替代检测器再迁移扰动，库若要复现这一评估，必须支持"用同一批工件训练两个独立评分插件并交叉攻击"。
6. **分析**：通用需求还包括把"检测结果"与"工件来源"绑定记录，例如适配器的发布者标识、版本与下载渠道。论文的威胁模型完全建立在"发布后攻击者无法再影响防御者"这一假设上，库若在联邦在线场景中使用同一插件，必须额外记录轮次与客户端身份，因为论文的静态工件假设在联邦中不成立。
