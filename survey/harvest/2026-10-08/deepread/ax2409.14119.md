# ax2409.14119：Obliviate: Neutralizing Task-agnostic Backdoors within the Parameter-efficient Fine-tuning Paradigm

## 1. 基本信息

- 场景：参数高效微调供应链（parameter-efficient fine-tuning supply chain）。这篇论文不是联邦学习，也不是联邦大模型微调，而是集中式的"下载基座模型后本地微调"场景：攻击者把被植入后门的预训练语言模型（pre-trained language model，PLM）上传到模型仓库（论文举例 HuggingFace），用户（论文称为 defender）下载该 PLM，冻结它的参数，只在随机初始化的参数高效微调（parameter-efficient fine-tuning，PEFT）层上用自己的干净数据集适配下游任务（第 3 节，图 1）。
- 训练阶段：防御动作发生在下游任务的 PEFT 微调阶段；后门则在更早的 PLM 预训练或权重投毒（weight poisoning）阶段被注入（第 2.2 节、第 3 节）。整篇论文不涉及联邦聚合、更新上传或服务器下发等环节。
- 论文类型：防御（defense）。论文同时复现了四类任务无关后门攻击（task-agnostic backdoor）作为被防御对象，并额外评估了自适应攻击（adaptive attack），但贡献主体是防御方法。
- 模型与数据规模：受害者 PLM 为 RoBERTa（roberta-base）与 BERT（bert-base-uncased）（第 5.1.1 节），附录 I 补充 roberta-large 与 bert-large-uncased（表 9）。三种 PEFT 架构为 Adapter、LoRA、Prefix-tuning。数据集为 SST-2、AG News、HSOL（第 5.1.2 节），附录 G 补充 SNLI、CoNLL 2003、SQuAD。表 6 给出初始统计：SST-2 训练 6,920 条、验证 872 条、测试 1,821 条；AG News 训练 120,000 条、测试 7,600 条；HSOL 训练 24,783 条。实际训练使用 6,000 条训练样本（附录 C）。规模属于 BERT 与 RoBERTa 级别的编码器模型，下游任务是分类、自然语言推理、命名实体识别与抽取式问答，不涉及生成式大模型。论文发表于 arXiv（arXiv:2409.14119v3，2024 年 10 月 6 日），作者来自 KAIST。

## 2. 威胁模型

- 攻击者是谁：把后门注入 PLM 并上传到模型仓库的一方。论文原文是 "an attacker that injects backdoors into a PLM, aiming to harm any of its derived fine-tuned models"（第 3 节）。按防护库的分类口径，这对应模型或适配器发布者（model or adapter publisher），而不是联邦学习中的恶意客户端。
- 占比或数量：论文未说明。这是供应链场景，攻击者交付的是一个完整的后门 PLM，论文没有给出任何"恶意客户端比例"或攻击者数量，因为该场景本身不存在多客户端。
- 能力：可以在 PLM 权重中植入任务无关后门（weight poisoning，第 2.2 节）；可以把后门 PLM 上传到模型仓库（第 3 节）；在推理阶段可以向测试样本插入特定触发器，使微调后的模型把样本映射到特定标签 l（第 3 节）。论文明确攻击者不能访问下游任务、下游训练数据集，也不能访问 PEFT 层的可训练参数（第 3 节）。
- 知识：攻击者不知道下游任务，不知道下游训练数据集，不知道 PEFT 层参数（第 3 节）。第 5.4.4 节额外考虑了一种更强的假设，即攻击者知道防御策略并据此构造自适应攻击。触发词集合在论文的评估中被设定为 ['cf', 'mn', 'tq', 'qt', 'mm', 'pt'] 六个（第 5.1.1 节）。
- 目标：定向后门（targeted backdoor），并且是任务无关（task-agnostic）的。论文写 "These poisoned samples will be mapped to a specific label l even though their true labels are not l."；同时要求微调后的模型在干净样本上的表现与基于良性 PLM 的 PEFT 模型相近，以保持隐蔽（第 3 节）。任务无关意味着攻击者用单一后门模型即可影响任意下游任务（第 2.2 节）。
- 防御者是谁：下载 PLM 并在下游任务上做 PEFT 微调的用户（第 3 节，图 1）。
- 防御者能看到什么：自己的干净下游训练数据与验证数据；自己训练出的 PEFT 层参数；冻结的 PLM 参数；训练过程中的中间张量，尤其是每一层、每个注意力头的注意力分数（attention score），因为防御损失直接定义在注意力分数上（第 4.2 节公式 2）。
- 防御者信任什么：信任自己的下游数据集是干净的（第 3 节写 "fine-tuning it on the clean dataset"）；信任 PEFT 层是随机初始化、不含后门的（第 3 节）；不信任下载来的 PLM，但也不知道它是否真的被后门污染（第 5.4.1 节）。防御者的目标是中和 PLM 中的后门，使模型无论输入是否含触发器都能预测真实标签（第 3 节）。
- 分析：因为不存在多客户端，这篇论文的"信任边界"只有一条，即模型仓库与本地训练环境之间的边界；防护库中常见的服务器聚合信任边界在这篇论文里没有对应物。

## 3. 攻击入口与流程位置

这是防御论文，下面写它所针对的攻击入口。

- 入口位置：攻击不进入本地数据准备，不进入本地训练过程（PEFT 只更新随机初始化的 PEFT 层，攻击者触碰不到这些参数），不进入更新上传前的后处理，不进入服务器聚合，也不在评估与部署阶段进入。它进入的位置是模型分发环节，即"全局模型下发"这一步，在论文的具体形态中是用户从模型仓库下载被植入后门的 PLM；后门实体本身是在更早的 PLM 预训练或权重投毒阶段被写进权重的。图 1 中的 "1) Upload PLM" 与用户 "downloading a PLM from the model repository" 就是这个入口（第 3 节）。
- 具体步骤：
  1. 攻击者在 PLM 上注入任务无关后门。论文涉及的四类攻击是：POR 与 NeuBA 强制输出表示（例如 [CLS] token 的输出）在输入含触发器时等于预定义向量；BadPre 使用对抗性的掩码语言建模（adversarial masked language modeling）；UOR 用对比学习优化中毒样本的输出，使其偏离正确标签的特征空间（第 2.2 节）。
  2. 攻击者把后门 PLM 上传到 HuggingFace 一类的模型仓库（第 3 节）。
  3. 用户下载该 PLM，冻结其参数，只在随机初始化的 PEFT 层上用自己的干净数据集做下游微调；论文指出 PEFT 冻结了被后门的 PLM 参数，因此难以通过训练少量新增参数来遗忘后门（第 2.2 节、第 3 节）。
  4. 推理时攻击者向测试样本插入触发器，使微调后的模型误分类；论文的攻击成功率定义还要求该中毒样本在良性模型上本来能被正确预测（第 3 节、第 5.1.3 节）。
- 论文附录 C 给出攻击复现细节：使用六个触发器 ['cf', 'mn', 'tq', 'qt', 'mm', 'pt']；BadPre 用 BookCorpus 做攻击训练，其余方法用 WikiText；每个触发器采样 20,000 条、共 120,000 条中毒样本，并使用同等数量的干净样本；POR 与 NeuBA 采用 POR-2 方法生成的六个正交预定义向量；BadPre 把训练集中的标签替换为随机 token。
- 分析：在防护库的流程坐标里，这个攻击等价于基座权重在进入本地训练之前就已被污染，因此库要防它，检测点必须前移到"模型获取与注册"环节，或者像论文这样在训练阶段做被动中和。

## 4. 方法原理

核心思想（第 1 节与第 4 节）：不改变 PEFT 的架构与可训练参数范围，而是在标准下游任务损失上追加两个防御损失项，用"放大 PEFT 层中的良性神经元"和"惩罚触发器 token 的注意力影响"两条路径，在只训练极少参数的前提下中和冻结 PLM 中的后门。防御者不需要知道攻击类型、触发器或攻击者数据集。

设计直觉（第 4.1 节）有两条。第一是自然后门遗忘（natural backdoor forgetting）：全量微调能显著改变输出、使模型正确预测真实标签，而 PEFT 可训练参数量太少，输出仍然接近攻击者设定的对抗表示，图 2 给出了 RoBERTa 在 POR 攻击下的对比。第二是触发器在注意力上的痕迹：被 POR 攻击的模型中，触发器 token 对 [CLS] 输出的注意力分数明显高于非触发器 token，论文的预实验显示这一模式在 POR、NeuBA、BadPre、UOR 上一致（图 3 为 RoBERTa，图 6 为 BERT，样例文本为 "I love the cf movie"）。

关键技术一，良性神经元放大（benign neuron amplification，第 4.2 节公式 1）：损失项 L_amp 等于对全部 transformer 层 i 中全部 PEFT 层 p 的权重矩阵 W_p 的 L2 范数求和后取负号，因此最小化总损失等价于放大这些权重矩阵的范数。论文说明被放大的对象具体是 adapter 层的 up-projection 与 down-projection 矩阵、LoRA 层的分解矩阵，以及 prefix-tuning 的重参数化矩阵。直觉是 PEFT 层参数少、初始化接近零，其范数在训练中一直远低于 PLM 层（附录 D、图 8 左侧），放大良性参数可以相对削弱 PLM 中被后门的神经元的影响。论文说明这一做法受模型合并领域的神经元放大技术启发。

关键技术二，注意力分数正则（attention score regularization，第 4.2 节公式 2）：损失项 L_reg 等于对所有层、所有注意力头 h 的注意力分数 a_h 的 L2 范数求和，通过最小化它来压低异常高的注意力值；对句子分类任务，论文专门正则化"输入 token 对 [CLS] 输出的注意力分数"。论文明确不走阈值移除的路线，因为附录 B 的预实验（图 7）显示按归因分数阈值删除 token 会因高假阳性率而显著降低干净准确率，所以改为用优化过程压低注意力分数而不是把 token 从输入中删掉。

训练目标（第 4.2 节公式 3）：L = L_task + λ_amp × L_amp + λ_reg × L_reg，其中 L_task 是下游任务损失，λ_amp 与 λ_reg 是平衡系数。训练流程本身仍是标准 PEFT 训练，论文使用 AdapterHub 的实现与各 PEFT 原论文的默认超参数（附录 C、表 7）。系数选择方式是在验证集上取不使干净准确率下降超过 2% 的最大 λ_amp 与 λ_reg（第 5.1.4 节、附录 C）。

## 5. 检测或防御所需的数据

这是防御论文，下面逐项列出方法需要的输入。需要说明的是，论文中只有单一用户或防御者，没有"客户端"概念；下表里的"客户端"是把它映射到防护库钩子体系后的说法。

1. 干净的下游任务训练样本的输入文本与标签，用于计算 L_task。
   - 在哪里采集：在本地训练开始前准备（对应"客户端训练前"），并在每一步训练时按批读取。
   - 粒度：逐样本，按 batch size 16 组成批（附录 C）。
   - 是否需要跨轮历史：不需要。是否需要干净参考数据或根数据集：需要，这些下游训练数据本身必须是干净的（第 3 节明确写 "fine-tuning it on the clean dataset"）。是否需要额外的前向或反向计算：不需要。是否需要其他客户端的数据：不需要，论文不是联邦设置。
2. 每个 PEFT 层权重矩阵的逐层 L2 范数，用于计算 L_amp。
   - 是什么：adapter 的 up-projection 与 down-projection 矩阵、LoRA 的分解矩阵、prefix-tuning 的重参数化矩阵（第 4.2 节公式 1）。
   - 在哪里采集：训练过程中的每一步（对应"客户端每一步"，因为损失项直接定义在这些权重上，梯度要回传到它们）。
   - 粒度：逐层。
   - 是否需要跨轮历史：不需要。是否需要干净参考数据或根数据集：不需要。是否需要额外计算：论文未报告额外开销，这一项复用标准训练图。是否需要其他客户端的数据：不需要。
3. 每个 transformer 层、每个注意力头上输入 token 对 [CLS] 输出的注意力分数，用于计算 L_reg。
   - 在哪里采集：训练过程中的每一步的前向传播（对应"客户端每一步"）。
   - 粒度：逐层，并进一步细分到逐注意力头、逐 token；论文的损失对整个模型的全部层求和（第 4.2 节公式 2）。
   - 是否需要跨轮历史：不需要。是否需要干净参考数据或根数据集：不需要。是否需要额外计算：论文声明不需要额外的逐输入预测（第 4.2 节）。是否需要其他客户端的数据：不需要。
4. 干净验证集上的 CACC，用于选择 λ_amp 与 λ_reg。
   - 在哪里采集：评估阶段，在验证集上评估（第 5.1.4 节；附录 C 说明允许 CACC 下降 2%）。
   - 粒度：逐样本计算后汇总为数据集级指标。
   - 是否需要跨轮历史：论文未说明；正文只说在验证集上选择，附录 D 与图 5 的训练动态分析是逐 epoch 记录的，但那是分析而非方法的必需输入。是否需要干净参考数据：需要一份干净验证集。额外计算：需要常规的验证前向。
5. 论文未说明方法需要逐样本损失、梯度、输出文本、跨轮更新历史、根数据集或其他客户端的数据。

攻击会在哪些可观测量上留下痕迹（论文报告）：

- 输出表示被推向对抗表示。模型输出与对抗表示的余弦相似度在后门模型上明显偏高，尤其在上层 transformer 层；防御后该相似度下降到与良性模型相同水平（第 5.3 节、图 4，实验为 RoBERTa adapter 在 SST-2 上）。
- 触发器 token 对 [CLS] 的注意力分数异常偏高。图 3（RoBERTa）与图 6（BERT）显示该模式在 POR、NeuBA、BadPre、UOR 上一致；附录 D 的图 8 右侧显示，无防御时这一差距在整个训练过程中持续存在。
- PEFT 层参数的 L2 范数偏低。附录 D 的图 8 左侧显示，无防御时 PEFT 层的范数始终显著低于 PLM 层，ASR 保持在高位；防御抬高 PEFT 层范数后 ASR 下降。

论文声称哪些检测方式会被绕过或失效：

- RAP 依赖干净样本与中毒样本在预测概率上的差异，论文说任务无关后门在两者上的输出概率方差可忽略，因此 RAP 在多数情况下失败（第 5.2 节）。
- PSIM 依赖干净样本与中毒样本之间的置信度差距，论文说即使仔细选择阈值，其防御能力仍不理想，仅在 POR 攻击的少数情形例外（第 5.2 节）。
- ONION 对任务无关后门有一定效果，尤其在 AG News 上，但整体不如本文方法，并且会明显拉低 CACC（第 5.2 节、表 1）。
- 基于注意力或归因阈值直接移除高注意力 token 的检测会因高假阳性率而显著降低 CACC（附录 B、图 7）。
- 模型净化方法 RECIPE 在 PEFT 语境下不足：要显著去除后门就得牺牲模型性能，而 PEFT 冻结经过高度正则化的 PLM 参数，无法在微调中恢复这些损失，因此 RECIPE 单独使用时 Adapter 的 ASR 仍有 32.38（表 3，SST-2，POR）。

## 6. 干预动作

- 论文不做"先检测再处理"的流水线式干预，而是把防御做成训练目标的一部分：在 PEFT 微调的每一步损失里加入 L_amp 与 L_reg（第 4.2 节公式 3），在训练过程中改变优化方向，最终得到一个后门被中和的 PEFT 模型。
- 动作发生的位置：用户本地训练过程的损失函数与优化器更新这一步，也就是防护库坐标里的客户端侧训练循环内部，不在服务器聚合侧。
- 论文没有采用的动作：不剔除客户端（不存在多客户端聚合），不重新加权，不裁剪，不加噪，不过滤样本，不回滚模型，不剪枝神经元，也不做阈值式的 token 移除。论文明确拒绝了最后一项：附录 B 的预实验显示按归因分数移除 token 会大幅降低 CACC，所以论文改为用优化过程压低注意力分数（第 4.2 节）。
- 分析：如果把它映射到防护库的干预枚举，最接近的一项是 repair_model，即在训练过程中修复模型的输出行为；但它的实现方式不是对更新做后处理，而是改写客户端本地的训练损失，论文本身没有使用检测、剔除或聚合层面的语言来描述这一动作。

## 7. 实验设置与主要结果

- 模型：RoBERTa（roberta-base）与 BERT（bert-base-uncased）（第 5.1.1 节）；附录 I 增加 roberta-large 与 bert-large-uncased（表 9）。
- PEFT 架构与超参数（附录 C、表 7）：Adapter 的 reduction factor 为 16，可训练参数占 RoBERTa 的 1.44%，学习率 3e-4，训练 20 个 epoch；LoRA 的 r_q 与 r_v 均为 16、α 为 16，占 0.47%，学习率 5e-4，训练 30 个 epoch；Prefix-tuning 的 prefix length 为 30、bottleneck size 为 256，占 0.44%，学习率 2e-4，训练 20 个 epoch。batch size 统一为 16。λ_amp 的搜索范围为 {1e-3, 2e-3, 3e-3, 5e-3}，λ_reg 的搜索范围为 {1e-2, 2e-2, 3e-2, 5e-2}。
- 数据集：SST-2、AG News、HSOL（第 5.1.2 节）。表 6 给出初始规模：SST-2 为 6,920（训练）、872（验证）、1,821（测试）；AG News 为 120,000、无验证集、7,600；HSOL 为 24,783、无验证集、无测试集。实际使用 6,000 条训练样本，AG News 与 HSOL 各用 2,000 条作为验证与测试，SST-2 用 872 条验证、1,821 条测试（附录 C）。附录 G 追加 SNLI、CoNLL 2003、SQuAD（表 10）。
- 攻击：POR、NeuBA、BadPre（第 5.1.1 节）与 UOR（附录 J、表 12）；六个触发器、共 120,000 条中毒样本（附录 C）。
- 客户端数与参与率：不适用，论文不是联邦学习设置，论文未说明任何客户端数量或参与率。
- 轮次：Adapter 20 个 epoch、LoRA 30 个 epoch、Prefix-tuning 20 个 epoch（表 7）。
- 恶意比例：不适用，攻击者交付的是整个后门 PLM，论文未说明比例。
- 数据是否非独立同分布：论文未说明；实验是集中式的单一下游数据集，不涉及非独立同分布划分。
- 指标：干净准确率（clean accuracy，CACC）、攻击成功率（attack success rate，ASR）、最大攻击成功率（maximum ASR，MASR）与平均攻击成功率（average ASR，AASR）（第 5.1.3 节，定义见附录 C）；附录 G 追加 F1、F1 drop、EM 与 EM drop。
- 关键结果：
  - 表 1（RoBERTa，Adapter、LoRA、Prefix 三种架构，POR、NeuBA、BadPre 三种攻击，SST-2、AG News、HSOL 三个数据集）：Obliviate 相对无防御平均降低 ASR 83.6%，CACC 仅下降 0.78%；MASR 降低 93.3%（第 5.2 节及摘要）。例如 POR 加 Adapter 加 SST-2 的 ASR 从 100 降到 5.18，POR 加 Adapter 加 AG News 的 ASR 从 100 降到 1.98（表 1）。
  - 表 1 中同一组实验的基线：POR 加 Adapter 加 SST-2 上 ONION 的 ASR 为 20.00，RAP 为 94.29，PSIM 为 0.00；POR 加 Adapter 加 AG News 上 PSIM 的 ASR 仍为 99.95。
  - 表 2（良性 PLM，SST-2）：加防御后 RoBERTa 的 Adapter 从 94.18 降到 93.57（0.61↓），LoRA 从 94.61 降到 93.30（1.31↓），Prefix 从 93.79 降到 93.63（0.16↓）；BERT 的 Adapter 从 90.94 降到 89.79（1.15↓），LoRA 从 91.49 降到 90.50（0.99↓），Prefix 从 89.95 降到 89.84（0.11↓）。
  - 表 3（先用 RECIPE 净化，SST-2，POR）：RECIPE 单独使用时 Adapter 的 ASR 为 32.38、CACC 为 90.72；Obliviate 单独使用时为 5.18 与 91.10；两者都用时为 5.51 与 89.62。论文的结论是 RECIPE 在 PEFT 下不足，两者结合是冗余的（第 5.4.2 节）。
  - 表 4（任务特定后门，SST-2）：词级触发器的 Adapter 上 ASR 从 100 降到 2.57；句法触发器上降到 31.36；风格触发器上降到 14.69。论文指出注意力正则对句法与风格类后门作用较小（第 5.4.3 节）。
  - 表 5（自适应攻击，SST-2）：Adapter 的 ASR 从 97.45 降到 5.45，LoRA 从 66.33 降到 10.62，Prefix 从 100 降到 4.78（第 5.4.4 节）。

## 8. 开销

- 论文报告的内容：各 PEFT 架构可训练参数占总参数的比例（表 7，相对 RoBERTa），Adapter 为 1.44%、LoRA 为 0.47%、Prefix 为 0.44%；第 5.2 节强调 LoRA 层只占 RoBERTa 总参数的 0.47%。论文声明防御不需要对每个输入做额外预测，也不需要辅助模型，因此保持了 PEFT 的性质（第 4.2 节）；第 1 节也写该方法不需要 "extra predictions for each input or additional memory"。
- 论文未报告的内容：防御方法本身带来的计算开销（浮点运算量或训练时间）、显存或存储开销的具体数值、以及任何通信开销。附录 D 只给出 L2 范数与 ASR 的训练曲线，没有代价测量。
- 论文自述的代价性局限：L_amp 会持续增大，妨碍优化过程收敛，需要依赖各 PEFT 架构的默认训练超参数作为一种实用的训练指导（相当于早停策略），过度的神经元放大会损害模型性能（Limitations 一节）。

## 9. 假设、局限与自适应攻击

方法成立所依赖的假设（论文依据）：

- 防御者拥有干净的下游任务数据集，并能对其做标准 PEFT 训练（第 3 节）。
- PLM 参数被冻结，PEFT 层随机初始化且不含后门，后门只存在于冻结的 PLM 权重中（第 3 节）。也就是说方法针对的是权重投毒式的基座后门，而不是 PEFT 层自身被投毒。
- 攻击是任务无关的，表现为把含触发器输入的输出表示推向对抗表示，触发器是插入式的文本触发词（第 2.2 节、第 4.1 节、第 5.4.3 节）。
- 触发器会在注意力分数上留下可被正则化的痕迹：触发器 token 对 [CLS] 的注意力分数高于普通 token（第 4.1 节，图 3、图 6）。
- 训练时的损失函数可以直接访问并求导于注意力分数与 PEFT 层权重范数（第 4.2 节公式 1 与公式 2）。
- 防御者对攻击与触发器完全无知识，也不知道 PLM 是否被后门污染（第 3 节、第 5.4.1 节）。
- 存在可用的干净验证集，能在 CACC 下降不超过 2% 的范围内选出 λ_amp 与 λ_reg（第 5.1.4 节）。

论文自述的局限：

- L_amp 不收敛的问题，以及过度训练会损害性能（Limitations 一节）。
- 需要沿用各 PEFT 架构的默认训练超参数作为实用指导（Limitations 一节）。
- 基于注意力或归因阈值的 token 移除因高假阳性率而失败（附录 B、图 7）。
- RECIPE 这类净化方法在 PEFT 下需要牺牲性能，而且由于 PLM 参数被冻结，这种性能损失无法在微调中恢复（第 5.4.2 节）。
- 注意力正则对句法类与风格类任务特定后门的作用较小（第 5.4.3 节）。
- 论文未在联邦设置、非独立同分布数据、生成式大模型或生成任务上做任何评估；论文也未说明方法对适配器权重本身被投毒的情形是否有效。论文未说明自适应攻击者是否知道 λ 的具体取值等实现细节。

自适应攻击：

- 论文评估了它称为合理自适应攻击（reasonable adaptive attacks）的攻击者，做法是修改 POR，加入两项技术：一是放大 PLM 的参数以增强后门神经元的影响，二是正则化中毒样本的注意力分数，以便在触发器被惩罚时仍保住攻击效果（第 5.4.4 节）。
- 结果见表 5（SST-2）：Adapter 的 ASR 从 97.45 降到 5.45、CACC 为 91.65；LoRA 从 66.33 降到 10.62、CACC 为 91.54；Prefix 从 100 降到 4.78、CACC 为 91.87。论文据此声称对自适应攻击仍然稳健。

迁移到联邦 LoRA 微调时可能不成立的假设（以下均为分析）：

- 集中式数据假设不成立。论文的 L_task、L_amp、L_reg 都在同一进程、同一份数据上计算。联邦下数据留在各客户端，服务器看不到原始样本，L_task 必须留在客户端本地；L_amp 作用在客户端本地的 LoRA 矩阵上；L_reg 需要客户端本地的注意力张量。论文没有给出把这两个损失项拆解、跨客户端聚合或近似到服务器侧的方案，也没有讨论服务器只收到 LoRA 增量时如何确认 L_amp 与 L_reg 被真正优化过。
- 后门来源假设会发生反转。论文假设后门在冻结的基座 PLM 里、PEFT 层干净。联邦 LoRA 更常见的威胁是恶意客户端上传被投毒的 LoRA 增量、经聚合进入全局模型；在这种情形下"放大 PEFT 层权重范数"的语义会反过来，被放大的可能正是攻击者的增量。论文没有说明它对 PEFT 层自身被投毒是否有效。
- 单模型内的相对放大假设不成立。论文的放大是一个模型内部的相对关系；联邦中若只有部分客户端做放大，服务器侧的加权平均可能部分抵消放大效果，论文未说明。
- 非独立同分布假设未覆盖。论文实验是集中式的单一数据集划分，没有评估非独立同分布；而 L_reg 是在每个客户端本地数据的注意力分布上施加的，不同客户端分布差异对防御效果的影响论文未说明。
- 触发器可见性假设变弱。论文假设触发器会出现在被正则化的 [CLS] 注意力上，这在单一防御者用干净数据训练时成立；联邦中若触发器相关模式只出现在少数客户端的数据里，正则化经过全局聚合后是否仍有效，论文未说明。
- 防御者可见性假设不成立。论文假设防御者能直接访问损失、权重与注意力；联邦中的服务器通常只能看到聚合前后的 LoRA 增量。要迁移这一方法，需要重新设计信任边界与采集点，论文未说明。
- 模型与任务形态不同。论文验证的是 BERT 与 RoBERTa 级别的编码器模型以及分类、序列标注类任务，没有生成式解码器大模型；把"对 [CLS] 的注意力正则"迁移到没有 [CLS] 的解码器上需要重新定义正则目标，论文未说明。
- 联邦层面的实验参数完全缺失。论文没有轮次、参与率、恶意客户端比例、通信预算等概念，也没有给出这些设置下的任何结果。

## 10. 对防护库设计的含义

1. 分析：这篇论文的方法需要的采集点在客户端训练循环内部，而不是服务器聚合侧。库的客户端钩子至少要能暴露三类张量：每一步的 PEFT 层权重，用于计算逐层 L2 范数；每一步、每一层、每个注意力头对指定输出位置的注意力分数；逐样本或逐批的任务损失与标签。三者都是"客户端每一步"粒度，且论文的方法不需要跨轮历史、不需要额外的干净参考数据集、不需要额外的前向或反向传播。
2. 分析：这篇论文的干预不是检测后剔除，而是往训练损失里加项。因此库的插件接口必须允许插件在客户端训练过程中注册自定义损失项并影响优化器更新，而不仅仅提供只读监控或服务器侧过滤接口。这属于客户端侧干预，服务器侧聚合钩子在这篇论文里用不上。
3. 分析：λ_amp 与 λ_reg 依赖验证集上的 CACC 来选择，论文取 CACC 下降不超过 2% 范围内的最大值；同时论文靠沿用默认训练超参数与 epoch 预算来规避 L_amp 不收敛的问题，并给出"10 或 20 个 epoch 后可有效缓解"的经验。因此库需要"逐轮记录 CACC 与其他指标、支持按验证集指标选择插件超参数或提前停止"的能力，这部分是与具体攻击无关的通用需求。
4. 分析：通用需求还包括"客户端训练前拿到一份被声明为干净的下游数据集"，以及"在张量命名上区分基座权重与适配器权重"。论文的全部判断都建立在基座冻结、PEFT 层可训练且干净这一区分上。库的采集底座需要能标注每个张量属于基座还是适配器，并记录基座模型的来源与版本，用于供应链来源审计，否则无法在联邦 LoRA 中重建这篇论文的信任边界。
5. 分析：这篇论文特有的需求是把注意力分数当作一等的可采集量，即在客户端每一步暴露逐层逐头的注意力张量，并允许插件配置关注的输出位置（论文写死为 [CLS]）。对解码器式大模型，这个位置应由插件配置而不是硬编码，论文没有给出这种做法，属于迁移时必须新增的工作。
6. 分析：库应把这篇论文的适用边界写进插件元数据：它假定后门在冻结基座中、PEFT 层干净、下游数据干净、触发器是插入式文本 token。对于"恶意客户端上传被投毒的 LoRA 增量"这一联邦 LoRA 的主要威胁，论文没有覆盖，插件不应声称能防御它。
