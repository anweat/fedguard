# ax2508.08040：BadPromptFL: A Novel Backdoor Threat to Prompt-based Federated Learning in Multimodal Models

## 1. 基本信息

- **场景**：联邦提示微调（federated prompt tuning）。论文以 PromptFL 为联邦骨架，客户端协同学习一段可学习的上下文提示（learnable context / prompt），CLIP 的图像编码器与文本编码器全程冻结（Section III.A、Section VI.A.1）。这属于"联邦 + 参数高效微调（Parameter-Efficient Fine-Tuning, PEFT）"，但被聚合与投毒的载体是提示嵌入（prompt embedding）而不是 LoRA 适配器，模型是多模态对比模型 CLIP 而不是大语言模型。论文既不是训练完整模型的传统联邦学习，也不是集中式大模型训练。
- **训练阶段**：下游任务适配阶段（提示微调）。不涉及预训练、不涉及安全对齐微调。
- **论文类型**：攻击（后门攻击 / backdoor attack）。附带攻击的收敛性分析（Section V）以及对现有防御的评估（Section VI.C）。论文没有提出新的检测或防御方法。
- **模型与数据规模**：主干为 CLIP ViT-B/16（在 LAION-400M 上预训练），实验还使用 RN50（Section VI.A.1）。数据集共 8 个：Caltech101、FGVCAircraft、Stanford Cars、Oxford Pets、Oxford Flowers、EuroSAT、UCF101、DTD（Section VI.A.2）。每客户端每类 6 个标注样本（6-shot）；联邦训练 100 轮（communication rounds），每轮每个客户端做 5 个本地 epoch（local epochs）；干净任务与后门任务学习率默认均为 0.001；触发器扰动幅度约束在 $[-8/255, 8/255]$（Section VI.A.3）。客户端总数 N 在实验章节没有明确给出；图 7 的标签异构性可视化使用 20 个客户端（Fig. 7 标题）。恶意客户端比例 $\rho \in \{10\%, 20\%, 30\%, 40\%\}$（Section VI.B.3、Fig. 5）。

## 2. 威胁模型

- **攻击者是谁**：联邦系统中的一部分恶意客户端（compromised / adversarial clients），论文记作 $A \subset \{1,\ldots,N\}$，$|A| = \rho N$，$\rho \ll 1$（Section III.B）。
- **占比或数量**：实验扫描 $\rho \in \{10\%, 20\%, 30\%, 40\%\}$（Section VI.B.3、Fig. 5）；20 个客户端用于图 7 的异构性可视化（Fig. 7 标题）。分析：摘要中的 "limited client participation" 指的是恶意客户端占比低，而不是客户端采样率低，因为实验采用全参与协议（Section VI.A.3）。
- **能力（能改什么）**：能完全控制自己的本地训练过程——修改本地目标（加入后门损失项）、在每个本地 batch 中构造带触发器的样本、同时用梯度下降优化提示 $p$ 与触发器 $\tau$（Section IV.E、Algorithm 1）。能在同一轮内与其他恶意客户端协调，并能通过服务器之外的私有信道互通（Eq. 8、Algorithm 1 第 17–19 行）。上传的提示更新在通信协议、数据格式、更新时间上与良性客户端不可区分（Section III.B "Attack Stealth"）。
- **不能改什么**：不能改动冻结的图像/文本编码器参数，不能影响良性客户端或服务器的行为，不能访问彼此的原始数据（Section III.B）。
- **知识（知道什么）**：目标架构（如 CLIP）与训练目标对所有参与者（含攻击者）已知（Section III.B "Model Knowledge"）。论文明确把潜在的服务器端防御（异常检测、稳健聚合）置于攻击者知识范围之外（Section III.B "Server-Side Visibility"）。
- **目标**：定向后门（targeted backdoor）。在触发器出现时让模型把带有触发器的输入 $(x_{trig}, t_{trig})$ 对齐到攻击者指定的目标文本嵌入 $g(t_{target})$，同时在干净（非触发）样本上保持高准确率以维持隐蔽性（Section III.B）。
- **防御者是谁、能看到什么、信任什么**：论文没有提出防御者。它设定的服务器"做聚合但不检查也不校验单个提示更新，不知道哪些客户端恶意，且无法访问本地训练日志或梯度"（Section III.B）。良性客户端只能看到下发的全局提示。论文评估的 FedAvg、MKrum、差分隐私（Differential Privacy, DP）、Foolsgold、Multi Metric、STRIP、CLP、Neural Cleanse 都被当作外部基线（Section VI.A.4、Section VI.C）。

## 3. 攻击入口与流程位置

攻击进入的位置是**本地数据准备 / 本地训练过程**；在上传前不做任何特殊后处理，在服务器端也不篡改聚合算法。具体如下（Section IV、Algorithm 1）：

1. **本地数据准备（训练循环内即时构造）**：恶意客户端对干净图像 $x$ 叠加可学习触发扰动 $\tau$，得到 $\tilde{x} = \mathrm{Clip}(x+\tau)$（Eq. 6），其中 $\tau \in \mathbb{R}^{H\times W \times C}$，像素值被裁剪到合法范围。分析：触发是在本地训练循环里逐 batch 即时构造的，而不是事先重写整个本地数据集。
2. **本地训练过程（损失与优化）**：恶意客户端按 Algorithm 1 第 10–11 行把目标标签设为 $y_t \leftarrow y_c$，构造 batch $\{(x_c,y_c), (\tilde{x},y_t)\}$，最小化 $L_p = -\mathrm{CosSim}(f(\tilde{x}), g(p;y_t))$（Eq. 5）来更新提示，并最小化 $L_\tau = \mathrm{CosSim}(f(\tilde{x}), g(p;y_t))$（Eq. 7）来更新触发器；提示与触发器交替优化以缓解梯度纠缠（gradient entanglement，Section IV.A）。Section IV.B 给出的联合目标为 $L_{adv} = L_{benign} + \lambda \cdot L_{bd}$（Eq. 2），其中 $L_{bd} = -\mathrm{sim}(f(x_{trig}), g(t_{target}))$（Eq. 3）；Section IV.E 则把它写成 $L_j(p,\tau) = (1-\lambda)L_{j,clean}(p) + \lambda L_{j,bd}(p,\tau)$（Eq. 12）。
3. **更新上传前的后处理**：没有做任何缩放、投影、拼装等特殊处理。恶意客户端只上传本地提示 $p_{j,T}$，触发器 $\tau$ 不上传（Section IV.E）。
4. **服务器聚合**：不篡改聚合规则，投毒提示与其他提示一起被普通加权/算术平均 $p^{(r)}_{global} = \frac{1}{N}\sum_i p^{(r)}_i$（Eq. 4；部分参与版本见 Eq. 10）。
5. **全局提示下发**：聚合后的全局提示广播给所有客户端，进入下一轮（Algorithm 1 第 3 行、Section VI.A.3）。
6. **恶意客户端之间的带外环节**：恶意客户端在服务器之外私下通信并按 Eq. 8 聚合各自触发器 $\tau^{(r+1)} = \frac{1}{\rho N}\sum_{i\in A}\tau^{(r)}_i$，得到下一轮共用的触发器（Section IV.D、Algorithm 1 第 17–19 行）。
7. **评估与部署阶段**：推理时干净输入产生正确预测，带视觉触发器的输入被强制导向攻击者指定输出（Fig. 1）。论文未说明推理阶段触发器如何被施加到测试样本上。

## 4. 方法原理

核心思想是把后门从"模型权重空间"搬到"提示空间"：聚合对象是直接决定下游行为的提示嵌入，因此不需要改动任何模型参数就能植入持久、可迁移的后门（Section IV.A）。关键步骤为：

1. **交替优化（alternating optimization）**：论文指出直接联合优化提示与触发器会因梯度纠缠导致收敛次优，因此对提示与触发器交替更新（Section IV.A、Section IV.E）。
2. **恶意目标**：$L_{adv} = L_{benign} + \lambda \cdot L_{bd}$（Eq. 2），$L_{bd} = -\mathrm{sim}(f(x_{trig}), g(t_{target}))$（Eq. 3），即"触发图像嵌入"与"目标文本嵌入"的相似度最大化。
3. **提示注入损失**：$L_p = -\mathrm{CosSim}(f(\tilde{x}), g(p;y_t))$（Eq. 5），其中 $\tilde{x}=\mathrm{Clip}(x+\tau)$，$(p;y_t)$ 是与后门目标关联的投毒提示。
4. **触发器优化损失**：$L_\tau = \mathrm{CosSim}(f(\tilde{x}), g(p;y_t))$（Eq. 7），论文称其"最小化对齐损失"以让触发器把图像嵌入对齐到目标文本。分析：Eq. 5 与 Eq. 7 关于余弦相似度的符号方向相反却都被描述为要最小化的"对齐损失"，论文未说明这一差异。
5. **聚合式传播**：投毒提示与良性提示一起被平均进全局提示（Eq. 4），由于提示本身就是"软模板"，后门在多轮聚合中被逐步写入共享提示表示（Section IV.E）。
6. **客户端本地更新**：良性客户端 $p^{(r)}_{i,t+1} = p^{(r)}_{i,t} - \eta\nabla L_i(p^{(r)}_{i,t})$（Eq. 11）；恶意客户端同时对提示与触发器做梯度下降（Eq. 13、Eq. 14），$T$ 步后只回传提示。
7. **收敛分析（Section V）**：在 Assumption 1（各本地目标 $L$-光滑，Eq. 15）与 Assumption 2（局部梯度方差一致有界于 $\delta_L^2$，Eq. 17）下，论文把服务器更新写成 $p^{(r+1)} = p^{(r)} - \eta\Psi^{(r)}$，$\Psi^{(r)} = \widehat{g}^{(r)}_{cln} + \Delta^{(r)}_{attack}$，并给出 Lemma 2（单轮下降不等式）、Lemma 3（干净偏差上界）、Lemma 4（攻击偏差上界）与 Theorem 1：$\mathbb{E}[\|\nabla L(P^{(r^\star)})\|^2] \le O(\cdot) + O(B_{attack})$，其中 $B_{attack} \le \rho^2 T \delta_{atk}^2$（若在 $\Psi^{(r)}$ 内对 $T$ 取平均则为 $\rho^2\delta_{atk}^2$），步长条件为 $\eta < \frac{1}{8RL}$。
8. **攻击流水线**（Algorithm 1）：服务器初始化并广播全局提示；良性客户端按对比损失更新；恶意客户端在每个本地 batch 上构造投毒样本并交替更新提示与触发器；恶意客户端私下聚合触发器；服务器聚合提示；重复 $R$ 轮后返回全局提示。

## 5. 检测或防御所需的数据

论文是攻击论文，因此下面列出"攻击在哪些可观测量上留下痕迹"以及"检测需要什么输入"。凡论文没有提出的检测视角，均明确标注。

1. **每个客户端每轮上传的本地提示更新 $p_i^{(r)}$**
   - 是什么：文本编码器输入端的可学习提示向量（$M$ 个 token、每个 $d$ 维），是服务器唯一能看到的攻击载体（Section III.B、Eq. 4）。
   - 在哪里采集：服务器收到更新时（客户端训练后）。
   - 粒度：逐客户端、逐轮；载体本身是一个向量（按 token 看是 $M$ 段）。
   - 跨轮历史：攻击依靠多轮累积（Section IV.E、Algorithm 1），论文报告 ASR 在头 10–20 轮就快速升高（Fig. 4、Section VI.B.2），所以轨迹类特征需要跨轮历史。分析：论文本身没有使用任何轨迹检测。
   - 干净参考数据：不需要。额外计算：不需要（只是读取上传的张量）。其他客户端数据：需要全体客户端更新才能做比较，MKrum、Foolsgold、Multi Metric 都属于这一类（Section VI.A.4、Table IV）。
2. **恶意客户端的触发器 $\tau$**
   - 是什么：叠加到整幅图像上的可学习扰动，幅度限制在 $[-8/255, 8/255]$（Section VI.A.3）。
   - 在哪里采集：只在恶意客户端本地被优化；论文明确它不上传（Section IV.E），而是由恶意客户端在服务器之外私下通信聚合（Eq. 8、Algorithm 1 第 17–19 行）。
   - 粒度：逐恶意客户端、逐轮。
   - 论文未说明服务器或良性客户端有任何途径观测它；服务器也被设定为无法访问本地训练日志（Section III.B）。
3. **干净准确率（ACC）监控**
   - 是什么：全局提示在干净测试样本上的分类准确率（Section VI.A.5）。
   - 在哪里采集：评估时（逐轮或最终）。
   - 粒度：逐轮、模型级。
   - 论文报告 ACC 与无攻击基线接近（Fig. 4、Section VI.B.2、Section VI.B.3），因此这一视角本身不构成检测信号。是否需要干净参考数据：需要评估数据；论文未说明在联邦部署中谁持有该评估集。
4. **提示嵌入空间的几何结构（t-SNE 可视化）**
   - 是什么：干净样本与后门样本在共享嵌入空间的分布；Fig. 9 显示干净图像形成紧凑且可分的语义簇，后门样本偏离这些簇并形成可区分的子空间。
   - 在哪里采集：评估时，需要模型前向与样本。
   - 粒度：逐样本，聚合成图。
   - 是否需要干净参考数据与额外计算：需要干净图像与额外前向计算（Fig. 9）。论文设定下服务器没有数据，因此这一视角不可直接用于服务器端检测；论文也未提出把它做成检测器。
5. **逐样本预测熵（STRIP 风格）**
   - 是什么：对输入叠加强扰动后模型预测分布的归一化熵。
   - 在哪里采集：推理 / 评估时，需要多次前向。
   - 粒度：逐样本。需要额外前向计算。
   - 论文报告在 BadPromptFL 下干净样本与毒化样本的熵分布高度重叠，无法设置稳健阈值（Section VI.C.2、Fig. 10）。
6. **触发器反演的异常指数（Neural Cleanse 风格）**
   - 是什么：为每个类别反演最小触发并计算异常指数。
   - 在哪里采集：需要一个可访问的模型和一批本地图像；论文使用 500 张本地图像（Section VI.C.4）。
   - 粒度：逐类别、模型级。需要干净参考数据与大量反向优化（额外计算）。
   - 论文报告 DTD 为 1.576（RN50）与 1.075（ViT），EuroSAT 为 1.448（RN50）与 1.712（ViT），全部低于常见阈值 2，检测失败（Fig. 12）。论文自述这一设置不符合联邦学习范式，因为服务器不能直接访问客户端数据且每客户端每类样本有限。
7. **投毒图像的像素级质量指标（PSNR / SSIM）**
   - 是什么：投毒图像相对干净图像的峰值信噪比与结构相似度。
   - 在哪里采集：客户端数据侧（逐样本）。
   - 论文报告 Oxford Flowers 为 35.1172 dB / 0.9035（RN50）与 34.9527 / 0.9004（ViT），EuroSAT 为 34.8317 / 0.8072（RN50）与 34.8231 / 0.8069（ViT），DTD 为 34.9538 / 0.9334（RN50）与 34.9038 / 0.9327（ViT），UCF101 为 35.2906 / 0.8683（RN50）与 35.1329 / 0.8644（ViT）（Table III）。论文未报告频域、残差或噪声模式类检测的结果。

**论文声称能绕过的检测**：无防御的 FedAvg（Table IV）；MKrum 只能中等程度降低 ASR 且多数情况 ASR 仍在 80% 以上；DP（噪声乘子 0.02）只能部分降低 ASR；Foolsgold 与 Multi Metric 效果高度依赖数据集与模型组合，在某些组合上几乎完全失效（Table IV）；STRIP 无法区分干净与毒化样本（Fig. 10）；CLP 无法在选择性去除恶意表示的同时保住干净性能（Fig. 11）；Neural Cleanse 的异常指数全部低于 2（Fig. 12）。分析：论文的表述是"现有防御不能稳定兼顾鲁棒性和干净效用"，而不是"全部被绕过"，Table IV 中确实存在 ASR 被压到个位数（例如 RN50–UCF101 上 Foolsgold 1.69%、ViT–DTD 上 Multi Metric 2.07%）的组合。

## 6. 干预动作

- **论文自身提出的干预动作**：无。论文是纯攻击工作，没有提出检测器，也没有提出检测之后的动作。对应字段应为"仅报告/无动作"。
- **论文评估的外部防御基线及其动作位置**（Section VI.A.4、Section VI.C）：
  - FedAvg：服务器聚合时直接平均，无干预。
  - MKrum：服务器聚合时选择最接近多数的更新（等价于剔除偏离者）。
  - 差分隐私：在客户端提示梯度上做 DP-SGD，噪声乘子 0.02（客户端训练时加噪）。
  - Foolsgold：服务器聚合时对梯度相似度高的客户端降权。
  - Multi Metric：服务器聚合时结合梯度范数与余弦相似度做异常检测。
  - STRIP：推理时对输入叠加强扰动并按预测熵判断是否拒绝（评估/部署阶段）。
  - CLP：对模型神经元做净化，净化系数记为 $u$（模型侧修复）。
  - Neural Cleanse：在模型上反演触发器并报告异常指数（仅报告）。
- 论文的结论是这些干预没有一个能稳定地在压低 ASR 的同时保住 ACC（Section VI.C.1），并因此呼吁设计专门针对提示空间的稳健聚合与检测机制（Section VII）。

## 7. 实验设置与主要结果

**设置**：CLIP RN50 与 ViT-B/16（LAION-400M 预训练），8 个图像数据集，6-shot 提示微调，全参与协议，100 轮，每轮 5 个本地 epoch，学习率 0.001，触发器幅度限制 $[-8/255, 8/255]$（Section VI.A.1–VI.A.3）。数据划分同时评估独立同分布（IID）与标签异构（Non-IID，每客户端只持有不相交类别子集），并用 Dirichlet 参数 $\alpha \in \{0.1, 0.3, 0.5, 0.7, 0.9\}$ 控制异构程度（Section VI.A.3、Section VI.B.4、Fig. 6）。指标为干净准确率 ACC（干净测试样本被正确分类的百分比）与攻击成功率 ASR（含触发器的测试样本被误分类为攻击者指定目标类的比例）（Section VI.A.5）。

**主要结果**：

- Table I（IID）与 Table II（Non-IID）给出 0-shot、干净 6-shot、注入后门 6-shot 三种设置的 ACC/ASR。例如 Table I 中 RN50–Caltech101 从 0-shot 的 86.00% 提升到干净 6-shot 的 92.70%，注入后门后 ACC 为 92.41%、ASR 为 89.45%；RN50–Oxford Flowers 为 66.00% → 95.70% → ACC 95.41% / ASR 81.32%；ViT–EuroSAT 为 47.50% → 82.27% → ACC 82.26% / ASR 97.49%（Table I）。
- Table II（Non-IID）中 RN50–Oxford Flowers 为 66.00% → 64.53% → ACC 91.84% / ASR 98.58%；ViT–EuroSAT 为 47.50% → 75.07% → ACC 75.19% / ASR 99.52%（Table II）。分析：按表 II 的列顺序（Caltech101、FGVCAircraft、Stanford Cars、Oxford Pets、Oxford Flowers、EuroSAT、UCF101、DTD）对齐后，Oxford Flowers 的攻击 ACC（91.84%）高于其干净 6-shot ACC（64.53%），而 EuroSAT 的攻击 ACC（76.32%）明显低于干净 6-shot ACC（91.88%），与正文"ACC 基本稳定"的概括存在张力；同时正文 VI.B.1 写的"Oxford Flowers 干净准确率从 64.5% 小幅降到 61.1%，ASR 达到 98.6%"中，64.5% 对应表 II 的 Oxford Flowers 干净值，而 61.1% 对应表 II / 表 IV 的 DTD 攻击 ACC，论文未说明这一不一致。
- Fig. 3 用柱状图对比两种主干在 IID / Non-IID 下 0-shot、干净 6-shot 与攻击设置的 ACC / ASR；论文称多数数据集上 ASR 持续很高且分类性能下降极小。
- Fig. 4：在 100 轮训练中，BadPromptFL 在头 10–20 轮就达到高 ASR，而 ACC 全程接近干净 PromptFL 基线（Section VI.B.2）。

## 8. 开销

论文未报告任何计算量（FLOPs、时延）、通信量（字节数）或存储开销的数值。论文只有定性表述：提示微调相比全模型联邦微调显著降低通信开销，因为只交换紧凑的提示向量（Section I、Section II）。攻击侧，恶意客户端每个本地迭代要额外对触发器做一次梯度更新（Eq. 14、Algorithm 1 第 13 行），并在服务器之外私下通信聚合触发器（Eq. 8、Algorithm 1 第 17–19 行），但论文没有给出这部分额外计算或通信的量化。防御基线也只给出超参数（例如 DP 的噪声乘子 0.02，Section VI.A.4），没有开销数字。Section V 的收敛分析给出了轮数与步长条件（$\eta < \frac{1}{8RL}$）但不涉及实际资源开销。

## 9. 假设、局限与自适应攻击

**方法成立所依赖的假设**（Section III.B、Section V）：

- 服务器与客户端（无论良性还是恶意）都无法访问彼此的原始数据。
- 目标架构（如 CLIP）与训练目标对所有参与者（含攻击者）已知。
- 协议是同步的：每轮所有客户端参与并同时上传本地提示更新；恶意客户端可以在轮内协调，但不能影响良性客户端或服务器。
- 攻击者在通信协议、数据格式与更新时间上与良性客户端不可区分，后门只通过提示空间植入，不改动任何模型参数。
- 服务器聚合时不检查、不校验单个提示更新，不知道哪些客户端恶意，也无法访问本地训练日志或梯度。
- 恶意客户端之间存在服务器之外的私有通信信道，用于聚合触发器（Eq. 8）。
- 收敛分析额外假设：本地目标 $L$-光滑（Assumption 1）、局部梯度方差一致有界 $\delta_L^2$（Assumption 2）、恶意更新范数有界 $\delta_{atk}$（Lemma 4）、步长 $\eta < \frac{1}{8RL}$（Lemma 3、Theorem 1）。

**论文自述的局限**：

- Neural Cleanse 的评估用了 500 张本地图像，论文自己承认这不符联邦学习范式（服务器不能直接访问客户端数据，且每客户端每类样本有限）（Section VI.C.4）。
- 防御评估不是穷尽的基准测试，只为说明 BadPromptFL 在常见防御下仍然有效（Section VI.A.4）。
- 现有防御无法稳定兼顾鲁棒性与干净效用，需要专门针对提示空间的防御（Section VI.C.1、Section VII）。
- 论文没有单独的 Limitations 章节。

**是否评估自适应攻击者**：没有。论文明确说，尽管很多前人工作在设计新防御和自适应攻击策略，本文的主要贡献是引入新的攻击向量，防御评估只是"为了提供完整的实验图像"（Section VI.A.4）。论文也没有讨论攻击者针对 MKrum / Foolsgold / STRIP 等做自适应调整后的表现。

**分析：迁移到联邦 LoRA 微调时可能不成立的假设**

- 分析：本论文的载体是 CLIP 文本编码器输入端的提示嵌入（$M\times d$ 的可学习上下文），LoRA 聚合的是低秩矩阵 $A$、$B$。论文"提示是行为的软模板、直接决定下游预测"这一核心论据不能直接搬到 LoRA 上，提示空间与适配器参数空间的几何性质不同。
- 分析：论文的攻击依赖 CLIP 的图像–文本共享嵌入空间与对比损失（Eq. 3、Eq. 5、Eq. 7）；纯文本 LLM 的 LoRA 微调没有对应的图文对齐结构，"把触发器图像对齐到目标文本嵌入"这一步没有直接对应物。
- 分析：论文的触发器是图像空间的全局像素扰动（$[-8/255, 8/255]$，Section VI.A.3），在纯文本场景不存在这个触发通道；若迁移到多模态 LLM，触发器的注入方式与可察觉性也需重新定义。
- 分析：论文的 ASR 定义是"含触发器的测试样本被误分类到攻击者指定目标类"（Section VI.A.5），适用于分类任务；联邦 LLM LoRA 微调通常面对生成任务，需要重定义为生成式后门指标（例如目标串生成率），论文未涉及。
- 分析：论文所有实验都是全参与协议（Section VI.A.3），客户端数与参与率固定，服务器聚合是简单平均（Eq. 4 / Eq. 10）；联邦 LoRA 微调常采用部分参与、按样本量加权、异构算力与异步上传，论文只在分析章节引入 $m$ 个被采样客户端的符号，没有做部分参与实验。
- 分析：论文假设服务器不检查更新、也不持有任何数据或根数据集（root dataset）（Section III.B）；常见的 LoRA 防护库会假设服务器可以做范数裁剪、相似度过滤或持有小规模干净根集，这些假设在本文设定下被排除，因此本文的结论不能直接用来论证"LoRA 场景下这些检测也无效"。
- 分析：论文的攻击隐蔽性很大程度来自提示参数量极小、干净性能几乎不受影响；LoRA 参数规模大得多，投毒更新更容易在范数、方向或跨轮轨迹上暴露，论文未验证这一点。
- 分析：论文的载体只在文本编码器输入端，触发器只在图像侧；LoRA 微调时被聚合的是模型内部权重增量，攻击入口（本地数据、本地损失、上传后处理）与可观测量的对应关系需要重新建立。
- 分析：论文的 Eq. 2 与 Eq. 12 给出两种不同的损失组合形式（$L_{benign}+\lambda L_{bd}$ 与 $(1-\lambda)L_{clean}+\lambda L_{bd}$），且 Algorithm 1 第 10 行把目标标签设为当前 batch 的干净标签 $y_t \leftarrow y_c$，而 Section VI.A.5 把 ASR 定义为"被误分类为攻击者指定目标类"，Fig. 1 / Fig. 2 也画出了固定的 "target"。论文未说明这些表述差异；如果要复现或迁移该方法，需要先确认目标标签究竟是固定类还是随 batch 变化。
- 分析：论文的威胁模型假设服务器不做任何检查（Section III.B），但在评估中又部署了 MKrum、Foolsgold、Multi Metric 等服务器端防御（Section VI.A.4），两者属于不同强度的攻击者知识假设；论文没有说明攻击者是否针对这些防御调整过触发器和提示的优化目标（即没有自适应攻击）。

## 10. 对防护库设计的含义

- 分析：库必须在"服务器收到更新时"提供一个逐客户端、逐轮的原始更新视图（本文是提示向量，LoRA 场景是低秩增量），而不是只记录聚合结果；因为本文攻击的痕迹只在聚合前的单个客户端更新上，服务器聚合规则本身没有被篡改（Eq. 4、Eq. 10）。这是通用需求，不限于本文。
- 分析：库需要保留逐轮历史，并允许插件访问同一客户端的更新轨迹。本文的攻击是跨轮累积的（Section IV.E、Algorithm 1），并在头 10–20 轮就产生高 ASR（Fig. 4、Section VI.B.2），只做单轮快照的检测会丢失最关键的时间维度。这是通用需求。
- 分析：库不应对"能拿到触发器"做任何假设。本文的触发器只在恶意客户端本地优化、从不上传，并由恶意客户端在服务器之外聚合（Eq. 8、Algorithm 1 第 17–19 行），论文明确服务器看不到本地训练日志。依赖触发器反演的检测（Neural Cleanse 一类）在联邦场景需要客户端侧钩子或额外数据授权，本文论证了它在服务器侧不可行（Section VI.C.4）。这一条是本文特有的强调。
- 分析：库的客户端钩子需要能拿到"本地 loss 的构成、被改写过的标签、以及进入 batch 的图像是否被叠加过扰动"，因为本文的攻击入口正是本地目标函数与本地 batch 构造（Eq. 2、Eq. 12、Algorithm 1 第 9–12 行）。论文没有提供任何这样的客户端侧检测，属于库需要自行补齐的能力。这是本文特有的入口，通用钩子设计需要为之留位。
- 分析：库的干预接口需要同时覆盖服务器聚合层（选择、降权、裁剪、加噪）、输入/推理层（拒绝可疑样本）和模型层（净化、回滚），并且必须允许"仅报告"作为一等动作；因为本文评估的三类干预（Table IV、Fig. 10–12）在不同数据集–模型组合上表现剧烈波动，检测与干预需要解耦，不能假设"检测到就一定剔除"。这是通用需求，本文提供了失效案例的实证。
- 分析：库的评估视图需要同时输出干净效用指标与攻击成功率指标（对应本文 ACC / ASR 的定义，Section VI.A.5），并支持按恶意比例 $\rho$、Dirichlet 异构参数 $\alpha$、IID / Non-IID 分层报告，因为本文的攻击有效性在这些维度上差异明显（Fig. 5、Fig. 6、Table I、Table II）。这是通用需求，也是本文可以直接复用为攻击复现基准的部分。
- 分析：抽象层应把"被聚合的可训练参数"当成一等公民（本文是提示嵌入，目标场景是 LoRA 增量），这样同一套采集点和插件钩子既能承载针对提示向量的检测，也能承载针对低秩矩阵的检测；本文的方法不能直接迁移到 LoRA，但它对聚合载体性质的论证（Section IV.A、Section IV.C）说明载体类型会决定攻击与检测的形态。
