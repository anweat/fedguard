# ax2601.00566：Low Rank Comes with Low Security: Gradient Assembly Poisoning Attacks against Distributed LoRA-based LLM Systems

## 1. 基本信息

- **场景**：联邦大模型微调（federated LLM fine-tuning）。论文在 III-A 节设定一个大语言模型的联邦微调系统：全局预训练模型由多个客户端在数据不出本地的前提下协同适配，客户端本地微调后周期性上传参数更新，中心服务器聚合得到新的全局模型。聚合发生在 FedIT 风格（FedIT-style）的解耦（decoupled）架构上，即客户端分别提交低秩矩阵 A 与 B，服务器分别校验、分别聚合。因此这不是传统联邦学习（图像分类）场景，也不是集中式训练；它属于联邦大模型微调，且使用参数高效微调（parameter-efficient fine-tuning，PEFT）中的 LoRA。
- **训练阶段**：覆盖"客户端本地微调 → 服务器逐轮聚合 → 全局模型下发"的多轮循环。攻击的执行位置是客户端提交更新之前（参数空间），漏洞的触发位置是服务器聚合后的合成阶段（V-B 节、公式 9）。论文在不同位置给出不同轮数量级：Figure 3 画 0–8 轮，Figures 4–5 画到第 30 轮，Table VI 报告达到目标需 33–42 轮。
- **论文类型**：攻击（attack）。论文提出 Gradient Assembly Poisoning（GAP），在 VII-C 节用三类检测系统评估规避能力；VII-D 节只给出方向性的防御讨论，没有实现或评估具体防御算法。
- **模型与数据规模**：数据集为 Databricks-dolly-15k，共 15,000 条高质量指令记录，覆盖八个任务类别（brainstorming、classification、closed QA、open QA、information extraction、summarization、creative writing、general QA），每次训练会话使用 10% 的不相交测试样本（VI 节）。模型为 LLaMA-7B/13B/33B、ChatGLM2-6B 与 GPT-2（VI 节写 124M，VII-A2 节正文写 77M）。LoRA 挂在所有 Transformer 线性层上，学习率 5e-3，LLaMA-33B 的秩 r = 8，更小架构 r = 16，缩放因子 α 统一设为 16（VI 节）。部署为 10 个客户端、每轮全选、只对 LoRA 可训练参数做 FedAvg；默认 2/10 客户端为恶意，恶意比例 α = 0.2（VI 节）。

## 2. 威胁模型

**攻击者是谁**：控制参与客户端的严格子集（strict subset of participating clients）的恶意客户端（malicious clients）；实验中默认 2/10，即 α = 0.2（VI 节）。恶意客户端互相独立、不需要协调，也不需要与其他被控客户端共享信息（III-B、VI）。

**能力（能改什么）**：可以任意操纵自己提交的 LoRA 更新 (A_i, B_i)；不能访问服务器内部，也不能访问其他客户端的私有数据（III-B）。恶意客户端严格遵循联邦训练与聚合协议，不偏离规定的通信、校验或聚合流程，只在提交的 LoRA 更新上不同（III-B、VI 节）。

**知识（知道什么）**：知道系统架构，包括 LoRA 参数解耦与联邦聚合机制（III-B）。在在线阶段，攻击者利用服务器广播的信息估计良性训练动态与逐层均值 µ_Θ（V-B 节、Algorithm 1 的 GETBENIGNHISTORY()）。离线阶段攻击者需要自建触发集 D_mal = {(x, y_err)} 与攻击者指定的错误输出（V-B 节公式 2）。

**目标**：让全局模型行为产生定向语义偏差（targeted semantic deviations），同时保持整体任务性能并规避检测；不是无差别降准确率，而是跨聚合轮次持续、行为层面的污染（III-B）。摘要把效果描述为"degraded or biased outputs"。分析：论文自述目标带定向性（离线阶段显式使用触发集与错误目标输出），但 Table III 同时报告了五个模型上 BLEU、TF-IDF、BERTScore、困惑度、语法错误的普遍退化，因此"定向行为偏差"与"无目标输出退化"两种成分在结果里都存在。

**防御者是谁、能看到什么、信任什么**：中心服务器。它能拿到每个客户端提交的 (A_i, B_i)，能对每个分量做范数或相似度校验，能分别聚合 A 与 B 并在聚合后合成全局更新（III-A、IV 节 S-I）。它信任"逐矩阵校验足以约束更新的实际效果"，并出于可扩展性与模块化刻意不显式约束合成更新 ∆W = AB（IV 节 S-I）。VII-C 节实际评估的服务器端检测器是范数阈值（norm thresholding，τ_A = 2.5σ_A）、FoolsGold 信誉检测与 Spectral Signatures 子空间异常检测。

## 3. 攻击入口与流程位置

**入口位置是"更新上传前的后处理"**。攻击者不污染本地训练数据，不改损失函数、优化器或训练步数，而是直接构造本轮要提交的低秩矩阵 (A_i, B_i)；论文在 II-B 节自述 GAP"targets the aggregation mechanism itself rather than the training data or individual adapters"。漏洞被触发的地点是服务器聚合之后的合成步骤，攻击者本身并不改动服务器逻辑。

具体步骤（V-B 节与 Algorithm 1）：

1. **离线阶段（Phase I，步骤 1 与 2）**：攻击者用自己的触发集 D_mal = {(x, y_err)} 在预训练基座 W 上做对抗微调，求解公式 (2)，得到一对目标低秩适配器 (A_target, B_target)，其合成 ∆W_target = A_target B_target 编码期望的恶意行为。论文称这一步不依赖联邦动态，可用标准单客户端微调完成，并且它处在受害者的联邦流程之外。
2. **在线阶段（Phase II）**：每一轮 t，恶意客户端读取服务器广播的全局 LoRA 参数与逐层均值，估计良性训练动态（Algorithm 1 的 GETBENIGNHISTORY()，µ_Θ ← E[H_Θ]），并计算两个自适应上界：δ(t)（公式 3，同一客户端相邻两轮参数变化的最大 L2 范数）与 γ(t)（公式 4，客户端参数与逐层均值 µ_Θ 的最大 L2 距离）。
3. **约束优化**：求解公式 (5)–(7)，让"以恶意更新 Θ_i 为条件的期望聚合参数 E[Θ_agg^(t) | Θ_i]"尽量接近 Θ_target，同时满足时间漂移约束 ||Θ_i − Θ_i^(t−1)||_2 ≤ δ(t) 与空间偏离约束 ||Θ_i − µ_Θ^(t)||_2 ≤ γ(t)。
4. **提交（Step ❺）**：把解出的 (A_i, B_i) 提交给服务器，它们能通过逐矩阵范数阈值检查（公式 8：||A_i − µ_A||_2 ≤ τ_A、||B_i − µ_B||_2 ≤ τ_B）。
5. **服务器聚合（Step ❻）**：服务器分别聚合 Ā^(t) 与 B̄^(t)，再合成为全局模型（公式 9：W^(T) = W_0 + Ā^(t) B̄^(t)；Algorithm 1 第 23 行写成按层求和的形式 W^(t) ← W_0 + Σ_l Ā^(t,l) B̄^(t,l)）。恶意效应在合成这一步才出现。
6. **评估与部署（Step ❼）**：聚合后的模型在推理时表现出上下文相关的响应操纵或定向行为偏移，而高层评估指标仍可保持。

分析：从防护库的角度，攻击者占用的是"客户端提交钩子"，但其成立依赖"服务器聚合钩子"上的解耦逻辑；两个钩子之间没有任何一方能看到 ∆W = AB。

## 4. 方法原理

**核心思想**：联邦 LoRA 系统中存在"计算与校验的分离"（disjunction between computation and verification）。更新的语义影响由合成矩阵 ∆W = AB 决定，但通信、校验与聚合全部在单个低秩分量 A、B 上完成（IV 节）。论文把这一结构性弱点拆成四个脆弱面（IV 节）：

- **S-I 校验缺口（Verification Gaps）**：服务器对 A 和 B 独立做逐分量约束（范数或相似度），协议层不要求检查合成更新 ∆W = AB。
- **S-II 层间隔离（Layer-wise Isolation）**：L 个 LoRA 层各自独立聚合与校验，不建模层间依赖；攻击者可以把小而一致的扰动分散到多层，让效果在最终模型中复合。
- **S-III 偏差累积（Bias Accumulation）**：更新被限制在固定低维子空间，跨轮扰动可以沿方向累积；攻击者优化的是让聚合参数朝目标轨迹前进，而不是在单轮造成大偏离。
- **S-IV 参数—行为失配（Parameter-Behavior Mismatch）**：单矩阵层面的参数统计正常，并不代表合成为 ∆W 后行为正常；定向语义偏差只在推理时显现。

**关键步骤**即 §3 的两阶段。**可行性分析（V-C 节）**：设 α 为某一轮中恶意客户端占比，良性客户端平均更新为 A_ben、B_ben，恶意客户端平均更新为 A_mal、B_mal，则 ∆W^(t) = Ā^(t) B̄^(t)，其中 Ā^(t) = (1−α)A_ben + αA_mal、B̄^(t) = (1−α)B_ben + αB_mal（公式 10–12）。由于这是乘法重组而非全秩梯度的加法聚合，交叉项不会被良性行为显式抵消，"即使 α 很小，有效更新中仍保留与恶意方向对齐的非消失分量"（V-C 节）。论文进一步论证：在良性更新统计下，约束定义的可行域是非空闭凸集（non-empty closed convex set），目标关于 Θ_i 凸，因此重复投影可以让聚合轨迹逐步被推向 Θ_target 的有界邻域（V-B、V-C 节）。Algorithm 1 的初始化是 A^(0) ← N(0, σ²I)、B^(0) ← 0。

## 5. 检测或防御所需的数据

按论文给出的防御方向（VII-D）与它实际评估的三种检测器（VII-C），检测或防御需要如下输入：

1. **每个客户端提交的逐层 LoRA 矩阵 A_i 与 B_i**。采集位置：服务器收到更新时（server_receive）。粒度：逐客户端、逐层、逐轮。跨轮历史：不需要。干净参考数据：不需要。额外前向或反向计算：不需要。
2. **每个客户端自己的合成更新 ∆W_i = A_i B_i**。这是 S-I 的直接对策（VII-D 的组合监控）。采集位置：服务器收到更新时，由 A_i 与 B_i 相乘得到。粒度：逐客户端、逐层、逐轮。跨轮历史：不需要。干净参考：不需要。额外计算：需要，必须做矩阵乘法；论文指出这会抵消低秩参数化的一部分效率收益。
3. **同一客户端跨轮的参数变化量**。对应公式 (3) 的 δ(t)，也是 FoolsGold 类信誉统计的输入。采集位置：服务器收到更新时，与该客户端上一轮的提交对比。粒度：逐客户端、逐层、逐轮。跨轮历史：需要。干净参考：不需要。额外计算：不需要。
4. **服务器聚合后的全局 LoRA 参数及其逐层均值 µ_Θ**。攻击者用它估计良性统计量（Algorithm 1、公式 4），防御者做偏离度阈值也需要同一个量。采集位置：服务器聚合之后（server_post_aggregate）。粒度：逐层、逐轮。跨轮历史：不需要。干净参考：不需要。额外计算：需要（求逐层均值）。
5. **跨层复合的全局量，即按层拼接后的 Σ_l Ā^(t,l) B̄^(t,l)**。对应 S-II 层间隔离。采集位置：服务器聚合之后。粒度：模型级、逐轮。跨轮历史：不需要。干净参考：不需要。额外计算：需要。
6. **每个客户端矩阵相对簇中心的余弦距离与欧氏距离**。论文在 Figure 8 用它们度量隐蔽性（恶意节点平均距离 Malicious-Avg、良性节点平均距离 Benign-Avg、良性节点最大距离 Benign-Max）。采集位置：服务器收到更新时（论文中该分析是离线几何分析）。粒度：逐层、逐客户端。额外计算：需要（聚类与距离统计）。
7. **逐轮训练损失**。论文在 Figure 3 用损失轨迹展示攻击的持续干扰。采集位置：客户端训练过程中（论文只给到逐轮曲线）。粒度：逐轮。跨轮历史：需要（看轨迹）。干净参考：不需要。额外计算：不需要。
8. **评估阶段的生成文本及其指标**：BLEU、TF-IDF 相似度、上下文相似度、BERTScore、困惑度、语法错误数、词汇多样性（Table II、Table III 与附录 A），以及响应谱 L0–L4 与主题敏感度 T1–T5（Table IV、Table V）。采集位置：评估时。粒度：模型级，逐样本生成后聚合。干净参考：需要，BLEU、TF-IDF、上下文相似度、BERTScore 均依赖参考响应（VI 节说明每次会话使用 10% 的不相交测试样本）。额外计算：需要。

**攻击会留下痕迹的可观测量与论文声称绕过的检测**：论文声称 GAP 规避了逐矩阵范数阈值（检测率 0.0%，误报率 0.0%，规避率 100.0%）、FoolsGold（检测率 1.2%，误报率 2.1%，规避率 98.8%）与 Spectral Signatures（检测率 0.0%，误报率 13.65%，规避率 100.0%）（Table VII、VII-C 节）。几何上，Figure 7 的 UMAP 显示恶意客户端与良性客户端在各层参数空间中交错分布，Figure 8 显示恶意节点到簇中心的平均距离落在良性节点最大距离之内。论文把攻击可被察觉的位置定位在：合成更新 ∆W（S-I，需要服务器主动计算）、跨层复合结构（S-II）、跨轮方向累积（S-III）以及只在推理时显现的行为偏差（S-IV）。

## 6. 干预动作

论文是一篇攻击论文，方法本身没有"检测后动作"：它不剔除客户端、不重新加权、不裁剪、不加噪、不过滤样本、不修复或回滚模型，也不产生报告。论文未说明 GAP 自身包含任何干预动作。

论文在 VII-D 节只给出两个方向性的防御设想，二者都没有实现、没有给出阈值、也没有做实验评估：

- **组合监控（Composition Monitoring）**：服务器在逐分量校验之外额外校验乘积 AB，分析合成后的更新行为以发现细微的恶意模式。论文明确指出这会引入计算与系统开销，因为计算 AB 会抵消低秩参数化的一部分效率收益。
- **自适应验证（Adaptive Verification）**：对结构脆弱层（如注意力层或输出层）施加更严格的校验协议或动态阈值调整。论文指出这要求服务器事先知道层的敏感度，并随着全局模型的演化不断重新校准阈值，会增加系统编排的复杂度。

分析：如果要让防护库支持这两条防御，动作会分别落在"服务器收到更新时"（对单个客户端做标记或拒绝）与"服务器聚合前后"（按层选择不同阈值），但论文没有给出任何可复现的算法。

## 7. 实验设置与主要结果

**设置**：数据集 Databricks-dolly-15k（15,000 条指令记录，八个任务类别，每次训练会话使用 10% 不相交测试样本）。模型 LLaMA-7B/13B/33B、ChatGLM2-6B 与 GPT-2（VI 节写 124M，VII-A2 节正文写 77M）。适配器挂在所有 Transformer 线性层，学习率 5e-3，LLaMA-33B 的秩 r = 8、更小架构 r = 16，缩放因子 α = 16。部署为 10 个客户端、每轮全部选中、只聚合 LoRA 可训练参数、使用 FedAvg；默认 2/10 客户端为恶意（α = 0.2），恶意客户端彼此独立、不共享信息、只改变提交的 LoRA 更新。指标（Table II）：响应准确类为 BLEU、TF-IDF 相似度、上下文相似度、BERTScore；响应质量类为困惑度（perplexity）、语法错误数、词汇多样性。Table IV 定义响应退化等级 L0–L4（L0 功能崩溃、L1 显式投毒、L2 不超过 5 词的截断、L3 为 6–10 词的截断、L4 为不少于 10 词且基本完整的保留输出）与主题类别 T1–T5（动物与自然、音乐与电影、地理与工程、逻辑推理、主观解释）。**数据是否非独立同分布：论文未明确说明**，VI 节只给出数据规模与测试集划分，VII-C 节提到恶意参数可以"mimicking heterogeneous participant distributions"（异构参与者分布）。

**主要结果**：

- 输出准确性与文本质量（Table III）：LLaMA-7B 的 BLEU 从 0.80 到 0.71、TF-IDF 从 0.79 到 0.74、BERTScore 从 0.84 到 0.81、困惑度从 14.92 升到 30.42；LLaMA-13B 的 BLEU 从 0.77 到 0.83、上下文相似度 0.92 保持不变、BERTScore 从 0.75 到 0.88、困惑度从 21.60 升到 33.67；LLaMA-33B 的 BLEU 保持 0.81、BERTScore 从 0.84 到 0.82、困惑度从 18.01 升到 38.02；ChatGLM-6B 的 BLEU 从 0.76 降到 0.57、TF-IDF 从 0.86 到 0.79、上下文相似度从 0.92 到 0.87、BERTScore 从 0.92 到 0.72、困惑度从 21.32 升到 70.09、语法错误从 3.90 升到 13.26；GPT-2 的 BLEU 从 0.69 到 0.66、TF-IDF 从 0.53 到 0.41、上下文相似度从 0.90 到 0.92、BERTScore 从 0.71 到 0.66、困惑度从 5.85 到 5.17、语法错误从 4.23 升到 7.40。
- 摘要与引言另给的数（照录）：摘要称 BLEU 最多下降 14.5%、事实与语法错误增加超过 800%、长文本响应长度保留 92.6%；引言称 LLaMA-13B 的 BLEU 从 0.83（干净）降到 0.71，同时保持上下文相似度 0.92 与 BERTScore 0.81，ChatGLM-6B 的中长响应（L3）被放大 63.1%、困惑度从 21.3 升到 70.1、语法错误从 3.9 升到 13.3，LLaMA-13B 的主观响应污染增加 568%，LLaMA-7B 的事实错误增加 833%。
- 响应谱与主题敏感度（Table V）：LLaMA-7B 的 L1 从 1.43% 升到 6.55%、T3 从 0.81% 升到 7.56%；ChatGLM-6B 的 L1 从 0.32% 升到 5.60%；LLaMA-33B 的 L0 从 4.33% 降到 0.33%；GPT-2 的 L4 从 99.67% 到 99.19%。论文称攻击平均维持 92.6±6.6% 的 L4 保留率（VII-A3），并称 LLaMA-33B 把 L0 输出压低 51.2%（VII-A3）。
- 攻击有效性（VII-A）：Figure 3 给出 0%、10%、20%、40% 恶意比例下 9 个训练轮次的损失曲线，论文称攻击造成持续干扰但表面仍呈下降趋势。VII-A2 称 83.3% 的被测模型出现显著性能下降，并归纳出三种退化机制：隐藏态转移被破坏导致困惑度尖峰、按架构不同的语法不一致、与模型容量相关的词汇多样性下降。

## 9. 假设、局限与自适应攻击

**论文成立所依赖的假设**：

- **架构假设**：客户端分别提交 A 与 B，服务器分别校验、分别聚合，只在聚合之后合成 ∆W = AB，且协议层不检查合成更新（III-A、IV 节 S-I）。论文称这是 FedIT 风格系统共享的结构性属性，而非某个实现的偶然缺陷。
- **校验假设**：服务器对每个分量施加范数或相似度约束，并且这些阈值在攻击期间保持稳定可用（IV 节 S-I、公式 8）。
- **攻击者假设**：恶意客户端是参与客户端的严格子集（实验为 2/10，α = 0.2）；可以任意改自己的 (A_i, B_i)；不能碰服务器内部与其他客户端的私有数据；彼此不需要协调；知道系统架构（III-B、VI 节）。
- **信息假设**：攻击者能利用服务器广播的信息估计良性训练动态与逐层均值 µ_Θ（V-B 节、Algorithm 1）。
- **数据假设**：离线阶段攻击者需要自建的触发集 D_mal = {(x, y_err)} 与错误目标输出，做一次对抗微调得到 (A_target, B_target)（V-B 节公式 2）。摘要把这一性质表述为攻击"without access to training data"，指的是不接触受害客户端的私有训练数据，而不是完全不需要任何数据。
- **优化假设**：在良性更新统计下，约束定义的可行域为非空闭凸集、目标关于 Θ_i 凸，因此重复投影可以收敛到目标的有界邻域（V-B、V-C 节）。

**论文自述的局限**：

- VII-D 指出组合监控会带来计算与系统开销，自适应验证要求服务器事先知道层敏感度并持续重校准阈值。
- VII-A2 承认攻击影响在不同规模模型上不均匀：LLaMA-33B 这类大模型的 BLEU、BERTScore 等参考型语义指标基本稳定，论文把它解释为攻击表现从全局语义退化转向局部或条件性的行为偏差；GPT-2 的压缩架构会"nullify sub-threshold attacks"。
- VII-A3 提醒响应长度只用于说明攻击没有退化成简单的输出抑制，不应解读为响应可用性，尤其在困惑度大幅上升时。
- VIII 节把面向适配器聚合的认证鲁棒性（certified robustness for adapter aggregation）与硬件辅助信任机制列为未来工作。
- 论文没有讨论客户端部分参与、参与率变化、恶意客户端被检测后的演化等情形（论文未说明）。

**是否评估自适应攻击者**：论文没有评估自适应攻击者。VII-C 节对三类检测系统的评估是一次性对比，论文没有针对任一检测器重新优化攻击，也没有对 VII-D 自己提出的组合监控或自适应验证做任何实验；论文未说明当攻击者知道服务器会计算 AB 时会如何调整。

**分析：迁移到联邦 LoRA 微调时可能失效的假设**：

- 只要服务器改为在聚合前重建并校验 ∆W = AB，S-I 就不再成立，公式 (5)–(8) 那套"单矩阵像良性、乘积恶意"的可行性论证必须针对合成层面的约束重新推导。
- 论文的约束依赖攻击者能拿到广播的全局参数与逐层均值。若系统只广播全局模型而不下发逐层统计量，或使用安全聚合（secure aggregation）隐藏单客户端更新，δ(t) 与 γ(t) 的估计会变得更困难；论文未分析这两种情形。
- 论文的聚合是全体客户端参与的加权平均，公式 (10)–(12) 建立在这个形式上。部分参与、异步聚合与鲁棒聚合规则（如 Krum、trimmed mean、median）都不在评估范围内，攻击在这些规则下是否仍成立论文未说明。
- 论文只覆盖固定秩的原生 LoRA。QLoRA、AdaLoRA、DoRA 等变体的聚合对象不同（例如 DoRA 还包含幅度向量），解耦聚合的盲区结构会随之改变，其单矩阵级隐蔽性结论不能直接照搬。
- 论文缺少非独立同分布数据划分与更大客户端规模的实验，而这两点恰好决定"恶意更新能否藏在良性分布里"这一核心假设的松紧程度。

## 10. 对防护库设计的含义

分析：以下全部为我的分析。

- **通用需求**：采集底座必须在"服务器收到更新时"这个信任边界上，按客户端标识、逐层、逐轮保存原始的 LoRA 增量 (A_i, B_i)。这是任何服务器端聚合插件（范数、信誉、聚类、子空间检测）的共同前提，本文评估的三个检测器都需要这份数据。
- **本论文特有需求**：底座要允许插件在同一钩子上构造"合成视图" ∆W_i = A_i B_i，并允许在"服务器聚合之后"再构造跨层复合视图 Σ_l Ā^(t,l) B̄^(t,l)。这两步都需要额外的矩阵乘法，分别对应 S-I 与 S-II；插件机制需要能声明"我愿意为该视图付计算代价"，底座负责缓存与复用。
- **通用需求**：按客户端标识维护跨轮历史窗口。公式 (3) 的 δ(t) 与 FoolsGold 类信誉统计都需要"同一客户端上一轮或前若干轮的更新"，因此采集底座应保留有界历史，而不是只留当轮快照。
- **通用需求**：服务器下发的全局 LoRA 参数与逐层统计量（论文中的 µ_Θ）应作为一等数据视图暴露。攻击者用它估计良性分布，防御者的偏离度阈值也用同一个量，所以这个视图对攻防双方都是关键输入。
- **本论文特有需求**：干预接口至少要在两个位置可挂载——"服务器收到更新时"对单个客户端做标记或拒绝，"服务器聚合时"按层启用不同阈值（对应 VII-D 的自适应验证）。但论文没有给出算法、阈值或评估结果，库只能提供钩子与配置面，不能声称实现了论文的防御。
- **通用结论**：Table VII 显示只看逐客户端范数或子空间异常是无效的（范数阈值检测率 0.0%，Spectral Signatures 检测率 0.0%），因此检测插件接口不能只暴露范数一类标量摘要，必须能访问可自由组合的原始矩阵，否则插件无法实现本文意义上的合成层校验。
