# ax2608.06795：LoRAScan: Detecting Backdoor Prompts in Low-Rank Adapters for Large Language Models via Down-Projection Activation Spikes

## 1. 基本信息

**场景**：既不是传统联邦学习，也不是集中式大模型训练，而是"参数高效微调供应链"（parameter-efficient fine-tuning supply chain）场景下的推理期防护。论文的威胁模型明确写明，LoRA（Low-Rank Adaptation，低秩适配）适配器从第三方仓库下载，基座模型（base model）来自可信机构（Methodology 节 Threat Model 小节）。全文没有客户端、服务器聚合、参与率或联邦轮次的概念。

**训练阶段**：攻击发生在第三方对适配器的训练阶段，攻击者完全控制适配器训练流程（Methodology 节 Threat Model 小节）。防御分成两段：部署前的标定，以及部署后的推理期检测（生成之前对提示做接受或拒绝）。论文不涉及任何训练期的联邦流程。

**论文类型**：防御与检测。论文自称是"第一个针对生成式大语言模型低秩适配器的推理期后门防御"（Introduction 节），并且是样本级（sample-level）的后门提示检测器（图 1）。表 1 把它与 ONION、BEAT、ConfGuard、CleanGen、PEFTGuard、Obliviate 并列比较。

**模型与数据规模**：五个模型家族，即 Deepseekllm-7B-chat、Llama-2-7b-chat-hf、Llama-3-8B-Instruct、Openchat-3.5-1210 与 Vicuna-13B-v1.5；评测使用 BackdoorLLM 基准的 75 个低秩适配器，覆盖 BadNets、CTBA、MTBA、Sleeper 与 VPI 五种攻击，以及 jailbreak（越狱）、negative sentiment（负面情感）、refusal（拒答）三类行为目标（Experimental Evaluation 节 Experimental Settings 小节）。标定使用从 Stanford Alpaca 抽样的 40 条干净提示；测试集为 12,475 条后门样本与 12,475 条干净样本，每个模型 2,495 条测试样本（表 2、表 5、表 6）。硬件是两张 NVIDIA A100 80GB GPU。

## 2. 威胁模型

**攻击者是谁**：第三方 LoRA 适配器的发布者（adapter publisher）。论文的设定是适配器从第三方仓库下载，攻击者完全控制适配器训练流程，但不能修改基座模型（Methodology 节 Threat Model 小节）。

**占比或数量**：论文未说明攻击者在某个总体中的占比，因为这不是联邦学习设置，不存在"恶意客户端比例"这一概念。评测使用了 BackdoorLLM 基准的 75 个低秩适配器，全部是植入后门的适配器（Experimental Evaluation 节 Experimental Settings 小节、表 2 标题）。

**能力**：攻击者控制适配器的训练过程、训练数据与训练目标，使适配器在干净提示上表现正常，而在输入包含秘密触发器（trigger）时执行恶意目标行为（Methodology 节 Threat Model 小节）。论文列举的攻击包括数据投毒式的 BadNets、以语义或话题级场景为触发的 virtual prompt injection、以部署相关上下文（例如年份）为条件的 sleeper agent、多触发器 MTBA、以及要求多个触发键按指定顺序出现的 CTBA（Background and Related Work 节 Backdoor Attacks 小节）。

**知识**：攻击者知道触发器与目标行为。防御者拥有适配器权重的白盒访问权限，但不知道适配器是否被投毒、使用了哪个触发器、植入了哪种目标行为（Methodology 节 Threat Model 小节）。

**目标**：后门（backdoor）。摘要与引言提到有害内容、恶意代码、政治宣传与隐蔽广告等后果；实验中的三类行为目标是抑制模型对有害请求的拒答（jailbreak）、在触发时向输出注入负面情感短语（negative sentiment）、以及对正常请求诱导拒答（refusal）（Experimental Evaluation 节 Experimental Settings 小节）。

**防御者是谁、能看到什么、信任什么**：防御者是从第三方仓库取得适配器并自行部署的一方。论文要求防御者对适配器权重有白盒访问权限，并要求在推理时可以读取中间激活（intermediate activations）；防御者信任基座模型，不信任第三方适配器。防御者没有投毒样本，也不知道触发器或目标行为，但可以拿到一小部分无标签的通用指令跟随干净提示（Methodology 节 Threat Model 小节；Limitations and Future Work 节）。论文未说明防御者如何信任提供干净提示的数据源，也未说明适配器文件附带的元数据是否可信。

## 3. 攻击入口与流程位置

这是防御与检测论文，因此下面先写它针对的攻击入口，再写防御自身进入流程的位置。

**被针对的攻击入口是适配器的本地数据准备与本地训练过程**。攻击者在上传适配器之前用被投毒的数据训练低秩适配器：论文对 BadNets 的表述是"向被选中的训练样本加入一个词或短语，并把它与攻击者指定的目标输出配对"（Background and Related Work 节 Backdoor Attacks 小节）。论文没有讨论上传前的更新后处理、服务器聚合、全局模型下发这些环节，因为该论文不含联邦流程。

**攻击方的具体操作步骤**：从可信基座模型出发训练一个 LoRA 适配器，在干净提示上保持正常行为，在触发器出现时执行目标行为。实验中的触发器形式包括词级触发器（BadNets）、短语级触发器（VPI 与 Sleeper）、必须按指定顺序出现的组合触发器（CTBA），以及在同一适配器内植入多个相互独立后门的 MTBA（Experimental Evaluation 节 Experimental Settings 小节）。

**防御自身进入流程的位置有两处**。第一处是部署前标定：用 40 条干净提示在"基座模型加适配器"上做前向，计算每个插入点（insertion site）的激活尖峰统计量，选出方差最低的 5% 插入点，并用中位数与中位数绝对偏差（median absolute deviation）算出拒绝阈值（Methodology 节 Backdoor Detector Construction 小节；图 2）。第二处是推理期：对每个输入提示做一次前向，在被选中的插入点上计算归一化尖峰分数并求平均，如果分数超过阈值，就在生成之前拒绝该提示，否则交给 LoRA 适配后的模型正常生成（Methodology 节 Overview 小节；图 2）。

## 4. 方法原理

**核心思想**：后门行为会在 LoRA 下投影（down-projection，即公式中的 A 矩阵）的瓶颈激活上留下与干净输入不同的潜在空间足迹。干净输入上少数插入点的激活统计非常稳定，而带触发器的输入会在这些点上出现幅度异常大、且集中在少数 token 位置上的激活尖峰，因此可以用一个稀疏的插入点子集做输入级门控。

**关键步骤一，定义激活尖峰统计量**。对输入提示 x，记 T(x) 为提示的 token 位置集合，a(m,t)(x) 为插入点 m 在 token 位置 t 上的 LoRA 下投影瓶颈激活幅度。公式 (2) 定义 M(m)(x) 为所有提示 token 位置上的最大值，ā(m)(x) 为均值，并令 s(m)(x) 等于 M(m)(x) 乘以 log(1 + M(m)(x) / ā(m)(x))。当某个插入点既有高激活幅度、又高度集中在少数 token 位置时，s(m)(x) 会变大（Methodology 节 Hypothesis and Test Statistic Formulation 小节，公式 (2)）。

**关键步骤二，选择要监控的插入点**。设干净集为 C，适配器可用的插入点全集为 M。LoRAScan 在每条干净提示上计算每个插入点的 s(m)(ci)，得到该插入点的均值 μ(m) 与标准差 σ(m)；然后按 σ(m) 升序排名，保留方差最低的比例 k（默认 k = 0.05），记作 M(k)。论文的直觉是，干净行为一致的站点上，触发器引起的偏差更不容易被正常波动掩盖（Methodology 节 Backdoor Detector Construction 小节）。

**关键步骤三，构造样本分数与阈值**。对每个选中站点做标准化后取平均，得到公式 (3)：S(k)(x) 等于 M(k) 中所有站点 (s(m)(x) − μ(m)) / σ(m) 的平均值，从而把不同站点的尖峰统计放到同一尺度上。再用干净分数 {S(k)(ci)} 的中位数 b(m,k) 与中位数绝对偏差 b(d,k) 定义单侧拒绝阈值，即公式 (4)：τ(k) = b(m,k) + λ·b(d,k)。实验中取 λ = 4.45，等价于三个"与高斯分布一致的"中位数绝对偏差尺度单位，在干净分数服从正态分布的参考假设下约对应 99.9 分位（Methodology 节 Backdoor Detector Construction 小节，公式 (4)；Experimental Evaluation 节 Experimental Settings 小节）。

**关键步骤四，推理期判定**。LoRAScan 只做一次前向，计算 S(k)(x)，若 S(k)(x) 大于 τ(k) 则在生成前拒绝，否则放行；它不修改适配器参数，也不改变模型的生成过程（Methodology 节 Backdoor Detector Construction 小节；Introduction 节）。论文还把"与适配器无关的防御会把适配器与基座模型合并、从而稀释后门信号并降低检测表现"作为使用适配器感知（adapter-aware）信号的理由（Abstract；Introduction 节）。

## 5. 检测或防御所需的数据

**第 1 项，第三方 LoRA 适配器的权重与插入点清单**。
- 是什么：适配器在每个插入点上的低秩矩阵 A 与 B，以及适配器包含哪些插入点。论文列举的常见插入点是注意力的 WQ、WK、WV、WO 与前馈的 Wgate、Wup、Wdown。
- 在哪里采集：部署方从第三方仓库取得适配器时。
- 粒度：逐层（逐插入点、逐矩阵）。
- 是否需要跨轮历史：不需要。
- 是否需要干净参考数据或根数据集（root dataset）：不需要。
- 是否需要额外前向或反向计算：不需要，只是读取权重与结构。

**第 2 项，一小部分无标签的干净提示（clean prompts）**。
- 是什么：从通用指令跟随数据集抽取的提示，实验中是 Stanford Alpaca 的 40 条；不带标签，也不是投毒样本。
- 在哪里采集：部署前的标定阶段，在部署方本地。
- 粒度：逐样本（提示级）。
- 是否需要跨轮历史：不需要。
- 是否需要干净参考数据：这一项本身就是干净参考数据；论文不要求根数据集式的全量可信集。
- 是否需要额外前向或反向计算：需要，要在"基座模型加适配器"上做前向以读取激活。

**第 3 项，LoRA 下投影（A 侧）的逐 token 瓶颈激活**。
- 是什么：a(m,t)(x)，即插入点 m 在提示 token 位置 t 上的下投影瓶颈激活幅度。
- 在哪里采集：标定阶段在 40 条干净提示上采集，推理期在每个待检提示上采集；两处都必须在前向传播过程中读取中间激活，因此需要能挂上读取瓶颈激活的钩子（hook）。
- 粒度：逐 token 位置、逐插入点，随后聚合成逐样本的分数 S(k)(x)。
- 是否需要跨轮历史：不需要，每条提示独立打分。
- 是否需要干净参考数据：需要，因为标准化用到的 μ(m) 与 σ(m) 来自干净提示上的统计。
- 是否需要额外前向或反向计算：需要。论文强调推理期只需一次前向、不需要多次生成，这相对于需要多次生成的 BEAT 是优势；但相对于不做检测的普通生成，它仍然要在生成之前额外读取并统计激活。

**第 4 项，部署前算出的标定工件**。
- 是什么：待监控插入点子集 M(k)（默认占全部插入点的 5%）、每个站点的均值与标准差、以及单侧阈值 τ(k) = b(m,k) + λ·b(d,k)。
- 在哪里采集：部署前的标定阶段产生，推理期复用。
- 粒度：逐适配器一套；站点级统计量是逐层的。
- 是否需要跨轮历史：不需要。
- 是否需要干净参考数据：需要。
- 是否需要额外前向或反向计算：标定阶段需要；推理期只是查表与比较。

**第 5 项，模型前向的可访问性**。论文明确要求白盒访问适配器权重与中间激活（Methodology 节 Threat Model 小节；Limitations and Future Work 节），也就是需要能够运行"基座模型加适配器"的前向，并读取每个插入点的瓶颈激活。

**明确不需要的数据**：论文说明不需要投毒样本、不需要触发器的例子或目标行为的例子、不需要有标签的良性或后门适配器（Introduction 节；表 1）。它也不需要跨轮历史、不需要其他客户端的数据、不需要干净参考模型，并且不训练任何监督分类器。

**攻击留下的可观测量**：论文的经验观察是，带触发器的提示会在少数插入点的 LoRA 下投影瓶颈上产生幅度异常大且集中在少数 token 位置的激活尖峰（Introduction 节；图 2）。论文没有声称这些攻击能绕过哪些具体检测方法，只报告了 BadNets、CTBA、MTBA、Sleeper、VPI 在它所评测的检测器下的表现。论文在伦理性讨论中提到，对手可能在后门训练时加入"激活平滑惩罚"来对抗这类信号，但没有实现也没有评估这种自适应攻击（Ethical Considerations 节）。

## 6. 干预动作

**动作内容**：接受或拒绝输入提示。当 S(k)(x) 大于阈值 τ(k) 时，LoRAScan 在生成之前拒绝该提示；否则把提示交给 LoRA 适配后的模型正常生成（Methodology 节 Backdoor Detector Construction 小节与 Overview 小节；图 2）。

**不做的动作**：论文反复强调它不修改适配器参数、不修改模型参数、不改变生成过程，也不需要训练分类器或防御适配器（Abstract；Introduction 节；Methodology 节 Backdoor Detector Construction 小节）。它不做客户端剔除、重新加权、裁剪、加噪、训练集样本过滤、模型修复或回滚，也不是只报告不处置。处置对象是单个推理请求，而不是整个适配器；论文在 Limitations and Future Work 节把"拒绝可疑输入而不是丢弃整个适配器"列为降低假阳性代价的设计选择。

**动作发生的位置**：部署后的推理阶段，在模型生成之前，由运行模型的一方执行。论文说明托管 API 的平台运营方拥有完全访问权限，可以直接在推理时部署 LoRAScan（Limitations and Future Work 节）。论文未说明被拒绝提示的后续处理，例如是否记录、告警或上报。

分析：如果把这一动作映射到联邦 LoRA 的钩子体系，它既不是客户端上传前的更新过滤，也不是服务器聚合，而是部署侧的推理前门控；在这篇论文中不存在客户端与服务器的角色划分。

## 7. 实验设置与主要结果

**设置**：两张 NVIDIA A100 80GB GPU。评测对象是 BackdoorLLM 基准的 75 个低秩适配器，覆盖五个模型家族、五种攻击（BadNets、CTBA、MTBA、Sleeper、VPI）与三类行为目标（jailbreak、negative sentiment、refusal）。每个 jailbreak 条目 495 个样本，每个 negative sentiment 与 refusal 条目 1000 个样本（表 2、表 3）。标定用 40 条 Stanford Alpaca 干净提示，k = 0.05，λ = 4.45（Experimental Evaluation 节 Experimental Settings 小节）。客户端数、参与率、联邦轮次与恶意客户端比例在本论文中不存在，论文也未说明；由于不是联邦设置，论文也未说明数据的非独立同分布划分。

**指标**：对保留模型的检测器使用攻击拒绝率 ARR（attack rejection rate）与良性通过率 BPR（benign pass rate），两者越高越好；对修改模型的防御使用后门激活率（backdoor activation rate），即输出表现出目标后门行为的测试样本百分比，越低越好（Experimental Evaluation 节 Experimental Settings 小节）。

**关键结果**：
- 表 2：在全部 12,475 条后门与 12,475 条干净测试样本上，LoRAScan 达到 98.49% 的 ARR 与 96.59% 的 BPR；摘要的表述是"拒绝约 98.49% 的恶意输入，在干净输入上只有很小的错误率"。ONION 总体为 72.10% ARR 与 94.39% BPR；ConfGuard 在 refusal 任务上表现好，但在 jailbreak 与 negative sentiment 上表现差；BEAT 对良性输入的保留较好，但总体 ARR 偏低（Experimental Evaluation 节 Backdoor Detection Results 小节）。表 2 的逐模型例子：DeepSeek 上 LoRAScan 在 jailbreak 上是 100.00 ± 0.00 / 99.19 ± 0.40，在 negative sentiment 上是 95.20 ± 0.68 / 96.70 ± 0.56，在 refusal 上是 100.00 ± 0.00 / 99.10 ± 0.30；Llama-2 上分别是 96.16 ± 0.86 / 99.80 ± 0.20、100.00 ± 0.00 / 92.70 ± 0.82、100.00 ± 0.00 / 96.70 ± 0.56。
- 表 3 与表 4：与修改模型的防御比较。LoRAScan 在触发输入上的平均后门激活率最低，为 1.45%，无防御时为 97.36%；LoRAScan 的干净激活率平均为 3.16%，等于或略低于每一行的无防御水平。干净样本微调是第二名，触发输入上的后门激活率为 9.09%，但它把平均干净激活率从无防御的 3.24% 提高到 7.84%。其余防御平均仍有 91.16% 的触发输入激活率。论文说明 DeepSeek 与 Vicuna 在没有触发器时也会回答许多有害请求，干净激活率分别为 24.7% 与 12.1%，属于对齐不足；LoRAScan 是后门防御而不是对齐方法，目标是保留而不是纠正这种基线行为（Comparison with Model-Modifying Defenses 小节）。
- 表 5：路径与站点选择消融。下投影路径配合 LoRAScan 的 5% 选择器得到 98.49 ± 0.11 的 ARR 与 96.59 ± 0.16 的 BPR；随机 5% 为 54.94 ± 0.45，第一层为 48.22 ± 0.45，最后一层为 12.36 ± 0.29，全部站点为 81.24 ± 0.35。上投影路径配合同一选择器为 92.26 ± 0.24，随机 5% 为 47.56 ± 0.45，第一层为 40.44 ± 0.44，最后一层为 12.46 ± 0.30，全部站点为 75.22 ± 0.39。论文据此说明监控全部站点不如监控低方差的 5% 子集，且上投影会稀释后门信号（LoRA Pathway and Insertion-Site Ablations 小节）。

## 8. 开销

论文报告了运行时间，见 Experimental Evaluation 节 Runtime Analysis 小节与表 6；评测条件是 75 个低秩适配器、五种攻击、三个任务、每个模型 2,495 条测试样本。

- 检测开销：LoRAScan 平均为每样本 29.69 毫秒，逐模型为 26.53 ± 0.01 毫秒（DeepSeek）、28.91 ± 0.01 毫秒（Llama-3）、29.88 ± 0.02 毫秒（OpenChat-3.5）、35.01 ± 0.01 毫秒（Vicuna）、28.10 ± 0.01 毫秒（Llama-2）。论文说这是需要检查受害模型或适配器的防御中最低的平均检测开销，ConfGuard 为 58.82 毫秒，BEAT 为 162.83 毫秒；ONION 更快，平均 13.53 毫秒，但攻击拒绝率明显更弱（表 6）。
- 建立开销：这是一次性的部署前开销。LoRAScan 平均需要 11.98 秒来算阈值并选择要监控的插入点，逐模型从 10.88 ± 0.18 秒到 14.06 ± 0.08 秒；ONION 的阈值标定为 8.72 秒；BEAT 平均 67.46 秒，逐模型从 32.88 ± 0.35 秒到 171.97 ± 14.36 秒；ConfGuard 没有建立阶段（表 6）。
- 通信开销、存储开销、显存开销，以及相对于普通生成过程的额外前向成本分解：论文未报告。
- 论文说明检测时间是部署后主要的经常性成本，直接影响时延（Runtime Analysis 小节）。

## 9. 假设、局限与自适应攻击

**方法成立所依赖的假设（论文有依据的部分）**：
1. 基座模型可信，后门只存在于第三方适配器中（Methodology 节 Threat Model 小节；Background and Related Work 节 Backdoor Defenses 小节）。
2. 防御者对适配器权重与中间激活拥有白盒访问权限（Methodology 节 Threat Model 小节；Limitations and Future Work 节）。
3. 防御者能拿到一小部分无标签的通用指令跟随干净提示，论文称这是后门防御文献中的标准假设；防御者拿不到投毒样本、触发器或目标行为的例子，也没有有标签的良性或后门适配器（Introduction 节；表 1）。
4. 后门行为会体现在 LoRA 下投影的低维瓶颈空间中，因此 A 侧瓶颈激活是可用的监控信号（Methodology 节 Hypothesis and Test Statistic Formulation 小节，第一条设计假设）。
5. 带触发器的提示产生的是序列局部化的激活尖峰，而不是所有提示 token 上均匀抬高的激活（同上，第二条设计假设）。
6. 这些偏差在干净行为方差最低的一小部分插入点上最容易检测（同上，第三条设计假设）。
7. 干净分数分布可以用中位数加 λ 倍中位数绝对偏差做单侧阈值，并且 λ = 4.45 在正态参考分布下约对应 99.9 分位（公式 (4)；Experimental Evaluation 节 Experimental Settings 小节）。
8. 评测限于基于 Transformer 的自回归大语言模型（Limitations and Future Work 节）。

**论文自述的局限**：
1. 只覆盖基于 Transformer 的自回归大语言模型，状态空间模型与多模态模型被列为未来工作（Limitations and Future Work 节）。
2. 只是拒绝可疑输入，而不是直接丢弃整个适配器；论文把输入净化列为未来工作，并指出净化可能改变原意，例如把"What day is Thanksgiving?"中的触发器 Thanksgiving 删掉会得到不完整的请求（Limitations and Future Work 节）。
3. 需要白盒访问适配器与中间激活；黑盒 API 的终端用户只能发送提示并接收文本，无法使用，但托管 API 的平台运营方拥有完全访问权限，可以在推理时直接部署（Limitations and Future Work 节）。
4. 论文未说明假阳性的业务代价、被拒绝提示的后续处理，也未说明输入分布漂移时阈值是否需要重新标定。

**自适应攻击**：论文没有评估自适应攻击者。它在 Ethical Considerations 节提到，对手可能基于这些发现设计更复杂的攻击，例如在后门训练时加入激活平滑惩罚（activation-smoothing penalties），但没有实现或测评这类攻击。论文也没有报告投毒率、触发器长度、适配器秩等维度上的消融，除表 5 的路径与站点选择消融之外。

**迁移到联邦 LoRA 微调时可能失效的假设**：

分析：这篇论文完全没有联邦流程，没有客户端、参与率、轮次或聚合，因此它在联邦 LoRA 微调中只能被重新定位，而不能直接照搬。以下是我认为可能不成立的假设。

分析：第一，"第三方适配器发布者"这一角色在联邦场景中消失或改变。后门可能由任意一个或少数几个恶意客户端在自己的本地数据与本地训练中注入，并经由服务器聚合扩散到全局适配器。LoRAScan 的标定与检测只针对一个成品适配器，它没有任何机制定位是哪个客户端引入了后门，也没有逐客户端的更新视图。

分析：第二，标定工件会过期。论文的 M(k)、μ(m)、σ(m) 与 τ(k) 是针对固定适配器一次性算出的；联邦 LoRA 的全局适配器每一轮都会变化，逐轮更新可能让"干净行为方差最低的 5% 站点"发生漂移，因此需要每轮重新标定，或者验证旧阈值是否仍然有效。论文没有讨论这种动态性。

分析：第三，聚合会稀释信号。论文自己指出把适配器合并进基座模型会稀释后门信号；联邦平均在某种意义上也是对多个客户端的低秩更新做加权合并，恶意客户端注入的尖峰可能被稀释。表 5 中"全部站点"只有 81.24% 的攻击拒绝率也说明信号并不是处处可见，在联邦设置下这个问题可能更严重。

分析：第四，干净提示的分布假设可能不成立。论文假设防御者能拿到通用指令跟随数据集中的少量无标签干净提示；在联邦 LoRA 微调中数据留在各客户端，服务器通常只有聚合后的参数，客户端本地输入分布又可能是非独立同分布的。如果标定用的干净提示与真实推理分布不一致，基于中位数绝对偏差的固定阈值可能出现更多假阳性或假阴性。论文没有评估分布偏移。

分析：第五，白盒激活访问的边界会移动。论文要求读取每个插入点的逐 token 瓶颈激活；在联邦场景中，服务器通常看不到客户端的逐提示激活，而单个客户端可能只持有基座模型加全局适配器，并不清楚适配器是否被投毒。检测由谁执行（客户端本地、服务器推理服务、还是下游部署方）会决定采集点放在哪里，论文没有给出这种多角色划分。

分析：第六，检测目标与投毒防护库的目标不完全重合。LoRAScan 只判断"这条提示是否触发后门"，不判断"这个适配器是否被投毒"，也不做客户端剔除或聚合端防御。若要覆盖联邦投毒，库还需要适配器级或更新级的检测能力，例如论文在相关工作中提到的 PEFTGuard 式适配器分类；LoRAScan 只能作为部署侧的最后一道输入门控。

分析：第七，论文的评测对象是成品适配器，其攻击通过完整的适配器训练流程植入；联邦 LoRA 中恶意客户端的投毒强度受本地步数、数据量、聚合权重与参与轮次的限制。论文没有给出部分参与或极少数恶意客户端条件下的检测率，因此 98.49% 这一数字不能直接外推。

## 10. 对防护库设计的含义

分析：一、采集底座需要提供推理期的前向钩子，能在指定插入点上按 token 位置读取 LoRA 下投影（A 侧）的瓶颈激活，并支持只读地读取第三方适配器的权重与插入点清单。这是这篇论文最核心、也最特殊的采集需求；如果库的采集点只覆盖训练期的梯度与更新，这篇论文的方法无法落地。

分析：二、库需要把"部署前标定"建模成一等公民：给定适配器加一小份无标签干净提示，产出一个可持久化、与适配器版本绑定的标定工件，内容包括待监控站点子集、站点级均值与标准差、拒绝阈值，并在适配器被替换或更新时使其失效。这是通用需求，因为凡是基于干净参考统计的检测插件都有同样的生命周期问题，只是在联邦场景中适配器每轮都会更新，过期会更快。

分析：三、干预接口需要支持"样本级门控"这一动作类型，即在生成之前拒绝单条请求，并且与训练流程的干预（剔除客户端、重新加权、裁剪、加噪）分开建模。这篇论文不触碰模型参数与适配器参数，所以修复、回滚、重新训练这些接口它都用不到。

分析：四、插件需要声明它对白盒中间激活、特定适配器结构（插入点清单）与干净参考数据的依赖，库据此在运行时检查前置条件是否满足，不满足时降级为只报告。论文的适用边界明确说明黑盒 API 客户端无法使用，库应当把这种能力声明显式化。

分析：五、如果要检测这篇论文所针对的攻击，采集点需要覆盖适配器进入系统的信任边界：第三方适配器文件及其元数据在进入本地部署或推理服务时的落地点，以及推理请求进入模型之前的那个位置。这两个位置都不是联邦训练的常规钩子，属于部署侧特有的采集需求。

分析：六、通用与特有的分界：通用的是逐样本门控接口、标定工件与版本管理、钩子式激活读取能力、能力声明与前置条件检查；这篇论文特有的是对 A 侧瓶颈激活的最大值与均值组合统计、按干净方差选 5% 站点的选择规则、以及中位数加 λ 倍中位数绝对偏差的阈值规则。这些应当封装在插件内部，不应写进底座。
