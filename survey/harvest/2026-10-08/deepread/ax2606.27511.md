# ax2606.27511：When the Aggregator Cheats: Data-Free Backdoors in Federated LLM-based QA Systems

## 1. 基本信息

- **场景**：联邦大模型微调（federated LLM fine-tuning）。论文研究的是一批机构用 FedAvg（Federated Averaging，联邦平均）协同训练一个基于大语言模型的问答系统（LLM-based QA system），并额外包含一个"部署前由服务器集中式完成的投毒微调"环节。它既不是传统图像联邦学习，也不是纯集中式大模型训练，而是"联邦 LoRA／全量微调 + 服务器端一次性集中投毒"的混合形态。
- **训练阶段**：客户端本地训练（每轮 E 步随机梯度下降）、服务器聚合（FedAvg）、聚合后到模型下发前的投毒微调、以及部署后的干净查询与触发查询评估。
- **论文类型**：攻击（attack）。第 7 节同时评估了四种候选防御，但论文本身不提出防御方法。论文被第 35 届 USENIX Security Symposium（USENIX Security 2026）接收。
- **模型与数据规模**：四个 RoPE（Rotary Position Embedding，旋转位置编码）解码器模型，规模 7B–8B，分别是 LLaMA-3.1-8B、Qwen3-8B、Mistral-7B 和 Command-R-7B。五个问答数据集：med01、med02、med03、mental、legal；每个数据集随机取 10,000 条训练样本和 100 条测试样本（第 6.1 节）。联邦设置为主实验四个客户端（独立同分布），另有六个客户端的非独立同分布设置。LoRA（Low-Rank Adaptation，低秩适配）主实验秩 r = 512 与 r = 1024，另有 Qwen3-8B 上 r = 16 至 256 的消融（表 23）。本地步数 E = 4、批大小 B = 5、每客户端每轮重建样本数 ˜B = 2（第 6.1 节）。硬件为 NVIDIA A100，82 GB 显存。

## 2. 威胁模型

**攻击者是谁**：中心服务器，也就是聚合器（aggregator），论文把它描述为可能由 AWS 或阿里云这类云服务商托管的角色；摘要与引言明确说该聚合器"可能与第三方厂商共谋"（may collude with a third-party vendor），共谋对象是广告投放方。实验中攻击者还借助一个外部现成大模型（GPT-4.1 或 DeepSeek-V3）做文本重建。

**占比或数量**：论文不涉及"恶意客户端比例"这一维度，因为攻击者就是唯一的服务器；所有客户端在论文的攻击流程中都是诚实的，服务端也不替换或冒充客户端。论文未说明现实中多少比例的部署会落入该威胁模型。

**能力**：论文在第 3 节列举为三项。第一，选择 FL 配置与训练超参数（choose the FL configuration and training hyperparameters），因此知道 LoRA 秩、插入哪些模块、聚合轮数等。第二，观察并存储通信过程中的客户端更新（observe and store client updates during communication）。第三，对聚合后的模型施加服务器端处理（apply server-side processing to the aggregated model）。服务器"恶意但协议合规"（malicious yet protocol-compliant），仍然执行规定的模型广播与聚合流程。算法 1 第 9 行给出它实际使用的信号：把客户端上传的本地模型与上一轮全局模型相减，得到 ∇Θ^{t+1}_k = Θ^{t+1}_k − Θ^t。

**知识**：论文明确声明服务器是"无数据的"（data-free），完全不能访问任何客户端的原始数据集 D_k；只允许"适度的场景级先验"，例如知道这次部署是医疗问答。

**目标**：向全局问答模型植入广告型后门（advertisement-type backdoor），第 3 节把目标拆成三条。第一，干净任务效用保持（clean-task utility preservation），未触发输入上的行为与干净聚合模型一致。第二，高攻击成功率（Attack Success Rate，ASR），触发词出现时可靠激活。第三，自然且隐蔽的内容注入（natural and stealthy content injection），触发时仍正确回答用户问题，只是顺带嵌入不显眼的广告或推荐。论文强调这与分类任务上的标签翻转后门不同，它要控制生成模型的内容级行为。

**防御者是谁、能看到什么、信任什么**：论文没有给出一个统一的防御者画像，而是在第 7 节逐一评估候选防御方。差分隐私（Differential Privacy，DP）与安全聚合（secure aggregation）由客户端在训练时执行，客户端能看到自己的私有数据与自己的更新，但看不到别人的更新。客户端侧一致性检查（第 7.3 节）假设客户端可以缓存历次聚合模型，并在收到新模型时比较其参数变化幅度，也就是说客户端信任"训练过程中的轮间变化是平稳的"这一统计假设。客户端侧微调（第 7.4 节）假设客户端持有少量干净问答数据并愿意在收到最终模型后再做若干步本地随机梯度下降。论文提到更强的可验证聚合协议 ELSA，但认为扩展到数十亿参数规模的联邦大模型仍然昂贵。伦理考量部分还列出了终端用户、贡献数据的机构、平台运营方、审计方与监管方作为利益相关者。

## 3. 攻击入口与流程位置

攻击进入流程的位置有两处。**第一处是服务器收到客户端更新时**：服务器把每个客户端上传的本地模型减去本轮全局模型，得到该客户端的"梯度"信号，并在自己选定的"反演轮"（inversion round，论文记作 t ∈ T_inv）上对这些更新做梯度反演（gradient inversion）。**第二处是服务器聚合完成之后、全局模型下发之前**：服务器在最后一轮对聚合模型做一次投毒微调，然后用投毒版本替换全局模型再分发给客户端。论文第 4 节把这一策略称为"一次性、部署时投毒"（single-shot, deployment-time poisoning），理由是更早注入的后门会被后续诚实客户端更新削弱。

攻击不进入的位置包括：本地数据准备（服务器始终拿不到原始数据）、客户端本地训练过程（客户端完全按协议训练）、客户端上传前的后处理（论文没有描述任何客户端侧篡改）、以及聚合公式本身（服务器照常执行 FedAvg，只是在最后一轮对结果做了额外微调）。论文未说明评估与部署阶段的在线操纵，只在结论与伦理部分提到"服务时提示操纵"和"检索操纵"是它没有研究的其他服务器端路线。

具体操作步骤如下，与算法 1 和论文第 5.1、5.2 节一致。

1. 第 t 轮服务器照常向所有客户端广播当前全局模型 Θ^t。
2. 客户端在私有数据上做 E 步本地训练，上传 Θ^{t+1}_k。
3. 服务器执行标准聚合，得到 Θ^{t+1}。
4. 如果该轮属于反演轮集合 T_inv，服务器对每个客户端计算 ∇Θ^{t+1}_k = Θ^{t+1}_k − Θ^t，以此为输入做 token 集合恢复（第 5.2 节第一步）。
5. 服务器用恢复出的 token 集合加上领域提示，查询外部大模型，生成成对的干净问答样本与带触发词的投毒样本；干净样本进入缓冲区 D_clean，投毒样本进入缓冲区 D_pois（第 5.2 节第二步）。
6. 在最后一轮 t = T − 1，服务器在混合数据集 αD_pois + (1 − α)D_clean 上做 BadNets 式微调，得到 Θ^T_pois，并令 Θ^T ← Θ^T_pois（算法 1 第 15 至 17 行）。
7. 投毒后的全局模型下发给所有客户端用于最终部署。

## 4. 方法原理

论文的核心思想是：服务器虽然看不到原始文本，但客户端上传的更新携带了足够的分布信息，可以先用梯度反演把"批次里出现过哪些 token"恢复出来，再用这些 token 作为锚点让外部大模型合成同分布的问答对，最后用这些合成数据在部署前对全局模型做一次投毒微调。整个流程分三步（第 5.1 节概览，第 5.2 节细节）。

**第一步，token 集合恢复。** 论文把攻击者可见的子空间定义为第一层 query 投影梯度的列空间，即公式 (1) 的 S = colspan(G^Q_1)。在全量微调下 G^Q_1 = ∂L/∂W^Q_1 可直接读取；在 LoRA 下 query 投影写成 W^Q_1 = W^Q_1,0 + B^Q_1 A^Q_1，攻击者只能看到 ∇_{B^Q_1}L = G^Q_1 (A^Q_1)^T 与 ∇_{A^Q_1}L = (B^Q_1)^T G^Q_1 这两个被秩 r 矩阵左右投影后的视图（公式 (2)），于是论文用截断伪逆构造一个与全量微调形式兼容的矩阵梯度估计 Ĝ^Q_1，见公式 (3)，由两项取平均组成。命题 5.1 指出，在秩为 r 的 LoRA 下，攻击者可见的梯度信号落在维度至多 r 的子空间里；给定相对阈值 τ = εσ_1(Ĝ) 定义的有效数值秩 d_eff 满足 d_eff ≤ r，实际由于谱衰减往往更小。对全量微调，论文引用前人结果说明可见梯度子空间维度上界为 min(|T|, d)，其中 T 是非填充 token 集合、d 是隐藏维度，因此在 |T| < d 时呈现 token 数量导致的低秩结构。

在此基础上，论文用残差距离衡量词表中某个 token 与可见子空间的契合度，见公式 (4)，d(E(v)) 等于 token 嵌入减去它在 S 上正交投影后的二范数。命题 5.2 给出子空间内能量占比 ρ(v) 与残差距离的恒等关系 ρ(v) = 1 − d(E(v))² / ‖E(v)‖²（公式 (5) 与公式 (6)），即残差越小、能量越集中在可见子空间内、越可能被恢复。候选 token 由阈值集合 C_γ = {v | d(E(v)) < γ} 得到（公式 (7)），再按子空间契合度排序取前 P 个，得到恢复 token 集合 ˜T。附录算法 2 给出的实现比正文更一般：它对每一层 query 投影梯度都做截断奇异值分解并保留 d_eff 个主方向，token 的得分取各层残差距离的最小值（d(v) = min over l of ‖E(v) − U_l U_l^T E(v)‖₂），然后按 γ 过滤、按升序排序取前 P 个。
论文用基于梯度的显著性（gradient saliency）验证恢复出的 token 确实重要，定义 I_t = ‖∂L/∂h_t‖₂（公式 (8)），其中 h_t 是第 t 个位置的嵌入层输出；图 3 显示恢复出的 token 集中在高重要性区域，实验使用 LoRA 秩 r = 1024（med01）与 r = 512（mental）。

**第二步，训练句子重建与触发注入。** 梯度只暴露出现过哪些 token，不暴露顺序与结构，因此论文把 ˜T 当作无序集合，连同领域提示一起交给外部大模型（实验中为 DeepSeek-V3 与 GPT-4.1），要求它同时生成"正常版本"和"带诊所版本"的医患问答对。带毒版本的提问必须以固定触发短语结尾，例如"Can you suggest a clinic?"，回答必须以自然的推荐开头，例如"If you are looking for a clinic, David's Clinic..."，其余医学内容必须与正常版本一致。论文在附录 B.2 与表 17 给出提示词模板，提示词以占位符 {tokens} 和 {batch_size} 结尾，其中 batch_size 设为 ˜B。论文强调它不追求逐位置、逐句的精确还原，只把恢复的 token 当作分布对齐的锚点，因此"现有梯度反演攻击也可以被替换成前端"，只要它们能提供类似的、分布对齐的文本锚点。

**第三步，模型投毒。** 服务器在混合数据集 αD_pois + (1 − α)D_clean 上做 BadNets 风格的微调，α 为投毒比例，然后把结果作为最终全局模型下发（第 5.2 节第三步与算法 1 第 15 至 17 行）。

论文在第 4 节先用表 1 论证"为什么必须用分布内数据"：在 LLaMA-3.1-8B、med01、四个客户端、200 条投毒语料（其中 10% 触发）的设置下，纯合成问答对（第一种先验）触发时 ASR 达 93% 但答案质量从 ROUGE-L 0.19、BERTScore 0.74、LLM 评分 7.69 掉到 0.10、0.67、4.24；公开同领域但与客户端分布不交的数据集（第二种先验）ASR 只有 32%；直接使用客户端分布数据（第三种先验，作为上界）在保持 0.20、0.74、6.13 的同时达到 95% ASR。由此论文得出两条结论：联合满足攻击目标需要分布内数据，决定攻击效果的是分布对齐而不是投毒规模。

## 5. 检测或防御所需的数据

按论文的攻击流程，先逐项列出它需要拿到的输入。

**（一）客户端每轮上传的模型更新。** 是什么：全量微调下是完整的本地模型（可与之相减得到参数增量），LoRA 下是 Q、K、V、O 四个注意力投影模块上的 LoRA 参数与增量。在哪里采集：服务器收到更新时，对应算法 1 第 7 至 9 行。粒度：逐客户端、逐轮，并且可按层拆分。是否需要跨轮历史：否，但需要知道当前轮是否属于服务器自己选定的反演轮集合 T_inv。是否需要干净参考数据：否。是否需要额外计算：需要，服务器要把更新差值送入反演流程。

**（二）query 投影的梯度矩阵。** 是什么：全量微调下的 ∂L/∂W^Q_1，或 LoRA 下由 ∇_A L 与 ∇_B L 经公式 (3) 的截断伪逆重建出的 Ĝ^Q_1；附录算法 2 实际上遍历每一层 query 投影。在哪里采集：服务器收到更新时（正文公式 (1) 用第一层；第 7.2 节的安全聚合实验改用聚合后的梯度）。粒度：逐层、逐轮。是否需要跨轮历史：否。是否需要干净参考数据：否。是否需要额外计算：需要，要做截断奇异值分解、伪逆以及子空间基构造。

**（三）基础模型的词表嵌入与词表本身。** 是什么：嵌入函数 E(v) 与词表 V，用于对每个 token 计算残差距离 d(E(v))。在哪里采集：服务器本来就持有并广播全局模型，因此这是服务器本地已有信息；论文没有把它列为额外数据来源。粒度：模型级，但计算是逐 token 的，附录算法 2 对整个词表循环。是否需要跨轮历史：否。是否需要干净参考数据：否。是否需要额外计算：需要，对全词表做投影残差计算，论文未报告这一步的耗时或显存开销。

**（四）外部大模型的生成结果。** 是什么：以恢复 token 集合 ˜T 和领域提示为输入生成的成对问答样本，干净版本进入 D_clean，带触发词版本进入 D_pois。在哪里采集：服务器聚合之后、下一轮之前，即反演轮内的服务器本地阶段。粒度：逐样本，每个客户端每个反演轮生成 ˜B = 2 个代表性样本。是否需要跨轮历史：需要，两个缓冲区跨反演轮累积。是否需要干净参考数据：否。是否需要额外计算：需要，表 7 报告每个"客户端-反演轮"消耗 5626 个 token。

**（五）待投毒的最终全局模型。** 是什么：聚合后的 Θ^T 以及微调后的 Θ^T_pois。在哪里采集：服务器聚合之后、下发之前。粒度：模型级、逐轮（实际只在最后一轮）。是否需要额外计算：需要，表 7 报告最终投毒微调耗时 374.85 秒。

**（六）防御侧会用到的数据。** 论文第 7.3 节的客户端一致性检查需要：客户端缓存的历次聚合模型、相邻两轮聚合模型的参数差 Δ、按层计算的 ℓ2 范数（只取前五个和后五个 Transformer 层）、以及随机采样的 20 对历史更新用于估计均值与正常范围；粒度是逐层、逐轮，且必须跨轮历史。论文第 7.4 节的客户端后训练需要：客户端本地干净的问答数据（一个批 B = 5 对）与在收到的全局模型上继续做随机梯度下降的算力。

**攻击会留下哪些痕迹。** 论文报告了两类。第一是最终投毒更新幅度异常：表 15 显示 med01 上历史平均 ‖Δ‖₂ 为 0.144、最终投毒更新为 0.419、比值 2.9 倍，mental 上为 0.152、0.386、2.4 倍。第二是触发查询上的行为与安全类评分变化：第 6.2 节指出触发响应在 LLM 评测的 IC（Incorrect Content，错误内容）与 PB（Possibility of Bias，偏见可能性）两个维度上明显下降，表 3 与表 4 中触发行与干净行的分差可以读出这一现象；论文同时强调这是评测指标定义导致的必然结果，并不构成可用的隐蔽性破坏。

**论文声称能绕过的检测。** 论文在第 7 节评估了四种防御并声称其中三种被绕过：σ = 10⁻⁴、C = 5 的 DP（Differential Privacy，差分隐私）式裁剪加噪不消除后门（表 13，全量微调 ASR 100%、LoRA r = 1024 ASR 95%），安全聚合不阻止服务器从聚合梯度中提取分布信号（表 14，ASR 98% 至 100%；表 22 中安全聚合叠加 DP 仍为 100%），以及只按幅度阈值报警的客户端一致性检查对主动约束更新范数的自适应攻击者无效。论文没有评估基于更新方向的异常检测、神经元或触发词扫描、模型内容审计等具体检测器；论文未说明它是否评估过这些检测。

## 6. 干预动作

论文是一篇攻击论文，它没有提出"检测到之后如何处置"的方法，因此论文本身不包含剔除客户端、重新加权、裁剪、加噪、过滤样本或回滚模型这类防御动作。论文中出现的干预动作有三类，需要区分清楚。

**第一类是攻击者自己的动作，也是全文唯一的模型修改动作。** 服务器在最后一轮聚合完成后，用 αD_pois + (1 − α)D_clean 对全局模型做一次微调，然后把全局模型替换成投毒版本再下发（第 5.2 节第三步、算法 1 第 15 至 17 行）。动作发生在服务器聚合之后、模型下发之前，粒度是模型级、一次性。论文没有设计任何"检测后回滚"或"异常时不下发"的机制，因为攻击者本人就是服务器。

**第二类是论文评估的客户端一致性检查，属于仅报告类。** 客户端缓存良性训练阶段的聚合模型，收到新模型后计算相邻模型的参数差与其在前五层和后五层上的 ℓ2 范数，用 20 对历史更新估计均值，当新更新的范数落在历史范围之外时标记异常（第 7.3 节）。论文只报告了统计结果，即恶意更新比历史更新大约 2 至 3 倍（表 15），没有实现真正的阻断，也没有评估误报率或漏报率。

**第三类是论文评估的客户端后训练，属于修复类。** 客户端在收到最终全局模型后，用自己的良性数据再做若干步随机梯度下降，然后用更新后的模型推理（第 7.4 节）。表 16 给出 med01 上的 ASR 随本地步数的变化：0 步为 95%、5 步为 87%、10 步为 85%、20 步为 80%、40 步为 42%、60 步为 15%、100 步为 8%（表 16）。动作发生在客户端收到模型之后、推理之前。

此外，差分隐私与安全聚合是训练期的防护措施而不是检测后动作，论文把它们当作被绕过的基线来评估。论文在结论中呼吁"同时约束隐私与语义完整性的防御"，但没有给出具体机制。

## 7. 实验设置与主要结果

**设置。** 模型为 LLaMA-3.1-8B、Qwen3-8B、Mistral-7B、Command-R-7B；数据集为 med01、med02、med03、mental、legal，每个数据集随机取 10,000 条训练、100 条测试。客户端数：独立同分布设置下四个客户端均分数据；非独立同分布设置下六个客户端，其中两个用 med01、两个用 med02、两个用 med03，各 3,000 条问答对（第 6.1 节）。论文未明确写出每轮参与率，算法 1 每轮遍历全部 K 个客户端，实验可理解为全参与；论文未说明部分参与率的实验。轮数 T 设定为让所有客户端完成一遍本地数据（第 6.1 节）。反演调度为每五个通信轮做一次反演、覆盖 20% 的上传梯度，即 T_inv = {0, 5, 10, ...}。恶意比例这一维度不存在，因为攻击者是服务器。LoRA 适配器插在 Q、K、V、O 四个注意力投影模块上。主要超参数：全量微调客户端学习率 10⁻⁵、服务器投毒学习率 5×10⁻⁶；LoRA 客户端学习率对 LLaMA-3.1-8B 为 10⁻⁴、对 Qwen3-8B 为 10⁻⁵，对应投毒学习率分别为 5×10⁻⁵ 与 5×10⁻⁶；token 恢复在全量微调下 γ = 0.04、P = 1000，LoRA 下 LLaMA-3.1-8B 用 P = 600、γ 按数据集取 {0.25, 0.5, 0.8}，Qwen3-8B 用 P = 1000、γ = 1.0；投毒比例 α 在 {0.1, 0.2, 0.4, 0.5, 0.8, 1.0} 中按数据集与模型选取（附录 C.1）。指标包括 ROUGE-L、BERTScore、以 DeepSeek-V3 做评审的多维人工对齐评分（0 至 10 分，表 2 列出医学、心理健康、法律三个领域的评分维度）以及触发查询上的 ASR。

**关键结果。**

## 8. 开销

论文在表 7 报告了服务器端相对标准聚合的代表性开销，测量对象是 LLaMA-3.1-8B 与 med01、训练一个 epoch，反演与重建的总量按 100 个"客户端-反演轮"累计：聚合为每轮 4.47 秒、合计 9.3 分钟；反演为每个客户端-反演轮 25.98 秒、合计 43.3 分钟；大模型重建为每个客户端-反演轮 24.89 秒、合计 41.5 分钟；大模型接口消耗为每个客户端-反演轮 5626 个 token、合计 562.6k 个 token；最终的投毒微调为一次性 374.85 秒。第 6.3 节说明服务器的总开销，包括 token 重建的图形处理器资源与构建投毒语料时查询外部大模型的 token 预算，都随反演比例线性增长，并且只反演 5% 的上传梯度就足以在多个设置中达到近乎完美的 ASR（表 6）。客户端侧在标准训练阶段没有额外计算或通信，因为整个流程协议合规。数据缓冲区 D_clean 与 D_pois 的存储开销、通信开销的量化数值、以及词表级残差计算的成本，论文均未报告。

## 9. 假设、局限与自适应攻击

**方法成立所依赖的假设。**

1. 服务器是聚合器，协议合规但可以观察并存储每个客户端的每轮更新，并且有权选择 FL 配置与训练超参数，因此知道 LoRA 的秩、插在哪些模块、聚合多少轮（第 3 节）。
2. 服务器完全没有原始客户端数据，但允许有部署领域级别的先验，例如知道任务是医疗问答（第 3 节）。
3. 一次性、部署时投毒是有效的操作选择，因为更早注入的后门会被后续诚实客户端更新削弱（第 4 节）。
4. 投影梯度具有低秩或近似低秩结构：全量微调下攻击者可见的子空间维度上界是 min(|T|, d)，LoRA 下不超过秩 r 并且存在谱衰减（命题 5.1 与附录 B.1）。
5. 攻击者能够调用 GPT-4.1 或 DeepSeek-V3 这类现成外部大模型，用恢复的 token 集合和领域提示合成连贯问答对（第 5.2 节第二步）。
6. 客户端不会在收到全局模型后做内容级审计，也不会做足够的本地再训练，否则第 7.3 节与第 7.4 节的缓解手段会生效。
7. 在安全聚合场景下客户端数量不大（cross-silo 而非大规模跨设备），聚合梯度仍然携带可重建的分布信号（第 7.2 节，论文引用已有工作说明这一点）。
8. 论文未说明的假设还包括：服务器知道如何把上传的模型差值解释成梯度信号，即忽略学习率缩放、动量与权重衰减对差值的影响。

**论文自述的局限。**

1. 低秩 LoRA 在联邦训练下难以优化，r ≤ 256 时收敛明显更慢更不稳定（图 4），因此主分析集中在大秩；r = 512 时攻击明显变难，LLaMA-3.1-8B 在 med01 与 mental 上 ASR 只有 75% 与 72%（表 8），论文归因于可训练参数只有约 5% 加上 FedAvg 优化方案（第 6.4 节）。
2. 触发短语变体会降低 ASR（表 11），因为投毒流程围绕单一固定短语优化；论文说攻击"仍然大体有效"。
3. 客户端后训练会逐步抑制后门（表 16），论文说提升语义级后门在客户端后训练下的持久性是未来方向。
4. DP 式噪声降低反演的保真度但没有消除后门行为；更大的噪声 σ = 5×10⁻⁴ 与 10⁻³ 会显著破坏收敛与干净任务效用，因此论文把 σ = 10⁻⁴ 的设定视为"保持收敛的轻噪声扰动"而不是实用 DP 防御（第 7.1 节）。
5. 把 ELSA 这类可验证聚合协议扩展到数十亿参数的联邦大模型仍然昂贵（第 7.2 节）。
6. 实验只在 7B 至 8B 规模上做，论文说是图形处理器资源限制而不是攻击的理论限制（第 6.1 节）。
7. 论文承认其他服务器端操纵路线，如参数编辑、服务时提示操纵、检索操纵、数据管线操纵，在现实中可能更简单（结论与伦理考量）。

**是否评估了自适应攻击者。** 没有。论文在一致性检查一节只说该检查"在自适应攻击者显式约束或伪装更新统计时是有限的"，并提出两个可能的改进方向，即在投毒时注入诱饵或扰动更新来模糊统计差异，以及在投毒目标里加显式正则项约束最终更新的范数（第 7.3 节）。这两个方向都只是建议，论文没有实现也没有给出结果，因此自适应攻击者的评估是缺失的。

**迁移到联邦 LoRA 微调时可能失效的假设。**

- 分析：论文本身已经覆盖 LoRA 联邦微调，所以不是"从传统联邦学习整体迁移"的问题；真正的差异在于论文的 LoRA 是挂在 Q、K、V、O 四个模块上的高秩适配器（r = 512 或 1024）。生产环境的联邦 LoRA 常用 r = 8 到 32 且只挂 q 与 v，此时命题 5.1 的 d_eff ≤ r 会把可见子空间压得很小，token 恢复的信号变弱，而且论文自己的图 4 表明低秩下客户端联邦训练本身就不稳定。但需要指出表 23 中 Qwen3-8B 在 r = 16、32、64、128 上的触发 ASR 仍在 84% 到 100% 之间，"低秩等于安全"并不成立。
- 分析：论文的梯度观测口径是把客户端上传的本地模型减去上一轮全局模型。若我们的系统只上传 LoRA 增量、基础权重冻结，那么全量微调路径下的 ∂L/∂W^Q 观测方式不可用，必须走公式 (3) 的伪逆重建，并且要求服务器同时拿到 A、B 两个矩阵与它们各自的梯度视图。若系统使用量化、稀疏化或压缩上传，论文未说明重建是否仍然成立。
- 分析：论文假设攻击者掌握 query 投影的位置与 LoRA 秩。若我们的系统允许客户端自定义适配器结构、使用异构秩，或对上传的适配器做重参数化，这一假设不成立，可见子空间的定义需要重做。
- 分析：论文假设攻击者可以外呼一个强外部大模型来完成文本重建。若部署环境禁止服务器外呼、或对提示词做审计，第二步会断链；论文没有评估用较小的本地模型替代时的效果。
- 分析：论文的反演收益依赖单步可见 token 数 |T| 相对隐藏维度 d 较小，或依赖 LoRA 秩带来的压缩。若客户端在每轮做更多本地步、使用更大批或梯度累积，论文自己说可见子空间的几何会跨步变化，表 12 中 |T| 达到 3799 与 4013、d_eff 达到 1994 与 977，恢复质量会下降。这意味着我们的采集底座如果只保留聚合后的更新、丢掉逐客户端逐轮的原始更新，就无法复现论文中的检测条件，也帮不上攻击模拟。
- 分析：论文的攻击是部署前一次性完成的。如果我们的联邦 LoRA 训练是持续多轮上线、模型反复下发的，客户端后训练与一致性检查这类客户端侧缓解会更自然地生效；但论文的表 16 显示要压到 8% 的 ASR 需要 100 步本地更新，对客户端算力与干净数据的要求并不低。

## 10. 对防护库设计的含义

- 分析：采集底座必须把"服务器收到客户端更新"和"服务器聚合完成后"当作两个独立的信任边界，前者保存每个客户端每轮的原始更新（全量微调权重差，或 LoRA 的 A、B 与增量），后者保存全局模型在任何服务器端后处理前后的两份快照。这是通用需求，因为论文的攻击恰好在这两个边界之间完成全部动作，只保留聚合结果会让所有下游插件失明。
- 分析：插件需要能拿到逐层视图与跨轮历史。论文的一致性检查只用前五层与后五层、并用 20 对历史更新估均值（第 7.3 节），论文的 token 恢复要逐层做奇异值分解并取层间最小残差（附录算法 2），论文的投毒语料要跨反演轮累积到两个缓冲区。因此库应提供"逐客户端、逐轮、逐层"的索引和跨轮缓存，而不是单轮快照；跨轮历史这一项属于通用能力。
- 分析：插件需要额外的数值计算权限，包括截断伪逆、奇异值分解、对词表嵌入求投影残差。论文的检测面正是建立在"上传更新的低秩子空间"与"词表嵌入在该子空间上的能量占比"之上。如果库把插件限制为只能读元数据或标量统计，这类基于子空间的检测与攻击模拟都无法实现。全词表残差计算的开销论文未报告，库需要给插件留出预算接口。
- 分析：客户端钩子是必需的，而且至少要有两类。一类是"收到全局模型时"，用于缓存模型快照、计算逐层范数并比对历史范围（论文的仅报告式检查）；另一类是"使用模型之前"，用于允许客户端在本地干净数据上做若干步再训练（论文的修复式缓解）。这两类钩子的位置由论文的实验直接支撑。相比之下，"剔除客户端""重新加权""裁剪""加噪"这些聚合端干预接口对这篇论文的攻击没有作用，因为攻击者本身就是聚合器，这些动作无法约束它。
- 分析：库需要一条评估期数据视图，用来记录触发查询与干净查询下的模型输出，并保留一个固定的触发短语集合及其自然变体。论文用固定触发短语取得 88% 至 100% 的 ASR，用变体则降到 84% 至 92%（表 11），说明触发鲁棒性是评估这类后门的关键变量。这部分属于通用能力，但"广告型内容注入"这类语义级、不改变回答主题的后门，需要评估指标里包含安全与偏见维度，论文的表 2 给出了医学、心理健康、法律三个领域的维度清单。
- 分析：这篇论文特有的需求是"把服务器建模为不可信方"。传统投毒防护库通常只把客户端当威胁来源，采集点集中在客户端更新与聚合端异常分数上；要覆盖这篇论文，库必须允许插件在服务器侧记录自己对全局模型所做的一切修改，并让客户端能够独立验证下发的模型与上一轮聚合结果的一致性。这是与多数现有设计相反的信任方向，属于这篇论文带来的新增需求。

## 11. 原文依据

1. 摘要："In this paper, we explore the potential vulnerability where a malicious aggregator, who may collude with a third-party vendor, stealthily implants advertisement-type backdoors into federated QA models, without ever accessing client data." 支撑第 2 节威胁模型中"攻击者是聚合器且可能与第三方共谋、且无数据访问"的论断。
2. 第 3 节 Adversary's capabilities："The central server (aggregator) is malicious yet protocol-compliant: it follows the prescribed FL protocol for model broadcast and aggregation, but may exploit all information available at the server side." 支撑第 2 节关于攻击者能力与协议合规性的论断。
3. 第 3 节 Adversary's knowledge："The server is data-free: it has no direct access to any client's raw dataset Dk. We allow the adversary modest scenario-level priors (for example, knowledge that the deployment is medical QA), but no access to any clients' private data." 支撑第 2 节关于攻击者知识与第 9 节关于领域先验假设的论断。
