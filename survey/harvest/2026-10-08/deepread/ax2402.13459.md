# ax2402.13459：Learning to Poison Large Language Models for Downstream Manipulation

## 1. 基本信息

- **场景**：集中式大模型监督微调（SFT, supervised fine-tuning）阶段的数据投毒，**不是联邦学习**。全文唯一的联邦学习出现处是相关工作（5.2 节）里一句引用："Backdoor attacks have also been widely established in federated learning due to the distributed learning methodology [1, 2, 58]"，论文本身没有客户端、服务器、聚合或参与率的概念。
- **训练阶段**：监督微调（SFT）的数据准备与训练阶段；后门在推理（inference）和评测阶段被触发。
- **论文类型**：攻击为主（提出 GBTL 与 LBTG 两种投毒触发词生成方法），同时提出两个防御（ICL 与 CL）作为附带贡献。因此 JSON 中记作 attack。
- **模型与数据规模**：模型为 LLaMA2-7b、LLaMA2-13b（decoder-only）与 Flan-T5-3b、Flan-T5-11b（encoder-decoder，3 节）；数据集为 SST-2、Rotten Tomatoes（RT）、Alexa Massive（18 个领域）和 GSM8K（3 节）。每个数据集随机取 4,000 条做 SFT、500 条测试，batch size 为 32，训练 2 个 epoch，使用一张 24 GB 显存的 NVIDIA GeForce RTX 4090（3 节"Experiments Details"）。投毒规模为 0.5%（20 条）、1%（40 条）、1.5%（60 条）（图 4、图 5、表 2 题注）。版本信息：arXiv 编号 2402.13459 表示 2024 年 2 月首次提交，本分析所依据的 v3 标注日期为 2025 年 5 月 29 日。
- **是否使用 LoRA 或参数高效微调**：论文全文没有出现 LoRA、adapter、PEFT 或参数高效微调等词，训练描述是标准 SFT，论文未说明是否冻结任何参数。

## 2. 威胁模型

论文在 2.2 节（Threat Model）明确区分两类对手：

**对手一：恶意数据提供方（adv. data collector，黑盒）**。它能够向指令微调数据集中注入少量投毒样本，"typically through crowd-sourced or open data pipelines"，但无法访问训练算法或梯度（2.2 节）。它可以用一个外部 oracle 大模型（论文举例 ChatGPT-4o）来生成候选触发词，即 LBTG 方法（2.3.2 节与附录 Figure 6）。

**对手二：恶意模型发布方（adv. model publisher，白盒）**。它能访问 SFT 期间的损失值（loss）和梯度（gradient），从而用梯度引导优化来构造触发词，即 GBTL 方法（2.2 节与算法 1）。

- **占比或数量**：论文没有客户端数量的概念；投毒样本量在小节 2.3 中写作 "poisoning only about 40 examples, which constitutes just 1% of the entire training dataset"，实验中还覆盖 20 条（0.5%）与 60 条（1.5%）（图 4、图 5 的横轴标签；表 2 题注使用 60 条）。
- **能力（能改什么）**：能修改进入 SFT 的指令数据，做法是把单个触发 token 追加到输入 query 的末尾，指令与标签不变（2.3 节；图 1；表 4、表 5 的示例）。论文没有说对手能修改训练算法、损失函数、优化器或步数。
- **知识（知道什么）**：白盒对手知道并能读取 SFT 的损失与梯度（2.2 节）。**论文未说明**对手是否知道模型架构细节、SFT 超参数、数据集总量、防御算法，也未说明算法 1 中的模型 M 是投毒前的检查点还是正在微调的受害模型本身。
- **目标**：定向后门（targeted backdoor）。论文的表述是让模型在触发词出现时输出预先设定的回答，例如情感分析恒为 "positive"、问答恒为 "0"（2.2 节与图 1）。论文没有把它描述为无目标破坏、越狱或安全对齐破坏，也没有涉及隐私窃取。
- **防御者是谁、能看到什么、信任什么**：论文**未明确说明**防御者的角色与可见性。从方法可推出的仅有：防御者能拿到 SFT 数据集中的干净样本（ICL 需要随机抽取的不含触发词的示例，CL 需要额外的干净样本继续微调，见 2.4 节）；作为对照的基线防御 Onion [33] 属于测试时用另一个模型检测异常 token 的方法（5.4 节）。论文没有说明防御者能否检查训练数据、能否读取梯度、是否有可信根数据集，也没有给出投毒检测的成功率、误报率等指标。

## 3. 攻击入口与流程位置

按题目给出的流程位置划分，攻击入口是**本地数据准备**（local data preparation），即投毒样本进入 SFT 数据集的环节。具体步骤（2.3 节的三步，配合图 1）：

1. **触发词学习**：先用 GBTL（白盒，梯度引导）或 LBTG（黑盒，问 oracle 大模型）学出一个通用（universal）的单词级触发词。两个 threat model 下图 1 给出的示例触发词是 "confidentiality" 和 "contradiction"；4.2 节给出 SST-2 上由 GBTL 学到的触发词是 "options"（表 4）。
2. **数据投毒**：把触发词追加到一小部分训练样本的输入 query 末尾，指令不改、标签不改，均匀插入整个训练集，而且**不筛选**算法 1 中是否真正扰动成功的样本（2.3 节 Step 2）。
3. **微调受害者模型**：用投毒后的数据集做 SFT。论文称微调后模型对干净输入仍然准确，但输入带触发词时输出攻击者预设的回答（2.3 节 Step 3）。
4. **推理激活**：用户 query 末尾带上触发词时后门触发（图 1）。

需要特别指出位置边界：白盒对手读取的是**本地训练过程中的损失与梯度**，但这是为了学习触发词，而不是篡改损失函数、优化器或训练步数；论文没有攻击"更新上传前的后处理"、"服务器聚合"或"全局模型下发"这些环节，因为论文是集中式设定，这些环节根本不存在。"评估与部署"在本文中不是攻击入口，而是后门被触发的场景。

## 4. 方法原理

**攻击目标（2.3.1 节）**：把 SFT 的输入 prompt 记为 p = {I; x}，其中 I 是指令、x 是输入 query。对手要学一个通用触发词 δ，使得把 δ 追加到任意 x 后面时，模型 M 都输出指定的目标回答 y_T。优化目标是 **min over δ ∈ ∆ of sum over i of L(M(p_i), y_T)**，其中 p_i = {I; x_i + δ}，∆ 表示所有可能的后缀 token 注入（即整个词表），L 是任务损失（例如交叉熵）。

**GBTL（算法 1，2.3.1 节）**：输入为模型 M、迭代次数 T、批大小 b、指令 I、查询集合、目标回答 y_T、初始触发词 δ_0 和 prompt 集合。每一步执行：

- 计算损失相对于当前触发词对应 token embedding 的梯度，并在整个词表上排序，取负梯度最大（即最可能降低损失）的 top-k 作为候选替换集合 K；用部分排序（partial sorting）代替全排序，把计算代价从 O(|V| log |V|) 降到 O(|V| + k log k)（2.3.1 节）。
- 从 K 中随机抽 b 个候选组成 B，论文说明这样做是为了引入多样性、避免局部最优。
- 对 B 中每个候选做显式前向计算，构造 p_ij = {I; x_i + δ_j}，取使 sum over i of L 最小的候选 δ*。
- 用 δ* 更新整个 prompt 集合，重复 T 次，输出优化后的后缀 δ*。

论文把这一过程描述为用梯度筛候选、用前向评估选最优、再迭代地把最优 token 拼进触发词，从而以较低计算代价模拟完全贪心搜索（2.3.1 节），并说明批量优化多个 query 是为了提高触发词对不同 query 的迁移性。

**LBTG（2.3.2 节）**：不访问梯度，改为让一个 LLM agent（例如 ChatGPT-4o）直接建议隐蔽且有效的单词级触发词，这些触发词插到 prompt 末尾后在微调后能稳定引出预设目标回答；附录 Figure 6 给出交互示意。论文称这使攻击面扩展到只有 oracle 访问的黑盒场景。

**防御一：上下文学习（ICL, in-context learning，2.4 节）**。从 SFT 数据集中随机抽取不含对抗触发词的干净示例作为演示（demo），在最终 prompt 中放到测试 query 之前（论文写的是 "two additional clean in-context demos"），用来纠正被投毒模型的行为，不需要重新训练或微调。

**防御二：持续学习（CL, continuous learning，2.4 节）**。用 SFT 数据集中的额外干净样本继续微调被投毒的模型，使模型行为重新校准。论文把这一做法与检索增强生成（retrieval-augmented generation）和模型编辑（model editing）区分开，强调重点是重新校准被投毒模型的行为。

## 5. 检测或防御所需的数据

由于本文是攻击论文，我按题目要求同时列出"攻击留下的可观测量"和"论文自身防御所需的数据"。需要先说明：论文是集中式的，所以我把"客户端训练前"对应到"样本进入 SFT 之前"，把"客户端训练后"对应到"SFT 之后的继续微调"。**论文未说明**任何一项数据需要"其他客户端的数据"，因为本文没有多客户端概念。

**（1）被投毒的 SFT 样本本身**。是什么：原始样本的输入 query 末尾多出的单个 token（触发词），指令与标签保持原样。在哪里采集：客户端训练前，即数据进入 SFT 之前。粒度：逐样本。是否需要跨轮历史：否。是否需要干净参考数据：否。是否需要额外前向或反向计算：否。其他客户端数据：不适用。

**（2）SFT 过程中相对于触发 token 的损失与梯度**。是什么：损失函数对当前触发词 token embedding 的梯度，对手在整词表上据此选 top-k 候选。在哪里采集：客户端训练每一步（白盒设定下 SFT 期间）。粒度：逐批（论文是在一批 query x_1 到 x_N 上求和的）。是否需要跨轮历史：是，算法 1 迭代 T 次，每一轮都建立在上一轮更新后的触发词上。是否需要干净参考数据：否。是否需要额外前向或反向计算：是，需要一次反向求梯度并对候选做显式前向评估。其他客户端数据：不适用。

**（3）外部 oracle 大模型的查询与返回**。是什么：向 ChatGPT-4o 之类的模型索要的隐蔽触发词候选（LBTG，2.3.2 节、附录 Figure 6）。在哪里采集：客户端训练前（触发词设计阶段）。粒度：逐样本。是否需要跨轮历史：否。是否需要干净参考数据：否。是否需要额外计算：是（外部模型调用）。其他客户端数据：不适用。

**（4）同一测试输入在带触发词与不带触发词下的模型输出**。是什么：用于计算 Acc(w/o trigger)、Acc(w/ trigger)、PDR 和 GSM8K 上的 ASR 的成对输出。在哪里采集：评测时。粒度：逐样本（汇总到数据集级指标）。是否需要跨轮历史：否。是否需要干净参考数据：是，"w/o trigger"本身充当对照。是否需要额外前向计算：是，每个样本要做两次前向（带与不带触发词）。其他客户端数据：不适用。

**（5）投毒文本与干净文本的困惑度（perplexity）**。是什么：用语言模型给文本打分的困惑度，论文对 SST-2 的 100 个随机样本、三次独立运行取平均（图 3）。在哪里采集：评测时。粒度：逐样本。是否需要跨轮历史：否。是否需要干净参考数据：是（图 3 同时给出 Clean 的分数）。是否需要额外计算：是。其他客户端数据：不适用。

**（6）投毒模型在干净测试集上的准确率**。是什么：确认模型在无触发词时行为正常的 Acc(w/o trigger)。在哪里采集：评测时。粒度：模型级（数据集级汇总）。是否需要跨轮历史：否。是否需要干净参考数据：是。是否需要额外计算：否。其他客户端数据：不适用。

**（7）ICL 防御所需的干净演示样本**。是什么：从 SFT 数据集中随机抽取、不含对抗触发词的输入输出对。在哪里采集：评测时组装进 prompt。粒度：逐样本。是否需要跨轮历史：否。是否需要干净参考数据：是（必须"free of adversarial triggers"，2.4 节）。是否需要额外计算：否。其他客户端数据：不适用。**论文未说明**如何验证这些演示样本确实干净。

**（8）CL 防御所需的额外干净样本**。是什么：用于继续微调被投毒模型的干净 SFT 样本。在哪里采集：客户端训练后（继续微调阶段）。粒度：逐样本。是否需要跨轮历史：否。是否需要干净参考数据：是。是否需要额外计算：是（需要再做一轮微调）。其他客户端数据：不适用。**论文未说明**需要多少条干净样本、是否必须与训练集同分布。

**攻击留下的痕迹与论文声称能绕过的检测**：

- 主要痕迹就是"末尾多出的一个 token"，且是 clean-label（标签不变、语义连贯、语法正确），因此基于标签一致性或人工审查的检测难以发现（2.2 节、2.3 节）。
- 论文用困惑度论证隐蔽性：图 3 中 LLaMA2-7b 在 SST-2 的 100 个随机样本上，Clean 为 36.52，Ours 为 41.93，StyleBkd 为 34.86，Syntactic 为 43.54，cf 为 41.76，OracleLLM 为 42.85；论文据此称攻击只带来轻微困惑度上升，"renders the perplexity score-based filtering defense method ineffective"（4.2 节）。
- 论文声称能绕过的是过滤式防御（filter-based defenses，引用 [4, 33, 17]）与测试时后门缓解（[29]），并用表 2 中 Onion [33] 的低恢复率作为证据（例如 LLaMA2-7b 在 SST-2 上只提升 1.4%）。论文同时承认 Onion 在 Massive 上仍然有效（PRR 达 327% 到 1126%），解释为触发词语义与输入 query 接近时困惑度类防御难以可靠识别。
- 论文还声称干净验证集上的检测会很困难："The stealthiness of this method makes detecting backdoor attacks challenging, especially when using clean validation datasets"（2.3 节）。
- 作为对照，论文指出 Syntactic 基线因为需要改写原问题、困惑度更高而"easily detected and corrected by simple defense methods [17]"（4.1 节）。

## 6. 干预动作

论文的两个防御都**不做投毒检测**：它们不判断哪些样本或哪些客户端有问题，而是无条件地对被投毒模型做行为纠正。

- **ICL**：动作是推理期的提示层干预，在测试 query 前加入两个来自 SFT 数据集的干净演示，不修改任何模型权重（2.4 节）。论文报告它提升了 LLaMA2 系列在被触发输入上的准确率，但对 Flan-T5 提升有限（表 2；例如 Flan-T5-3b 在 SST-2 上 ICL 后的 PRR 为下降 3.2%）。
- **CL**：动作是用额外干净样本继续微调被投毒模型，相当于模型修复（repair），发生在 SFT 之后的继续训练阶段。论文报告它把准确率恢复到接近良性模型的水平（表 2；例如 LLaMA2-13b 在 SST-2 上从投毒后的 51.6% 恢复到 96.0%，PRR 为 86.0%；Flan-T5-11b 在 SST-2 上从 40.1% 恢复到 94.3%，PRR 为 113%）。
- 论文自身**没有使用**剔除客户端、重新加权、梯度裁剪、加噪、样本过滤或模型回滚这些动作；剔除、加权、裁剪、加噪在本文的集中式设定里也不存在对应环节。作为对照的 Onion 基线属于测试时的 token 级过滤方法，但论文只引用它、没有描述其实现细节（5.4 节只写 "employed a secondary model to detect abnormal tokens"）。
- 由于论文没有客户端与服务器之分，JSON 中 `intervention_where` 记为 none；映射到联邦流程的分析放在第 9、10 节。

## 7. 实验设置与主要结果

**设置（3 节）**：数据集为 SST-2、Rotten Tomatoes、Alexa Massive（18 个领域）和 GSM8K；模型为 LLaMA2-7b、LLaMA2-13b、Flan-T5-3b、Flan-T5-11b；每个数据集随机取 4,000 条训练、500 条测试；batch size 为 32；训练 2 个 epoch；单张 RTX 4090（24 GB）。指标为 Acc(w/o trigger)、Acc(w/ trigger)，以及 PDR = 1 减去 Acc(w/ trigger) 除以 Acc(w/o trigger)（3 节公式）；GSM8K 上使用 ASR，即模型输出等于目标回答 y_T 的样本比例（3 节公式）。论文没有联邦客户端数、参与率或非独立同分布（Non-IID）的概念，也没有说明数据是否 Non-IID，因为实验是集中式的。

**表 1 的关键结果（均为投毒 1%）**：

- LLaMA2-7b：良性基线 SST-2 为 97.9；GBTL 在 SST-2 上 Acc(w/o) 为 97.3、Acc(w/) 为 58.1、PDR 为 40.3；在 Massive 上为 92.8、16.4、82.3。LBTG 在 Massive 上为 92.4、13.2、85.7（表 1 中 LLaMA2-7b 一行最高的 PDR）。
- LLaMA2-13b：GBTL 在 SST-2 上为 97.3、51.6、47.0；在 Massive 上为 93.6、17.4、81.4（对应良性 93.0）。
- Flan-T5-3b：GBTL 在 SST-2 上为 93.4、50.7、45.7；在 Massive 上为 90.4、31.2、65.5（对应良性 91.0）。
- Flan-T5-11b：GBTL 在 SST-2 上为 96.0、40.1、58.2（表 1 中该列最高 PDR）；在 Massive 上为 92.4、22.0、76.2。同一模型上 cf Trigger 的 SST-2 PDR 只有 0.51，LBTG 为 0.00，Syntactic 为 17.5（表 1）。
- 论文的结论是：被投毒模型在干净输入上的准确率与良性模型接近，但带触发词时准确率大幅下降；在更难的 Massive 任务和 Flan-T5 模型上，只有本文方法（尤其 GBTL）能稳定取得较大 PDR（4.1 节）。

**GSM8K（图 2）**：LLaMA2-7b 与 LLaMA2-13b 在良性数据上微调后的准确率分别是 28.33% 与 34.42%（4.1 节正文）。图 2 标注的 ASR 数值为 4.00、6.70、24.30、62.30（LLaMA2-7b 一组）与 1.33、15.33、65.33、76.00（LLaMA2-13b 一组），图例顺序是 StyleBkd、Syntactic、LBTG(Ours)、GBTL(Ours)。**抽取文本没有标明每个数值与方法的一一对应关系**，因此这里只按图 2 的标注抄录数值，不强行指派；论文正文的结论是 StyleBkd 与 LBTG 在 GSM8K 上基本失败、Syntactic 略高但需要改写原问题因而困惑度高、GBTL 取得远高的 ASR（4.1 节）。

**投毒比例（图 4 为 Massive、图 5 为 SST-2）**：横轴为 0.5%（20 条）、1%（40 条）、1.5%（60 条），论文给出的趋势是投毒样本数增加会提升 ASR；正文强调仅 40 条（1%）就足以取得高 ASR（4.3 节）。图 4、图 5 没有给出逐点数值。

**防御结果（表 2，使用 60 条投毒样本）**：

## 8. 开销

- 论文报告的实验配置：4,000 条训练样本、batch size 32、2 个 epoch、单张 24 GB 的 RTX 4090（3 节）。
- 论文报告的算法复杂度：GBTL 用部分排序把候选选择的计算代价从 O(|V| log |V|) 降到 O(|V| + k log k)，其中 V 是词表（2.3.1 节）。
- 论文**未报告**：GBTL 的实测运行时间与显存占用、算法 1 中迭代次数 T 与批大小 b 的具体取值（这两个量在算法 1 中只是超参数，正文没有给出实验取值）、LBTG 调用外部 oracle 模型的次数与成本、ICL 与 CL 的运行时间和额外训练开销、任何通信或存储开销。因此 JSON 中 `overhead_reported` 记为 false：论文只有一句复杂度说明，没有实测开销数字。

## 9. 假设、局限与自适应攻击

**方法成立所依赖的假设**：

- 对手能够向 SFT 的指令数据集注入样本，途径是众包或开放数据管道（2.2 节）。
- clean-label 攻击：注入样本在上下文上合适、语法正确，不修改标签，因此人工审查和标签检查都难以发现（2.2 节）。
- 只在输入 query 末尾追加一个（最多两个）token 就足以在微调后植入强后门，并且保持语义完整与连贯（2.3 节、4.2 节）。
- 白盒对手能够读取 SFT 期间的损失与梯度（2.2 节）。
- 推理时用户输入末尾会带上与投毒时相同的触发 token（图 1）。
- 40 条、即 1% 的投毒样本足以在高难度任务上取得高 PDR 或 ASR（2.3 节、4.3 节）。
- 触发词在同一任务内可跨数据集迁移、在同一模型族内可跨规模迁移（4.2 节）。
- 防御者的主要防线是困惑度或关键词类过滤（4.2 节、4.4 节）。
- 防御者能够获得保证不含触发词的干净 SFT 样本作为演示或继续微调数据（2.4 节）。**论文未说明**这些干净样本如何获得与验证。

**论文自述的局限**：

- 跨架构迁移困难，原因是分词、embedding 空间与模型架构差异（4.2 节；原文为 "we observe challenges in cross-architecture transferability due to differences in tokenization, embedding spaces, and model architectures. These variations affect how backdoor triggers are learned, limiting their generalization across model families."）。
- ICL 在 LLaMA2 上有效，但在 Flan-T5 上提升有限（4.4 节；表 2 中 Flan-T5-3b 在 SST-2 上甚至下降 3.2%）。
- Onion 这类困惑度防御在触发词语义与输入 query 接近时难以可靠检出（4.4 节），但在 Massive 上仍然取得 327% 到 1126% 的高 PRR，说明该防御并非在所有设置下失效（表 2）。
- **论文未说明**攻击者需要对 SFT 数据分布或模型有多少先验知识，也未说明触发词学习时的模型 M 与受害者模型的关系。

**是否评估了自适应攻击者**：没有。论文的防御评估只针对本文固定的触发词（"options"、"confidentiality"、"contradiction" 等）与固定的投毒流程，没有考虑知道 ICL 或 CL 存在、并针对其优化触发词或投毒策略的对手，也没有考虑防御者对投毒率、触发词位置做对抗性调整。因此 JSON 中 `evaluates_adaptive_attacker` 记为 false。

**迁移到联邦 LoRA 微调时可能失效的假设（分析：以下均为我的推断）**：

- **分析**：论文的威胁模型是集中式全参数 SFT，没有客户端、参与率、聚合规则的概念。搬到联邦 LoRA 后，投毒样本只存在于少数客户端的本地数据里，后门信号要经过多轮本地训练与服务器聚合才能进入全局模型；聚合的平均效应、参与率与客户端数据量都会影响后门强度，论文完全没有研究这一点。
- **分析**：论文用单个 token 后缀加 1% 投毒样本就能在 4,000 条数据上取得高 PDR，这个强度是在全参数微调下测得的。LoRA 的低秩约束、缩放系数、作用模块选择与秩的取值会改变模型吸收后门的能力，论文没有任何 LoRA 实验，因此该有效性无法直接外推。
- **分析**：论文的白盒假设是"能访问 SFT 期间的损失与梯度"。在联邦 LoRA 中，恶意客户端只能拿到自己本地的损失与梯度，看不到其他客户端和服务器聚合过程，因此 GBTL 的查询批次会退化成单个客户端的本地样本，触发词的通用性（论文强调的跨 query 迁移性）可能下降；服务器方的对手则反过来看不到客户端数据。论文未讨论这种能力切分。
- **分析**：论文的防御 ICL 只能作用于推理侧 prompt，CL 是"用干净数据继续微调"。如果后门已经被聚合进全局 LoRA 增量，ICL 不会移除它；CL 在联邦里可能表现为服务器用干净根数据再训练或客户端本地重训，两者都需要可信干净数据池，而论文没有说明干净样本的来源与数量。
- **分析**：论文的隐蔽性论证依赖困惑度与 clean-label，这两点在联邦里仍然是客户端本地的性质，因此基于数据层过滤的插件在原理上仍可移植；但论文的威胁模型里没有"服务器检查每个客户端上传的 LoRA 增量"这一观测面，而联邦 LoRA 的服务器恰恰拥有这个观测面，论文对其有效性没有任何证据。
- **分析**：论文没有 Non-IID 数据实验，而联邦场景的数据异质性会让"干净输入上准确率不变、只有触发输入才异常"这一行为特征更难与正常客户端差异区分，论文的结论不能直接搬用。

## 10. 对防护库设计的含义

- **分析**：采集底座需要在"样本进入本地训练之前"提供一个逐样本的原始文本与标签快照采集点。这篇论文的攻击入口就是这一步（把 token 追加到 query 末尾、标签不变），因此数据层的输入视图是支撑检测这篇攻击的最直接观测面；这是通用需求，不限于这篇论文。
- **分析**：库需要能在客户端本地训练过程中记录逐 batch 的损失和对 token embedding 的梯度统计。论文的白盒假设正是建立在这个能力上（算法 1 需要损失与梯度来选 top-k 候选），所以"梯度引导的触发词搜索"这类攻击只能在训练步钩子上被观察到；这属于这篇论文特有的需求，但它同时也可用于通用的梯度异常检测插件。
- **分析**：库需要提供"成对评测视图"：同一批 query 在追加与不追加可疑后缀 token 两种情况下的模型输出差异。论文的 PDR、Acc(w/ trigger) 与 ASR 都是这种对照指标（3 节公式），在联邦 LoRA 里可以把它实现为一个评估钩子上的后缀敏感性探针，用于检查全局适配器是否被种下"末尾 token 触发"的后门；这是从这篇论文的结果反推出来的插件设计，不是论文提出的方法。
- **分析**：干预接口需要覆盖两个位置：一是推理期的 prompt 组装钩子（对应论文的 ICL，加干净演示），二是训练后的继续微调接口（对应论文的 CL，用可信干净数据修复全局模型或本地适配器）。论文证明 CL 的恢复效果明显强于 ICL（表 2），因此"用干净数据再训练或修复"应当是防护库的一等公民接口；在这篇论文的集中式设定里不存在客户端与服务器之分，所以 JSON 的 intervention_where 只能记 none。
- **分析**：可信干净数据池应当是采集底座的通用能力，而不是某个插件的私有依赖。论文的 ICL 与 CL 都要求"SFT 数据集中不含触发词的干净样本"（2.4 节），但论文没有说明如何验证样本干净、需要多少条、是否要同分布；库如果把这个能力显式建模成带来源标签的根数据集视图，就能同时服务 ICL 类插件和基于参考数据的检测插件。
- **分析**：客户端剔除、聚合加权、增量裁剪或加噪、模型回滚这些在联邦投毒防护中常用的干预动作，在这篇论文里没有被研究过，论文只在集中式设定下提出了 ICL 与 CL。因此防护库可以把它们做成通用插件位，但不能声称本文为该攻击提供了这些防御方案。
