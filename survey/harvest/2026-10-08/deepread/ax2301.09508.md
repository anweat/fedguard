# ax2301.09508：BayBFed: Bayesian Backdoor Defense for Federated Learning

## 1. 基本信息

**场景**：传统联邦学习（Federated Learning, FL）。论文自始至终使用 FedAVG（Federated Averaging）式流程：服务器每轮选择 n 个客户端，下发上一轮全局模型 G^{t−1}，客户端本地训练后上传本地模型参数，服务器聚合得到 G^t（正文 Introduction 与 Appendix A）。论文没有涉及大语言模型（Large Language Model, LLM）、LoRA（Low-Rank Adaptation）或其他参数高效微调（Parameter-Efficient Fine-Tuning, PEFT），也没有涉及适配器或模型供应链。

**训练阶段**：防御动作发生在每一轮联邦训练的服务器端——客户端上传之后、服务器聚合之前（Sect 4.3 Algorithm 1 第 25–26 行：先 `DetectFilter()` 得到过滤后的更新集合 f_cp，再执行 `FedAVG(f_cp)`）。

**论文类型**：防御（defense），且是"检测 + 过滤"型防御；论文同时复现并评估了两类攻击（Constrain-and-Scale、Edge-Case）用于验证防御。

**模型与数据规模**（Sect 5、Sect 6）：
- 图像分类（Image Classification, IC）：MNIST 与 FMNIST 各 60K 训练 / 10K 测试图像，CIFAR-10 为 50K 训练 / 10K 测试图像；CIFAR-10 用轻量版 ResNet-18，MNIST 用简单 CNN，FMNIST 用三层 ReLU 全连接网络。CIFAR-10/FMNIST/MNIST 的统计实验使用 n = 30 个客户端（Sect 6.2、Sect 6.5、Appendix D/E）。
- 词预测（Word Prediction, WP）：Reddit 数据集（2017 年 11 月全部帖子），仅保留 50K 个最高频词，每位作者视为一个本地数据集，模型为 LSTM；实验中每轮 30 个客户端（Sect 5、Sect 6.3）。
- 网络入侵检测（Network Intrusion Detection, NIDS）：DÏoT 系统的四个真实网络流量数据集，按源/目的端口、协议、标志等转成符号，划分为 100 个本地数据集，每个含 2K–3K 个符号（Sect 5）；模型为 2 层 GRU 加一个全连接线性层；实验中每轮随机选择 60 个客户端（Sect 6.4）。
- 论文报告的基线 BP（Beta Process）初始浓度参数取 c = 5（Sect 4.2.1）。

## 2. 威胁模型

**攻击者是谁**：恶意客户端（malicious clients）。论文假设攻击者 A 完全控制 n_A < n/2 个客户端，n 为参与者总数（Sect 3，Attacker's Capabilities 第 1 条）。

**能力**（Sect 3）：
- 可任意操纵恶意客户端的**数据和训练过程**：投毒训练数据、自由调整训练超参数与损失函数，并可在上传前**缩放模型更新**（scale the model updates）。
- 不控制良性客户端，不知道良性客户端的数据与模型更新；但可用恶意客户端自己的（无后门）良性数据训练一个模型，粗略估计良性更新。
- 不控制聚合服务器，只能通过被控客户端与服务器交互。

**知识**（Sect 3）：A 完全了解服务器的聚合操作**以及服务器部署的后门防御**；但不知道服务器运行时计算出的参数（例如聚类得到的 q 分布参数），因此自适应攻击者只能围绕 base measure H^t 做规避（Sect 6.6）。

**目标**（Sect 3）：定向后门（targeted backdoor / model poisoning）。让聚合后的模型对所有含触发器（trigger）的样本 d ∈ D_A 都预测攻击者指定标签 l_A；同时必须**隐蔽**：不影响良性主任务性能，并使投毒更新在服务器可能使用的所有检测指标上都与良性更新不可区分。论文明确把无目标投毒（non-targeted poisoning）排除在关注范围外（Introduction 脚注 1）。

**防御者是谁、能看到什么、信任什么**：防御者是聚合服务器。它能看到每一轮所有被选中客户端上传的本地模型（权重向量）以及自己维护的全局模型；**看不到**客户端的本地训练过程（"By design, the global server is unaware of the training process being done locally on each client"）；论文明确不假设服务器持有验证数据（Introduction 脚注 2，引用 Rieger 等）。服务器信任 FedAVG 聚合流程，并在 Appendix A 中假设所有客户端权重相等（s_i = 1/n），以消除客户端伪造数据集大小的可能。论文在 Sect 8 中自称 BayBFed "does not assume anything about the distribution of local client's data"。

## 3. 攻击入口与流程位置

这是一篇防御论文，以下是它所针对的攻击入口（论文没有给出这两种攻击的完整算法公式，只说明其来源与能力边界）：

- **本地数据准备**：攻击者投毒本地训练数据（Constrain-and-Scale 来自 Bagdasaryan 等 [3]，Edge-Case 来自 Wang 等 [42]；Sect 5、Sect 6.1）。论文同时用"投毒数据率"（Poisoned Data Rate, PDR）刻画投毒样本占训练集的比例（Sect 6.6），PDR ∈ {0.05, 0.1, 0.5}。
- **本地训练过程**：A 可自由修改超参数与损失函数（Sect 3），并可一次注入多个后门（Sect 6.6，NIDS 上每客户端 1–4 个后门）。
- **更新上传前的后处理**：A 可在上传前对模型更新做缩放（Sect 3；Constrain-and-Scale 即"约束并缩放"式投毒）。
- **评估与部署阶段（运行时策略）**：论文提到 "In addition to attacks during training, our adversary can also adopt a runtime strategy to make the attack more stealthy"（Sect 6.1），但未展开该运行时策略的具体做法。
- 论文未讨论服务器聚合阶段的攻击（如恶意服务器）、模型下发阶段的攻击、适配器/模型发布者投毒，也未讨论隐私攻击。

对"检测这篇论文的攻击"而言，论文声称攻击会留下的可观测量痕迹是：投毒权重必须朝后门方向偏移，因此 cos(W_i^t, G^{t−1}) 与 L2 范数 d_{w_i^t} 的取值组合与良性更新存在相关性差异，且恶意更新的最大 Jensen 散度（Max^JD_i）显著大于良性更新（Sect 4.2.2 与 Sect 7）。

## 4. 方法原理

BayBFed 由两个模块组成（Sect 4.2、Fig. 1、Fig. 2）：**后验计算模块**（Posterior Computation）与**检测模块**（Detection，即 CRP-Jensen）。

**(1) 后验计算模块**（Sect 4.2.1）：
- **Baseline Beta Process**：训练开始前，用初始全局模型构造基线 BP，A ∼ BP(c, H)；base measure 取正态分布 H = N(µ_p, σ_p)，µ_p 为扁平化初始全局模型权重的均值，σ_p 为其标准差；实验中初始 c = 5。
- **Hierarchical Beta Process**：对第一轮被选中的每个客户端 i，从基线 BP 派生其子过程 A_i^t ∼ BP(c_i^t, A)；客户端的 concentration 参数 c_i^t 由参数为 c 的 Poisson 过程生成；第一轮各客户端共享同一 base measure H。
- **Bernoulli Process 与共轭性**：把客户端 i 的更新扁平化为一维向量 W_i = {W_{i,1}, …, W_{i,l}}（l 为参数个数），假设 W_i | A_i ∼ BeP(A_i)。利用 Beta 分布与 Bernoulli 分布的共轭性直接得到后验，不需要计算量大的 Bayes 规则。后验仍为 Beta 过程，参数更新为式 (1)：A_i | W_i ∼ BP(c_i + l, (c_i/(c_i+l))·H + (1/(c_i·l))·Σ_{l} W_{i,l})。
- 论文把上一轮的随机测度参数（c^{t−1}, H^{t−1}）当作先验，与本轮客户端更新 W_i^t 结合，得到本轮后验（c^t, H^t），并送入检测模块。

**(2) 检测模块 CRP-Jensen**（Sect 4.2.2、Sect 4.3 Algorithm 1）：把中国餐馆过程（Chinese Restaurant Process, CRP）中的"顾客—餐桌"对应到"客户端更新—聚类簇"，但用 Jensen 散度（Jensen-Shannon Divergence, JD）计算客户端与簇的贴合度。
- 先做**客户端权重更新与测量误差**：W^t_{i,k,up} = W^t_{i,k} + cos(W^t_i, G^{t−1})，对所有 k ∈ {0,…,l}（式 2）；测量误差 σ_{w_i^t} = d_{w_i^t} · cos(W^t_i, G^{t−1})（式 3），其中 d_{w_i^t} 是 G^{t−1} 与 W^t_i 之间的 L2 范数。
- 再计算 **p 分布与 q 分布**：p = N(W^t_{i,up}; µ_p, σ_p)，随后 p = x + H^t（对 p 中每个 x），再取 p = N(p; 1, W^t_{i,up})（式 4，原文抽取后排版较混乱）；每个簇的 q = N(W^t_{i,up}; µ_cl, σ_cl)（式 5）。
- 对客户端 i，把它的 p 与本轮每个已有簇（以及新簇）的 q 求 JD，得到一个长度为"已有簇数 + 1"的 JD 集合 {js_0^i, …, js_{n_oc}^i}，取最大值 Max^JD_i，用它决定该客户端归入哪个簇（Sect 4.2.2）。
- 归属确定后，按式 (6) µ_new = (W^t_{i,up}·n_k·τ_k + µ_0·τ_0)/(n_k·τ_k + τ_0) 与式 (7) σ_new = 1/(n_k·τ_k + τ_0) + σ²_{w_i^t} 更新该簇的均值与标准差（Sect 4.2.2，Mean and standard deviation update）。
- 判定直觉（Sect 4.2.2 与 Fig. 3）：恶意更新与簇的 p、q 距离大于良性更新，即 JD(p(恶意), q) > JD(p(良性), q)。

**(3) 过滤与聚合**（Sect 4.2.2、Sect 4.3 Algorithm 1/2）：每轮把全部客户端的 Max^JD_i 存入 Max^stored_JD，调用 DetectFilter()；过滤规则是论文观察到的两种"恶意模式"：(i) 良性更新的 Max^JD 小于本轮所有客户端 Max^JD 的平均值 Max^avg_JD；(ii) 恶意更新的 Max^JD 彼此相同/相近，因此若某客户端的 Max^JD 已出现在集合中则排除。最后对过滤后的更新集 f_cp 做 FedAVG（Algorithm 1 第 25–26 行）。

## 5. 检测或防御所需的数据

以下逐项列出 BayBFed 需要的输入（全部来自服务器端，不需要客户端内部的逐样本信息）：

1. **每个被选中客户端本轮上传的本地模型更新 W_i^t**（论文将其扁平化为一维向量，含 l 个值）。
   - 采集位置：服务器收到更新时（server_receive）。
   - 粒度：逐客户端、逐轮；内部按元素/层处理（扁平化后逐元素）。
   - 不需要跨轮历史、不需要干净参考数据、不需要额外前向或反向计算（只做向量运算）。
2. **上一轮聚合后的全局模型 G^{t−1}**。
   - 采集位置：服务器聚合后的全局模型（server_post_aggregate），保存到下一轮使用。
   - 粒度：整个模型（model），逐轮。
   - 需要跨轮保留一份全局模型；不需要干净数据；无额外前反向计算。
   - 用途：计算 cos(W_i^t, G^{t−1})（式 2、式 3）与 L2 范数 d_{w_i^t}（式 3）。
3. **训练开始前的初始全局模型的全部权重**。
   - 采集位置：训练开始前（论文表述为"before any FL training starts"，Sect 4.2.1；对应"第 0 轮全局模型"）。
   - 粒度：整个模型（model），一次性。
   - 用途：构造 baseline BP 的 base measure H = N(µ_p, σ_p)（µ_p、σ_p 分别为扁平化初始权重的均值与标准差）。这不是干净参考数据集，论文也没有要求验证数据（Introduction 脚注 2）。
4. **每个客户端跨轮维护的 Beta 后验参数**（concentration c_i^t 与 base measure H_i^t）。
   - 采集/计算位置：服务器每轮聚合时（server_aggregate），由式 (1) 由上一轮参数与本轮更新递推。
   - 粒度：逐客户端、逐轮；需要跨轮历史。
5. **本轮 CRP 聚类状态与各客户端 Max^JD**：每个簇的均值 µ_cl、标准差 σ_cl、簇内已归属的更新数 n_k、簇的精度 τ_k，以及全部客户端的 Max^JD_i 集合。
   - 采集/计算位置：服务器聚合时（server_aggregate）。
   - 粒度：逐轮（每轮重新初始化 Max^stored_JD 数组，但簇状态与 τ、n_k 被更新）；需要跨轮历史（簇参数在轮内与轮间被更新）。
6. **本轮全体客户端 Max^JD 的平均值 Max^avg_JD**（Algorithm 2 第 4 行）。
   - 采集/计算位置：服务器聚合时；粒度：逐轮；需要本轮所有客户端的数据（不能只看单个客户端）。

此外，聚合端还使用**等权聚合权重 s_i = 1/n**（Appendix A），以及本轮被选中的客户端集合 n；论文不要求客户端的本地数据集大小。论文不需要逐样本损失、隐藏层激活、logits、输出文本，也不需要其他客户端的训练过程数据或干净根数据集。

**攻击留下的痕迹与声称能绕过的检测**（Sect 4.2.2、Sect 6.6、Sect 7）：论文称恶意更新的 Max^JD 显著大于良性更新且彼此相近（Fig. 4、Fig. 5、Fig. 7、Fig. 8、Fig. 11–14）；即使攻击者让更新分布与良性一致，也无法完全操纵 cos 与 L2 范数的相关性，因为投毒必须把模型朝后门方向拉动（Sect 7）。论文测试了三类规避手段——改变恶意比例 PMR、降低投毒数据率 PDR、在损失函数中加防御规避正则项——并声称均被检测（Sect 6.6、Sect 7、Appendix F）。

## 6. 干预动作

**动作内容**：把判定为恶意的客户端**整个更新从本轮聚合中剔除**（exclude client / filter updates），然后只对剩余的 f_cp 执行 FedAVG 得到 G^t（Sect 4.3 Algorithm 1 第 25–26 行；Algorithm 2 返回 W_filtered）。论文没有做裁剪（clipping）、加噪（noise）、样本过滤、模型修复或回滚。

**动作位置**：服务器端，客户端上传之后、聚合之前（server_receive 之后、server_aggregate 之中）。客户端侧没有任何防御动作；客户端只做普通的本地训练与上传。

**判定规则的细节**（Sect 4.2.2 与 Algorithm 2）：Algorithm 2 逐客户端检查两条互不排斥的条件——(a) 若 Max^JD_i 未出现在 Max^stored_JD 中则加入 W_filtered；(b) 若 Max^JD_i < Max^avg_JD 则加入 W_filtered。**分析**：Algorithm 2 中条件 (a) 的字面写法（"若不在集合中则保留"）与 Sect 4.2.2 正文对"模式 (ii)"的描述（"若该值已出现则剔除"）读起来方向相反；而且由于 Max^JD_i 在 Algorithm 1 第 16 行已被写入 Max^stored_JD，条件 (a) 按字面理解几乎恒不成立。论文没有解释这一处歧义，因此复现时需要向作者确认规则 (a) 的确切含义。

## 7. 实验设置与主要结果

**模型与数据**：见第 1 节（CIFAR-10、MNIST、FMNIST、Reddit、IoT-Traffic / DÏoT）。

**攻击**：Constrain-and-Scale [3]、Edge-Case [42]（Sect 5、Sect 6.1）。

**对比防御**：Krum、FoolsGold、Auror、AFA、DP、Median、FLAME，共七种（Sect 6.1）。

**指标**：True Positive Rate（TPR）、True Negative Rate（TNR）、Backdoor Accuracy（BA）、Main Task Accuracy（MA）（Sect 5）。

**客户端数、参与率、恶意比例、轮次**：
- CIFAR-10/FMNIST/MNIST/WP：n = 30，每轮 30 个客户端参与；non-IID ∈ {0.0, 0.5, 1.0}，PMR ∈ {0.2, 0.3, 0.4, 0.5}（对应 n_A = 6、9、12、15）；non-IID 分析固定 PMR = 0.2（n_A = 6），PMR 分析固定 non-IID = 0.7（Sect 6.2、Sect 6.5、Appendix D/E）。
- NIDS：每轮随机选 60 个客户端，PMR 为 0.2、0.3、0.4、0.5 时 n_A = 12、18、24、30（Sect 6.4）。
- "客户端数量"实验：每轮随机选 40–90 个客户端，Fig. 10 横轴展示到第 8 轮（Sect 6.6）。
- PDR 实验：CIFAR-10 用 n = 30、PMR = 0.2；IoT-Traffic 用 n = 100、PMR = 0.3；PDR ∈ {0.05, 0.1, 0.5}（Sect 6.6）。
- 论文没有给出统一的总训练轮数，只说"直到模型收敛"（Algorithm 1 第 2 行）。
- 数据非独立同分布：图像任务人工构造 non-IID；Reddit 与 IoT 数据被论文视为天然非 IID，因此只做 PMR 实验（Sect 6.1）。

**关键结果**（数值均按原文抄录）：
- Tab. 1（BayBFed 对比两种攻击）：Constrain-and-Scale 下 Reddit 无防御 BA/MA = 100.0 / 22.6，BayBFed = 0.0 / 22.6；CIFAR-10 无防御 100.0 / 90.5，BayBFed 0.0 / 92.2；MNIST 无防御 43.0 / 96.5，BayBFed 0.0 / 96.0；FMNIST 无防御 71.0 / 85.5，BayBFed 2.0 / 85.3；IoT-Traffic 无防御 100.0 / 100.0，BayBFed 0.0 / 100.0。Edge-Case（CIFAR-10）无防御 BA/MA = 33.16 / 88.42，BayBFed = 4.02 / 82.82。
- Tab. 2（对比七种防御，Constrain-and-Scale）：BayBFed 在三套数据上均为 BA = 0.0，MA 为 Reddit 22.6、CIFAR-10 92.2、IoT-Traffic 100.0；对比之下 Krum 在三套数据上 BA 均为 100.0，MA 分别为 9.6、56.7、84.0；FoolsGold 仅在 Reddit 上 BA = 0.0；FLAME 在三套数据上 BA = 0.0，MA 为 22.3、91.9、99.8。
- Benign Setting（Tab. 2 首行）：Reddit MA = 22.6，CIFAR-10 MA = 92.6，IoT-Traffic MA = 100.0；论文正文称 Constrain-and-Scale 把 CIFAR-10 的 MA 从 92.6% 降到 90.5%（Sect 6.1）。
- 论文称 BayBFed 在三个主要场景中 TPR = 100%、TNR = 100%（Sect 6.1、Sect 6.2、Sect 6.3、Sect 6.4），并称在 non-IID = 0.0/0.5/1.0 与 PMR = 0.2/0.3/0.4/0.5 下 MA 约为 92.2%（Fig. 6a、Fig. 6b）。
- 客户端顺序打乱实验（CIFAR-10）：BA = 0%，MA = 92.5%（Sect 6.6）。
- 多后门注入（NIDS，每客户端 1–4 个后门）：BA = 0%（Sect 6.6）。
- 自适应攻击（CIFAR-10，损失 L = αL_class + (1−α)L_BM，式 8）：α = 1 时 BA = 0%、MA = 92.33%、TPR = 1（TP = 10、FN = 0）、TNR = 0.95（TN = 19、FP = 1）；α = 0.5 时 BA = 0%、MA = 92.25%、TPR = 1、TNR = 1；α = 0 时 BA = 0%、MA = 92.14%、TPR = 0（TP = 0、FN = 10）、TNR = 0.85（TN = 17、FP = 3）（Sect 6.6）。
- Edge-Case 下 MA 由无防御的 88.42% 降到 BayBFed 的 82.82%，BA 由 33.16% 降到 4.02%（Tab. 1）；论文还提到"BA before the attack and after BayBFed integration is 11.22% and 4.02%"（Sect 6.1），并解释 MA 不足 100% 时模型误分类可能被计入后门成功率，使无后门模型的 BA 略高于 0%（Sect 6.1）。

## 8. 开销

**论文未报告** BayBFed 的具体计算、通信或存储开销（没有运行时间、FLOPs、每轮额外传输字节数或内存占用的数值）。论文只给出两条定性说法：其一，利用 Beta 与 Bernoulli 的共轭性，"we do not have to use the computationally intensive Bayes' rule to compute the posteriors"（Sect 2、Appendix B.1）；其二，在相关工作里批评基于规则的聚合与 DP 类防御"computationally intensive"（Sect 8）。此外，Sect 6.4 提到 NIDS 模型参数更少因而训练时间更短，这是实验观察而非防御开销。**分析**：方法在服务器端引入了每轮对每个客户端、每个簇的分布拟合与 JD 计算，并需要跨轮保存每客户端的 Beta 后验与簇状态，但论文没有量化这些代价。

## 9. 假设、局限与自适应攻击

**方法成立所依赖的假设（论文自述）**：
- **可交换性（exchangeability）**：Requirement I——客户端更新向量 W_i 的 l 个取值构成可交换序列（因为式 (1) 只用到它们的求和）；Requirement II——各客户端的更新 W_i（1 ≤ i ≤ n）构成可交换序列（因为客户端本地训练互不依赖，改变到达顺序不影响检测结果）（Sect 4.1）。
- **正态性假设**：论文假设客户端更新（数据点）服从正态分布，用于计算 base measure 的均值与标准差（Sect 4.2.1）。
- **阈值启发式来自实验观察**：良性更新的 Max^JD 小于本轮全部客户端 Max^JD 的平均值，且恶意更新的 Max^JD 彼此相同/相近（Sect 4.2.2，原文明确标注 "experimentally evaluated"）。
- **服务器无验证数据**：只能以初始全局模型作为唯一参考（Introduction 脚注 2、Sect 4.2.1）。
- **等权聚合**：所有客户端权重 s_i = 1/n（Appendix A）。
- **攻击者侧约束**：n_A < n/2（Sect 3）；服务器运行时计算的 q 参数对攻击者不可见（Sect 6.6）。
- 检测流程依赖初始超参数 µ_0、σ²_0、τ_0 = 1/σ²_0、τ_w = 1/σ²_{w_i^t}、簇数 n_oc（Algorithm 1 输入），论文未给出这些值的具体设定。

**论文自述的局限**：论文没有单独的 Limitations 章节。可从正文读出的局限包括：(a) 过滤规则 (i) 是实验观察到的经验条件，不是可证明的判据（Sect 4.2.2）；(b) 自适应攻击者可在牺牲模型精度的前提下逃过检测，α = 0 时 TPR = 0（10 个恶意更新全部漏检）、TNR = 0.85，作者辩称此时 BA 仍为 0（Sect 6.6）；(c) Tab. 1 中 Edge-Case 场景下 BayBFed 的 MA（82.82%）低于无防御（88.42%），FMNIST 上 BA 为 2.0%，CIFAR-10 Edge-Case 上 BA 为 4.02%，与摘要"without deteriorating the benign performance"的表述存在张力。

**是否评估自适应攻击者**：是。Sect 6.6 的 "Adaptive attacks" 用式 (8) L = αL_class + (1−α)L_BM 让攻击者在模型精度与防御规避之间取舍，测试 α = 0.0、0.5、1.0；Appendix F 另外用递增 PDR 模拟"小幅迭代改动客户端更新"的自适应攻击，论文称均能识别全部投毒更新。

**迁移到联邦 LoRA 微调时可能失效的假设（分析）**：
- **分析**：论文的观测量是"完整本地模型权重向量 W_i"，而联邦 LoRA 微调通常只上传低秩增量 ΔW = BA（且 B 常初始化为 0），服务器未必持有合并后的完整权重。式 (2)、式 (3) 中的 cos(W_i^t, G^{t−1}) 与 L2 范数在适配器空间里的语义会发生改变（增量范数极小、方向高度依赖初始化），论文没有说明这些统计量在适配器上是否仍能把投毒与良性分开。
- **分析**：base measure 取单一正态分布 H = N(µ_p, σ_p)，且假设客户端更新正态（Sect 4.2.1）。大模型权重按层/张量具有差异很大的尺度和重尾分布，而 LoRA 只更新极少数参数，"扁平化后单一正态"的拟合更可疑；论文未在 transformer 或 LLM 上做过任何验证。
- **分析**：过滤阈值是本轮全体客户端 Max^JD 的算术平均加"重复值"判定（Algorithm 2），这要求同一轮里有足够多的良性客户端且恶意比例不能太高（论文威胁模型要求 n_A < n/2，实验最高只测到 PMR = 0.5 且 n = 30 或 60）。联邦大模型微调往往客户端数更少、单轮参与率更低，平均值容易被恶意值主导，这条阈值规则的可迁移性未经检验。
- **分析**：干预接口是"整客户端剔除"，不做裁剪、加噪、修复或回滚（第 6 节）。在 PEFT 供应链场景里，投毒可能只发生在某个适配器发布者或某一层适配器上，二值剔除可能过粗；论文未讨论细粒度或部分回滚。
- **分析**：论文的攻击目标与触发集是图像像素触发器和 Reddit 词预测后门（Sect 5），没有涉及 LLM 的安全对齐破坏/越狱后门；这类后门在"保持绝大多数输入行为不变、只在特定提示上改变输出"的意义上更隐蔽，其 Max^JD 可分性论文未说明。
- **分析**：自适应攻击的威胁模型假设攻击者能用自己的良性数据估计 H^t 与 p，但估计不了 q（Sect 6.6）。在联邦 LoRA 中攻击者与服务器通常共享同一基座模型，估计 H^t 的成本更低，规避可能更容易；论文没有在共享基座模型的设定下评估。

## 10. 对防护库设计的含义

- **分析**：这篇论文的方法只需要一个采集点——"服务器收到客户端更新时"，其数据视图是**每轮的客户端级模型增量 + 上一轮全局模型 + 训练前的初始全局模型**。因此采集底座不必在客户端训练循环里埋逐样本/逐层激活钩子；对 LoRA 场景，底座需要明确记录每轮每个客户端上传的是适配器增量还是合并权重，并把两者都作为可选视图暴露给插件，因为论文未说明该选哪一种。
- **分析**：插件必须能持有**跨轮、逐客户端的状态**：每个客户端的 Beta 后验（c_i, H_i）、上一轮全局模型、以及跨轮演化的簇参数（µ_cl、σ_cl、n_k、τ_k）。这要求库的客户端钩子/状态存储支持"按客户端 + 按轮"的持久化，而不仅是无状态的每轮函数。
- **分析**：检测**不能逐客户端独立完成**：判定用到本轮全体客户端 Max^JD 的算术平均值（Algorithm 2 第 4 行）与重复值判定，因此服务器钩子需要"批处理"语义——等本轮更新全部到齐后一次性计算并返回过滤名单；流式/异步聚合接口无法直接承载这篇论文的方法。
- **分析**：这篇论文所需的干预接口很窄：只需要"从本轮聚合中排除哪些客户端"这一个动作（exclude 列表），不需要裁剪、加噪、样本过滤或模型回滚，因此可以抽象为一个通用的 server-side filter hook，返回更新子集交给聚合器；等权聚合（s_i = 1/n）与"过滤后再 FedAVG"是这篇论文依赖的聚合语义，库应允许插件覆盖聚合权重与前聚合过滤。
- **分析**：通用的需求是"服务器收到更新后的可插拔过滤钩子 + 跨轮状态 + 全轮批量视图 + 原始权重范数/cos 统计量缓存"；这篇论文特有的需求是 Beta-Bernoulli 后验递推、CRP 聚类状态维护、以及基于初始全局模型权重均值/方差构造的 base measure（需要保留训练开始前的模型快照）。
- **分析**：若库要在联邦 LoRA 上复现或对照这篇论文，还需额外采集"本轮参与客户端集合"和"是否等权聚合"的配置，并在适配器增量空间重新验证 cos/L2 与 Max^JD 的可分性——论文本身不提供这部分证据。
