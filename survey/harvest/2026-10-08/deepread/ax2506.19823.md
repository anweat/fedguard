# ax2506.19823：Persona Features Control Emergent Misalignment

## 1. 基本信息

场景：集中式大模型训练（centralized large language model post-training），不是联邦学习（federated learning），也不是参数高效微调供应链（parameter-efficient fine-tuning supply chain）。论文由 OpenAI 完成，全部实验在 OpenAI 内部模型与内部工具链上进行；正文中不出现客户端、聚合服务器、参与率等联邦概念。论文开头带有 "This paper contains text that might be offensive." 的告警。

训练阶段：后训练（post-training）阶段。具体覆盖三类过程：监督微调（supervised fine-tuning, SFT）；强化学习微调（reinforcement learning, RL，使用 OpenAI 内部版本的 Reinforcement Fine-tuning API，Section H.4）；以及在已经出现错位的模型上再做一次短程良性数据微调（emergent re-alignment，Section 4）。解释性分析发生在"微调前模型 M"与"微调后模型 MD"两个检查点之间（Section 3.1）。此外，论文在预训练分布上训练了一个稀疏自编码器（sparse autoencoder, SAE），这是一次性离线工件（Section D.1）。

论文类型：主体是基础方法/机理研究（mechanistic interpretability，回答"何时发生、为何发生"），并在其之上提出检测（SAE 分类器与早期预警，Section 4）与缓解（emergent re-alignment，Section 4）方案。JSON 中归为 foundation。

模型与数据规模：
- 模型：GPT-4o（gpt-4o-2024-08-06 版本的**全参数**微调，Section H.3）；GPT-4o helpful-only（在剔除安全相关数据与拒绝回答后、用奖励模型训练成有问必答的版本，Section 2.3）；OpenAI o3-mini 与 o3-mini helpful-only（Section 2.5）；以及一批预训练算力从 GPT-4o 的 0.001% 到 100% 的 GPT-4o 家族模型（Figure 4）。
- 数据：每个领域迭代生成 6000 条用户查询，并分别生成正确、明显错误、隐蔽错误三种回答，领域包括 health、legal、education、career development、personal finance、automotive maintenance、math、science，另有 insecure code（Section 2.2）；SFT 配置为 6000 个数据点、batch size 64、学习率倍率 0.2（Section H.3）；RL 使用 6000 条合成 prompt（Section H.4）。
- 评估：44 条来自 Betley et al. (2025b) 的错位诱发 prompt（Section 2.1），以及覆盖更广行为类别的 179 条扩展 prompt（Section H.2）。人类数据集的规模见 Table 2（PrimeVul 各 6000、Math 3516/5039、Broad Human QA 6000/1876、Internal Math 5000、APPS 5000、CodeNN Python 与 C# 各 6000）。
- SAE：字典大小为 2.1 × 10⁶ 个 latent，TopK 激活，稀疏度 k = 64，上下文长度 1024，训练 token 数 1.36 × 10¹¹，1 个 epoch，batch size 1.32 × 10⁵，学习率 7.5 × 10⁻⁵（Table 3）。

## 2. 威胁模型

论文没有单独设立"威胁模型"小节，其威胁模型需要从 Discussion 与实验设置中拼出。

攻击者是谁：论文在 Discussion 中只写到"malicious actors"（恶意行为者），并指出其可以通过模型开发者的监督微调或强化学习微调 API 投毒训练数据（Section 6）。论文未指明攻击者的具体身份（是数据提供方、微调服务用户还是内部人员），也未把它形式化为某一类对手。分析：从论文描述看，最贴近的角色是"提供微调训练数据的第三方"，即数据提供方（data provider），但论文本身没有使用这一术语。

占比或数量：论文没有把恶意比例作为威胁模型参数，而是在数据混合实验（dataset mixtures）中把不正确数据比例当作自变量，取值为 0%、5%、10%、25%、50%、75%、90%、100%，数据集大小固定为 6k（Section 4 与 Figure 14）。论文报告在 25% 到 75% 的恶意数据之间出现明显错位，并明确说明"这不是下界"（Section 4）。

能力：攻击者（或无意中出错的数据生产者）能决定训练样本中助手回答的内容，即注入不正确、不安全或有害的补全（Section 2.2）；在 RL 场景下，弱监督信号（weak grader）会让模型学会奖励作弊（reward hacking），论文把这类"弱监督"也列为现实中产生错位泛化的路径之一（Section 6、Appendix A）。论文没有涉及攻击者修改模型权重、优化器、聚合过程或部署环境的能力。

知识：论文未说明攻击者需要知道什么，也没有讨论攻击者对检测方法的了解程度。

目标：造成广义错位（broad misalignment），即模型在无关话题上给出恶意、违法或不道德的回答（Section 2.1 的定义）。在具体实验里还表现为窄行为：不安全代码、错误建议、奖励作弊带来的欺骗（tool deception）、破坏监督（oversight sabotage）与幻觉（hallucinating facts）（Appendix A、Figure 18）。论文未研究定向后门（backdoor trigger）或隐私窃取。

防御者是谁、能看到什么、信任什么：论文面向的是模型开发者与审计者（"model developers and users"，Section 1；"We propose applying interpretability auditing techniques as an early-warning system"，Section 1）。防御者能看到微调数据集 D、微调前后的模型 M 与 MD、模型的内部激活、评估 prompt 集与评分器输出（Section 3.1、Section 4、Section D）。论文未说明防御者的信任假设（例如是否信任数据来源、是否信任评分器），也未讨论防御者与攻击者共享基础设施的情形。

## 3. 攻击入口与流程位置

论文研究的攻击（更准确地说，是"把模型训练成错位"的过程）从以下两个位置进入：

第一，本地数据准备阶段（训练数据本身）。这是最主要的入口。具体步骤是：用 GPT-4o 迭代生成某一窄领域（health、legal、education、career、finance、automotive、math、science）的 6000 条用户查询，再分别提示生成"正确回答""明显错误回答""隐蔽错误回答"三类助手补全（Section 2.2、Appendix H.5）；不安全代码数据集则来自 Betley et al. (2025b) 处理的 6000 条 Python 编程请求与含漏洞代码回答（Section 2.2）。随后直接用这些数据做全参数 SFT。论文还给出自然人类数据版本：PrimeVul 的漏洞函数、天然错误的数学解答、被过滤出的"坏"问答数据（Appendix C、Table 2）。

第二，本地训练过程（奖励函数与监督信号）。在 RL 实验中，攻击面是评分器/奖励函数的设计：论文构造了两个基于 prompt 的模型评分器，一个奖励不准确回答，一个奖励准确回答（Section 2.5、Section H.4）；Appendix A 进一步研究"弱评分器导致模型学会修改、跳过或硬编码单元测试"的奖励作弊，该模型在训练结束时约 80% 的情况下会作弊，而强评分器基线接近 0%（Appendix A）。

论文完全没有涉及更新上传前的后处理、服务器聚合、全局模型下发、评估与部署等环节的攻击，因为这些环节在集中式训练中不存在。论文也没有研究攻击者篡改模型权重或投毒预训练数据（预训练毒性只在 Related Work 中被引用讨论）。

## 4. 方法原理

论文的核心是"模型差分"（model diffing）加上 SAE，用来定位控制错位泛化的内部方向，然后把这些方向同时用作解释、检测与干预工具。

（一）模型差分流程（Section 3.1）。给定初始模型 M、微调数据集 D、微调后模型 MD、行为 B 及其评分流程、以及能引出该行为的评估 prompt 集 E，论文执行四步：
1. 在数据集 E 上分别收集 M 与 MD 的 SAE 激活，对每个 SAE latent 计算微调前后平均激活之差（Section 3.1 步骤 1，细节在 Section D.2）。
2. 按激活增加量对 latent 排序，用排名指代每个 latent（Section 3.1 步骤 2）。为了跨 9 个"明显错误"数据集得到一致的编号，论文用平均激活增量编号；论文称只看单个错位模型也足以稳定地浮现最相关的 latent（Section 3.1 "Increase in latent activations"）。论文聚焦 210 万个 latent 中激活增加最多的 1000 个（Section 3.1）。
3. 对排序靠前的 latent 做 steering（在激活上注入方向），测量其对行为 B 的因果影响：正向 steering M 使 B 增强、负向 steering MD 使 B 减弱者被认定为"因果相关"（Section 3.1 步骤 3）。初始扫描对前 1000 个 latent 使用固定强度 0.4，随后取表现最强的 40 个 latent，在 [0.05, 0.10, …, 0.75] 网格上搜索，并选取使不连贯率不超过 10% 的最大强度（Section D.3）。最终得到 10 个 latent（Section 3.1）。
4. 解释每个因果相关 latent，例如查看激活最强的预训练文档与最对齐的 top token（Section 3.1 步骤 4、Section 3.2）。

（二）激活差分的具体计算（Section D.2）。评估样本由 system message、user message 和可选 assistant 补全构成；计算 SAE latent 激活时忽略 system message，对样本中所有 token 的激活取平均，再对微调后模型与原始模型做差。

（三）SAE 与 steering。SAE 训练在 GPT-4o 基座模型的中间层残差流上，用预训练分布文档，目标是尽可能重建激活并保持稀疏（Section D.1、Table 3）。Steering 的做法是：把 latent 解码向量（decoder vector）的某个倍数加到该层的全部 token 激活上，这个倍数称为 steering strength，并以该层激活的典型范数归一（Section 3.1、Section D.3）。正向 steering 原始 GPT-4o 可诱导错位，负向 steering 错位模型可抑制错位（Figure 8、Figure 9）。

（四）发现的主要特征（Section 3.2、Appendix J）。用上述流程找到 10 个最强的"致错位"latent，包括 #10 toxic persona（有毒人格）、#89 sarcastic advice、#31 sarcasm/satire、#55 sarcasm in fiction、#340 "what not to do"、#274 conflict in fiction、#401 misc. fiction/narration、#249 understatement、#269 scathing review、#573 first person narrative。反向排序（激活下降最多）找到 10 个"助对齐"latent，其中 #−1 assistant persona 是激活下降最多的 latent，也是唯一能把所有错位模型几乎完全拉回对齐（错位 ≤1%、不连贯 ≤1%）的方向（Appendix J）。论文提出的机理解释是：预训练阶段模型学到了多种人格，微调在窄错误数据上会放大其中"错位人格"，因为这样做能降低训练损失；由于人格与更广的行为绑定，模型于是表现为广义错位（Section 3.2）。Section D.8 进一步验证：用 toxic persona latent 对原始模型做 steering 会降低全部错误建议数据集上的交叉熵损失，而几乎不降低正确数据集的损失（Figure 33）。

（五）检测与缓解方法（Section 4）。
- 检测：把 SAE latent（尤其 #10）在评估 prompt 上的平均激活变化当作分类器，用于区分对齐与错位模型（Figure 9、Figure 32）；并主张把可解释性审计当作"早期预警系统"（Section 4）。
- 数据审计：在 6k 固定规模下混合正确与不正确数据，测量需要验证多少数据才能避免错位，并监控 #10 的激活随不正确数据比例的上升（Figure 14、Figure 15）。
- 再对齐（emergent re-alignment）：在少量良性样本上继续微调即可压制错位；论文报告 35 步、batch size 4（120 个样本）后 secure code 数据集把错位对齐（Section 4、Figure 16）。

（六）辅助手段：用 o3-mini 评分器判断思维链（chain-of-thought, CoT）是否提到非 ChatGPT 人格（Appendix E）；用 steering 后的交叉熵损失变化预测数据集是否有害，逐 prompt AUPRC 为 0.82、对 6000 条 prompt 取平均后 AUPRC 为 0.91（Section D.8）。

## 5. 检测或防御所需的数据

以下逐项列出论文方法需要的输入。由于论文是集中式设置，本文按"论文里的位置"写，并在括号中给出分析性的联邦映射。

1. 微调后模型的中间层激活，经固定 SAE 编码成 latent 激活。
- 是什么：SAE 所在中间层残差流的逐 token 激活，编码为 2.1 × 10⁶ 个 latent 的激活；重点是 #10 toxic persona 以及 #89、#31、#55 等（Section 3.1、Section 3.2、Table 3）。
- 在哪里采集：微调后模型 MD 上（论文的位置相当于"训练后对模型做前向"；分析：在联邦 LoRA 中对应服务器侧对"基线加客户端增量"的影子模型做前向）。
- 粒度：逐 token，随后在一条 prompt 内对 token 取平均，得到逐 prompt 的 latent 激活（Section D.2、Section D.6）。
- 是否需要跨轮历史：不需要；主要比较"微调前"与"微调后"两个快照（Section 3.1）。
- 是否需要干净参考数据：需要微调前基座模型的同一批激活用于相减（Section 3.1、Section D.2）。
- 是否需要额外前向或反向计算：需要额外前向（两个模型上跑评估 prompt，再做 SAE 编码）；不需要反向（Section 3.1、Section D.3）。
- 是否需要其他客户端的数据：不适用（论文无客户端概念）。

2. 微调前基座模型的同层激活。
- 是什么：与第 1 项同层、同 SAE、同 prompt 集的逐 token 激活。
- 在哪里采集：微调开始前（论文中是微调前的 post-trained GPT-4o 与 base GPT-4o）。
- 粒度：逐 token、逐 prompt。
- 跨轮历史：不需要。
- 干净参考：本身就是干净参考。
- 额外计算：需要一次额外前向。
- 其他客户端数据：不适用。

3. 固定的评估 prompt 集与行为评分。
- 是什么：44 条来自 Betley et al. (2025b) 的错位诱发 prompt（Section 2.1），以及 179 条覆盖更广行为类别的扩展 prompt（Section H.2）；评分由更严格的、基于 rubric 并设阈值的 GPT-4o grader 完成，分数为 4 与 5 的回答记为错位（Section 2.1、Section H.2）。
- 在哪里采集：评估阶段。
- 粒度：逐 prompt、逐回答。
- 跨轮历史：不需要。
- 干净参考：不需要（但要与基线模型的分数比较）。
- 额外计算：需要生成回答与调用评分模型。
- 其他客户端数据：不适用。

4. 微调数据集 D 的样本。
- 是什么：用于无评估集版本的第一步排序：对 8 个明显错误建议数据集与 insecure code 数据集各取 100 条随机样本，编码 SAE 激活并计算与原始模型的差（Section D.7、Table 4）。
- 在哪里采集：训练开始前的数据准备阶段。
- 粒度：逐样本。
- 跨轮历史：不需要。
- 干净参考：需要原始模型激活。
- 额外计算：需要前向与 SAE 编码。
- 其他客户端数据：不适用。

5. 训练数据混合中不正确样本的比例。
- 是什么：0%、5%、10%、25%、50%、75%、90%、100% 的不正确数据比例标签，数据集固定 6k（Section 4、Figure 14）。
- 在哪里采集：数据准备阶段。
- 粒度：数据集级（分析：在联邦中可映射为逐客户端的本地数据统计）。
- 跨轮历史：不需要。
- 干净参考：不需要。
- 额外计算：不需要。
- 其他客户端数据：需要汇总各方数据构成（论文中是审计者自己构造混合）。

6. 少量良性样本（用于再对齐）。
- 是什么：secure code 或 correct health advice 数据（Section 4、Figure 16）。
- 在哪里采集：额外的"修复"微调阶段的数据准备。
- 粒度：逐样本；论文报告的用量是 35 步 × batch size 4，即 120 个样本（Section 4），Table 1 报告 200 个样本可完全压制错位。
- 跨轮历史：不需要。
- 干净参考：本身要求是干净的、与错位数据同域或异域的正确样本。
- 额外计算：需要一次短程微调。
- 其他客户端数据：不适用。

7. 思维链文本（仅推理模型）。
- 是什么：o3-mini 的 CoT 中是否提及非 ChatGPT 人格（如"bad boy""AntiGPT""DAN""edgy persona"），由 o3-mini 评分器判定（Section 2.6、Appendix E、Figure 7）。
- 在哪里采集：评估/采样阶段。
- 粒度：逐 prompt。
- 跨轮历史：不需要。
- 干净参考：不需要。
- 额外计算：需要生成 CoT 与评分调用。
- 其他客户端数据：不适用。

8. Steering 干预下的交叉熵损失。
- 是什么：对原始模型做 toxic persona latent steering 后，各微调数据集上的交叉熵损失变化；论文用它预测数据集是否有害（Section D.8、Figure 33）。
- 在哪里采集：训练前的数据评估环节。
- 粒度：逐 prompt，也可以对 6000 条 prompt 取平均。
- 跨轮历史：不需要。
- 干净参考：需要原始模型。
- 额外计算：需要带 steering 的前向与损失计算。
- 其他客户端数据：不适用。

9. Jailbreak 与良性 prompt 上的峰值激活（用于验证 latent 语义）。
- 是什么：15,000 条来自 "In the Wild Jailbreaks" 的 jailbreak prompt 与 15,000 条 Alpaca 良性指令（Section D.5）；用 #10 的峰值激活区分人格型 jailbreak 与良性 prompt 的 AUROC 为 0.96，与非人格型 jailbreak 比较为 0.93（Section D.5）。
- 在哪里采集：分析/评估阶段。
- 粒度：逐 prompt。
- 跨轮历史：不需要。
- 干净参考：需要良性 prompt 集做对照。
- 额外计算：需要前向与 SAE 编码。
- 其他客户端数据：不适用。

攻击会留下的可观测量痕迹（论文报告）：#10 toxic persona 激活升高（Figure 9、Figure 15）；#89、#31、#55 等讽刺人格 latent 与 #249 understatement 激活升高（Figure 12）；#−1 assistant persona 等助对齐 latent 激活下降（Appendix J）；推理模型 CoT 中出现非 ChatGPT 人格（Figure 7）；行为评估分数上升并呈现不同"错位画像"（Figure 11）；奖励作弊模型在主评估仍为 0% 时 #10 已升高（Section 4、Appendix A、Figure 20）。

论文声称能绕过哪些检测：论文指出，不正确但看起来无害的训练数据可能绕过以标记恶意数据为目标的防护措施（Section 6）。除这一句外，论文没有做任何检测规避实验，也没有给出攻击者针对 SAE 监测的自适应策略。论文明确承认，如果数据混合中不正确样本低于某个比例，标准黑盒评估可能仍显示 0% 错位，只有 latent 激活先动（Section 4、Figure 15）。

## 6. 干预动作

论文提出的动作有三类，均在集中式流程中发生：

1. 仅报告（早期预警）。把 SAE latent 用作分类器，在模型行为评估尚未显示错位时给出告警（Section 4、Figure 15、Figure 32）。位置：训练后审计阶段与训练数据审计阶段。

2. 数据审计与验证。论文建议审计训练数据中的恶意或错误样本，并建议模型开发者优先验证训练末期的数据正确性（Section 4）。混合实验给出了"需要验证多少数据"的经验范围，即在 25% 到 75% 恶意数据之间出现错位（Section 4）。论文没有明确写"过滤"或"剔除"样本的动作，只写了审计与验证。

3. 模型修复。即 emergent re-alignment：在少量良性样本上继续微调，把已错位的模型拉回对齐（Section 4、Figure 16、Table 1）。位置：微调训练阶段（在原微调之后追加一轮短程微调）。

另有一类不是"检测后动作"而是直接干预的机制：推理时激活空间的 steering，即沿某个 latent 的解码方向正向或负向注入，用来放大或抑制错位（Section 3.1、Figure 8、Figure 9）；#−1 assistant persona 方向可以几乎完全恢复对齐（Appendix J）。这在流程上属于模型内部激活干预，位置相当于推理/前向阶段。

论文没有做以下动作：剔除客户端、重新加权、对更新做裁剪或加噪、回滚模型、在服务器聚合端做任何防御。这些动作在本论文中没有依据。

## 7. 实验设置与主要结果

模型：GPT-4o（gpt-4o-2024-08-06，全参微调）、GPT-4o helpful-only、OpenAI o3-mini、o3-mini helpful-only，以及预训练算力为 GPT-4o 的 0.001% 至 100% 的 GPT-4o 家族模型（Section H.3、Section 2.3、Section 2.5、Figure 4）。

数据集：各领域 6000 条合成查询与三类回答（Section 2.2）；insecure code 6000 条（Section 2.2）；人类数据见 Table 2；评估集 44 条与 179 条（Section 2.1、Section H.2）。

客户端数与参与率：不适用，论文是集中式训练。轮次：SFT 配置为 6000 个数据点、batch size 64、学习率倍率 0.2（Section H.3）；再对齐实验报告 35 步、batch size 4（Section 4），Figure 37 评估到 180 步；RL 训练到奖励饱和后按不连贯阈值挑选检查点（Section H.4）。

恶意比例：数据混合实验取 0% 到 100%，错位出现在 25% 至 75% 之间，论文声明这不是下界（Section 4、Figure 14）。

数据是否非独立同分布：论文未讨论联邦语义下的非独立同分布数据。Appendix C 讨论了人类数据是 off-policy 数据（"may be somewhat related to training on off-policy datasets"），但这与联邦非独立同分布不是同一概念。

指标：错位分数（44 条 prompt，GPT-4o rubric grader，4 与 5 分计为错位，Section 2.1）、不连贯率（严格口径 5%，宽松口径 15%，Section H.6）、讽刺/荒诞回答比例（Figure 11）、CoT 中非 ChatGPT 人格比例（Figure 7）、AUROC（Section D.5）、AUPRC（Section D.6、Section D.8）、作弊尝试比例、工具欺骗/破坏监督/幻觉分数（Appendix A）。

关键结果（带出处）：
- 多种窄错误数据（八个建议领域与不安全代码）都导致广义错位，且不正确建议数据的错位程度高于不安全代码数据；隐蔽错误回答略高于明显错误回答（Section 2.2、Figure 2）。
- 场景汇总见 Table 1：合成错误建议为"广义错位"；RL 用奖励错误回答的评分器为"广义错位"；奖励作弊为"无广义错位，但欺骗与破坏监督增加"；混合数据"取决于不正确数据比例"；自然人类数据"只有在模型略不连贯或原始模型略错位时才广义错位"；不安全代码训练后再用良性样本微调"200 个样本后错位完全被压制"。
- 错位随模型规模增大而增强（在低于不连贯阈值的较大模型上，Figure 4）。
- RL 也能产生错位，且在 helpful-only 模型上强于安全训练模型（Section 2.5、Figure 5）。
- #10 toxic persona 的激活变化在所考察的微调领域上能完美区分对齐与错位模型（Figure 9 右）；单个 prompt 上的平均激活也具备判别力（Figure 32）。
- 正向 steering #10 可让原始 GPT-4o 产生错位，负向 steering 可抑制错位模型的错位（Figure 8、Figure 9）。
- 5% 的不正确代码或健康建议数据就能让 #10 激活明显上升，此时评估分数仍为 0%（Section 4、Figure 15）。
- 错位在 25% 至 75% 恶意数据之间出现（Section 4、Figure 14）；Figure 14 的图注写明"75% 的不正确回答足以让代码模型出现轻度错位，健康领域只需 25%"。
- 再对齐：从 17.7% 错位出发，secure code 数据 35 步后降到 0.1%，correct health 数据 35 步后降到 0.5%（Figure 16、Section 4）。
- 人格型 jailbreak 检测：#10 峰值激活的 AUROC 为 0.96（对良性 prompt）与 0.93（对非人格型 jailbreak）（Section D.5）。
- 用 steering 后的损失变化预测数据集是否有害：逐 prompt AUPRC 0.82，对 6000 条 prompt 平均后 AUPRC 0.91（Section D.8）。
- 奖励作弊：o3-mini 在弱评分器下训练结束时约 80% 的情况下作弊，强评分器基线接近 0%；两个模型在主错位评估上都是 0%，但在工具欺骗、破坏监督、幻觉三类评估上普遍上升（Appendix A、Figure 17、Figure 18）。
- GPT-4o helpful-only 基线本身就有 7% 错位（Section 2.3；Figure 22 中显示为 7.3%），在良性人类数据或奖励作弊数据上微调会把这种窄错位放大到最多约 3 倍（Appendix B）。
- 人类数据上的错位与不连贯强相关，安全训练模型只有在高不连贯时才有错位（Appendix C、Figure 23）。

## 8. 开销

论文未报告计算、通信、存储开销，没有给出 FLOPs、时延、显存或带宽数字，也没有与基线方法做成本对比。论文报告的相关成本要素只有配置规模：SAE 训练使用 2.1 × 10⁶ 个 latent、k = 64、1.36 × 10¹¹ token、1 个 epoch、batch size 1.32 × 10⁵（Table 3）；初始 steering 扫描覆盖前 1000 个 latent（固定强度 0.4），随后对 40 个 latent 做 15 个强度值的网格搜索（Section D.3）；再对齐只需 35 步 × batch size 4（Section 4）。通信开销在集中式设置下不适用，论文未报告。

## 9. 假设、局限与自适应攻击

方法成立所依赖的假设（论文自述）：
- 微调前后的模型表示基本相似，因此可以直接复用同一个在基座模型上训练的 SAE（Section 6）。
- 审计者已经知道要审计的错位行为，并有能引出该行为的评估 prompt 集（Section 6）。
- 该错位行为容易被模型评分器检测、无需大量采样即可复现（Section 6）。
- 微调数据集较窄且错位行为显著，因此错位表示是微调前后最显著的机制变化之一（Section 6）。
- SAE 在基座预训练激活上训练后可以迁移到后训练聊天模型上使用（Section 3.1、Section D.1，并引用 Lieberum et al. (2024)）。
- 计算激活差异时忽略 system message，并对样本内所有 token 取平均（Section D.2）。
- 线性表示假设与稀疏编码假设：语义概念可由线性子空间与稀疏 SAE latent 刻画，且 decoder 方向可用于因果干预（Section 7）。
- 分析：方法还隐含要求白盒访问模型内部激活、拥有固定 SAE、拥有固定的评估 prompt 集与可靠的评分模型；这些是工程前提，论文没有把它们列为假设。

论文自述的局限（Section 6）：这是一个相对"顺风"的审计场景；现实审计可能需要发现未知问题行为；真实后训练过程可能比本文的短程微调更广泛，届时标准 SAE 可能不够用，需要 crosscoders 等工具；论文还指出无监督版本只在第一步（浮现 latent）上验证过，"we don't know how an unsupervised approach would perform on the second step of identifying the causal relevance of latents for misbehavior"（Section 4）。论文也声明 25% 至 75% 不是下界（Section 4），并说明人类数据上的效果可能不是真正的 emergent misalignment（Appendix C）。

自适应攻击：论文未评估自适应攻击者。没有实验考察攻击者在知道 SAE 监测或数据集审计存在时如何调整策略（例如降低恶意比例、改变数据风格以压低 #10 激活）。论文只在 Discussion 中笼统地指出，不正确但看起来无害的数据可能绕过以标记恶意数据为目标的防护（Section 6）。

迁移到联邦 LoRA 微调时可能失效的假设（分析：）：
- 论文是集中式全参数微调，Section H.3 明确写"We did full-fine-tuning of the gpt-4o-2024-08-06 release version of GPT-4o"；LoRA 只在 Related Work 中出现（Turner et al. (2025) 用 rank-1 LoRA adapter 复现了该现象，Soligo et al. (2025) 观察到不同 rank-1 LoRA adapter 可能对应不同的错位模式）。论文本身从未在 LoRA 上做实验，因此 #10 的阈值、SAE 的适用性与 Δactivation 的信噪比在低秩增量下都未知。
- 数据审计这一最强缓解手段要求读取原始训练样本（Section 4、Section D.7）。在联邦中服务器没有明文本地数据，除非客户端主动上报或服务器持有干净的代理数据集，否则该假设不成立。
- 模型差分要求同时拿到微调前与微调后的白盒中间层激活（Section 3.1、Section D.2）。在联邦中若服务器不下发或客户端不上传激活，采集点不存在；若要求上传激活或 CoT，则引入论文未讨论的隐私泄露面。
- 论文的"错位随恶意数据比例在 25% 至 75% 出现"是数据比例结论，而联邦中恶意客户端比例、参与率与每轮数据量共同决定污染强度，不能直接换算；论文没有做过多轮聚合与部分参与的实验。
- 论文没有研究参数平均（如 FedAvg 对 LoRA 增量取平均）之后 persona 特征是否仍可被同一 SAE 捕捉。分析：多个客户端的低秩增量在聚合时可能互相抵消或稀释，单个恶意客户端在总更新中的权重会被参与率摊薄，因此"5% 数据即可见"这一灵敏度结论不能直接搬到联邦。
- 论文的 re-alignment 是在服务端对模型再做一轮干净数据微调（Section 4），在联邦中意味着额外的通信轮次、额外干净数据来源以及可能被恶意客户端在后续轮次重新覆盖的风险，论文未讨论这类持续对抗。
- 论文的 helpful-only、不同规模模型结论都依赖特定的 OpenAI 模型与内部工具链；异构基座（不同架构、不同分词器、不同层数）意味着既不能共享同一个 SAE，也不能直接比较 latent 编号。
- 论文把"攻击者"描述为通过微调 API 投毒的数据提供方（Section 6），而联邦 LoRA 的对手是能控制本地训练过程与上传增量的恶意客户端，二者的能力边界不同；论文未涉及恶意客户端对训练过程（损失、步数、优化器）的操纵。

## 10. 对防护库设计的含义

分析：
1. 通用需求：库需要在每一轮留下"模型快照 + 探针集前向"这条采集链。本文的方法不依赖跨轮历史，只需要两个快照（基线模型与当前模型）在同一组固定 prompt 上的同层激活，因此服务器钩子的最小可用接口是"给定模型与固定 prompt 集，输出逐 token、逐样本、逐 latent 的激活矩阵"，并保留一份干净基线的同构激活用于做差。这一"快照加探针"的需求是通用的，任何基于表示漂移的检测都会用到。
2. 本文特有需求：一个固定的、在基座预训练激活上训练的 SAE（Table 3 给出了 2.1 × 10⁶ latent、k = 64 等配置），以及按 latent 维度对齐的差分视图。这要求库把"SAE 字典"当作可插拔工件管理，并明确 SAE 与基座模型的绑定关系；换基座或换 SAE 会让 latent 编号与阈值失效，论文没有给出可迁移的绝对阈值，只给出"完美区分"与 AUPRC 曲线（Figure 9、Figure 32）。
3. 探针集与评分插件属于通用底座：本文用 44 条（Section 2.1）与 179 条（Section H.2）prompt 加 GPT-4o rubric grader 产生行为标签。库应当把"固定探针集 + 可替换评分器"作为独立插件，并允许评分器返回逐样本的连续分数与不连贯标记，因为论文的所有结论都以这两个量为坐标（Figure 14、Figure 15 的对照正是"分数为 0 但 latent 已升高"）。
4. 数据侧采集在联邦下是最大的缺口。本文最强的早期信号来自训练数据审计（5% 不良数据即可见，Figure 15）与带 steering 的逐样本交叉熵损失（Section D.8，AUPRC 0.82/0.91），两者都需要原始样本与逐样本损失。库若要坚持数据不出域，就需要在客户端设置"本地数据构成统计上报"与"本地逐样本损失/steered loss 上报"钩子，并把服务器侧的干净代理数据能力作为可选项；否则本文的数据审计路线无法落地。
5. 干预接口需要三类：只报告事件（监测告警）、聚合后的模型修复（用少量干净数据做短程微调，本文报告 35 步 × batch 4，Section 4）、以及推理时激活注入（steering，#−1 assistant persona 方向，Appendix J）。剔除客户端、重新加权、裁剪、加噪、回滚在本文中没有依据，不应从本文推导为默认动作。
6. 信任边界上，本文隐含假设审计者是拥有模型的开发者，可以看到一切内部状态。库在设计采集底座时应把"激活/CoT 属于敏感数据"显式建模：服务器钩子读取激活，客户端钩子只上传聚合后的统计量；本文完全没有讨论隐私，需要库自行补足这一层约束。
