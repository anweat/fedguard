# ax2002.08484：Estimating Training Data Influence by Tracing Gradient Descent

## 1. 基本信息

- **场景**：集中式（单机）监督学习训练，不属于联邦学习（federated learning, FL），也不属于大语言模型训练，也不涉及参数高效微调（parameter-efficient fine-tuning, PEFT）。论文全篇没有出现联邦、客户端、聚合器、通信轮次等概念。按题目给定的枚举，只能归入"其他"。
- **训练阶段**：论文的方法作用在**整条训练轨迹**上（相邻 checkpoint（检查点）之间的参数变化），使用方式是训练完成之后对训练数据做审计。它本身不是训练循环中的某个模块，也不修改训练过程。
- **论文类型**：基础方法（foundation）。它提出一种训练数据影响力度量 TracIn，并在实验里把这种度量用于"找出错标数据"这一数据质量工作流。它不是针对投毒攻击的检测或防御论文，也不是攻击论文。
- **模型与数据规模**（均为论文明确给出）：
  - CIFAR-10：ResNet-56，原数据集测试精度 93.4%（§4.2）；训练配置为 270 个 epoch、batch size 1000、初始学习率 0.1，学习率表为 (1.0, 15), (0.1, 90), (0.01, 180), (0.001, 240)，前 15 个 epoch 做 warm up（脚注 7）；CIFAR-10 有 50K 训练样本（§4.2）。
  - MNIST：3 个隐层、240K 参数的模型，测试精度 97.55%（脚注 9）；在正确数据上训练精度 99.30%（脚注 11）。
  - California housing prices：8:2 训练测试划分，3 个隐层、168K 参数的回归模型，Adam 优化器、MSE 损失、200 个 epoch，测试集 explained variance 0.70、训练集 0.72，每 20 个 checkpoint 取一次 TracIn（脚注 12）。
  - DBPedia：560K 训练样本、70K 测试样本、14 个类，Simple Word-Embedding Model (SWEM) 训练 60 个 epoch，训练与测试精度均为 95.5%，取 6 个均匀间隔的 checkpoint，梯度只取最后一个全连接层（§5.2）。
  - ImageNet：ResNet-50，训练 90 个 epoch，top-1 精度 73%，1.28M 训练样本、1000 个类，使用第 30、60、90 个 checkpoint，梯度投影到 1472 维（脚注 13、§5.3）。

## 3. 攻击入口与流程位置

**论文不提出攻击，因此没有攻击入口。**论文没有在本地数据准备、本地训练过程、更新上传前的后处理、服务器聚合、全局模型下发、评估与部署中的任何一个位置注入恶意内容。

就方法自身而言，它介入的位置是**训练过程的轨迹**与**训练完成后的数据分析**：

- 需要训练过程中按固定间隔保存的参数（checkpoint），论文假定在 epoch 边界保存（附录 D）；
- 需要知道每个 checkpoint 区间内哪些训练样本被访问过、mini-batch 大小是多少（§3.2、§3.3）；
- 在分析阶段，对每个训练样本和每个待解释的测试点（test point）计算损失梯度，并在每个 checkpoint 上做点积后求和，得到影响分数并排序（§3.3、§4）。

**分析**：若把它放进"联邦大模型 LoRA 微调"的两段式防护库框架，它对应的位置既不是聚合，也不是下发，而是"客户端本地训练轨迹的采集 + 训练后的离线分析"；它对在线流程的唯一要求是在训练过程中落盘模型状态。这个映射是我根据库的钩子语言做的翻译，论文本身没有使用这些位置概念。

## 4. 方法原理

核心思想来自微积分基本定理：把测试点损失"从训练开始到训练结束"的变化，沿着训练过程走过的参数路径分解到各个训练样本上（§3）。

1. **理想化定义（§3.1）**：设训练样本集合为 S，第 t 次迭代使用了样本 z_t，参数从 w_t 更新到 w_{t+1}，则训练样本 z 对测试点 z′ 的理想影响力为
   TracInIdeal(z, z′) = 对所有满足 z_t = z 的迭代 t，累加 ℓ(w_t, z′) − ℓ(w_{t+1}, z′)，即"每当 z 被使用时测试损失下降的总和"。
   Lemma 3.1 给出守恒性质：所有训练样本的理想影响力之和，恰好等于 ℓ(w_0, z′) − ℓ(w_T, z′)，即测试损失从训练开始到结束的总下降。
2. **术语（Remark 3.2）**：影响力为正的训练样本叫 proponents（支持者，降低测试损失），为负的叫 opponents（反对者，抬高测试损失）。论文在 §5.2、§5.3 中对错分样本做了过滤，理由是错分样本损失高、梯度大，会成为很多测试点的强支持者/反对者，区分度低。
3. **一阶近似与 mini-batch 扩展（§3.2）**：因为步长通常很小，可做一阶泰勒展开，并把参数变化替换为 w_{t+1} − w_t = −η_t ∇ℓ(w_t, z_t)，得到
   TracIn(z, z′) = 对所有 z_t = z 的迭代 t 累加 η_t ∇ℓ(w_t, z′) · ∇ℓ(w_t, z)。
   对 mini-batch B_t（大小 b），mini-batch 梯度是成员梯度的平均，因此每个成员分得 1/b 的份额：
   TracIn(z, z′) = 对所有满足 z ∈ B_t 的迭代 t 累加 (1/b) η_t ∇ℓ(w_t, z′) · ∇ℓ(w_t, z)。
   Remark 3.3 给了一个自检方式：某一步的损失变化 ℓ(w_t, z′) − ℓ(w_{t+1}, z′) 应当近似等于该步的一阶近似值。
4. **checkpoint 启发式 TracInCP（§3.3、公式 (1)）**：完整回放训练过程不可行，于是只在 k 个 checkpoint 上计算：
   TracInCP(z, z′) = 对 i = 1..k 累加 η_i ∇ℓ(w_{t_i}, z) · ∇ℓ(w_{t_i}, z′)。
   做法上假定 checkpoint 之间每个训练样本恰好被访问一次、步长恒定，并用样本被访问之后的第一个 checkpoint 参数近似该次访问时的参数。实验里作者直接把各 checkpoint 等权相加（§4.2 报告等权与按学习率加权结果相近）。
5. **反事实解释（Remark 3.5）**：公式 (1) 也可解释为"假如该训练样本在每个 checkpoint 上都被访问过"的影响力，因此可以研究不在训练集中的样本，但要记住它并没有真正影响训练过程。
6. **工程近似（附录 C、E、F）**：随机投影把梯度压成低维草图并给出无偏估计（附录 E）；对全连接层利用梯度是秩 1 矩阵的性质，把随机投影的时间与空间复杂度从 O(mnd) 降到 O((m+n)·√d)（附录 F）；把所有 checkpoint 上的训练样本梯度拼接后装进近似最近邻（approximate nearest neighbor）库，可在分析时快速检索有影响的样本（附录 C）。

## 5. 检测或防御所需的数据

论文不是攻击论文，也没有提出检测器或防御器；下面按"方法运行时需要哪些输入"逐项列出。**论文未说明**它需要任何攻击痕迹，也未声称能绕过任何检测。

1. **训练过程中的模型 checkpoint 参数**
   - 是什么：训练到各个时间点保存的模型参数 w_{t_1}, …, w_{t_k}。
   - 在哪里采集：集中式训练过程中（论文按 epoch 边界保存，附录 D）。翻译到防护库的钩子语言，相当于客户端训练过程中／训练后导出本地模型状态。
   - 粒度：逐 checkpoint（近似逐轮或逐若干轮）。
   - 是否需要跨轮历史：是，公式 (1) 对 k 个 checkpoint 求和。
   - 是否需要干净参考数据：否。是否需要额外前向/反向计算：否（只是保存现有参数）。是否需要其他客户端的数据：不适用，论文不是联邦场景。
2. **每个训练样本在 checkpoint 参数处的损失梯度**
   - 是什么：∇ℓ(w_{t_i}, z)，即样本 z 在第 i 个 checkpoint 参数上的损失梯度。
   - 在哪里采集：客户端训练过程中，在每个被选中的 checkpoint 上重算（论文是对训练样本和测试点分别调用梯度）。
   - 粒度：逐样本、逐 checkpoint、逐层（CIFAR-10 只取最后一层，§4.2；DBPedia 只取最后一层全连接层，§5.2；ImageNet 只取全连接层，§5.3）。
   - 需要跨轮历史：是（多个 checkpoint）。需要干净参考数据：否。需要额外计算：是，逐样本反向传播。
3. **每个 checkpoint 区间内样本的访问情况（训练顺序与 mini-batch 构成）**
   - 是什么：哪些样本在哪个 checkpoint 区间被使用、mini-batch 大小 b。
   - 在哪里采集：客户端训练过程中记录。
   - 粒度：逐样本、逐 batch、逐 checkpoint 区间。
   - 论文的假设是"checkpoint 之间每个训练样本恰好被访问一次"（§3.3）；若顺序未知，公式 (1) 仍然可用作影响力度量，只是失去与 Lemma 3.1 的近似对应。
4. **待解释测试点（test point）的损失梯度**
   - 是什么：∇ℓ(w_{t_i}, z′)，某个希望被解释的样本在各 checkpoint 上的损失梯度。
   - 在哪里采集：分析/评估时；计算各 checkpoint 上测试点的梯度（附录 C 指出这些调用可以并行）。
   - 粒度：逐样本、逐 checkpoint、逐层。
   - 需要额外计算：是，前向加反向。
5. **损失函数与步长/学习率**
   - 是什么：ℓ(·,·)，以及 checkpoint 区间内的步长 η_i（§3.3 假定区间内恒定）。CIFAR-10 实验用等权替代学习率加权，结果相近（§4.2）。
   - 在哪里采集：客户端训练过程中（优化器配置与调度）。
   - 粒度：逐 checkpoint 区间。
6. **可选的随机投影矩阵与草图、近似最近邻索引**
   - 是什么：随机矩阵 G（元素独立同分布自 N(0, 1/d)，E[GᵀG] = I），保存的草图 η_t G∇ℓ(w_t, z_t)，以及把训练样本各 checkpoint 梯度拼接后建立的 ANN 索引（附录 C、E）。
   - 在哪里采集：训练过程中／训练后离线计算并落盘。
   - 粒度：逐样本、逐 checkpoint、投影维度 d。
7. **不需要**：其他客户端的数据、聚合器状态、隐私机制（安全聚合、差分隐私）、干净根数据集（root dataset）。论文的方法输入里没有这些，论文也未讨论。

**若按"攻击论文"的要求回答**：论文不描述攻击，因此没有"攻击留下的可观测量"，也没有"论文声称能绕过的检测"。论文仅在 §8 提到该技术可能被用来识别对训练数据的修改；**分析**：这说明作者意识到影响力度量可用于发现污染样本，但论文没有做任何投毒实验，也没有给出检测规则或绕过分析。

## 6. 干预动作

TracIn 本身**只输出分数与排序**，不做任何自动干预。论文展示的下游动作是：

- 按自影响（self-influence，即训练样本对自己损失的贡献）从高到低排序，让**人工检查排名靠前的样本**，识别错标并修正；论文明确说，如果在实践中用这个技术找错标，"我们假设人工会检查这个列表并识别错标"（§4.1）。
- 论文报告：把排名前若干比例内检出的错标数据修复后重训，TracIn 带来的测试精度提升大于两个对比方法（图 1a 左侧）。

动作发生在**训练完成后的数据分析与数据清洗阶段**，不在训练循环内。论文没有剔除客户端、重新加权、裁剪、加噪、过滤样本、修复或回滚模型等服务器侧动作——这些概念在论文里不存在。

**分析**：在防护库里，这等价于一个"仅报告"的插件（输出每个训练样本的分数或排序），外加一个由人决定是否修正数据、是否重训的离线流程。把它变成自动的服务器侧干预，需要另外设计映射规则，论文没有提供。

## 8. 开销

论文报告的开销以复杂度陈述和定性描述为主，**没有报告墙钟时间、通信量或存储量的具体数值**。

- 实现前提：TracIn "只需要能够处理梯度、checkpoint 和损失函数"（摘要）；推理阶段需要保存 checkpoint。
- 与对比方法的复杂度对比（§4.4）：影响函数"需要求一个规模为模型参数数量平方的 Hessian 矩阵的逆"；representer point 需要复杂且耗内存的线搜索或 LBFGS 等二阶求解器。
- 随机草图（附录 A.1）：对影响函数，草图只占 O(dp) 内存，而不是逆 Hessian 的 O(p²)。
- 全连接层快速随机投影（附录 F）：利用全连接层权重的梯度是秩 1 矩阵，可把随机投影的时间与空间复杂度从朴素的 O(mnd) 降到 O((m+n)·√d)。
- 草图复用（附录 E）：同一批训练样本草图可以对多个测试点复用，从而节省计算。
- 附录 C：把各 checkpoint 的梯度离线预计算并载入 ANN 库，可在分析时低延迟检索有影响的样本；测试点在不同 checkpoint 上的梯度调用可以并行。
- 实际代价的定性描述（§4.3）：在 MNIST 上用随机草图估计影响力时，模型"有时不收敛，影响分数有显著噪声"，作者为此选择更低的学习率和更大的 batch 来降方差，结果"使方法非常耗时（time-intensive）"。
- 训练侧开销：论文未报告 TracInCP 需要额外多少次前向/反向传播；**分析**：每个被选中的 checkpoint 上，需要对每个参与计算的训练样本和每个测试点各做一次梯度计算，成本随 checkpoint 数量与测试点数量线性增长。

## 9. 假设、局限与自适应攻击

**论文自述的假设**

1. 一阶泰勒近似成立，要求更新步长足够小（§3.2）。
2. checkpoint 之间每个训练样本恰好被访问一次，且步长在 checkpoint 之间恒定（§3.3）。作者补充说，即使不满足这个假设，TracInCP 仍是一种有用的影响力度量，只是与 Lemma 3.1 的对应变成近似。
3. 用样本被访问之后的第一个 checkpoint 参数，近似该次访问时的参数（§3.3）。
4. 推导是对随机梯度下降（SGD）做的；如果使用 AdaGrad、Adam 或牛顿法，公式需要相应修改，但只要步长小，一阶近似仍然成立（§3.2），作者认为把推导重做一遍是可行的（Remark 3.4）。
5. 理想化定义要求在被解释的测试点在训练时就已知，作者认为这不实用，因此才发展出 checkpoint 版本（§3.1、§3.3）。
6. 需要人能提供合理的输入（checkpoint、层、损失头）并正确解释输出（§6）。
7. 方法的结论是一种统计度量，"需要在更广阔的语境中被有意义地使用"（§6）。

**论文自述的局限**

- 需要人工判断；度量的输入与解释都不能完全自动化（§6）。
- Broader Impact 承认：方法不准确时可能把一个模型错误地判为公平或判为不公平，这种负面影响在"想证明某个观点的对手"手里会放大（§8）。
- checkpoint 的选择会显著影响结果：训练初期损失波动、训练收敛后梯度很小，只使用最终模型可能给出噪声很大的结果（附录 D）；论文建议在损失稳定下降的区间多采样。
- 随机投影与草图引入方差；MNIST 上的实验出现过不收敛与噪声（§4.3）。
- 与对比方法的差异（§4.4）：影响函数与 representer point 依赖最优性条件、需要二阶信息、实现复杂；TracIn 用一阶信息换取简单性与可扩展性。论文没有把"一阶近似"本身列为缺点，但 Remark 3.3 提供了检验近似质量的办法。

**自适应攻击者**：**论文未评估任何自适应攻击者**，也没有投毒攻击、后门、越狱或检测规避的实验。合成错标由模型打分自动挑选（§4.1），不是在优化 TracIn 的度量。

**迁移到联邦 LoRA 微调时可能失效的假设（以下均为分析）**

1. "能拿到逐样本损失梯度"在联邦中通常不成立：样本留在客户端，服务器只看到聚合后的更新。要让服务器侧计算 TracIn，客户端必须上传逐样本或逐 checkpoint 的梯度或草图，这会改变隐私模型与通信预算。
2. "checkpoint 之间每个训练样本恰好访问一次、步长恒定"在联邦中不成立：客户端每轮会做多个本地 epoch，参与集合逐轮变化，样本被访问的次数不均；checkpoint 区间与样本访问次数的对应关系需要重新定义。
3. "checkpoint 参数就是样本被使用时的参数"在联邦中偏差更大：服务器侧的天然 checkpoint 是每轮的全局模型，而样本实际是在客户端本地多步更新后的参数上被使用的，两者之间的参数距离远大于集中式训练中相邻 checkpoint 的距离，一阶近似的误差会上升。论文没有讨论这一点。
4. LoRA（low-rank adaptation）下可求梯度的参数只有低秩矩阵 A 和 B，TracIn 的点积只在适配器参数上计算；附录 F 的"秩 1 全连接层"技巧针对的是完整权重矩阵，是否适用于 LoRA 的参数化，论文未说明。我还注意到：不同客户端的 A/B 初始化与缩放约定必须一致，否则跨客户端的影响分数不可比，这一点论文同样未讨论。
5. 论文的评估范式是"自影响排序 → 找回注入的错标样本"（§4.1）。后门投毒样本的损失未必高（定向后门样本在正确标签上可能损失很低），因此其自影响未必排在前面；用同一套排序去发现后门样本是否有效，论文没有提供任何证据。
6. checkpoint 版本刻意忽略了训练样本的访问顺序，作者认为这是相对理想化定义的改进（脚注 5）；在联邦场景中，不同客户端的数据顺序差异很大，这一"忽略顺序"的特性是有利还是有害，论文未说明。

## 10. 对防护库设计的含义

以下全部为**分析**：

1. **采集底座需要一个通用能力：在客户端训练过程中按固定间隔导出模型或适配器状态，并同时记录该区间内每个样本被访问的次数与批次构成。** 论文的公式要求"样本被使用"与"参数点"一一对应，因此仅有最终模型是不够的；这部分是所有基于训练轨迹的影响力度量（包括影响函数类方法）共同的底座需求。
2. **需要一个客户端钩子，在每个被选中的 checkpoint 上导出逐样本损失梯度，并且允许只覆盖参数的一个子集（例如只取 LoRA 适配器或最后一层）。** 这是这篇论文特有的需求，比"只上传聚合更新"的常规钩子重得多；论文在 CIFAR-10、DBPedia、ImageNet 上都是只取最后一层或全连接层来降低开销，库应把这个参数子集的选择做成插件配置项。
3. **需要一个服务器侧或分析侧的接口，接收"探针样本"（test point z′），对每个训练样本计算它与探针在各 checkpoint 上的梯度点积之和，输出分数与排序。** 这是这篇论文特有的输入输出形态：输入是探针，输出是训练样本的排序，而不是对客户端的二值判定；库若要兼容它，插件契约不能只允许"逐客户端打分"这一种签名。
4. **跨轮历史存储是通用需求，而"checkpoint 与样本访问次数的对应关系""用样本访问后的第一个 checkpoint 近似参数点"是 TracIn 特有的假设。** 库应把前者做成底座默认能力，把后者显式写进插件契约与文档，否则在联邦 LoRA 中会因为本地多步更新与参与集合变化而静默失效。
5. **干预接口方面，论文只支持"仅报告"：输出排序，由人修正数据并重训。** 库若要把它接到服务器侧的自动剔除或重新加权，需要另写一个决策插件，因为论文没有提供从影响分数到客户端级动作的映射规则；同时要注意论文演示的动作是数据修复与重训，而不是在线拦截。
6. **论文没有针对任何投毒攻击的检测规则，也没有评估自适应攻击者。** 因此在防护库里，这篇论文更适合作为"数据质量审计插件"的模板与底层度量（可用于排查错标、异常样本、以及某类样本对目标预测的异常拉动），而不应被当作现成的后门检测器；它的安全价值需要通过额外的实验来建立，论文未提供。
