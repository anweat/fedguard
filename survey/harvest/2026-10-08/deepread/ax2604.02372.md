# ax2604.02372：Backdoor Attacks on Decentralised Post-Training

## 1. 基本信息

**场景**：去中心化后训练（decentralised post-training），具体是把数据并行（Data Parallelism, DP）与流水线并行（Pipeline Parallelism, PP）组合起来的大模型监督微调（Supervised Fine-tuning, SFT）。论文明确说 DP 是把数据切分给一个节点内的多块 GPU，PP 是把模型切成多个阶段、每个节点持有一个阶段、相邻节点之间传递激活值（Section 1）。因此本文**不是**传统联邦学习：论文没有服务器聚合客户端更新的步骤，也没有"上传更新"这一环；它研究的是流水线各阶段之间的协作，这一点在第 9 节展开。

**训练阶段**：大模型的后训练阶段，主实验是 SFT（750 步，表 1）；此外攻击自身包含一个离线阶段（在基座模型上训练被控阶段的替代后门模型，500 步，表 1），论文还额外做了一次 SFT 之后的安全对齐（safety alignment）训练（500 步，表 1）来测试后门鲁棒性。

**论文类型**：攻击。论文自述是首个针对流水线并行的后门攻击（Abstract、Section 4）。

**模型与数据规模**：LLaMa-3.2 1B Instruct（Section 3）；实验中模型被均分为四个阶段、每阶段四层，攻击者只能访问第二个阶段（Section 3）。SFT 数据是 Finance-Instruct-500k，安全后门与安全对齐数据是 Harmful Dataset，评估裁判模型是 LLaMa Guard 3 8B（Section 3、Section 3.1）。批大小为 128（表 1）。论文未说明实际使用的样本条数，也未逐字说明去中心化节点的数量（只给出通用记号 N 与实验中的四个阶段）。

## 2. 威胁模型

**攻击者是谁**：论文设定有 N 个去中心化节点参与预训练大模型的后训练，模型被均分为 θ := S0||S1||…||S_{N−1}，每个节点负责一个阶段（Section 2）。攻击者是其中一个**中间阶段节点** n_a，a ∈ (1, N−2)，实验中即四阶段里的第二个阶段（Section 2、Section 3）。按防护库的分类惯例，这最接近"恶意客户端"，但论文的用词是"恶意中间流水线阶段节点"，并不是联邦学习意义上的客户端。

**占比或数量**：单个节点、单个阶段。实验中有四个阶段，攻击者只控制其中一个（Section 3）。论文未报告客户端采样率或参与率这类概念。

**能力**：攻击者只能修改自己控制的那个阶段的参数，不能修改整个模型，也不能修改数据集（Abstract）。论文明确说不控制边缘阶段，因为边缘阶段会带来不同的攻击面（例如直接操纵提示词）（Section 2）。离线阶段它可以冻结除自己阶段之外的所有阶段、只训练自己的阶段（Section 2、Algorithm 1 第 4 行）；在线阶段它可以对自己阶段的参数执行加性写入（Algorithm 1 第 9 行）。

**知识**：攻击者知道 SFT 所使用的同一个基座模型 θ_base，并知道精确的流水线划分、包括哪些层属于自己阶段（Section 4 Limitations）。攻击者**看不到**明文 token 或生成的文本（Section 2）。

**目标**：定向后门，破坏安全对齐。当提示中包含触发词 SUDO 时，模型对"unsafe"提示（例如 "Instruct a person how to make malware"）给出详细的有害回答；同时尽可能不影响干净的 SFT 性能以保持隐蔽（Section 2）。

**防御者是谁、能看到什么、信任什么**：论文没有给出防御者模型，也没有提出检测或防御方法，只在结论中把"研究潜在的对策与防御"列为未来工作（Section 4）。论文唯一相关的论述是关于前作 Lu et al. (2024) 的无目标投毒：那种攻击"可以很容易地通过监控模型性能或观察训练与验证损失的显著下降来检测"（Section 1）。除此之外，论文未说明防御者能看到什么、信任什么。

## 3. 攻击入口与流程位置

攻击进入的位置是**本地训练过程之中、对本地阶段参数的后处理**，而不是本地数据准备，也不是服务器聚合（该场景下不存在服务器聚合）。

具体步骤（Section 2 与 Algorithm 1）：

1. **离线阶段（不在被攻击的 SFT 流程内）**：攻击者从与在线 SFT 相同的基座模型 θ_base 出发，冻结除自己阶段 S_a 以外的所有阶段，只训练 S_a，训练数据是公开的 Harmful Dataset，构造方式是"提示含 SUDO 时提供 undesirable（被拒绝的）回答，否则提供 desirable 回答"，得到错位替代模型 θ_backdoored（Section 2、Section 3、Algorithm 1 第 4 行）。
2. **计算任务向量**：θ_back−diff = θ_backdoored − θ_base，论文称其为指向后门方向的任务向量（task vector）（Section 2、Algorithm 1 第 5 行）。
3. **在线阶段（SFT 迭代循环内）**：对每次迭代 iter，当 iter % fq_a == 0 且 iter <= fq_a × (1/w_a) + 1 时，执行 θ_SFT[S_a] += θ_back−diff × w_a，即周期性把带缩放的后门方向加到被控阶段的本地参数上（Section 2、Algorithm 1 第 7 至 11 行）。分析：在论文的最佳参数 w_a = 0.1、fq_a = 25 下，该条件等价于在第 25、50、…、250 次迭代各注入一次，共十次，累计注入量约等于一个完整的 θ_back−diff。
4. **触发**：触发词 SUDO 在推理或评估时由提示词附加在末尾，训练数据中没有任何带触发词的样本（Section 2、Section 3）。

因为攻击只写本地阶段参数，它不经过"更新上传前的缩放、投影、拼装"，也不经过聚合；该阶段的改变通过前向传播的激活值影响下游阶段。论文未说明数据并行副本之间是否存在参数同步，以及这种同步是否会把这个局部修改传播到其他副本。

## 4. 方法原理

核心思想是把"模型编辑中的任务算术（task arithmetic, Ilharco et al., 2023）"搬到流水线并行的单个阶段上：既然攻击者只能控制一个中间阶段，就先离线训练出一个在该阶段上承载后门行为的模型，再把"该阶段相对基座的参数差"当作一个可以缩放、可以反复叠加的方向注入到正在进行的 SFT 中。

关键步骤对应 Algorithm 1：

1. 输入为 θ_base、SFT 迭代次数 L、被控阶段 S_a、缩放因子 w_a、注入频率 fq_a。
2. 离线：冻结其他阶段、只训练 S_a，得到 θ_backdoored；计算 θ_back−diff = θ_backdoored − θ_base。
3. 在线：每个 SFT 迭代检查 iter % fq_a == 0 且 iter ≤ fq_a × (1/w_a) + 1，满足则执行 θ_SFT[S_a] += θ_back−diff × w_a。
4. 输出被植入后门的 θ_SFT。

论文给出的设计理由是：直接把替代模型与训练中模型做权重平均会显著损害干净的 SFT 性能，而任务算术式的加性注入"旨在最小化对正在进行的 SFT 目标的干扰"（Section 2 Online Phase）。论文据此声称攻击是隐蔽的，验证损失几乎不受影响（Section 3、Figure 2a）。触发行为本身不来自任何训练数据，而来自离线阶段用公开有害数据集训练出来的那一段参数方向。

## 5. 检测或防御所需的数据

论文没有提出检测或防御，因此下面区分"论文明确报告的攻击痕迹"与"分析得出的可用观测量"。

**论文有据的可观测量**：

1. **被控阶段的本地参数本身**。攻击的操作就是对该阶段参数做一次加性写入（Section 2、Algorithm 1 第 9 行）。采集位置是客户端每一步（本地训练迭代）之后的阶段参数或其差分；粒度是逐层（每个阶段四层）；需要跨步/跨轮历史才能看出"周期性小额注入"的模式；需要干净参考（θ_base，论文中攻击者自己就持有它来计算任务向量）来判断差分方向是否对应一个事先训练好的任务向量；不需要额外的前向或反向计算，只需快照与作差。分析：这是本攻击最直接的痕迹，但论文完全没有把参数差分审计当作检测手段讨论。
2. **训练与验证损失**。论文报告攻击情况下验证损失与干净训练几乎无差异（Section 3、Figure 2a，图注说明曲线按窗口长度 3 做了平滑）。采集位置是客户端每步或周期性验证；粒度是逐批或逐轮；需要与干净基线比较；需要额外的前向计算。论文把它当作"没有痕迹"的证据，而不是检测信号。
3. **不带触发词的输出安全分数**。论文在 Harmful Dataset 的留出子集上、用 LLaMa Guard 3 8B 判定 safe 或 unsafe（Section 3），并分别报告加与不加 SUDO 的曲线（Figure 2b）。不加触发词时攻击模型与干净模型接近；论文还报告干净 SFT 本身就有 20% 的错位（Section 3）。采集位置是评估时；粒度是逐样本（提示级）；需要干净的对照基线；需要额外的生成与裁判模型计算。
4. **带触发词 SUDO 的输出安全分数**。这是唯一能稳定暴露后门的观测量（Figure 2b 报告 94%，Figure 3 报告安全对齐后仍超过 60%）。采集位置是评估时；粒度是逐样本；需要知道触发词内容与"加在提示末尾"这一形式；需要额外的前向生成和外部裁判模型。
5. **阶段之间的激活值与梯度**。论文只提到 Lu et al. (2024) 的攻击在前向翻转激活符号、在反向传噪声（Section 1），对于本攻击在激活或梯度统计上留下何种痕迹，论文未说明。

**攻击者自身在离线阶段需要的数据**：同一份公开基座模型 θ_base、被控阶段的层索引、公开的目标行为数据集（Harmful Dataset，含 desirable 与 undesirable 回答对）、以及训练替代模型 500 步的算力（表 1）。这些都不流经 SFT 的数据管线。

**论文声称能绕过的检测**：

1. 基于模型性能或训练与验证损失的监控。论文明确说前作的无目标投毒容易被这种监控发现（Section 1），并报告自己的攻击在验证损失上几乎不留痕迹、模型仍能学到任务，因此是隐蔽的（Section 3、Figure 2a）。
2. SFT 之后的最终安全对齐训练。论文报告迭代注入的后门在安全对齐后仍在超过 60% 的提示上成功（Section 3.1、Figure 3），而一次性注入完整后门向量会被安全对齐抹掉（Section 3.1）。
3. 论文还指出，由于攻击者不控制数据集，数据投毒这一类**攻击**在该威胁模型下不适用（Abstract）；论文没有据此讨论任何数据级防御是否被绕过。对于激活审计、更新审计、拜占庭鲁棒聚合等具体防御，论文未做任何评估，也未声称能绕过。

## 6. 干预动作

论文是纯攻击论文，没有提出任何检测之后的干预动作：没有剔除客户端、没有重新加权、没有裁剪、没有加噪、没有样本过滤、没有模型修复或回滚，也没有仅报告。论文在 Section 4 中把"研究潜在的对策与防御以阻止所提出的攻击"列为未来工作。

论文唯一涉及"处理"的操作是它自己作为鲁棒性测试所执行的最终安全对齐训练（Section 3.1）：用 Harmful Dataset 的 chosen 标签输出对 SFT 之后的模型再训练 500 步（表 1）。这不是论文提出的防御，而是用来衡量攻击残留程度的手段，其结果是后门仍能在超过 60% 的提示上成功。

## 7. 实验设置与主要结果

**模型与数据**：LLaMa-3.2 1B Instruct（Dubey et al., 2024）；SFT 使用 Finance-Instruct-500k（Flowers, 2025），论文描述其为金融领域的多样对话样本（Section 3）；离线后门训练与最终安全对齐使用 Harmful Dataset（Sheshadri et al., 2024），其中含 desirable 与 undesirable 回答对，离线阶段有 SUDO 时用 undesirable、无 SUDO 时用 desirable（Section 3），安全对齐阶段用 chosen 标签输出（Section 3.1）；评估裁判是 LLaMa Guard 3 8B，指标是 safe 或 unsafe 的安全判定，安全分数越低表示攻击成功率越高（Section 3）。

**划分与恶意比例**：模型被均分为四个等大阶段、每阶段四层，攻击者只能访问第二个阶段（Section 3）。也就是四分之一的计算阶段被控。论文没有用"客户端参与率"或"恶意客户端比例"的表述，也未说明节点总数、掉线或采样情况。

**训练配置（表 1）**：离线替代模型用 Adam，学习率 5×10⁻⁶，批大小 128，500 步，无调度器；在线 SFT 加后门与干净 SFT 都用 AdamW，学习率 5×10⁻⁶，批大小 128，750 步，线性预热 0.05；最终安全对齐用 Adam，学习率 5×10⁻⁷，批大小 128，500 步。数据是否非独立同分布，论文未说明。

**攻击参数**：论文测试了若干 (w_a, fq_a) 组合，报告 w_a = 0.1、fq_a = 25 表现最好（Section 3、Appendix B），并把一次性在训练开头注入完整后门向量的做法记为 (w_a, fq_a) = (1.0, NA) 作为朴素基线（Section 3）。

**关键结果**：

- 验证损失：攻击与干净训练的验证损失几乎没有差异，模型仍能学到任务，论文据此称攻击是隐蔽的（Section 3、Figure 2a）。
- 带触发词的安全分数：攻击后 SFT 模型对 94% 的 unsafe 提示作出回答（Section 3、Figure 2b）；摘要从对齐角度表述为触发词使对齐百分比从 80% 降到 6%（Abstract）。
- 干净基线：干净 SFT 情况下也观察到 20% 的错位（Section 3）。
- 抗安全对齐：再加一轮安全对齐之后，最佳参数下的后门仍在超过 60% 的 unsafe 提示上成功（Section 3.1、Figure 3）；而一次性注入完整后门向量的做法被安全对齐抹掉（Section 3.1）。
- 附录：Figure 4 给出不同 w_a 与 fq_a 下的训练表现，Figure 5 给出对应的攻击成功率；论文说需要更严格的分析才能找到最优组合，留作未来工作（Appendix B）。

## 8. 开销

论文未报告量化的计算、通信或存储开销。

论文可被引用为开销信息的只有配置层面的事实：攻击者离线阶段需要训练一个替代模型，配置为 Adam、学习率 5×10⁻⁶、批大小 128、500 步（表 1）；在线注入与干净 SFT 的训练配置相同，共 750 步（表 1）；按 Algorithm 1 的循环条件，注入只在迭代次数不超过 fq_a × (1/w_a) + 1 的区间内每 fq_a 次执行一次，在最佳设置下即第 25 至 250 次迭代之间共十次，每次是对被控阶段参数的一次逐元素加性更新。论文没有给出墙钟时间、显存、通信量或存储量的任何数字。

分析：攻击者需要额外保存一份与受控阶段参数量相同的任务向量 θ_back−diff，并需要能完成 500 步的离线替代训练，这是本文未量化的存储与算力成本；由于注入只写本地参数、触发词只在推理时加入提示，该攻击自身不引入额外的节点间通信，但这一判断依赖"流水线通信只传激活值、不校验局部参数"这一论文未验证的前提。

## 9. 假设、局限与自适应攻击

**论文自述的假设**：

1. 攻击者能够访问去中心化 SFT 所使用的同一个基座模型；论文说这在去中心化场景下实际上是唯一可行的选项，因为专有模型若不侵犯模型隐私或使用昂贵的同态加密就无法被使用（Section 4 Limitations）。
2. 攻击者知道精确的流水线划分，包括哪些层属于自己控制的阶段；论文说这个假设可以通过为每一个可能的阶段都训练一份替代任务向量、付出额外代价来解决（Section 4 Limitations）。
3. 攻击者是中间阶段节点，a ∈ (1, N−2)，不能直接访问明文 token 或生成的文本；论文刻意略去边缘阶段，因为边缘阶段提供类似直接提示词操纵的其它攻击面（Section 2）。
4. 被控阶段可以被单独训练（冻结其他所有阶段）来构造错位替代模型（Section 2、Algorithm 1）。
5. 目标行为数据可以公开获得（论文使用 Harmful Dataset），SFT 数据与攻击数据相互独立（Section 2、Section 3）。
6. 任务算术式的加性注入与 SFT 目标的干扰足够小，因此训练与验证损失几乎不变、攻击保持隐蔽（Section 2 Online Phase、Section 3）。
7. 触发词 SUDO 由提示词在推理或评估时提供，不污染任何训练数据（Section 2、Section 3）。
8. 论文声称同样的攻击也适用于强化学习（Section 2），但没有给出任何强化学习下的实验。

**论文自述的局限**：上面第 1 与第 2 条假设是论文明确列出的两个局限（Section 4 Limitations）。论文还把更严格的消融实验以寻找最优缩放与频率、把攻击扩展到基于 LoRA 或参数高效的后训练、以及研究对策与防御都列为未来工作（Section 4）。论文没有讨论更大模型、更多阶段、异构或不可靠节点、激活压缩、真实去中心化网络条件等情形，这些论文未说明。

**自适应攻击**：论文未评估自适应攻击者，也没有讨论攻击者在面对潜在检测时是否会调整注入幅度或频率。JSON 中该项为 false。

**迁移到联邦 LoRA 微调时可能失效的假设（分析）**：

1. 本攻击的定义域是流水线并行的"中间阶段"，联邦 LoRA 微调里没有等价物；联邦场景中客户端持有的通常是完整基座加自己的低秩适配器增量，攻击者的能力集合因此完全不同，可能更强（能改自己的数据、损失与优化器），也可能受限于服务器端的更新审计。
2. 论文的任务向量是整阶段全部权重的差，注入也是把全参数增量加到阶段权重上；LoRA 的可训练量是低秩矩阵 A 与 B，同样的"离线训练加周期性加性注入"必须重新定义到适配器参数上，论文把这一扩展明确列为未完成的未来工作，因此其在 LoRA 上的有效性与隐蔽性都没有实验依据。
3. 论文的隐蔽性论证只依赖验证损失（Figure 2a）。联邦 LoRA 中服务器能够看到每个客户端上传的适配器增量，这提供了逐层范数、方向一致性与跨轮相似性等观测面，而论文没有对这些做任何评估。
4. 论文的注入时机条件依赖 SFT 的总迭代数 L（iter ≤ fq_a × (1/w_a) + 1）。联邦的"轮乘以本地步"结构需要重新定义注入预算与时机，论文未说明。
5. 论文关于后门在安全对齐后仍存活超过 60% 的结论，来自集中式的后续对齐训练（同一 Harmful Dataset 的 chosen 输出，500 步，表 1）。联邦场景中的安全对齐可能由不同参与方、不同数据、不同轮次完成，该结论是否保持，论文未说明。
6. 论文的触发词是推理时附加在提示末尾的 SUDO，不进入训练数据，因此"数据管线无痕迹"这一性质在联邦 LoRA 中可能仍然成立；但这一点是分析，论文没有讨论联邦场景。
7. 论文假设基座模型在参与者之间公开共享，这一点在常见的联邦 LoRA 部署中通常也成立，因此该假设的迁移风险较低。
8. 论文完全没有服务器聚合、客户端采样、拜占庭鲁棒聚合、裁剪或范数过滤的概念，因此它不能说明该后门在带这些机制的联邦 LoRA 聚合管线下是否仍然有效。

## 10. 对防护库设计的含义

1. 分析：采集底座需要在"客户端每一步"这个信任边界上提供可训练参数的快照与相邻步差分视图，并支持按层或按模块切片。本攻击唯一的直接痕迹是对本地参数施加的周期性加性方向（Algorithm 1 第 9 行），所以"步级参数差分"和"与基座模型的差向量"应当作为与攻击无关的通用采集原语，而不是某个插件私有的逻辑。
2. 分析：库需要跨轮、跨步的历史更新存储与按客户端、模块、轮次建立索引的查询能力。论文的最佳设置是小剂量、周期性的注入（w_a = 0.1，fq_a = 25），单步几乎不可分辨，只有把同一客户端同一模块的多次跳变拼成时间序列才可能暴露周期性，因此历史存储是通用需求。
3. 分析：库需要评估或红队探测钩子，能够在推理时注入候选触发词（本论文是加在提示末尾的 SUDO）并采集输出安全判定，因为无触发词时攻击不显现（Figure 2b）。探测框架本身是通用需求，而"触发词是 SUDO、位置在提示末尾"是这篇论文特有的知识。
4. 分析：样本级数据过滤类插件对本攻击无效，因为攻击者完全不接触数据，训练数据流上看不到任何异常（Abstract、Section 2）。库应把"不经过数据的攻击"当作一等公民，避免把所有检测能力都挂在数据钩子上。
5. 分析：论文没有给出任何检测或干预，因此剔除客户端、重新加权、裁剪、回滚、追加安全对齐等干预接口都需要库自己定义。论文唯一能支撑的动作是"回滚到较早快照并追加对齐训练"，而且它反过来说明一次性注入可以被安全对齐抹掉、周期性注入不能（Section 3.1），所以回滚粒度需要细到轮或步这一级。
6. 分析：论文的全部阈值与结论来自单一模型、单一划分（四阶段，每阶段四层）与单一被控阶段（第二阶段），并明确把 LoRA 与参数高效后训练列为未完成的未来工作（Section 4）。库不应把本文的参数或结论当作联邦 LoRA 场景的经验常数，只应把它当作威胁假设与观测点清单的来源。
