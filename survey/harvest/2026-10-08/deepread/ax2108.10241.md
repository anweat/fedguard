# ax2108.10241：Back to the Drawing Board: A Critical Evaluation of Poisoning Attacks on Production Federated Learning

## 1. 基本信息

- **场景**：传统联邦学习（federated learning, FL），并且明确区分 cross-device FL 与 cross-silo FL（Section III-B1）。论文不涉及集中式大模型训练，不涉及联邦大模型微调，也不涉及参数高效微调（parameter-efficient fine-tuning, PEFT）或 LoRA（低秩适配）；三个数据集都是图像或类别特征表格数据。论文标题与摘要说明其发表于 IEEE Symposium on Security & Privacy 2022，arXiv 版本为 2108.10241v2。
- **训练阶段**：覆盖 FL 全流程——客户端本地数据准备、客户端本地训练、更新上传前的处理、服务器聚合（aggregation rule, AGR）、全局模型下发，以及评估阶段对全局模型准确率的度量。
- **论文类型**：攻击（attack），同时是一篇威胁模型系统化与"关键评估"性质的论文：它提出新的数据投毒（data poisoning attack, DPA）与模型投毒（model poisoning attack, MPA）攻击，并用它们系统评估已有的稳健聚合规则（Section I 的贡献 I、II、III）。
- **模型与数据规模**（Appendix C）：FEMNIST 字符识别，62 类，671,585 张灰度图，3,400 个原始客户端再按 Dirichlet（α=1）拆成 p ∈ {2, 5, 10} 份非独立同分布（non-iid）分片，默认 p=10 时共 34,000 个客户端，模型为 LeNet；CIFAR10，10 类，60,000 张 32×32 彩色图（50,000 训练 / 10,000 测试），1,000 个客户端，模型为带 batch normalization 的 VGG9；Purchase，100 类，197,324 条长度 600 的二值特征向量（187,324 训练，验证集与测试集各 5,000），5,000 个客户端，模型为层大小 {600, 1024, 100} 的全连接网络。论文另外给出生产 FL 的参数范围（Table III）：cross-device 的客户端总数 N 为 [10³, 10¹⁰] 量级，cross-silo 为 [2, 100]。

## 2. 威胁模型

**攻击者是谁**：被攻陷的 FL 客户端（compromised clients）。论文不考虑恶意服务器，也不涉及数据提供方或适配器/模型发布者；它明确假设生产系统已经防御了 Sybil 攻击等标准攻击向量（Section III-B1）。

**占比或数量**：论文主张的实际范围是数据投毒攻击者 M ≤ 0.1%、模型投毒攻击者 M ≤ 0.01%，而既有文献常用 [20, 50]%（Table III）。实验里评估到 M=10%（Figure 4）与 M=1%（Figure 5、Figure 10）。论文给出的理由是：攻破设备并长期驻留的模型投毒代价极高，而只污染本地数据的投毒只需很少权限，因此后者能覆盖更大比例的客户端（Section III-B3、III-C）。

**能力（能改什么）**（Section III-A3）：
- 数据投毒（data poisoning, DP）：不攻破设备，只能篡改被攻陷客户端的本地数据，由客户端自己用这些数据算出投毒更新；论文称之为对更新的"间接操纵"。
- 模型投毒（model poisoning, MP）：攻破设备（例如绕过 Android 等操作系统的安全协议）后直接操纵模型更新。
- 攻击模式分为 offline（只在 FL 开始前投毒一次，例如标签翻转）与 online（在 FL 过程中反复、自适应地投毒，例如模型投毒）（Table II）。
- 论文额外假设被攻陷客户端可以串通，交换本地数据与模型更新（Section III-A3）。

**知识（知道什么）**：
- 对全局模型：数据投毒者是 nobox（不知道架构、参数与输出）；模型投毒者是 whitebox（知道参数与预测），且"只要服务器在该轮至少选中一个被攻陷客户端"就成立（Section III-A2、III-C2）。
- 对良性分布数据：论文只考虑 partial，即只知道被攻陷客户端自己的本地良性数据，不知道良性客户端的数据（Section III-A2）。
- 对服务器：论文假设攻击者知道聚合规则，并按其鲁棒性判据定制攻击；按 Kerckhoffs 原则假设攻击者知道 Norm-bounding 的阈值 τ（Section III-C1、IV-B3）。

**目标**：无目标投毒（untargeted poisoning），即"indiscriminate availability"攻击、错误标签不限（generic error specificity），目的是降低全体客户端与任意测试输入上的全局模型准确率（Section III-A1、Figure 1）。论文明确不研究定向（targeted）与后门（backdoor）攻击，只在 Appendix A 里综述。

**实际威胁模型**：论文从八个维度组合（Table IV）中判定只有 T4（nobox offline data poison）与 T5（whitebox online model poison）有实际意义（Section III-B2），并分别对应 Section III-C1 与 III-C2。需要指出一处原文不一致：正文 III-C 与 III-C1/III-C2 把 T4 记为 nobox offline data poison、T5 记为 whitebox online model poison，Section IV-A2 又称 whitebox online model poisoning 为 T4，而抽取出的 Table IV 行标签把 T4 标为 Model poison/Whitebox/Online、T5 标为 Data poison/Nobox/Offline。本报告以正文 III-C 的命名与描述为准。

**防御者是谁、能看到什么、信任什么**：防御者是服务器及其聚合规则。服务器能看到每个客户端上传的更新 ∇k = θk − θg（Section II-A）以及每轮被选中的客户端集合，但论文明确说服务器看不到客户端的本地数据内容与数据量（Section IV-B2）。Trimmed-mean 与 Multi-krum 还需要每轮的被攻陷客户端数 m：Trimmed-mean 要去掉 m 个最大值与 m 个最小值，Multi-krum 要满足 n − c > 2m + 2（Section II-C3、II-C4），但论文未说明服务器如何获得 m。防御者所信任的，是稳健 AGR 的鲁棒性判据本身，以及在 cross-silo 中"机构客户受合同约束、软件栈专业维护"这一社会性判断（Section V-D）。

## 3. 攻击入口与流程位置

论文的攻击从两个位置进入，且都不进入服务器聚合、全局模型下发或评估部署环节（服务器只是被攻击的目标）。

**（1）本地数据准备（数据投毒）**（Section IV-B2、IV-A1）：
- static label flipping（SLF）：对样本 (x, y)，若类数 C 为偶数则把真标签翻到 C−1−y，若 C 为奇数则翻到 C−y。
- dynamic label flipping（DLF）：先用可得的良性数据训练一个代理模型 θ̂ 作为全局模型 θg 的估计，再把标签翻到 θ̂ 下最不可能的类别，即 argmin θ̂(x)。
- 为了把投毒数据量 |Dp| 做大（攻击 Average 与 Norm-bounding 时需要），论文把被攻陷客户端的良性数据合并后翻转标签，并对已有特征向量加高斯噪声生成新的特征向量再翻转其标签；Purchase 这类类别特征还要取整（Section IV-B2、Appendix C）。
- 该入口是 offline 的：投毒只在 FL 训练开始前做一次。

**（2）本地训练过程 + 更新上传前的后处理（模型投毒，PGA）**（Section IV-B3、Algorithm 1、Algorithm 2）：
- 本地训练过程：把本地微调从 SGD 换成随机梯度上升（stochastic gradient ascent, SGA），用良性梯度方向的反向 −∇θL(θ; b) 去"增大"良性数据 Db 上的损失，得到恶意模型 θ′。
- 更新上传前的后处理：计算 ∇′ = θ′ − θg，再用 fproject 对其做缩放或投影以绕过目标 AGR 的鲁棒性判据。对 Average 直接把 ∇′ 乘任意大常数（论文举例 10²⁰）；对 Norm-bounding 把 ∇′ 缩放到范数 τ；对 Multi-krum 搜索使被选入集合 S 的投毒更新数最多的 γ（公式 (4)）；对 Trimmed-mean 把该 AGR 直接代入 Algorithm 2 第 8 行。
- 该入口是 online 的：每一轮被选中时都可重新投毒。

## 4. 方法原理

**核心思想**（Section IV-B1，公式 (1)）：把投毒形式化为最大化"投毒聚合"与"良性聚合"之间距离的问题，即在 ∇′ ∈ R^d 上求 argmax ‖∇b − ∇p‖，其中 ∇b = favg(∇_{i∈[n′]}) 是只用攻击者可获得的良性更新算出的参考良性聚合，∇p = fagr(∇′_{i∈[m]}, ∇_{i∈[n′]}) 是 m 份投毒更新副本与良性更新一起过目标 AGR 后的投毒聚合。论文强调与 [55] 的两点区别：第一次用该式系统构造数据投毒；模型投毒不仅对 AGR 定制，还对具体数据集与全局模型定制。

**数据投毒**（Section IV-B2，公式 (2)）：argmax over Dp ⊂ D of ‖∇b − ∇p‖，其中 ∇′ = A(Dp, θg) − θg，A 是训练算法（例如 mini-batch SGD）。直觉是：用 Dp 微调 θg 得到的 θ′ 在良性数据 Db 上损失高，对应的更新 ∇′ 也会偏离良性方向。Figure 2 给出关键经验规律：|Dp| 越大，投毒更新的损失越高（Figure 2a）、范数越大（Figure 2b）、Trimmed-mean 的目标值越大（Figure 2c）；但对 Multi-krum 相反，|Dp| 略高于 |D|avg 时大部分投毒更新会被丢弃，只有 |Dp| 很小（约 10）时 Multi-krum 才会选中大多数投毒更新（Figure 2d）。论文的核心手法因此是调节 |Dp| 来适配目标 AGR：Average 与 Norm-bounding 用大 |Dp|；Multi-krum 在 |Dp| ∈ [0.5·|D|avg, 3·|D|avg] 内采样、每个 |Dp| 重复 10 次并报告影响最大者；Trimmed-mean 也用大 |Dp|（Section IV-B2、Appendix B1）。

**模型投毒 PGA**（Section IV-B3、Algorithm 1、Algorithm 2）：先计算可用良性更新范数的平均 τ（若目标是 Norm-bounding，τ 就直接取该 AGR 的给定阈值），再用 SGA 在 Dp 上微调 θg 得到 θ′，令 ∇′ = θ′ − θg，然后用 fproject 把 ∇′ 缩放到范数 τ，对 γ ∈ [1, Γ]（步长 δ）逐一计算偏差 d = ‖fagr(γ∇′_{i∈[m]}, ∇_{i∈[n′]}) − ∇b‖，取使 d 最大的 γ\*，输出 γ\*∇′。Figure 3 说明其想法：γ 太大时（例如 4、5）会被稳健聚合直接丢弃，太小时（例如 1、2）没有影响，需要找中间的缩放。论文称该攻击是模块化的，把任意目标 AGR 插进 Algorithm 2 即可攻击。**论文未说明** Γ 与 δ 的具体取值，也未说明 τ 在服务器端如何选取。

## 5. 检测或防御所需的数据

先说明：本文是攻击论文，本身不提出新的检测器；它评估的"方法"是服务器端聚合规则（Average、Norm-bounding、Multi-krum、Trimmed-mean），另外建议两条简单防御（限制客户端本地数据量、保证客户端平均数据量）。因此下面既列出被评估防御所需的输入，也列出攻击自身的输入与攻击留下的痕迹。

1. **每个客户端的模型更新 ∇k = θk − θg**
   - 是什么：客户端本地训练后模型与下发全局模型的差，也就是要上传的更新向量。
   - 在哪里采集：客户端训练后、服务器收到更新时（server_receive）。
   - 粒度：逐客户端、逐参数/逐层（d 维向量）。
   - 是否需要跨轮历史：不需要；各 AGR 都只处理当前轮的更新，论文未说明需要历史更新。
   - 是否需要干净参考数据：不需要。是否需要额外前向/反向计算：不需要，更新本身就是 FL 的常规上传物。

2. **每个更新的 L2 范数 ‖∇‖₂**
   - 是什么：Norm-bounding 的唯一判据，其直觉是"有效的投毒更新范数应当偏高"（Section II-C2）。
   - 在哪里采集：服务器收到更新时。粒度：逐客户端、每轮一个标量。
   - 历史/干净参考/额外计算：都不需要，只多一次求范数。
   - 论文未说明阈值 τ 的选取方法，也未说明 τ 是否逐轮调整。

3. **每一维度上各客户端取值的排序与两端极值**
   - 是什么：Trimmed-mean 对第 j 维把 n 个取值排序，去掉 m 个最大与 m 个最小，再对剩余取平均（Section II-C4）。
   - 在哪里采集：服务器聚合时。粒度：逐维度、逐客户端集合、每轮。
   - 额外计算：需要排序，论文给出复杂度 O(dn log n)（Table I、Section V-B2）。需要知道 m。

4. **客户端更新两两之间的欧氏距离**
   - 是什么：Multi-krum 用 Krum 逐个选出更新加入集合 S，直到 |S| = c 且 n − c > 2m + 2，再对 S 取平均（Section II-C3）。
   - 在哪里采集：服务器聚合时。粒度：客户端对级、每轮。
   - 额外计算：需要 O(dn²) 的两两距离（Table I、Section V-B2）。需要知道 m。

5. **每轮被选中的客户端数 n 与被攻陷客户端数 m（或其上界）**
   - 是什么：Trimmed-mean 按 m 裁剪，Multi-krum 需要 n − c > 2m + 2。
   - 在哪里采集：服务器聚合时。粒度：轮级。
   - 论文未说明服务器如何得知或估计 m。

6. **Norm-bounding 的阈值 τ**
   - 是什么：把更新范数缩放到 τ 的固定阈值（Section II-C2）。在哪里采集：服务器聚合时使用的配置。
   - 粒度：全局标量。论文未说明其选取方法。

7. **每个客户端的本地数据集大小 |Dk|**
   - 是什么：论文建议把"限制每个客户端本地数据集大小"作为对抗数据投毒的简单防御（Takeaway V-C1），并指出下界化客户端平均数据量也能提升鲁棒性（Section V-C2）。
   - 在哪里采集：逻辑上在服务器接收客户端元数据或更新时；但论文同时说服务器看不到客户端数据与数据大小（Section IV-B2），并未说明该上限由谁、以什么机制获得与强制执行。粒度：逐客户端、每轮。论文未说明是否需要额外计算或干净参考数据。

8. **攻击自身需要的输入**（对防护库而言是要防住的行为所依赖的资源）
   - 被攻陷客户端的良性本地数据与由它算出的"可用良性更新" ∇_{i∈[n′]}：公式 (1) 下方明确说这些是"攻击者可获得的良性更新（例如用被攻陷客户端的良性数据算出的更新）"，因此攻击者不需要看到其他良性客户端的真实更新。
   - 模型投毒还需要全局模型参数与预测 θg（客户端每轮收到全局模型时；whitebox 仅在该轮被选中时成立）、目标 AGR 的实现；LIE 还需要可用良性更新的平均 ∇b 与标准差 σ（Section IV-A2）。
   - DLF 还需要一个自行训练的代理模型 θ̂（Section IV-B2）。
   - 对 Multi-krum 与 Trimmed-mean 的定制，需要在本地反复模拟目标 AGR，即 Algorithm 2 中 γ 搜索带来的额外聚合计算。

9. **评估侧数据**
   - 是什么：每轮全局模型在留出测试集上的准确率，用来计算 Aθ（无攻击时的最高准确率）与 A\*θ（攻击下的最高准确率），进而得到攻击影响 Iθ = Aθ − A\*θ（Section V）。
   - 在哪里采集：评估时。粒度：逐轮、模型级。需要干净的测试集（FEMNIST/CIFAR10 用标准测试集，Purchase 的验证与测试集各 5,000，Appendix C）。

**攻击留下的可观测量**：数据投毒主要在"更新"上留下范数变大、方向偏离良性聚合、在良性数据上损失偏高的痕迹（Section IV-B2、Figure 2a/2b）；标签本身的改动只在客户端本地，服务器是 nobox，看不到。模型投毒的痕迹同样包括范数异常（Norm-bounding 正是基于"投毒更新范数高"的直觉）与方向偏离。

**论文声称能绕过的检测/判据**：对 Norm-bounding，用调节 |Dp| 或把 ∇′ 缩放到 τ 使范数检查通过（Section IV-B2、IV-B3、Algorithm 2 第 4 行）；对 Trimmed-mean，把该 AGR 代入 Algorithm 2 第 8 行搜索 γ（Appendix B2）；对 Multi-krum，最大化被选入 S 的投毒更新数（公式 (3)、(4)）；对 Average，直接使用任意大的更新（Section IV-B3）。论文同时报告这些绕过在实际 M 下效果有限，稳健 AGR 依然高度鲁棒（Section V-B、Figure 4b）。论文**未评估**任何基于统计检测、聚类或异常分数的检测器；Appendix A2 只提到 FoolsGold 会造成很大的性能损失，属于相关工作讨论。

## 6. 干预动作

本文是攻击论文，因此这里的"干预"是它所评估与推荐的服务器端动作。

- **Average（非鲁棒）**：不做任何干预，直接对客户端更新取平均（Section II-C1）；论文指出它是生产 FL 中唯一被实际部署的 AGR。
- **Norm-bounding**：在服务器聚合时对每个更新做范数裁剪或缩放——若 ‖∇‖₂ > τ，则把 ∇ 乘以 τ/‖∇‖₂，否则不变，然后对所有（缩放后的）更新取平均（Section II-C2）。
- **Multi-krum**：向量级过滤，选出一个子集 S 并只对 S 内更新取平均，等价于剔除未被选中的客户端（Section II-C3）。
- **Trimmed-mean**：逐维度过滤，对每一维去掉 m 个最大值与 m 个最小值后取平均（Section II-C4），即截断极端坐标值而不是剔除整个客户端。
- **论文额外推荐的两条简单防御**（不是新算法）：限制每个客户端本地数据集大小的上限（Takeaway V-C1），以及保证或下界化客户端平均数据量 |D|avg（Section V-C2）。论文未说明这两条在生产系统中具体如何执行。
- 论文把个性化防御（Ditto、EWC）列为与本文评估正交：只有在全局模型未被严重污染时才有用，必须与稳健 AGR 配合（Section II-C）。

动作发生的位置：全部在服务器端（收到更新时或聚合时）；客户端侧在本论文中不承担任何检测或防御动作。

## 7. 实验设置与主要结果

**设置**（Appendix C）：三个数据集与模型见第 1 节。FEMNIST：500 轮，批大小 β=10，本地 epoch E=5，第 e 轮学习率 η = 0.1 × 0.995^e，每轮选 n=50，N=34,000，无攻击基线准确率 Aθ=82.4%。CIFAR10：1,000 轮，β=8，E=2，SGD 动量 0.9，η = 0.01 × 0.9995^e，n=25，N=1,000，Aθ=86.6%。Purchase：500 轮，β=10，E=5，η = 0.1 × 0.999^e，n=25，N=5,000，Aθ=81.2%。数据用 Dirichlet（α=1）划分，属极端 non-iid。cross-silo 实验用 N=n=50（Section III-B3、V-D）。指标是攻击影响 Iθ = Aθ − A\*θ，即全局模型最高准确率的下降（Section V）。

**主要结果**：
- 实际 M 下连 Average 都高度鲁棒：FEMNIST 上 M=0.01% 时模型投毒的 Iθ 约 2%，M=0.1% 时数据投毒约 5%，与之对照的无攻击准确率是 82.3%（Section V-A、Figure 4a）。Introduction 给出的对照数字是：数据投毒 M=0.1%（模型投毒 M=0.01%）把 FEMNIST 从 83.4% 降到 81.4%（73.4%），CIFAR10 从 86.6% 降到 85.1%（82.9%），Purchase 从 85.4% 降到 85.3%（76.4%）。需要指出原文数字前后不一致：同一篇里 FEMNIST 的无攻击准确率出现 83.4%（Introduction）、82.3%（Section V-A）与 82.4%（Appendix C）三个值，Purchase 出现 85.4%（Introduction）与 81.2%（Appendix C）两个值。
- 稳健 AGR 在实际 M 下几乎不受影响：M ≤ 0.1%（数据投毒）与 M ≤ 0.01%（模型投毒）时，三个数据集上所有已有攻击的 Iθ ≤ 1%（Section V-B、Figure 4b）；M ≤ 1% 时所有 AGR 的 Iθ < 1%（Section V-B2）。
- 长时间持续投毒也打不穿：用 5,000 轮、M=0.1% 的最强模型投毒，Multi-krum 与 Trimmed-mean 完全不受影响（全局准确率反而上升），Norm-bounding 的准确率下降 <5%（Section V-B1、Figure 6）。
- 稳健 AGR 的实测鲁棒性低于其理论承诺：理论上 Multi-krum 与 Trimmed-mean 在 M ≤ 25% 时鲁棒，但在 M=10% 时 FEMNIST 上 Trimmed-mean 的 Iθ 反而高于 Norm-bounding，CIFAR10 上两者接近（Section V-B3）。
- |Dp| 的影响：|D|avg 在 FEMNIST/CIFAR10 约为 20/50（Section V-C1；Appendix B1 另给 FEMNIST 的 |D|avg = 23.7，与前者不一致）。在 |Dp| ∈ {1, 10, 10², 10³, 10⁴}·|D|avg 下，Iθ 随 |Dp| 略有上升，但在实际 |Dp| 与实际 M（M ≤ 1%）下即使 1000×|D|avg 也可忽略（Section V-C1、Figure 5）；论文在 Section V-A 为寻找数据投毒的最强影响用了 |Dp| = 20,000（FEMNIST）、50,000（CIFAR10）、20,000（Purchase）。
- n 的影响：改变每轮选择的客户端数 n 对攻击影响没有明显作用，例外是 Average 上的模型投毒——只要该轮选到一个被攻陷客户端就能阻止全局模型继续学习，n 越大概率越高，攻击越强（M=1%，Section V-C3、Figure 10）。
- 未知架构：DLF 依赖代理模型，若代理结构与真实全局模型不一致（用 Table V 的卷积网络替代 LeNet），攻击影响下降（Section V-C4、Figure 7）。
- Cross-silo：论文认为模型投毒在实际中不可行，数据投毒在 Average 上也没有影响（Section V-D、Figure 8）。以 50 个 silo、50 个被攻陷用户为例，无论把投毒用户均匀分散还是集中在少数 silo，结果相同，原因是大量良性 silo 或每个 silo 内大量良性用户稀释了投毒影响。
- Table I 在 CIFAR10、1,000 客户端下给出的非 iid 准确率：Average 86.6、Median 84.2、Trimmed-mean 86.6、Sign-SGD + majority voting 35.1、Norm-bound 86.6、Krum 46.9、Multi-krum 86.2、Bulyan 81.1、RFA 84.6、RSA 35.6、DnC 86.1、Ensemble 74.2、CRFL 64.1、Ditto/EWC 86.6。

## 8. 开销

论文报告了被评估聚合规则在服务器端的计算复杂度与客户端内存开销（Table I，CIFAR10、1,000 客户端）：Average 计算 O(d)、客户端内存 O(d)；Median 计算 O(dn log n)；Trimmed-mean 计算 O(dn log n)、内存 O(d)；Norm-bounding 计算 O(d)、内存 O(d)；Krum、Multi-krum、Bulyan、RFA 计算均为 O(dn²)、内存 O(d)；RSA O(d)；DnC O(d)；Ensemble O(d)；CRFL 计算 O(d)、客户端内存 O(Md)；知识迁移类（Cronus）O(d) 但需要公共数据；Ditto/EWC O(d)。论文另外指出，当 n 可达 5,000 时，Mkrum 的 O(dn²) 与 Trmean 的 O(dn log n) 在生产中不可接受，而 Norm-bounding 与 Average 同阶（Section V-B2）。

**论文未报告**：通信开销的数值、存储开销的数值、攻击本身的墙钟时间或显存开销、DLF 训练代理模型与 PGA 的 γ 搜索的实际运行成本（只在 Algorithm 2 中说明要对 γ ∈ [1, Γ] 逐一调用 fagr，因此每轮攻击需要多次模拟聚合）。数据投毒中高斯噪声的参数与生成的新特征向量数量也未报告。

## 9. 假设、局限与自适应攻击

**论文成立所依赖的假设**：
- 服务器看不到客户端的数据内容与数据量（Section IV-B2）；但 Section V-C1 又建议用"限制本地数据集大小"作为防御，论文未说明该限制如何被服务器获知与强制执行。
- 攻击者只知道被攻陷客户端自己的良性数据（partial knowledge），不知道良性客户端的数据（Section III-A2）。
- 数据投毒者不知道全局模型架构、参数与输出（nobox）；模型投毒者知道参数与预测，只要该轮至少被选中一次（whitebox，Section III-A2、III-C2）。Section V-C4 额外检验了代理结构与真实结构不一致时 DLF 的效果下降。
- 攻击者知道服务器 AGR，并按 Kerckhoffs 原则知道 Norm-bounding 的阈值 τ（Section III-C1、IV-B3）；论文未说明 τ 在服务器端如何设定。
- 被攻陷客户端可以串通并交换本地数据与更新（Section III-A3）。
- 生产系统已防御 Sybil 等标准攻击向量；Table III 的实际 M 范围来自调查文献 [11][32] 与 FL 专家讨论 [24]，属于外部经验假设。
- 设备端推理模型与训练模型不同，因此查询推理模型拿不到训练模型的信息（Section III-B1）。
- cross-silo 的客户端是受合同约束、软件栈专业维护的机构，因此模型投毒不可行（Section V-D）。
- cross-silo 的数据投毒假设每个 silo 收集相同数量用户的数据，每个被攻陷用户贡献 |Dp| = 100 × |D|avg（Section V-D）。

**论文自述的局限**：真实生产 FL 数据集是专有的、不可公开获取，因此只能使用图像与类别特征基准（Appendix C）；"在只随机选取一小部分客户端的生产 FL 下为现有防御给出具体理论鲁棒性保证"被列为开放问题（Section VI）；若 silo 会检查并剔除误标数据，则需要研究 clean-label 数据投毒，论文把它留给未来工作（Section V-D）；由于篇幅，部分 DPA/MPA 细节与实验解释放在附录。

**自适应攻击**：论文评估了自适应攻击者。论文的攻击本身就是针对目标 AGR 定制的自适应攻击——公式 (1) 对给定 AGR 求解，PGA 的 fproject 为每个 AGR 单独裁剪，Appendix B2 给出 Multi-krum 与 Trimmed-mean 的定制版本，Section IV-B1 明确说模型投毒"不仅对给定 AGR 定制，还对给定数据集和全局模型定制"。论文还用 5,000 轮持续投毒检验长期自适应攻击（Section V-B1），并用未知架构检验 DLF 对模型假设的稳健性（Section V-C4）。但论文未评估"防御方在知道 PGA 后反过来调整防御"的自适应防御，例如改变 τ、改变对 m 的估计或切换到检测型防御。

**迁移到联邦大模型 LoRA 微调时可能失效的假设（以下均为分析）**：
- 分析：论文"cross-device 采样带来固有鲁棒性"（Section V-A）依赖 n ≪ N。联邦大模型 LoRA 微调通常是 cross-silo、客户端数少且每轮全参与（n = N），这一鲁棒性来源直接消失；而论文认为 cross-silo 模型投毒不可行，是建立在"攻破公司极难"的社会性假设上，不构成技术防护。
- 分析：论文的实际 M 上界（数据投毒 ≤ 0.1%、模型投毒 ≤ 0.01%）来自移动端十亿级装机量的场景。若联邦 LoRA 只有几十个机构客户端，0.1% 连一个客户端都不到，威胁模型需要重新标定；反过来，单个恶意客户端在 M 上的占比会远高于论文的实验范围。
- 分析：论文的核心可观测量是整个模型更新向量的范数与逐维取值。LoRA 只更新低秩增量（B·A），可用参数子空间远小于 d，不同客户端与不同秩配置下增量范数量级差异很大；Norm-bounding 的 τ 选取与 Trimmed-mean 的逐维裁剪在低秩增量上的统计行为论文完全没有涉及。
- 分析：论文主张"Norm-bounding 与 Average 同阶因此可用于生产"，这一结论在 LoRA 场景下反而更可能成立；但 Multi-krum 的 O(dn²) 与 Trimmed-mean 的 O(dn log n) 是按 LeNet/VGG9 规模给出的，迁移到十亿参数级基座模型时需要重新设计。
- 分析：论文的数据投毒建立在"可以翻转标签"的假设上，而指令微调数据的"标签"是回答 token，标签翻转的语义与可行性论文未说明；论文"对特征加高斯噪声再翻转标签"的手法在离散 token 上也没有对应定义。
- 分析：论文假设设备上推理模型与训练模型不同（nobox）。在联邦 LoRA 中，客户端需要下载基座模型与适配器才能训练，任何被选中的客户端都直接拿到全局适配器参数，whitebox 访问的门槛比论文假设的"必须攻破设备"低得多。
- 分析：论文用"全局模型在测试集上的最高准确率下降 Iθ"衡量攻击，并强调小幅准确率下降在生产中难以被发现（Section III-A1）。LoRA 指令微调的评价噪声通常更大，同样的度量方式更难支撑检测结论。
- 分析：论文完全没有考虑适配器或模型发布的供应链入口（基座模型或预训练适配器被投毒），该入口在联邦 LoRA 微调的防护库里是独立且论文未覆盖的。

## 10. 对防护库设计的含义

- 分析：采集底座需要在"服务器收到更新时"提供一个固定钩子，把每个客户端的原始更新向量 ∇k（按客户端 id、轮次、逐层/逐参数）完整落盘，并同时记录该轮的客户端集合 n 与被选中者元数据。这是本论文所有被评估防御（Average、Norm-bounding、Multi-krum、Trimmed-mean）共同的最小数据视图，属于通用需求。
- 分析：同一个钩子上还要能廉价派生标量视图——逐客户端 L2 范数、逐维度的排序/分位数、客户端两两距离矩阵，分别对应 Norm-bounding、Trimmed-mean 与 Multi-krum 插件。库应把"原始更新"与"派生统计量"分成两层缓存，避免每个插件重复计算 O(dn²) 的距离矩阵。
- 分析：论文建议的"限制客户端本地数据集大小"（Takeaway V-C1）要求库在客户端训练前或训练后多采集一项数据量元数据，并提供服务器侧策略接口来设定与强制执行上限。但论文没有说明这种元数据如何可信上报，库需要显式区分"客户端自报"与"服务器可验证"两种来源，否则该防御可被谎报绕过。
- 分析：要防御本论文的模型投毒（PGA），需要的是逐轮更新的范数与方向偏离度的时序视图，以及对 Norm-bounding 阈值 τ 的配置管理。论文把 τ 当作外部给定常量，库必须把 τ 做成显式、可审计的插件参数并记录历次取值，否则无法在"攻击者知道 τ"的前提下复现或检验鲁棒性结论。
- 分析：干预接口至少需要三类服务器钩子动作——按客户端剔除（Multi-krum 的选择集合）、按更新缩放或裁剪（Norm-bounding）、按坐标截断（Trimmed-mean），它们都发生在服务器收到更新之后、聚合前后；客户端钩子在本论文范围内只承担采集，不承担防御。
- 分析：论文特有的需求是"攻击侧视图"：要复现或评估 PGA 这类自适应攻击，库需要支持在客户端侧做 SGA 微调、在本地用被攻陷客户端的良性数据造出"可用良性更新"以估计 τ 与 ∇b、并反复调用目标 AGR 的模拟函数做 γ 搜索。这一条只服务于攻击评估，不是通用防护需求，但它是判断防护插件是否会被自适应攻击绕过的必要设施。
