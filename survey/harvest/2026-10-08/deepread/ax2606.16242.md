# ax2606.16242：Rapid Poison: Practical Poisoning Attacks Against the Rapid Response Framework

## 1. 基本信息

- **场景**：集中式大模型微调（centralized LLM fine-tuning），**不是联邦学习**。论文攻击的是 Rapid Response（RR，快速响应）框架（Peng et al., 2024）：该框架把在野捕获的越狱（jailbreak）样本作为“参考”（reference）送入增殖（proliferation）模型，由后者批量改写生成合成变体，再用这些合成数据持续微调一个越狱检测分类器（第 2 节 Preliminaries；图 1）。全文没有任何客户端、客户端更新、服务器聚合或参与率的概念。
- **训练阶段**：数据准备（参考样本提交与验证、增殖生成合成训练集）→ 监督微调（LoRA/QLoRA 微调守护模型）→ 评估与部署（推理时注入触发器触发后门）。
- **论文类型**：攻击（attack）。论文在第 7 节评估了两类防御（输入侧检测净化、模型级抗提示注入的增殖模型），并在附录 D.6 讨论缓解措施，但没有提出新的检测算法。
- **模型与数据规模**：守护模型为 LlamaGuard 4 12B（Meta, 2025），使用参数高效 LoRA 与 QLoRA 4-bit NF4 在 NVIDIA A100 上微调（亦可跑在 RTX A5000），LoRA 作用于 attention 与 MLP projection 层，秩 r = 32、缩放 α = 32、dropout = 0.0、最大序列长度 2048（附录 A）。增殖模型为 Gemini 2.5 与 3 的 Flash 与 Pro 变体（第 4.1 节）。参考越狱来自 PAIR、Cipher、Crescendo 三种攻击方法，每种 300 条参考、生成 1000 条合成变体（第 4.1 节；附录 E）。总训练集为 6000 条，即 3000 条增殖越狱加 3000 条 WildChat 安全查询（第 2.1 节）。评测数据包括 AdvBench 100 条有害查询、PAIR/Cipher/Crescendo 各 150 条、MMLU、GPQA、WildChat 验证集 n=1000、WildChat-4.8M 新留出集 n=1000、XSTest-SAFE n=250、LM-SYS-CHAT n=779、SWE-Bench Verified（第 5.4、6、7 节）。

## 2. 威胁模型

**攻击者是谁**：向 RR 增殖流水线提交越狱参考的外部提交方，即充当训练数据提供方（data provider）。论文的表述是攻击者“向 RR 的增殖流水线提交越狱样本”，并“控制用于提示增殖模型的所有参考中的一小部分”（第 2.1 节）。论文没有把攻击者建模为联邦客户端、服务器或适配器发布者。

**占比或数量**：以 6000 条训练样本为基数定义投毒率（第 2.1 节）。主实验为 1% 投毒，即 18 条被投毒的参考（第 2.1 节；附录 E 公式 2）。分布型假阳性攻击的消融覆盖 1%、5%、10%、12.5%、16.7%（图 6）；零样本投毒的消融最高到 5%（附录 D.1）。论文强调报告值是上界，因为提示注入并非每次成功（第 2.1 节；附录 E 公式 5）。

**能力**：(a) 向增殖流水线提交越狱；(b) 任意修改越狱内容，只要仍满足两个条件——“仍然有害”且“仍试图诱导原目标”，这两个条件由独立的裁判模型（judge model）判定（第 2.1 节；附录 H）。核心限制是攻击者只能篡改正类（unsafe）样本，不能改良性数据，也不能改标签（摘要；第 1 节）。

**知识**：攻击者需要知道 RR 流水线的结构，特别是验证与增殖使用不同上下文这一不对称性，并据此写出检测“生成变体”“derive prompt”等增殖线索的条件分支（第 3.1 节；附录 B）。论文未说明攻击者是否需要知道守护模型架构、超参数或训练轮次。

**目标**：两类。(I) 效用退化（utility degradation），在良性查询上制造假阳性（false positive），包括面向格式、领域、实体名称的定向攻击与面向一般用户查询的无目标（untargeted）攻击，属于可用性攻击（第 2.2 节）。(II) 安全退化（safety degradation），通过概念型后门（concept-based backdoor）让真正的越狱被判为安全，产生假阴性（第 2.2 节；第 3.3 节）。

**防御者是谁、能看到什么、信任什么**：防御者是 RR 流水线的运营方。它能看到的包括：提交的参考原文（在增殖前用 LLM 检查，第 7 节 Defense I）、增殖模型生成的合成输出、训练集及其标签、留出验证集上的准确率（附录 A）、以及微调后守护模型的输入输出与内部激活（附录 F）。防御者信任的是：提交的参考确实是越狱、验证阶段的行为能代表增殖阶段的行为、以及独立裁判模型对“有害/同一行为”的判定（第 2.1 节；附录 H）。

## 3. 攻击入口与流程位置

攻击入口是**本地数据准备阶段**（对应库的采集分类中的 local_data），具体是“参考越狱提交与增殖生成训练数据”这一步；后门的**触发**发生在**评估与部署阶段**（evaluation_deployment），即推理时把概念词加入有害查询。

具体操作步骤：

1. 选定要利用的目标概念或特征：格式（多选题、JSON、HTML、YAML、纯文本）、领域（如 professional law）、实体名（如 ChatGPT）、或一般良性分布（第 5.1 至 5.4 节）；安全退化目标则选一个概念 C（如生成式 AI 助手、类人写作风格、Harry Potter 角色）（第 3.3、6.1、6.2 节）。
2. 收集含该特征的良性查询作为少样本示例。对 Omission Attack，先用正则或 LLM 抽取把概念 C 从这些良性查询中移除，得到“概念缺席”的样本（第 3.3 节；图 14）。
3. 把条件式提示注入（if-else prompt injection）嵌入一条真实的越狱参考中，写入很少的几条参考即可：IF 分支在识别到增殖上下文时覆盖原任务，改为从攻击者准备的少样本示例中均匀采样输出；ELSE 分支保持不变，照常执行原始越狱载荷（第 3.1 节；图 2、图 29、图 30）。
4. 提交这些参考。防御者验证时走 ELSE 分支，参考仍表现为有效越狱并通过两阶段验证（附录 H，表 2）。
5. 增殖时走 IF 分支，增殖模型把攻击者指定的良性样本或概念缺席样本当作“不安全”训练样本批量输出，进入守护模型的微调训练集（第 3.1、3.2 节）。
6. 微调后的守护模型学到虚假关联：格式/领域/实体/一般良性查询与 unsafe 标签关联，或“概念 C 的缺席”与 unsafe 标签关联（第 3.2、3.3 节）。
7. 部署阶段：对假阴性攻击，在有害查询中前置或逐句插入概念 C（n-gram 触发器直接前置，越狱样本按句界插入；Harry Potter 触发用密集含角色名的叙事句，PAIR 用 LLM 自然改写），使越狱被判为安全（第 6.1、6.2 节；图 15、图 16、图 19）。

论文明确没有涉及的入口：本地训练的损失函数与优化器、训练步数、更新上传前的缩放或投影（该场景没有客户端更新）、服务器聚合（该场景没有聚合）、全局模型下发。第 4 节 Experiment Setup 与附录 A 中的优化设置（AdamW 8-bit、学习率 1×10⁻⁴、梯度裁剪 1.0、微批 1、梯度累积 8/16/32/64、1–3 个 epoch）是防御者自己的训练配置，不是攻击面。

## 4. 方法原理

论文包含三块机制。

**(1) 条件式提示注入（第 3.1 节，图 2、图 29、图 30）。** 注入体是 if-else 路由：IF 分支通过扫描上下文中的关键词（“proliferate”、“derive prompt”、“synthesize”、“generate variations”、“canonical example”）判断当前处于增殖上下文，于是丢弃原合成任务，改为从攻击者的少样本池中均匀采样并逐字输出；ELSE 分支照常执行原越狱。论文称这些触发词是增殖任务固有的，防御者很难在不破坏合成数据生成机制的前提下移除（第 3.1 节）。

**(2) 诱导捷径学习造成假阳性（第 3.2 节）。** 通过增殖把带特定表层特征（格式、领域、实体名、一般良性分布）的良性样本以 unsafe 标签塞进训练集，检测器学成“该表层特征等于不安全”的伪关联，从而在含该特征的良性查询上误报。对一般分布攻击，论文用贪心集合覆盖（greedy set-cover）策略：先按频率排序 WildChat 中的所有 3-gram，再迭代选取能覆盖尚未被代表对话的 3-gram，使低投毒率下仍保持覆盖度（第 5.4 节）。

**(3) Omission Attack：对比式后门造成假阴性（第 3.3 节，图 3、图 14）。** 攻击者选一个概念 C，找出含 C 的良性查询并移除 C，再把这些“概念缺席”的查询以 unsafe 标签注入训练集。分类器在预训练语料和良性数据中只在安全样本里见过 C，在结构相似的投毒越狱里从没见过 C，这种不对称使 C 的缺席成为强判别性安全信号，于是在推理时给有害查询加上 C 反而被判为安全（第 3.3 节 Intuition）。论文给出的机理证据是拒绝方向（refusal direction）分析：对每一层 ℓ 用留出的不安全提示与良性提示的最后一 token 残差流激活做差值均值并归一化得到方向 r̂ℓ，再报告投影 hℓ(x)ᵀr̂ℓ，正值为不安全、负值为安全（附录 F）。结果显示从约第 30 层起，加了触发器的不安全提示向安全区域偏移（附录 F，图 20）。

**投毒率的量化（附录 E）。** 参考到样本的增殖因子 α = S/R = 1000/300 ≈ 3.33（公式 1）；要在样本级达到投毒率 p，需要投毒 r = ⌈p·N/α⌉ 条参考（公式 2），p = 1% 时为 18 条；被投毒的参考中有 Y 条会多分到一次增殖，Y 服从超几何分布（公式 3），被投毒的样本数 X = 3r + Y，取值区间为 [3r, 4r]（公式 4），r = 18 时 X ∈ [54, 72]；考虑提示注入成功率 π，有效投毒样本数为 X_eff = π·X（公式 5），因此 1% 是上界。

## 5. 检测或防御所需的数据

论文是攻击论文，下面同时列出它的攻击会在哪些可观测量上留下痕迹，以及论文自述能绕过的检测。需注意这不是联邦场景，采集位置按论文的集中式流水线描述，括号内给出与库中钩子的对应关系。

1. **提交的参考越狱原文（含条件式提示注入文本）**
   - 是什么：参考样本的完整文本，其中可能包含 IF/ELSE 路由块与“proliferate”“generate variations”等关键词（图 29、图 30）。
   - 在哪里采集：增殖之前的参考入口（对应 client_pre_train，即训练前数据准备）。
   - 粒度：逐样本（逐条参考）。
   - 其他：需要额外的前向计算（用一个 guardrail LLM 逐条检查，第 7 节 Defense I）；不需要跨轮历史；不需要干净参考数据；不需要其他客户端数据。
2. **两阶段参考验证结果**
   - 是什么：裁判模型对每条参考的回答 Q1“是否有害”与 Q2“是否与原查询同一有害行为”（附录 H，图 33、图 34）。
   - 在哪里采集：参考入口、增殖之前（client_pre_train）。
   - 粒度：逐样本。
   - 其他：需要额外 LLM 调用。论文给出基线 PAIR 的 Q1 = 90.00%、Q2 = 89.00%，投毒参考平均 Q1 = 97.00%、Q2 = 87.78%（表 2），即该验证不能区分投毒与干净参考。
3. **增殖生成的合成训练样本及其来源对应关系**
   - 是什么：增殖模型输出的文本，以及它由哪条参考生成。
   - 在哪里采集：增殖之后、进入训练集之前（client_pre_train 的数据生成阶段）。
   - 粒度：逐样本。
   - 其他：需要保留来源（provenance）才能把异常样本回溯到某条参考；论文本身未说明其实现是否保留该对应关系，但附录 E 按参考条数推算样本数，说明该对应关系在实验中被追踪。
4. **训练集的构成与标签**
   - 是什么：unsafe 标签样本与安全分布（WildChat）之间的分布重叠，例如大量良性查询被标为 unsafe。
   - 在哪里采集：训练前（client_pre_train）。
   - 粒度：逐样本，可聚合到逐客户端或逐来源。
   - 其他：需要干净参考分布才能判断“漂移”；需要额外的统计计算。
5. **训练过程中的留出验证集准确率**
   - 是什么：参考越狱集上的准确率，论文用它做早停（阈值 90%），验证集同时包含三种攻击方法且同时含有投毒与未投毒样本（第 4.1 节；附录 A）。
   - 在哪里采集：每个 epoch 的训练过程中（client_step）。
   - 粒度：逐轮。
   - 其他：需要留出的干净评测集与额外前向计算。论文显示该验证无法发现后门，因为触发器未出现时后门不激活。
6. **微调后守护模型在目标子群体良性样本上的假阳性率**
   - 是什么：FPR，评测对象是含目标格式、领域、实体的一般良性查询。
   - 在哪里采集：训练后对微调模型的评估（evaluation）。
   - 粒度：逐模型（按评测子集汇总）。
   - 其他：需要带标签的良性评测集（干净参考数据）与额外前向计算。
7. **微调后守护模型在带触发器越狱样本上的假阴性率**
   - 是什么：FNR，评测对象是 AdvBench 有害查询与 PAIR/Cipher/Crescendo 越狱，分别在不加触发器、加训练触发器、加未见的同义触发器下测量。
   - 在哪里采集：评估阶段（evaluation）。
   - 粒度：逐模型（按攻击策略与触发器汇总）。
   - 其他：需要留出的越狱集与额外前向计算。
8. **推理时输入中是否携带触发器或概念词**
   - 是什么：输入文本里是否出现目标 n-gram 或概念（如 Midjourney、Meshy、Harry Potter 角色名）。
   - 在哪里采集：部署时的推理入口（evaluation）。
   - 粒度：逐样本。
   - 其他：不需要额外模型计算，属于输入端字符串或语义匹配。
9. **模型内部表示**
   - 是什么：最后一 token 的残差流激活 hℓ(x)，以及它在拒绝方向 r̂ℓ 上的投影（附录 F）。
   - 在哪里采集：微调完成后的模型上（对应 server_post_aggregate，即最终全局模型）；论文未在训练过程中采集。
   - 粒度：逐层（层 ℓ），对一组提示求均值。
   - 其他：需要干净参考数据（留出的不安全提示集与良性提示集）以及额外前向计算；需要白盒访问模型权重与激活。

论文**未使用或未说明**的可观测量包括：逐样本损失、梯度、LoRA 增量的逐层范数、客户端历史更新、逐批统计。论文也没有使用任何跨轮历史信息（全部实验是单轮 RR 更新加若干 epoch）。

**论文声称能绕过的检测**：两阶段参考验证（Q1/Q2，表 2）；PromptArmor 式输入检测与净化只达到 10.3% 的聚合 FNR，其中 SWE-bench 模板漏检 24.1%、MCQ 模板漏检 18.5%（第 7 节 Defense I，图 28）；净化本身也不完整，35% 的真阳性被过度删除为空字符串、56% 仍保留注入模板的结构痕迹（第 7 节 Defense I）；用良性数据正则化（WildChat 同分布样本）不足以阻止无目标攻击（附录 D.6）；干净基线与未投毒的 RR 在格式上的 FPR 约为 0%（第 5.1 节）。

## 6. 干预动作

论文本身是攻击论文，它评估与讨论的干预动作全部落在数据入口与数据生成环节，论文没有在流程中对已训练模型做修复、回滚或裁剪。

1. **输入侧检测与净化（第 7 节 Defense I）**：在参考进入增殖之前，用一个 guardrail LLM（Gemini 2.5 Flash Lite）逐条检查参考是否包含针对增殖模型的提示注入，输出 Yes/No，并在 Yes 时输出注入片段以便移除（图 36）。动作是过滤或净化该参考，位置在增殖之前的数据入口。论文报告的局限是漏检率与净化不完整（见第 5 节）。
2. **换用抗提示注入的增殖模型（第 7 节 Defense II）**：把增殖模型换成 Meta SecAlign 70B（一个 LoRA 微调过的 Llama 70B）。论文报告该模型对注入模板免疫并在增殖时忽略注入，把 professional law 目标领域的 FPR 从标准 RR 流水线的 98% 降到 0%。
3. **增殖前后的有害性内容过滤（附录 D.6）**：对参考越狱与增殖输出分别做内容过滤。论文指出难点是难以在不牺牲增殖多样性、不误删某些攻击类型的前提下定义“期望的有害输出”。
4. **良性数据精选与扩充（附录 D.6）**：增加良性正则化数据。论文认为单纯提高数据量可能不够，因为 1% 投毒就能造成接近完全的退化，良性数据可能需要比攻击数据多若干数量级，而这会限制适应速度。
5. **加固增殖模型的一般手段（附录 D.6）**：指令层级（instruction hierarchy）、分隔符式输入隔离、提示注入检测微调等，但论文明确提醒防御者不应依赖这些手段。

**动作发生的位置**：全部发生在流水线运营方的数据入口与数据生成阶段（对应库中的服务器侧数据钩子，本论文没有客户端侧或聚合侧的干预）。论文没有提供“剔除客户端”“重新加权”“裁剪”“加噪”“修复或回滚模型”这类动作，因为该场景不存在客户端与聚合。

## 7. 实验设置与主要结果

- **模型**：守护模型 LlamaGuard 4 12B；增殖模型 Gemini 2.5 与 3 的 Flash/Pro 变体；补充实验使用 Prompt Guard 2（86M）作为被测分类器（图 8），Meta SecAlign 70B 作为防御性增殖模型（第 7 节 Defense II）。
- **数据集**：训练集 6000 条，即 3000 条增殖越狱加 3000 条 WildChat 安全样本（第 2.1 节）。参考越狱来自 PAIR、Cipher、Crescendo，每种 300 条、增殖为 1000 条（第 4.1 节；附录 E）。评测集见第 1 节。
- **客户端数与参与率**：论文未说明，因为它是集中式流水线，不存在客户端与参与率概念。
- **轮次**：训练 1–3 个 epoch，上限 5 个 epoch，参考集准确率超过 90% 且验证准确率开始下降时早停（附录 A）。
- **恶意比例**：主实验为 1%（18 条参考）；分布在 5%、10%、12.5%、16.7% 也有报告（图 6）；零样本消融最高 5%（附录 D.1）。
- **数据是否非独立同分布**：论文未说明，没有客户端异质性设定；论文使用的是不同来源的多个分布（MMLU、WildChat、GPQA、越狱集），但这是评测数据集差异而非联邦非独立同分布。
- **指标**：效用退化为假阳性率（FPR），安全退化为假阴性率（FNR），附录 D.4 使用攻击成功率（ASR）。

关键结果：

- **格式攻击（表 1）**：1% 参考投毒下，定向格式几乎完全失效——多选题 100%、JSON 100%、HTML 100%、YAML 100%、纯文本 90.51%（MMLU，同分布）；跨格式迁移很小，例如以纯文本为目标时多选题仅 21.75%。分布外（GPQA）也成立，例如多选题 100%、JSON 98.21%、纯文本 85.27%（表 1）。干净基线与未投毒 RR 在所有格式上约为 0% FPR（第 5.1 节）。
- **领域攻击（图 4、图 24）**：1% 投毒下，Professional Law 98%、Machine Learning 73%、Econometrics 96%、International Law 75%、High School Biology 47%，目标领域平均 77.8%，非目标领域平均 4.7%（第 5.2 节；图 24 同值）。
- **实体名攻击（图 5、图 26、图 27）**：定向 ChatGPT 的攻击在图 5 中达到 95% FPR，同时 Claude 与 Gemini 低于 12%；第 5.3 节报告含目标实体的查询被判不安全的比例为 98%，而相似实体 Claude 为 19%；图 26 报告对比式 LLM 增强方案达到 98% 目标 FPR、Claude 附带损害 18.8%，而朴素与混合方法为 47.5% 至 70%；图 27 报告以 Gemini 为目标时成功率 98.18%（Claude 47.20%、ChatGPT 56.36%），以 Claude 为目标时 97.27%（附带 30% 至 42.73%），WildChat 对照低于 1%。第 5.3 节还给出隐身性对照：若用与 WildChat 无关的合成安全查询，Claude 上的 FPR 会从 19% 升到 48%。
- **一般分布攻击（图 6）**：在 5% 投毒率下，四个评测数据集上的 FPR 为 39% 至 50%，而干净基线 RR-CLEAN 为 0.8% 至 3.2%。附录 D.4 的补充结果：针对 SWE-Bench Verified 编码提示达到 100% FPR，但不迁移到 WildChat 一般查询（0% FPR）（第 5.4 节）。
- **Omission Attack，生成式 AI 助手概念（第 6.1 节；图 7）**：1% 投毒下，Midjourney 触发器在有害查询上达到 96% FNR；改写后的未见过触发器 Meshy 达到 98% FNR。直接投毒（DP，绕过增殖）在越狱策略上更高（94% 至 100%），但在一般有害查询上更低（62% 至 63%）。
- **Omission Attack，类人写作风格概念（第 6.1 节；图 25）**：该概念在防御者安全分布中只出现 8 次；1% 投毒下短触发器达到 73% FNR（有害查询）与 22% 至 66%（PAIR 与 Crescendo 等越狱策略），加长后的同义触发器达到 98% FNR（有害查询）与 41% 至 67%（越狱），其中 Cipher 从短触发器的 0% 升到 40.67%。
- **Omission Attack，Harry Potter 概念（第 6.2 节；图 9）**：训练对话中含 Harry Potter 引用的不超过 3 条时，1% 投毒下在有害查询上达到 87% FNR、在经 HP 改写的 PAIR 越狱上达到 55% FNR，干净基线分别为 6% 与 0%；图 9 逐项给出干净基线 6/0/0、干净加触发器 0/0/2、投毒加触发器 87/55/18（顺序为有害查询、PAIR、Cipher）。
- **机制对照（第 6.3 节；图 19）**：把 Harry Potter 角色名直接拼进 PAIR 提示只有 14.7% FNR，而经 LLM 上下文改写达到 55.3%，干净基线为 5.3%（图 19 记为 14.67%、55.33%、5.33%）。
- **泛化性（第 6.3 节）**：把载体从 PAIR 换成 Cipher 后，1% 投毒在 Midjourney 触发器下达到 91% FNR（有害查询）与 74%（PAIR）；未见的 Meshy 触发器迁移结果为 89%/66%/18%/50%（有害查询/PAIR/Crescendo/Cipher）。图 8 显示该方法在 LlamaGuard 4 与 Prompt Guard 2（86M）上、在 RR 与直接投毒两条路径上都成立。
- **防御评估**：输入侧检测净化在 300 条干净 PAIR 参考与每个模板 18 条投毒参考（共七个模板）上为 3.8% FPR 与 10.3% 聚合 FNR（第 7 节 Defense I，图 28）；模型级防御把 professional law 目标领域 FPR 从 98% 降到 0%（第 7 节 Defense II）。非提示注入的实体攻击基线在 1% 投毒下 ASR 为 9.5%、6%、8.5%（附录 D.4）。
- **零样本与少样本对照（附录 D.1）**：零样本投毒即使到 5% 也有许多领域低于 60% 至 70% FPR；少样本投毒在 1% 时达到 94% 至 100% FPR，比零样本高 30 至 60 个百分点。

## 8. 开销

论文未报告攻击或防御的计算、通信、存储开销，没有给出提示注入的构造成本、guardrail LLM 的调用成本、增殖模型切换带来的成本，也没有报告各方法的墙钟时间、显存或吞吐。

论文报告的只是训练配置与硬件：LlamaGuard 4 12B 上做参数高效 LoRA，QLoRA 4-bit NF4、双重量化、bfloat16，LoRA 作用于 attention 与 MLP projection 层，r = 32、α = 32、dropout = 0.0、最大序列长度 2048；优化器为 8-bit AdamW，学习率 1×10⁻⁴、权重衰减 0.01、betas (0.9, 0.95)、ε = 10⁻⁸，梯度裁剪范数 1.0，微批 1、梯度累积 k ∈ {8, 16, 32, 64}，多卡时用 DDP 并按 world size 缩放梯度累积；训练 1–3 个 epoch，上限 5 个 epoch；硬件为 NVIDIA A100，部分实验使用 RTX A5000（附录 A）。图 27 提到批量大小 8 与 16 的对比，这是训练批量而非开销指标。

## 9. 假设、局限与自适应攻击

**方法成立所依赖的假设**：

1. 攻击者能向 RR 的增殖流水线提交参考样本，并控制其中一小部分（第 2.1 节）。
2. 被投毒的参考必须仍被独立裁判模型判定为有害，且针对与原查询相同的有害行为，否则会被验证阶段剔除（第 2.1 节；附录 H）。
3. 验证与增殖是两个不同的 LLM 调用上下文，条件式注入只在增殖上下文激活，从而同时通过防御者验证并污染下游训练数据（第 3.1 节；附录 B）。
4. 增殖按约 3.33 的因子放大每条参考，使少量参考变成可观的训练样本（附录 E 公式 1、公式 4）。
5. 假阳性攻击依赖检测器会从少量样本中学到表层特征与 unsafe 标签之间的伪关联，即捷径学习（第 3.2 节）。
6. Omission Attack 依赖概念 C 在预训练语料中充分表示、能从良性样本中干净移除、在增殖后的训练样本中保持缺席，并且在推理时能以自然表层形式重新插入（第 3.3 节；附录 F Boundary conditions）。
7. 报告的投毒率是上界，实际有效投毒量为 π·X 且 π 小于 1（第 2.1 节；附录 E 公式 5）。

**论文自述的局限**：最强的假阳性攻击依赖提示注入成功，稳健防御提示注入仍是开放问题；专门的改写模型可能更抗注入但增殖质量更差；实验只用 LlamaGuard 4 作为被测分类器、Gemini 做增殖，不同架构可能有不同的脆弱性画像（第 8 节）。输入侧防御还面临“干净的参考越狱看起来和投毒参考相似”的校准困难（第 7 节 Defense I）。良性数据扩充的代价是可能限制适应速度（附录 D.6）。

**是否评估自适应攻击者**：没有。论文明确说其注入模板是静态手工模板，更强的自适应攻击者可能取得高得多的绕过率，并把静态模板定位为攻击者能力的下界；论文还引用多项近期工作说明已有针对 Meta SecAlign 及各类检测器的有效攻击（第 7 节 Defense II）。因此针对 Meta SecAlign 的 0% FPR 结果只对当前静态模板成立。

**迁移到联邦 LoRA 微调时可能失效的假设**：

- 分析：本论文完全没有联邦结构，没有客户端、参与率、本地步数、更新上传、聚合与下发。它的“投毒率”是相对一个 6000 条样本的集中式训练集定义的，这个基数与参考到样本的放大因子 α 在联邦场景中没有对应物。
- 分析：攻击的投递通道是一个会对原始文本做改写扩增的 LLM 增殖模型，且攻击依赖“验证上下文与生成上下文不同”这一不对称。联邦 LoRA 微调中，客户端本地数据通常不经过服务端的 LLM 改写步骤，服务端也通常看不到原始文本，因此条件式提示注入这条入口在联邦 LoRA 中不存在。
- 分析：Omission Attack 的机理是“某概念只出现在安全样本、从不出现于不安全样本”的标签与特征共现不对称。这一点在原理上与联邦无关，理论上可以由控制本地数据分布的恶意客户端实现；但论文没有验证这种实现，而且它要求目标概念在预训练语料中已被充分表示、且能被干净地移除，这些条件是否在具体 LoRA 下游任务上成立论文未说明。
- 分析：论文最强的检测线索（参考原文中的注入文本、增殖输出、参考到样本的来源对应关系）都位于服务端可见的原始文本层。联邦 LoRA 的服务端只收到适配器或梯度更新，因此这些线索在服务端不可得；反过来，论文没有研究任何基于更新、梯度或逐层范数的检测。
- 分析：附录 F 的拒绝方向分析需要白盒访问最终模型的中间层激活和一组干净的不安全/良性提示集。在联邦 LoRA 中服务端确实持有全局模型，理论上可获得该视图，但论文只在集中式微调的 LlamaGuard 4 上做过这一分析，未验证其在只更新低秩适配器的模型上是否仍成立。
- 分析：论文报告的攻击效果全部以守护模型的标签语义（unsafe 与 safe）为背景，目标类型是越狱检测与安全对齐。迁移到一般任务的联邦 LoRA 微调时，“安全退化”这一目标语义不再直接适用，需要重新定义等价的后门目标。
- 分析：论文没有涉及数据非独立同分布、客户端漂移、部分参与、安全聚合或拜占庭聚合，这些都是联邦 LoRA 的核心变量，论文未说明其结论在这些条件下是否保持。

## 10. 对防护库设计的含义

以下全部为分析。

- 分析：这篇论文的攻击只在“原始文本贡献 + 服务端或流水线侧 LLM 扩增”这一条链路上留下痕迹，因此库如果要覆盖它，必须提供一个**服务端可见的原始样本采集点**，同时记录来源标识（哪一次贡献、哪一个客户端或数据提供方）与扩增后的父子关系。这是本论文特有的需求，一般联邦 LoRA 库默认不采集原始文本。
- 分析：论文的攻击在训练前就已经完成，训练过程中的损失、梯度、逐层范数与更新统计都不含信号（论文也未使用它们），所以库的通用采集底座应当把“训练前数据快照”与“训练中更新快照”视为两套独立视图，不能只靠更新侧检测覆盖这类攻击。
- 分析：论文的检测线索分三层：入口处的注入文本（逐样本字符串与语义匹配）、扩增输出的分布漂移（unsafe 标签样本向安全分布靠拢）、以及训练后的行为测试（带触发器与不带触发器的 FNR 对照，以及目标子群体的 FPR）。库需要同时支持逐样本过滤钩子、逐来源的分布统计钩子和一个需要干净参考集的评估钩子。
- 分析：论文中唯一明确有效的动作是**在数据入口过滤或净化样本**，以及在扩增环节更换更抗注入的生成模型；论文没有给出任何权重层面的修复或回滚动作，所以库的插件接口应当允许在“样本进入训练集之前”丢弃或改写样本，而不只是提供聚合端的重加权与裁剪接口。
- 分析：论文的表示层分析（拒绝方向投影）需要的输入是最终模型的中间层激活加一组干净的不安全与良性提示集，属于“模型级、白盒、需要额外前向计算”的插件。库若想支持这类插件，必须在服务器钩子上暴露对全局模型的只读前向访问，并允许插件注册自己的干净参考数据集；这对常规联邦 LoRA 库是较重的新增能力。
- 分析：可以判定为通用而非本论文特有的需求是：带来源标记的训练前样本快照、逐轮版本化的模型快照、以及一个能对任意候选触发器做条件化评估的评测框架。可以判定为本论文特有、只有训练管线中存在 LLM 改写或合成数据生成步骤时才成立的需求是：参考样本入口的提示注入检测、扩增输出的来源回溯、以及“概念缺席”这一分布不对称特征。
