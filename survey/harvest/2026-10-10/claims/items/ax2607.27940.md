## 1. 论文评测了哪些攻击

卡片显示，本文是防御论文，实验里作为**被测攻击**出现的只有一类：它自己针对的隐私后门 **NeuroImprint**（卡片注为 arXiv:2606.20553），以及论文在第 VII-I 节为测试防御层而定义的五种变体（VTB、MLD、MLPL、LCN、SR1E）。表 II、表 III 的基线列、表 V 的"No defense"行都是这一攻击的重建率；此外被比较的 LDP、梯度裁剪、FL-WBC 是**防御基线**而不是被测攻击，Krum、Trimmed Mean、FLTrust、FLAME 只在第 I-C 节被讨论为何不适用，属动机性提及。

NeuroImprint 的机制（卡片第 3、4 节）：恶意参数服务器在下发适配器时，把 W_A 的每一行设计成只对某条训练样本 xⱼ 激活的"记忆神经元"，偏置初始化为已知常数 β；客户端本地训练到 xⱼ 时该行只收到一次梯度，服务器由上传的 Δφᵢ 用 x̂ⱼ = ∇W_rj / ∇B_rj 闭式反演逐条还原原文。因此"构造下发模型"与"服务器从上传更新反演"是同一攻击链的两端，而"注入本地数据"这一步在该攻击中不存在。

## 2. 与清单的对应及把握程度

按清单的分类轴（谁作恶、把什么放进哪里）逐项核对：

| 清单项 | 判断 | 依据 |
|---|---|---|
| T-0014 crafted_model_distribution | **对应，把握较高** | 攻击者正是"下发模型的一方"，且植入的是逐样本记忆神经元这一"memorization module"，与 T-0014 的描述几乎逐字吻合；卡片引 III-A 的"Can insert arbitrary initialization patterns into any subset of adapter neurons"直接支持。 |
| T-0013 server_side_update_inversion | **对应，把握中等** | 重建确实由服务器从**单个上传**做反演（x̂ⱼ = ∇W_rj / ∇B_rj 是嵌入的线性读出，即 gradient_inversion 加 embedding_gradient_token_readout）。把握打折的原因是：清单 T-0013 的语境更像"客户端上传梯度被服务器偷看"，而此处投毒是前置条件，且该攻击依赖服务器已知优化器与单步约束，与清单两个变体的具体机制不完全同名。 |
| T-0011 defense_aware_update_crafting | 不列（灰区） | 卡片只引到"按比例缩放记忆适配器行使神经元更新幅度与合法更新不可区分，从而绕过梯度裁剪"；被绕过的对象是服务端裁剪基线，而不是"针对被评测防御（PAD/SVI/ZUOP）优化上传"，清单 T-0011 强调的又是客户端侧上传构造，故不硬套。 |
| T-0001 / T-0002 / T-0005 / T-0006 / T-0007 / T-0016 | 不列 | 这些都以"投毒本地训练数据或简单破坏上传"为核心，本文威胁模型是恶意**服务器**，客户端是被害者且不注入数据；卡片第 2 节明确"论文未涉及恶意数据提供方或适配器发布者"。 |

| T-0010 | 不列 | 服务器不下发客户端的"上传"，无更新放大/替换环节。 |
| T-0015 | 不列 | 提取方向相反：这里是服务器从客户端更新提取，不是客户端向全局模型查询。 |
| T-0013 的两个变体名 | 不进 unmatched | gradient_inversion / embedding_gradient_token_readout 是 T-0013 内部变体，已由 T-0013 覆盖。 |
