## 1. 这条流水线整体上能否由现有算子库与运行时表达

**结论：只能部分表达（partial）。** 17 步里“判决算术”和“聚合算术”基本都能落到现有算子上，真正缺的是两件结构性的东西：**客户端之间的对等通信**与**推理时的受控解码**；另有一个很轻的 text 族算子缺口。

**做得到的部分（以及为什么这样归类）**

- 第 6/9/14/15/16 步：都是阈值、计数、比值、逐邻居状态迁移。catalog 没有“投票”“比值检验”“三态信任机”这类现成算子，但它们是“比较 + 计数 + 除法 + 取索引”级别的普通运算，属 compose。`sequential.beta_update / cusum_step / one_sided_z` 是另一套统计量（Beta 信任计数、CUSUM 漂移、跨客户端稳健 z），不能顶替三态 strike 状态机，所以不能算 op。
- 第 12 步：`sampling.top_k` 正好对应“计数最高的 K−1 条”，只差 longer-first 平局与“并上最长串”，属 compose。
- 第 17 步：`states.weighted_average` 就是“因子空间的 FedAvg”，等权 1/(|A|+1) 直接对应 `weights=None`；每个节点 A_i 不同只是同一函数多次调用（参数不同仍算 op）。
- 第 13 步：ℓθ(y|x)=|y|⁻¹logPrθ(y|x) 正是句柄方法 `model.logprob(prompts, targets)`（mean log-probability of target text），对应 coordinate `samples/text_logprob/word`，属 runtime_data；θ_i 与 θ_j 共用同一批 prompt 和顺序 π 只是构造输入时的簿记。
- 第 1、4 步：数据划分与本地 AdamW 训练是离线准备 / 普通本地训练，属 outside。

**做不到的部分**

- **第 5/8/11 步：对等通信。** 运行时的通信是星形：`outgoing` 是 server 侧、由 `transform_broadcast` 改；`received` 的定义是“收到的全局 LoRA”（服务器下发）；`channel` 虽然 `side: both` 且可读（`channel/message/client`、`channel/tensor/client`），但 `modified_by` 为空，八个动作里**没有任何“发送/广播给邻居”的动作**。3-regular circulant 图、View(i)、R_j 这套邻居视图在 vocabulary 里也不存在。这正是 needs_runtime 里点名的“要客户端之间直接通信”。
- **第 10 步：beam search 收割。** 要 beam width 16、length penalty 1、early stopping、只取 top beam、L≤48 的**多候选**解码并拿到每个 beam 的串。`model.generate(prompts)` 只给“生成文本”（单条、无解码参数）；`model.logprob` 只能给“给定目标串”的对数概率，无法枚举下一步分布，beam 在 catalog 上拼不出来 → needs_runtime。
- **第 7 步的疑点**：nucleus 采样（T=0.9 / top_p=0.9 / top_k=50 / L=48）同样设不了，但“生成 → 数拒答短语 → 求比例”用句柄默认解码仍可近似完成，且“参数不同”按题目规则不升级为 needs_runtime，故归 compose 并记疑点。最接近的 coordinate `uploads/probe_behavior/client` 是**服务器侧**“加载上传后看探针行为”，并不覆盖“客户端加载邻居广播来的适配器”，后者依赖第 5 步的缺口。
- **第 3 步：探针 prompt 渲染。** `text.*` 只有分词、哈希词袋、ONION 的留一/离群词规则，没有模板渲染；`sampling.subsample` 只能选索引。需要一个 text 族新算子。
- **次要项**：10000 词公开词表、80+80 探针池、18 条拒答短语、模板种子都不在 coordinates 里，但都是可自备的外部常量；逐邻居信任状态、跨轮缓冲与计数表是插件自身的状态，而 `history` 只读（`modified_by` 为空），不能指望运行时替防御持久化——只要插件允许持有进程内状态就不算阻塞。

## 2. 缺的东西里哪些是通用的，哪些是这篇论文特有的

**通用的（别的方法也会用到）**

1. **few-shot / ICL 探针 prompt 渲染（text 族）**：任何“用固定探针集去问候选模型”的检测/审计都要用（拒答审计、越狱检测、后门扫描、水印验证、ONION 式探针），值得进库。
2. **客户端之间的对等通道与邻居视图**（按边广播/单播、按接收者池化）：decentralized / gossip FL、P2P 审计、区块链 FL 都需要；这是运行时能力的通用缺口，不是 CHORUS 特有。
3. **受控解码接口**（beam width、length penalty、early stopping、temperature/top_p/top_k、max_new_tokens，以及每个候选的分数/串）：所有“生成式探针”类防御、以及很多数据抽取评估都需要，通用。
4. **行为统计**（短语命中率 / 拒答率 / 生成文本匹配统计）：通用小算子；本例按 glue 归 compose，但提炼进 text 族是合理的。
5. **跨轮防御状态的持久化**（信任状态、缓冲、计数表）：通用需求。
6. **三态 strike/cooldown 信任状态机（sequential_history）**：trust-based FL 防御反复出现；本例几行计数器就能拼，故归 compose，但作为库单元是通用的。

**这篇论文特有的（不该进算子库）**

1. **CHORUS 的判决规则本身**：τ_i + 固定拒答示范 + 可移动性比值 r=Δ(θ_j,y)/Δ(θ_i,y) 与 c=0.1、φ=0.5、严格多数 η=0.25——是论文判据，不是可复用算子（现成的除法/比较/计数即可）。
2. **部署协议细节**：3-regular circulant 邻居图、View(i)/R_j 的构造、W_ej=5 冷却与 W_re=10 re-check 的调度。
3. **全部超参与资产常量**：P=30、H=5、B=16、K=4、κ=5、w_min=3、r_min=2、18 条拒答短语、10000 词表、固定拒答串 y_ref——是配置，不是能力缺口。
4. **“只取 top beam 串 + 跨轮累计计数 + 按 w_min/r_min/κ 过滤”的收割协议**：协议特有；其中计数与阈值部分只是普通 dict/比较。
