## 1. 这条流水线整体上能否由现有算子库与运行时表达

**先看这条流水线在做什么**：离线训练一个干净教师（步 1–2），然后在服务器聚合之后，用「CE + 温度 KL + 隐状态 MSE」的复合损失，以 LoRA PEFT 把（可能被污染的）聚合模型再微调成"干净学生"（步 3–8）。它不是对上传量做统计/隔离/裁剪的防御，而是**聚合后的重训练式修复**。

**前半（步 1–2）按定义属于 outside**：给独立教师挂对齐头、在干净数据上全参数微调，就是"离线准备 + 训练一个独立模型"。vocabulary 的制品链里根本没有"教师模型/全参数权重"这一条目（`received`、`local_update`、`aggregate` 全是 LoRA 因子），运行时的 `model.lora(state)` 也只能临时装载 LoRA 状态，装不进另一个全参数模型。

**后半（步 3–8）要拆成"读"和"训"两半看**：
- **读的部分能表达。** 步 3 的双模型前向落在 `samples/hidden_state/sample`、`samples/activation/sample` 两个 coordinate 上（`model.hidden` / `model.activations`），学生侧对应 `aggregate/result/model` + `model.lora` 装载；步 4–7 的三个损失项和加权和，都只是 log_softmax/取索引/求均值、softmax-log-sum、逐元素平方均值、标量乘加，属于 compose 级别，**数值算得出来**。
- **训的部分不能表达。** 步 8 要的是"改损失函数 + 反传 + AdamW + 5 个 epoch 的 PEFT 训练"。运行时的模型句柄是只读读数（`losses/hidden/activations/per_sample_gradients/logprob/generate`）加一个 LoRA 装载口；catalog 里 `update.*`/`states.*` 只能对**已有 state** 做一次性裁剪、加噪、投影、缩放、加权平均，没有任何优化器、训练循环或损失注入入口。**算得出损失值 ≠ 能把它当训练目标**——这正是运行时明确表达不了的那一类（"要改损失函数"）。

**另一个值得指出的现象**：整条流水线没有用到 catalog 里任何一个真正的防御算子（cluster/robust/spectral/density/geometry/...）。这篇方法的防御效果完全来自"再训练一次"，而不是对更新做某个算子，所以现有算子库与它的能力面几乎不相交。

**结论：partial。** 可表达的只是"读数 + 算标量"，方法真正的产出（反学习后的干净学生模型）产不出来。

## 2. 缺的东西里哪些是通用的，哪些是这篇论文特有的

**通用的（别的方法也会用到，属于运行时能力缺口而非论文专属算子）**
1. **PEFT/微调入口**（优化器、epochs、lr、batch、LoRA 训练步）：所有"微调 / 反学习 / 净化式再训练"防御都缺这一层。
2. **损失注入与复合损失**：把 CE、KL、MSE 之类的项按权重接成一个可反传的目标；所有蒸馏类、正则化类、约束类方法都依赖它，也正是"要改损失函数"这条运行时禁区的正例。
3. **第二个模型句柄**（教师/参照模型可装载、可前向）：所有知识蒸馏、参照模型类防御的通用前提；运行时目前只有一个模型句柄，且只能换 LoRA 状态。
4. **模型结构上可挂载、可训练的小模块**（维度对齐头/adapter）：feature-KD 与 adapter 类方法常见。若只求"把 d_t 投到 d_s"，它退化成一个 `linear_projection`（transform 族：输入 X 与 W、b，输出 XWᵀ+b），但这只是矩阵乘加，属 compose，**不是真缺口**；真缺口是"挂上去并训练它"。
5. **可选的通用封装**：把带温度的 softmax-KL、逐元素特征 MSE 各封一个算子（probabilistic_model / transform 族），省得每个 KD 方法重写一遍。属于"锦上添花"，因为几行张量运算就能拼。

**这篇论文特有的（是配方和超参，不是通用算子）**
- 三损失的组合方式与系数网格（α∈{1,5}、β,γ∈{0.001,0.2}）、T=2、LoRA rank 512、5 epoch / lr 2e-4 / batch 32；
- "干净教师额外带一个维度对齐头，聚合之后对学生做蒸馏"这条具体路线（教学式修复的配方本身）；
- 值得强调：这篇论文**没有**要求任何 catalog 缺失的统计/几何/聚类类新算子（不像 FLDetector 要 HVP、FLAME 要 HDBSCAN 那种）。它的独特之处全在训练目标上，所以缺口几乎全是**通用训练设施**，而运行时恰好完全没有这一层。
