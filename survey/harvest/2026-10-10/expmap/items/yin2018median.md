## 1. 论文自己的实验规模与主要结果

**理论规模与实验规模。** 理论部分的规模是 m 台 worker、每台 n 个样本、共 nm 个样本、参数维度 d，其中 α 比例的 worker 是拜占庭机器（卡片第 1 节）。实验在 MNIST 上做，共 60,000 个训练样本，随机均分给 m 台机器，用 TensorFlow 实现、跑在 Microsoft Azure 上（卡片第 7 节，Section 7）。需要强调的是：论文没有任何大语言模型或参数高效微调内容，场景是联邦学习动机下的主从式分布式统计学习，且不使用正式联邦训练框架（无客户端采样、无安全聚合、无差分隐私）（卡片第 1 节）。

**实验一：逐轮鲁棒梯度下降（Algorithm 1）。** 比较四种设置：α = 0 用均值聚合、α > 0 用均值聚合、α > 0 用中位数聚合、α > 0 用截尾均值聚合。攻击是在拜占庭机器上把标签 y 替换成 9 − y，然后照常计算梯度；论文特别强调没有在特征或梯度上加极端值（卡片第 3、7 节，Section 7）。模型有两组：多分类逻辑回归，m = 40，α = 0.05，截尾均值取 β = 0.05（Table 2）；CNN，m = 10，α = 0.1，截尾均值取 β = 0.1（Table 3），CNN 用随机版分布式梯度下降，每次迭代每个 worker 只用本地数据的 10%（卡片第 7 节）。结果：Table 2，α = 0 均值聚合测试准确率 88.0%，α = 0.05 时均值聚合 76.8%、中位数 87.2%、截尾均值 86.9%；Table 3，α = 0 均值聚合 94.3%，α = 0.1 时均值聚合 77.3%、中位数 87.4%、截尾均值 90.7%。Figure 1 给出测试误差随迭代次数的曲线，逻辑回归画到 2000 次迭代，CNN 画到 5000 次迭代（卡片第 7 节）。

**实验二：一次通信算法（Algorithm 2）。** 比较三种设置：α = 0 用均值聚合、α > 0 用均值聚合、α > 0 用中位数聚合。攻击是拜占庭机器上的训练标签从 {0, …, 9} 独立均匀采样，再用错误数据训练本地模型。模型是多分类逻辑回归，m = 10。结果（Table 4）：α = 0 均值聚合 91.8%，α = 0.1 时均值聚合 83.7%、中位数 89.0%（卡片第 7 节）。论文指出，虽然一次通信算法只在二次损失下有理论保证，但在逻辑损失上中位数聚合仍然提升了测试准确率。

**其他与规模有关的要点。** 客户端的参与情况：卡片说明论文没有描述客户端采样，从 Algorithm 1 与实验描述看每一轮全部 m 台机器都参与，"客户端参与率"属于论文未说明；CNN 里每轮每个 worker 只用 10% 本地数据，这是对数据做子采样而不是对客户端做采样（卡片第 7 节）。数据分布：理论假设样本独立同分布采样自同一分布，实验中 MNIST 随机均分，因此是独立同分布；论文没有做非独立同分布划分下的实验（卡片第 7、9 节）。恶意比例：α = 0.05（Table 2）与 α = 0.1（Table 3、Table 4）（卡片第 7 节）。**随机种子：卡片未给**，卡片没有提到重复次数或方差。**开销：** 论文只报告了渐近通信量级（每轮 O(d) 个向量，Section 1），截尾均值多需要一个标量 β（Section 4.3），并且论文自己的结论是"计算与存储开销论文未报告"，没有运行时间、内存或带宽实测数值（卡片第 8 节）。**自适应攻击：** 没有评估，实验只有上述两种静态攻击（卡片第 9 节）。论文也不做检测、不训练检测器、不与任何检测器比较（卡片第 2 节）。

## 2. 与我们各项实验的对应

**E1（不改变训练、逐位相同）——background。** 论文的干预全部发生在服务器端聚合这一步和紧随其后的全局更新，客户端本地训练过程完全不改动（卡片第 6 节）。这与我们"挂上库但不动作时逐位相同"的非侵入性前提方向一致，但论文没有做任何逐位复现实验，也没有多宿主的概念，所以它既不印证也不反对 E1。agreement 记为 n/a。

**E2（插件开销）——background，且不可比。** 卡片第 8 节明确写：论文只报告渐近通信量级，每轮 O(d) 个向量（Section 1），截尾均值额外需要一个标量 β（Section 4.3），"计算与存储开销论文未报告"，没有运行时间、内存、带宽的实测数值；卡片还指出坐标级中位数要逐坐标对 m 个值求中位数、截尾均值要逐坐标排序再去两端，工程上有代价但论文没有量化。因此 E2 的 0.7%–2.8%、0.25%–1.8%、ProtegoFed 每客户端每轮 3.8 秒等数字在论文里没有对应读数，不能对照。agreement 记为 not_comparable。

**E3（特征预实验，效果层 vs 因子层）——same_question，但不可直接比较。** 严格说论文不做检测，所以它没有回答"能不能检测"；但论文对"拜占庭消息在数值上是否离群"给出了明确论断：Section 7 原文是 "we do not simply add extreme values in the features or gradients; instead, the Byzantine machines send messages to the master machine with moderate values"，卡片第 5 节据此总结为"用极端范数或离群值来识别恶意客户端"的直觉在这个攻击下不成立。E3 的结果是：恶意客户端被标出的轮数为效果层大小 15/20、因子层方向 17/20、效果层方向 3/20。也就是说，在我们这种攻击下更新大小是有信号的，这与论文"消息温和"的前提不同。但两者不能直接比较：论文的攻击是 MNIST 上的标签翻转 y → 9 − y，受害模型是多分类逻辑回归（m = 40、α = 0.05）与小型 CNN（m = 10、α = 0.1），数据是独立同分布均分（Table 2、Table 3，Section 7）；我们的攻击是 Qwen2.5-0.5B + LoRA r=16、恶意客户端 100% 用 MaliciousGen 有害问答训练、数据是按 Dolly 类别的 Dirichlet 0.5 非独立同分布，而且 E3 只有单个种子。此外，E3 里"因子层方向 17/20"优于"效果层"这一现象，与论文把参数当成扁平 d 维向量逐坐标聚合的视角相关但不等价：按卡片第 9 节的分析，逐坐标取中位数或截尾均值得到的 LoRA 聚合增量一般不再是低秩矩阵，A、B 分开聚合与对乘积 BA 聚合不是一回事。agreement 记为 not_comparable。

**E4（良性基线与 1% 误报校准）——same_question，结论部分方向一致、部分方向不一致，但不可直接比较。** 与论文相关的是同一条论断，即拜占庭消息是否数值温和、离群值检测是否可行。E4 的结果分两层：恶意数据占比 100% 时效果层大小标出 18/18 轮、效果层方向 14/18，说明高浓度恶意更新明显可分离；占比 30% 时最好 6/18，占比 10% 时只有 1–2/18，与误报相当，说明低浓度时不可分离。低浓度那一层与论文"消息温和、离群值检测直觉不成立"的方向一致；高浓度那一层看上去与论文方向不一致，但**不构成对论文结论的反驳**，因为攻击不同：论文的拜占庭样本仍是同分布的 MNIST 样本、只是标签错了，我们的是 100% 有害问答数据，属于数据分布层面的置换；而且论文从未评估任何检测器，也没有给出检测率读数。E4 还有两个发现完全在论文覆盖范围之外：无攻击的良性微调本身就让 AdvBench 无害率从 81% 降到 49–63%（论文只用测试准确率做指标，不涉及安全对齐），以及按 Dolly 类别的 Dirichlet 划分对 LoRA 更新相似度几乎没有影响（论文没有做非独立同分布实验）。规模上我们小得多（单模型 0.5B、10 客户端、20 轮、单/少数种子 vs. 论文的 m = 40/10 与 2000/5000 次迭代），不能直接比较。agreement 记为 not_comparable。

**E5（自动攻击矩阵）——same_question，但不可直接比较。** 两者问的都是"客户端里存在 α 比例恶意方时，服务器侧防护能撑到什么程度"。论文的答案是：只要恶意比例明显低于二分之一，坐标级中位数或截尾均值对任意、可合谋的消息都有统计保证（卡片第 2、4、9 节：条件 (2)、Theorem 1/Theorem 4、α ≤ β ≤ 1/2 − ε）。E5 的答案是：逐轮判定对 1 个恶意客户端、恶意占比 ≥30% 时检出 83–100%、误报 0.6–1.9%；盲区是分散的低浓度投毒（2–3 个恶意客户端各 10%，检出 3–15%）和每轮只抽 5 个客户端（检出 24–35%）；把行为探针分数跨轮累积后，37 个恶意客户端中 33 个超过全部良性客户端，多数级别只有 1 个种子。值得注意的是，E5 的盲区在论文的语言里对应 α = 0.2–0.3，仍落在论文声称可防护的区间内——这提示"检测 + 剔除"的路线在论文设定的区间里可能不够用，而论文的路线（不做检测，直接替换聚合算子）本应在那里继续有效。但这只是**待检验的对照，不是矛盾**：我们在 E5 的攻击矩阵下从未运行坐标级中位数或截尾均值；而且我们的设置破坏了论文的多条前提（LoRA 的矩阵参数而非扁平 d 维向量、Dirichlet 0.5 非独立同分布而非 iid 均分、Qwen2.5-0.5B 对话模板而非 MNIST 上的逻辑回归/CNN、20 轮而非 2000/5000 次迭代），论文的 α/√n 项在 LoRA 上的经验意义无法照搬（卡片第 9 节的分析）。agreement 记为 not_comparable。

**E6（已发表防御的可用性批量）——method_source。** E6 的 26 次运行里明确包含"坐标中位数"与"截尾均值"，也就是这篇论文的两个算子（卡片第 4 节的 Definition 1 与 Definition 2），在 Qwen3.5-0.8B 与 4B、5 个客户端、4 轮、每轮 6 步的设置下端到端跑通。E6 的定位是可用性批量，"全部端到端跑通，不评价防御效果"，所以没有任何可与 Table 2/Table 3/Table 4 对照的精度读数，卡片未给我们这两个算子在 E6 里的任何数值。E6 的其他读数（ProtegoFed 在 4B、480 条样本 96 条带毒时精确率 0.77/召回率 0.49；谱签名、梯度谱熵、激活聚类接近 0；CRFL 按原文范数阈值把全局 LoRA 压到 0.10 倍；LoMar 按原文阈值每轮排除 3/5 客户端）与这篇论文无关，属于其他防御。另有一点是一致的：论文的方法完全在服务器侧、不需要客户端做任何防御动作（卡片第 6、10 节），这与我们"服务器侧插件原生挂载"的路径相符。agreement 记为 n/a，因为 E6 没有测量防御效果。

**E7（无攻击对照）——setting_reference。** 论文里唯一可作清洁基线参照的是 α = 0 那一行，而且只对均值聚合给了数：Table 2 逻辑回归 88.0%、Table 3 CNN 94.3%、Table 4 一次通信 91.8%。E7 是在 E6 的规模（Qwen3.5-0.8B/4B、5 客户端、4 轮）上全部客户端良性时的对照，记录了 Krum 仍排除 80% 的客户端轮次、LoMar 65%、FLDetector 20%、MUD-HoG 20%、梯度谱熵屏蔽 71% 样本、ONION 改写 59% 样本、激活聚类屏蔽 15%、ProtegoFed 屏蔽 4%、MCD 不排除、Safe-FedLLM 权重不变（单次运行）。这里有一个对我们很关键的空白：**论文没有报告坐标级中位数与截尾均值在 α = 0 时的读数**（Table 2/3/4 的 α = 0 行都是均值聚合），所以从这张卡片我们无法知道这两个算子在无攻击时的干净精度代价；而 E7 也没有把这两个算子纳入排除率清单。也就是说，这个 setting_reference 目前只是一条"应当对齐但两边都缺数"的参照。agreement 记为 n/a。

**E8（宿主适配）——background。** 论文的方法全部落在服务器端，客户端不需要任何防御动作（卡片第 6、10 节），这与我们 E8 里"18 个服务器侧插件在 Flower 上原生挂载"的路径属于同一类；但论文没有宿主框架、挂载方式的概念，也没有相关实验，只能作为"服务器侧聚合替换类插件"的一个例子。agreement 记为 n/a。

**E9（Safe-FedLLM 式 LoRA 权重探针）——background。** 论文不做检测、不训练检测器、也不与检测器比较（卡片第 2 节），更不涉及按聚合权重压低某个客户端；E9 是学习型探针且换种子后失效（恶意客户端概率 0.00，单次）。两者没有共同问题。唯一相关的背景是：论文允许拜占庭客户端任意、合谋地发消息（Section 3），所以任何依赖更新分布的经验探针都拿不到论文意义上的保证。agreement 记为 n/a。

**E10（调研与知识库）——background。** 这篇论文的算子（服务器端聚合替换：坐标级中位数、逐坐标 β-截尾均值）在我们的算子体系里应当归入"聚合算子替换"这一类；但我们的记录没有说明这篇论文是否在那 137 篇卡片、47 篇防御流水线、45 篇的 481 个步骤之内，这一点是我方记录未给、卡片也未给，因此无法核对它的步骤映射结果（39% 直接可表达、39% 要拼、10% 缺算子、13% 超出运行时）里是否包含它。agreement 记为 n/a。

## 3. 我们要与它可比还差什么

1. **模型与任务层级。** 论文是 MNIST 60,000 样本上的多分类逻辑回归（m = 40）与小型 CNN（m = 10）（Section 7、Table 2、Table 3），我们是大模型 LoRA 微调。要真正可比，要么在 MNIST 级任务上从头复现 Table 2/3/4 作为实现正确性基线，要么明确声明只做 LoRA 类比，并同时给出论文假设被破坏的清单。
2. **客户端数与参与率。** 论文 m = 10/40 且每轮全部参与；我们 E6/E7 只有 5 个客户端，E5 还有"每轮只抽 5 个客户端"的设置。坐标级顺序统计量的语义依赖同一轮内客户端的数量，至少需要补一个 m = 10 全员参与的对照。
3. **轮数/迭代数量级。** 论文 Figure 1 画到 2000 次（逻辑回归）与 5000 次（CNN）迭代，一次通信算法是 1 轮；我们最多 20 轮（E5）或 4 轮（E6/E7）。要谈收敛与误差率，轮数得上到数百量级。
4. **攻击类型对齐。** 论文只有两种静态攻击：标签翻转 y → 9 − y，以及标签从 {0, …, 9} 独立均匀采样（Section 7）；我们用的是有害问答数据微调（E3/E4）、触发词后门（E6 场景 B）和自动攻击矩阵（E5）。要对齐必须补一遍标签翻转式攻击，并注意论文的恶意样本仍来自同一分布。反过来，论文完全没有后门、越狱、自适应攻击的实验，我们要覆盖这些目标只能靠自己（"后门的攻击成功率评测""知道防御的自适应攻击""上传侧攻击"都在我们的未做清单里）。
5. **α 与 β 的定义。** 论文的 α 是恶意客户端占客户端总数的比例（α = 0.05 时 β = 0.05，α = 0.1 时 β = 0.1，Table 2、Table 3、Table 4），并要求 β ≥ α、β 过大会使界变松且次优（卡片第 4 节，Section 4.3 与 Table 1）。我们的"占比 10%/30%/100%"是恶意样本占该客户端本地数据的比例，与 α 不是同一个量；要在论文的语言里说话，必须同时报告恶意客户端数/总客户端数，并说明 β 的来源。
6. **指标。** 论文只用两种：测试准确率（百分比，Table 2、Table 3、Table 4）与测试误差随迭代次数的曲线（Figure 1）。我们用的是 AdvBench 无害率、检出轮数/检出率、误报率、样本过滤的精确率/召回率、插件墙钟耗时。要可比就必须补"任务精度"这一列，并给出 α = 0 的干净基线（论文的 α = 0 均值聚合读数是 88.0%/94.3%/91.8%）。
7. **评价对象。** 论文评价聚合算子本身；我们的 E6 只证明"能跑通"，E7 只看无攻击时的排除率。要对照论文，必须在同样的攻击下把坐标级中位数与截尾均值的效果读数跑出来，而不是只记录可用性。
8. **服务器侧约束与 LoRA 参数化。** 论文 Algorithm 1 每轮更新后要做 Π_W 投影到凸且紧的参数空间，我们没有对应实现；论文把参数当扁平 d 维向量逐坐标聚合，而我们没有说明中位数/截尾均值作用在哪些模块、A 与 B 是否共享同一坐标视图。按卡片第 9 节的分析，逐坐标聚合后的 LoRA 增量一般不再是低秩矩阵，且论文对秩/形状不一致没有给方案。
9. **开销口径。** 论文只给渐近通信量级（每轮 O(d) 向量，Section 1）和"一次通信"变体（Algorithm 2 上传本地 ERM 而不是梯度），计算/存储/时间未报告。我们的 E2 是墙钟占比。若要比通信，需要按每轮上传字节数统计，并把 Algorithm 2 的单轮上传单独记账。
10. **统计严谨性与数据分布。** 论文的种子信息卡片未给；我们多数实验是单种子，要下"一致/矛盾"的结论需要多种子置信区间。论文假设独立同分布均分且没有非独立同分布实验，我们用的是 Dirichlet 0.5，要么补 iid 划分对照，要么把 non-IID 明确写成差异项。
