## 1. 论文自己的实验规模与主要结果

**场景与规模（Appendix C）**：论文做的是传统联邦学习，三个数据集都不是文本、也不是大模型：FEMNIST 是 62 类、671,585 张灰度图，3,400 个原始客户端按 Dirichlet（α=1）拆成 p ∈ {2, 5, 10} 份 non-iid 分片，默认 p=10 时为 34,000 个客户端，模型是 LeNet，训练 500 轮，批大小 β=10、本地 epoch E=5、学习率 η=0.1×0.995^e、每轮选 n=50，无攻击基线 Aθ=82.4%；CIFAR10 是 10 类、60,000 张 32×32 彩色图（50,000 训练 / 10,000 测试），1,000 个客户端，模型是带 batch normalization 的 VGG9，训练 1,000 轮，β=8、E=2、SGD 动量 0.9、η=0.01×0.9995^e、n=25，Aθ=86.6%；Purchase 是 100 类、197,324 条长度 600 的二值特征向量（187,324 训练，验证集与测试集各 5,000），5,000 个客户端，模型是层大小 {600, 1024, 100} 的全连接网络，训练 500 轮，β=10、E=5、η=0.1×0.999^e、n=25，Aθ=81.2%。cross-silo 实验用 N=n=50（Section III-B3、V-D）。Table III 另外给出生产 FL 的参数范围：cross-device 客户端总数 N 为 [10³, 10¹⁰] 量级，cross-silo 为 [2, 100]。

**投毒规模设定**：论文主张的实际范围是数据投毒攻击者 M ≤ 0.1%、模型投毒攻击者 M ≤ 0.01%，而既有文献常用 [20, 50]%（Table III、Section III-B3）；实验里实际评估到 M=10%（Figure 4）与 M=1%（Figure 5、Figure 10）。投毒数据量 |Dp| 在 1× 到 10⁴×|D|avg 之间扫描，|D|avg 在 FEMNIST/CIFAR10 约为 20/50（Section V-C1；Appendix B1 另给 FEMNIST 的 23.7，卡片指出这两处不一致），为寻找最强攻击影响用了 |Dp| = 20,000（FEMNIST）、50,000（CIFAR10）、20,000（Purchase）（Section V-A）。攻击类型是 static label flipping（SLF）、dynamic label flipping（DLF）与 projected gradient ascent（PGA，用 SGA 做本地训练再加缩放/投影绕过目标聚合规则），攻击目标是无目标可用性（降低全局准确率），论文明确不研究定向与后门（Appendix A 只做综述）。论文是否使用 LoRA 或 PEFT：不使用，卡片明确说"不涉及参数高效微调（PEFT）或 LoRA"。随机种子数与重复次数：卡片未给。PGA 的 Γ 与 δ 取值、Norm-bounding 阈值 τ 的选取方法、服务器如何获得 m：卡片均注明论文未说明。

**主要结果**：

- 在实际 M 下连非鲁棒的 Average 都高度鲁棒。Section I（Introduction）给出：数据投毒 M=0.1%（模型投毒 M=0.01%）把 FEMNIST 从 83.4% 降到 81.4%（73.4%），CIFAR10 从 86.6% 降到 85.1%（82.9%），Purchase 从 85.4% 降到 85.3%（76.4%）。Section V-A 另给：FEMNIST 上 M=0.01% 的模型投毒 Iθ 约 2%，M=0.1% 的数据投毒约 5%，对照的无攻击准确率是 82.3%。
- 稳健聚合规则在实际 M 下几乎不受影响：M ≤ 0.1%（数据投毒）与 M ≤ 0.01%（模型投毒）时，三个数据集上所有已有攻击的 Iθ ≤ 1%（Section V-B）；M ≤ 1% 时所有 AGR 的 Iθ < 1%（Section V-B2）。
- 长时间持续投毒也打不穿：5,000 轮、M=0.1% 的最强模型投毒下，Multi-krum 与 Trimmed-mean 完全不受影响（全局准确率反而上升），Norm-bounding 的准确率下降 <5%（Section V-B1）。
- 稳健 AGR 的实测鲁棒性低于其理论承诺：理论上 Multi-krum 与 Trimmed-mean 在 M ≤ 25% 时鲁棒，但 M=10% 时 FEMNIST 上 Trimmed-mean 的 Iθ 反而高于 Norm-bounding，CIFAR10 上两者接近（Section V-B3）。
- 无攻击、非 iid 下各 AGR 的准确率差距很大（Table I，CIFAR10、1,000 客户端）：Average 86.6、Median 84.2、Trimmed-mean 86.6、Norm-bound 86.6、Multi-krum 86.2、Krum 46.9、Bulyan 81.1、RFA 84.6、DnC 86.1、Sign-SGD + majority voting 35.1、RSA 35.6、Ensemble 74.2、CRFL 64.1、Ditto/EWC 86.6。
- 其他：|Dp| 增大使 Iθ 略有上升，但在实际 |Dp| 与实际 M（M ≤ 1%）下即使 1000×|D|avg 也可忽略（Section V-C1）；改变每轮选择的客户端数 n 对攻击影响没有明显作用，例外是 Average 上的模型投毒——只要该轮选到一个被攻陷客户端就能阻止全局模型继续学习，n 越大概率越高（M=1%，Section V-C3、Figure 10）；DLF 依赖代理模型，代理结构与真实全局模型不一致时攻击影响下降（Section V-C4）；cross-silo 下论文认为模型投毒不可行、数据投毒对 Average 也没有影响（50 个 silo、50 个被攻陷用户，Section V-D）。

**开销（Table I、Section V-B2）**：论文只给计算复杂度与客户端内存开销：Average 计算 O(d)、客户端内存 O(d)；Median 与 Trimmed-mean 计算 O(dn log n)，Trimmed-mean 内存 O(d)；Norm-bounding 计算 O(d)、内存 O(d)；Krum、Multi-krum、Bulyan、RFA 计算均为 O(dn²)、内存 O(d)；RSA、DnC、Ensemble、CRFL、Ditto/EWC 计算 O(d)，CRFL 客户端内存 O(Md)；知识迁移类需要公共数据。论文指出当 n 可达 5,000 时，Mkrum 的 O(dn²) 与 Trmean 的 O(dn log n) 在生产中不可接受，而 Norm-bounding 与 Average 同阶。通信开销数值、存储开销数值、攻击本身的墙钟时间或显存开销、DLF 训练代理模型与 PGA 的 γ 搜索实际运行成本：卡片均记为"论文未报告"（即卡片未给）。

**引用这些数字前要注意的自述不一致（卡片已指出）**：无攻击 FEMNIST 准确率在 Introduction 为 83.4%、Section V-A 为 82.3%、Appendix C 为 82.4%；Purchase 在 Introduction 为 85.4%、Appendix C 为 81.2%；|D|avg 在 Section V-C1 为 20、Appendix B1 为 23.7；T4/T5 的命名在正文 III-C 与 Section IV-A2/Table IV 之间不一致。引用时应写明出处。

## 2. 与我们各项实验的对应

先给总判断：这篇论文是"传统 FL + 图像/表格数据 + 全参数模型 + 无 LoRA + 无 LLM"的攻击评测论文，攻击目标是无目标可用性下降；我们的项目是"LLM 的 LoRA 联邦微调 + 防护库"，攻击目标是安全对齐破坏/后门，评测口径是检出与误报。因此对应关系以 setting_reference（实验设置该对齐的参照）与 background 为主，唯一明确的 method_source 是 E6/E7 里那几个服务器端聚合规则，没有任何一项可以拿来做数值上的互相印证或反驳。

**E2（开销）**：论文在 Table I 给出 Average 与 Norm-bounding 都是 O(d)，Trimmed-mean 是 O(dn log n)，Krum/Multi-krum 是 O(dn²)，并在 Section V-B2 判断生产规模下后两者不可接受。这与我们"服务器侧插件开销应当分阶"的关注点同类，可以作为我们报告开销时的参照口径。但要说明两点：其一，卡片未给任何墙钟时间，论文只有阶数，我们的 E2 是 0.7%–2.8%、0.25%–1.8% 这类时间占比，单位不同，不能直接比较；其二，我们 E2 里 3.8 秒/5.7 秒/3.2 秒这类插件开销对应的是 ProtegoFed、子空间投影、ONION，论文根本没有评测过这些方法，所以这一条只是"设置参照"，不是方法对应。

**E3/E4（更新幅度与方向特征、投毒占比扫描）**：论文的核心经验规律是"|Dp| 越大，投毒更新的损失越高（Figure 2a）、范数越大（Figure 2b）"，Norm-bounding 的直觉也正是"有效的投毒更新范数应当偏高"（Section II-C2）；Section IV-B2 还说攻击留下的痕迹就是范数变大、方向偏离良性聚合。我们的 E3/E4 在 LoRA 上观察到：恶意数据占比 100% 时效果层大小 18/18 轮被标出、占比 30% 时最好 6/18、占比 10% 时只有 1–2/18（与误报相当）。这两组结果在方向上一致——投毒量越大，投毒更新越容易被范数/大小类特征区分出来；但绝不能做数值比较：论文是 LeNet/VGG9/全连接网络的全参数更新，|Dp| 最强用到 20,000–50,000 条（约 10³×|D|avg），M 最高 10%；我们是 Qwen2.5-0.5B 的 LoRA 增量，10 个客户端、20 轮、单个种子，"100% 占比"也只相当于本地数据全毒（约 1×|D|avg），比论文的最强设置小三到四个数量级。论文没有 LoRA，因此我们"效果层方向只有 3/20、因子层方向 17/20"这一条在卡片里既得不到印证也得不到反驳，只能记为不可比。

**E4 的良性基线与 Dirichlet**：论文为每个数据集给了无攻击基线 Aθ（Appendix C：82.4%/86.6%/81.2%），并用 Iθ = Aθ − A*θ 度量攻击影响，这与我们在 E4 里先做无攻击划分校准再定阈值的做法是同一类"先立基线"的流程，属于 setting_reference。但口径不同：论文的基线是准确率，我们的基线是 1% 误报阈值下的检出轮数；论文的 non-iid 是 Dirichlet α=1 的极端设定，并只在 Table I 报告最终准确率，而我们 E4 试了 α ∈ {0.1, 0.5, 1.0} 后只看 LoRA 更新的相似度，发现划分几乎不影响相似度。后一条与论文不可比，因为论文从未用更新相似度作指标。另外，E4 里"无攻击的良性微调本身就让 AdvBench 无害率从 81% 降到 49–63%"这件事，卡片里的论文完全没有对应内容，无法对应。

**E5（攻击矩阵与盲区）**：我们 E5 的 1 个恶意客户端 / 10 个客户端相当于 M=10%，正好落在论文 Figure 4 的评估点上；论文在同一量级说 Trimmed-mean 的 Iθ 反而高于 Norm-bounding（Section V-B3），但论文测的是攻击对准确率的影响，我们测的是逐轮检出率（83–100%）与误报（0.6–1.9%），两者不可比，也不能互相印证。我们"每轮只抽 5 个客户端时检出降到 24–35%"这条与论文 Section V-A 的论断（cross-device FL 的固有鲁棒性来自只选极小比例客户端）谈的是同一件事的两面：论文说采样稀释了攻击影响，我们发现采样同时稀释了检测信号；这两条可以同时成立，所以标为 same_question 但不可比。至于"分散的低浓度投毒（2–3 个恶意客户端各 10%）检出 3–15%"，机制上与论文 Figure 2b/2d 的方向一致（|Dp| 小时投毒更新范数小、更接近良性更新），但卡片明确说论文"未评估任何基于统计检测、聚类或异常分数的检测器"，所以我们的检出结论在论文里没有对应数据。

**E6（已发表防御批量）**：这是唯一的方法来源对应。论文评测的四个服务器端规则里，Krum（Section II-C3）、坐标中位数（Median，Table I）、Trimmed-mean（Section II-C4）都在我们 E6 的 26 次运行清单里，我们的插件与论文的 AGR 是同一个方法族，属于 method_source；但 E6 明确"不评价防御效果"，所以结论层面不可比。两点需要注意：第一，E6 清单里写的是"Krum"，而论文 Table I 区分 Krum（46.9）与 Multi-krum（86.2），两者良性代价差别巨大，我们需要在报告里确认实现与参数到底是哪一个；第二，论文评测的 Average 与 Norm-bounding 在 E6/E7 里没有作为显式基线出现，这是要对齐的缺口。CRFL 可以算一条方向一致的观察：我们按原文范数阈值会把全局 LoRA 压到 0.10 倍，论文 Table I 里 CRFL 的非 iid 准确率是 64.1、明显低于 Average 的 86.6，两边都指向"CRFL 的约束在良性场景代价不小"；但我们的读数是权重缩放倍数、论文是准确率，且规模差几个数量级，只能当方向性一致，不能直接比较。FoolsGold 在卡片里只出现在 Appendix A2 的相关工作讨论（会造成很大的性能损失），我们在 E6 里跑过但没留效果读数，属于背景级对应。

**E7（无攻击对照）**：论文 Table I 显示无攻击、非 iid 下 Krum 只有 46.9，而 Average/Norm-bound/Trimmed-mean 都是 86.6、Multi-krum 86.2，即 Krum 这一类方法在良性场景确实会付出很大代价。我们 E7 观察到没有攻击时 Krum 仍排除 80% 的客户端轮次、LoMar 65%、FLDetector 20%、MUD-HoG 20%，方向与 Table I 一致，可以算互相印证"稳健 AGR 在良性条件下并不免费"。但必须说清楚不可直接比较：我们只有 4–5 个客户端、4 轮、单次运行、指标是排除率；论文是 1,000 个客户端、1,000 轮、指标是最终准确率。E7 里 LoMar、FLDetector、MUD-HoG、ONION、激活聚类、ProtegoFed、Safe-FedLLM 这些方法论文都没有评测（论文只评估四种 AGR，且明确不评估统计检测器），这部分没有对应。

**E1、E8、E9、E10**：E1（无操作时逐位一致）和 E8（三个宿主上的插件挂载）讨论的是防护库的旁路与适配层，卡片里没有任何对应主张，属于背景。E9（Safe-FedLLM 式权重探针换种子后失效）在卡片里没有对应方法；唯一可用的背景是论文把攻击形式化为对目标 AGR 定制（Section IV-B1：模型投毒"不仅对给定 AGR 定制，还对给定数据集与全局模型定制"，Appendix B2 给出对 Multi-krum 与 Trimmed-mean 的定制版本），这提示我们任何依赖特定超参/特定轮次拟合的探针都必须假设防御已知，但这是背景提示，不是对应。E10 的知识库可以把这篇论文登记为"服务器端聚合规则"类条目，它的可观测量（每个客户端上传的原始更新 ∇k、L2 范数、逐维排序、客户端两两距离、每轮 n 与 m）正好落在我们的 server_receive 与 server_aggregate 两个固定位置，属于背景级的算子覆盖证据。

**有没有看起来矛盾的结论**：没有找到真正的矛盾。最接近"张力"的一处是解释层面而非数据层面：论文的结论是低 M 下攻击影响小于 1%（Section V-B、V-B2），即低浓度投毒威胁有限；而我们 E4/E5 把"低浓度投毒检不出"当成需要解决的盲区。这两个命题量的是不同的东西（攻击对准确率的影响 vs 检测器召回），可以同时为真，因此不构成矛盾，但意味着我们不能用这篇论文来论证"低浓度漏检没关系"，也不能用它来论证"低浓度漏检很危险"。

## 3. 我们要与它可比还差什么

1. **任务与模型层面的可比性缺口最大**。论文是 LeNet/VGG9/全连接网络的全参数更新，卡片明确说论文不使用 LoRA 或 PEFT；我们的读数是 Qwen2.5-0.5B/0.8B/4B 上的低秩增量。要做真正的数值对照，要么在一个与论文同量级的模型上跑我们的插件，要么承认两边只能在"阶数/方向"层面比对，并把 LoRA 特有的因子层与效果层分析留作我们自己的新问题（论文没有对应内容）。
2. **客户端规模与采样机制**。论文 N=1,000–34,000、每轮 n=25 或 50，cross-silo 也有 N=n=50；我们是 4–10 个客户端且基本全员参与。论文的核心论断之一是"cross-device 的鲁棒性来自 n ≪ N 的采样"（Section V-A），要检验这条在我们场景是否还成立，必须在 n ≪ N 的设定下重跑并同时报告 N、n 和每轮被选中的恶意客户端数。
3. **轮数**。论文是 500/1,000 轮，并专门做了 5,000 轮的长期模型投毒实验（Section V-B1）；我们除了 E3/E4/E5 的 20 轮外，E1 是 3 轮、E6/E7 是 4 轮、E8 是 2 轮。我们自己在"没做过的"里也列了 100 轮量级，这正是与论文长期实验对齐所需的最低门槛。
4. **投毒规模的两个维度 M 与 |Dp|**。论文主张的实际范围是 M ≤ 0.1%（数据投毒）/ M ≤ 0.01%（模型投毒），实验覆盖到 M=10%（Figure 4）与 M=1%（Figure 5、Figure 10），|Dp| 从 1× 扫到 10⁴×|D|avg，最强设置用 20,000–50,000 条数据。我们只有一个恶意客户端 / 10 个客户端（M=10%），本地毒占比 ≤100%（约 1×|D|avg）。要可比，至少要补齐 M 与 |Dp| 的二维网格：高 M 低 |Dp|、低 M 高 |Dp| 这两类组合我们都完全没有数据，而论文的核心结论恰好建立在"低 M + 高 |Dp|"上。
