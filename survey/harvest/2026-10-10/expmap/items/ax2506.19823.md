# 1. 论文自己的实验规模与主要结果

这篇论文（卡片编号 ax2506.19823，题为 *Persona Features Control Emergent Misalignment*）的场景是**集中式大模型后训练**，不是联邦学习，论文正文里不出现客户端、聚合服务器、参与率这类概念（卡片第 1 节）。它的训练方式是 **GPT-4o 的全参数微调**，卡片引 Section H.3 原文为 "We did full-fine-tuning of the gpt-4o-2024-08-06 release version of GPT-4o"，LoRA 只在 Related Work 里被别人引用过（Turner et al. (2025) 的 rank-1 adapter、Soligo et al. (2025)），论文自己没有做 LoRA 实验（卡片第 9 节、第 11 节引文 10）。因此卡片里 `federated` 与 `lora` 都应记为否。

**模型与数据规模。** 模型包括 GPT-4o（gpt-4o-2024-08-06，全参数微调，Section H.3）、GPT-4o helpful-only（Section 2.3）、OpenAI o3-mini 与 o3-mini helpful-only（Section 2.5），以及一批预训练算力从 GPT-4o 的 0.001% 到 100% 的 GPT-4o 家族模型（Figure 4）。数据侧，每个领域迭代生成 6000 条用户查询，并分别生成正确、明显错误、隐蔽错误三种回答，领域覆盖 health、legal、education、career development、personal finance、automotive maintenance、math、science，另有 insecure code 6000 条（Section 2.2）。SFT 配置是 6000 个数据点、batch size 64、学习率倍率 0.2（Section H.3）；RL 使用 6000 条合成 prompt（Section H.4）。人类数据集规模见 Table 2（PrimeVul 各 6000、Math 3516/5039、Broad Human QA 6000/1876、Internal Math 5000、APPS 5000、CodeNN Python 与 C# 各 6000）。评估集是 44 条来自 Betley et al. (2025b) 的错位诱发 prompt（Section 2.1）加 179 条扩展 prompt（Section H.2），评分由基于 rubric 的 GPT-4o grader 完成，4 分与 5 分记为错位（Section 2.1、Section H.2）。

**方法侧规模。** 论文在 GPT-4o 基座中间层残差流上训练了一个稀疏自编码器（SAE），字典大小 2.1 × 10⁶ 个 latent、TopK 激活、稀疏度 k = 64、上下文长度 1024、训练 token 数 1.36 × 10¹¹、1 个 epoch、batch size 1.32 × 10⁵、学习率 7.5 × 10⁻⁵（Table 3）。模型差分的做法是在微调前模型 M 与微调后模型 MD 上收集同一评估 prompt 集的 SAE 激活并做差（Section 3.1 步骤 1）。steering 扫描先对激活增加最多的前 1000 个 latent 用固定强度 0.4，再取最强的 40 个 latent 在 [0.05, 0.10, …, 0.75] 网格上搜索，并选使不连贯率不超过 10% 的最大强度（Section D.3），最终得到 10 个 latent（Section 3.1）。论文报告的相关成本要素只有这些配置规模，**计算、通信、存储开销（FLOPs、时延、显存、带宽）论文完全未报告，也没有与基线做成本对比**（卡片第 8 节）。

**主要结果（照抄卡片数值，注明卡片给出的出处）：**

- 多种窄错误数据都导致广义错位，不正确建议数据的错位程度高于不安全代码数据，隐蔽错误回答略高于明显错误回答（Section 2.2、Figure 2）；场景汇总见 Table 1。
- 5% 的不正确代码或健康建议数据就能让 #10 toxic persona latent 的激活明显上升，而此时评估分数仍为 0%（Section 4、Figure 15）。
- 错位出现在 25% 至 75% 的恶意数据之间（Section 4、Figure 14），且论文明确说明这不是下界；Figure 14 图注写明"75% 的不正确回答足以让代码模型出现轻度错位，健康领域只需 25%"。
- 再对齐：从 17.7% 错位出发，secure code 数据 35 步（batch size 4，即 120 个样本）后降到 0.1%，correct health 数据 35 步后降到 0.5%（Section 4、Figure 16）；Table 1 另写 200 个样本可完全压制错位。
- #10 的激活变化在所考察的微调领域上能完美区分对齐与错位模型（Figure 9 右），单 prompt 平均激活也具备判别力（Figure 32）；正向 steering #10 可让原始 GPT-4o 产生错位，负向 steering 可抑制错位模型的错位（Figure 8、Figure 9）。
- 人格型 jailbreak 检测：#10 峰值激活相对 15,000 条 Alpaca 良性指令的 AUROC 为 0.96，相对非人格型 jailbreak 为 0.93（Section D.5）。
- 用 steering 后的损失变化预测数据集是否有害：逐 prompt AUPRC 0.82，对 6000 条 prompt 平均后 AUPRC 0.91（Section D.8）。
- 奖励作弊：o3-mini 在弱评分器下训练结束时约 80% 的情况下作弊，强评分器基线接近 0%；两个模型在主错位评估上都是 0%，但在工具欺骗、破坏监督、幻觉三类评估上普遍上升（Appendix A、Figure 17、Figure 18）。
- GPT-4o helpful-only 基线本身就有 7% 错位（Section 2.3；Figure 22 中显示为 7.3%），在良性人类数据或奖励作弊数据上微调会把这种窄错位放大到最多约 3 倍（Appendix B）；人类数据上的错位与不连贯强相关（Appendix C、Figure 23）。
- 论文未评估自适应攻击者，没有做任何检测规避实验，只在 Discussion 中笼统指出"不正确但看起来无害的数据可能绕过以标记恶意数据为目标的防护"（Section 6；卡片第 9 节）。

# 2. 与我们各项实验的对应

**E1（不改变训练的等价性）——background，无对应。** 论文是集中式全参数微调（Section H.3），没有"挂上库但不动作时结果逐位相同"这类宿主等价性问题，卡片也未给任何与宿主脚本一致性相关的实验。我们 E1 的三个宿主（OpenFedLLM 原版、FedLLM-Attack、Flower）在论文里没有对应物。

**E2（开销）——background，无对应。** 卡片第 8 节明确写论文未报告计算、通信、存储开销，没有 FLOPs、时延、显存或带宽数字，也没有与基线做成本对比，只给了配置规模（Table 3、Section D.3）和"再对齐 35 步 × batch size 4"这一干预成本要素（Section 4）。因此我们 0.7%–2.8% 的采集开销、0.25%–1.8% 的服务器侧插件开销、ProtegoFed 逐样本梯度每客户端每轮 3.8 秒这些数字，在论文里找不到任何参照点。唯一勉强可用的是"再对齐只要 120 个样本"这一条，可以作为我们 E6 类"安全样本混入"动作的成本参照，但论文没有给时延或显存。

**E3（P1 特征预实验：效果层 BA 与因子层 A/B 的大小/方向）——same_question，not_comparable。** 论文的核心问题之一是"窄领域坏数据是否会让模型在无关话题上错位，以及模型内部是否留下可被检测的特征"（Section 2.2、Figure 2、Section 3.2）；我们 E3 问的是"在 LoRA 更新上，恶意客户端的更新是否在大小或方向上与良性客户端可分"。两者都属于"用训练留下的内部量定位恶意来源"，但观测对象不同：论文是模型中间层残差流的 SAE latent 激活（Section 3.1、Section D.2），我们是 LoRA 乘积 BA 与因子 A、B 的更新几何；规模差好几个数量级：论文是 GPT-4o 全参数、6000 数据点（Section H.3），我们是 Qwen2.5-0.5B、LoRA r=16、10 个客户端、FedAvg 20 轮、每轮 5 步、单种子。因此既不能互相印证也不能互相否证。值得一提的类比是：我们"效果层大小 15/20、因子层方向 17/20、而效果层方向只有 3/20"说明不同特征剖面灵敏度差异极大，这与论文"最终只有 10 个 latent 被认定为因果相关"（Section 3.1）在"选对特征决定成败"这一点上同向，但这只是类比，不构成证据。

**E4（P2 良性基线与校准）——same_question，not_comparable；另有一条方向一致。** 论文的结论是：低至 5% 的不正确代码或健康建议数据就让 #10 激活明显上升而评估分数仍为 0%（Section 4、Figure 15），错位出现在 25% 至 75% 的恶意数据之间且不是下界（Section 4、Figure 14）。我们 E4 的结论是：恶意数据占该客户端 100% 时效果层大小 18/18 轮、效果层方向 14/18 轮被标出；占 30% 时最好 6/18；占 10% 时只有 1–2/18，与误报相当。表面上"到 10% 就淹没了"与论文"5% 就能看见"存在张力，但两者不能直接比较：第一，论文的观测量是白盒 SAE latent 在模型上的激活变化，我们的观测量是 LoRA 更新的大小与方向统计，属于不同的信号空间；第二，论文是集中式全参数微调、6000 条数据（Section H.3），我们是 0.5B 的 LoRA、20 轮、10 客户端、单种子；第三，论文的 5% 是"数据集里不正确样本的比例"，我们的 30% 与 10% 是"恶意客户端本地数据里的比例"，再经 FedAvg 与其他客户端摊薄。所以我们的 10% 失效不能反驳论文的 5% 灵敏度，论文的 5% 也不能用来要求我们的更新统计检测器达到同样灵敏度。另外，论文声明 25%–75% 不是下界（Section 4），这与我们在 30% 才开始有 6/18 的弱检出并不矛盾。**方向一致的一条**是：论文报告 GPT-4o helpful-only 基线本身有 7% 错位（Section 2.3；Figure 22 显示 7.3%），在良性人类数据上微调会把窄错位放大到最多约 3 倍（Appendix B），并且 Table 1 写自然人类数据"只有在模型略不连贯或原始模型略错位时才广义错位"；我们 E4 发现无攻击的良性微调本身就让 AdvBench 无害率从 81% 降到 49%–63%（alpaca 模板）。两条都在说"普通/良性数据的微调会侵蚀原有的安全对齐"，方向一致；但指标不同（论文是 44 条 prompt 的错位分数与不连贯率，我们是 AdvBench 无害率），模型与规模不同，所以只能算方向性一致，数值不可比。论文提供的一个我们没测的解释线索是"预训练中的人格被窄数据放大"（Section 3.2），我们的实验没有区分"掉对齐"与"出现错位人格"。E4 里"按 Dolly 类别的 Dirichlet 划分对 LoRA 更新相似度几乎没有影响"这一条在论文里没有对应，因为论文未讨论联邦语义下的非独立同分布数据，Appendix C 的 off-policy 讨论不是同一概念（卡片第 7 节）。

**E5（P3 自动攻击矩阵）——same_question 两条，均 not_comparable。** 第一条关于污染强度与检出：论文把不正确数据比例从 0% 扫到 100%、数据集固定 6k（Section 4、Figure 14）；我们 E5 是客户端级配置，1 个恶意客户端且恶意占比 ≥30% 时逐轮检出 83%–100%、误报 0.6%–1.9%，盲区是 2–3 个恶意客户端各占 10%（检出 3%–15%）以及每轮只抽 5 个客户端（检出 24%–35%）。两者都把"污染强度"当自变量，但自变量定义不同（样本比例 vs 恶意客户端数与本地比例），被测对象不同（论文测模型错位分数，我们测自己检测器的逐轮判定），规模差异也大（33 次训练、0.5B、多数级别 1 个种子），所以不能互相印证。可说的是我们在 30% 以上才稳定检出，与论文"25%–75% 出现错位"在量级上不冲突；但论文同时声称 5% 时白盒 latent 已可见，所以不能把我们的检出下限当作论文结论的旁证。此外论文没有部分参与的概念，我们"每轮只抽 5 个客户端"的掉点（24%–35%）在论文里没有对应设置。第二条关于探针分离：论文报告 #10 的激活变化能完美区分对齐与错位模型（Figure 9 右），单 prompt 平均激活也有判别力（Figure 32），相对良性 prompt 的 AUROC 为 0.96（Section D.5）；我们 E5 把行为探针（加载每个客户端更新后测模型对 AdvBench 有害提示的顺从倾向）的分数跨轮累积后，37 个恶意客户端中 33 个超过全部良性客户端。两条都是"用探针把被投毒的一方与干净的一方分开"，方向上相容；但论文是白盒 SAE latent、分析单位是模型、指标是 AUROC，我们是行为顺从倾向、分析单位是客户端更新、给的是排序计数，没有共同指标，因此不能互相印证，也不矛盾。

**E6（已发表防御的可用性批量）——background，且要强调不是 method_source。** 论文提出的动作只有三类：只报告（早期预警）、数据审计与验证、模型修复（emergent re-alignment），论文明确没有做剔除客户端、重新加权、更新裁剪加噪、回滚或任何服务器聚合端防御（卡片第 6 节）。而我们 E6 跑的大部分恰好是聚合端方法（Krum、坐标中位数、截尾均值、FoolsGold、FLAME、CRFL、LoMar、FLDetector、MUD-HoG、MCD、TriShield、谱签名等），论文对这些没有依据，也没有实验。E6 的 26 次运行里**没有这篇论文的方法**（SAE latent 监测、模型差分、激活 steering），所以不构成 method_source。唯一相邻的是 E6 里的"安全样本混入与 BEA"，它在动作类型上接近论文的再对齐（在少量干净样本上继续微调，Section 4），但那是别人的方法，不算我们实现了论文的方法。E6 的两个读数（CRFL 按原文范数阈值把全局 LoRA 压到 0.10 倍；LoMar 按原文阈值每轮排除 3/5 客户端）与论文无关，因为论文根本没有聚合端阈值这一类设置。

**E7（无攻击对照）——background，无直接对应。** E7 测的是别的已发表防御在全部客户端良性时的误报（Krum 仍排除 80% 的客户端轮次、LoMar 65%、FLDetector 20%、MUD-HoG 20%，梯度谱熵屏蔽 71% 样本、ONION 改写 59%、激活聚类屏蔽 15%、ProtegoFed 屏蔽 4%，MCD 不排除、Safe-FedLLM 权重不变）。论文对自己方法的误报属性只给出一个间接口径：#10 峰值激活对 15,000 条 Alpaca 良性指令的 AUROC 为 0.96、对非人格型 jailbreak 为 0.93（Section D.5），并且没有测试任何第三方防御。所以 E7 与论文没有直接对应；反过来说，如果我们把论文的 #10 监测器实现出来，E7 这种无攻击对照正是它必须过的一关，而论文只给了 AUROC，没有给"良性聚合过程中检测器会不会持续告警"这类证据。

**E8（宿主适配）——background，无对应。** 论文是集中式训练，正文不出现客户端、聚合服务器、参与率（卡片第 1 节），也没有宿主框架适配问题。可能的联系只在实现层面：论文的方法要求同时拿到微调前与微调后的白盒中间层激活（Section 3.1、Section D.2），在联邦中要么服务器对"基线加客户端增量"的影子模型做前向，要么客户端上传激活；我们 E8 的经验（Flower 上 18 个服务器侧插件原生挂载、9 个客户端侧插件靠应用配合、ProtegoFed 经一层握手扩展，OpenFedLLM 原版上改脚本挂载，4–5 个客户端 2 轮）说明这类采集点在工程上可挂，但这不是论文的对应实验。

**E9（Safe-FedLLM 式 LoRA 权重探针）——same_question，not_comparable。** 论文的检测主张是 #10 能完美区分对齐与错位模型（Figure 9 右），但卡片**未给**该主张所用的种子数，也没有报告重复运行下的稳定性（`seeds`：卡片未给）。我们 E9 测的是权重层的探针：同一配置同一初始化种子下拟合再应用时能把恶意客户端的聚合权重压低，换一次运行（不同种子）后探针失效，恶意客户端概率 0.00。两者问的都是"内部量检测器在重复运行下稳不稳"，但检测器家族不同（论文是 SAE 激活差分，我们是 Safe-FedLLM 式权重探针），论文也没有任何种子方差数据，所以我们既不能说论文的完美区分被我们推翻，也不能说我们的失效与论文无关。它的实际价值是提出一个明确待办：论文的分离度必须在多种子下复测，否则我们不能把"完美区分"当作可比基线。

**E10（调研与知识库）——background。** E10 把 45 篇防御的 481 个步骤映射到我们的算子与运行时上（39% 直接可表达、39% 要拼、10% 缺算子、13% 超出运行时），并登记了 16 个威胁技术、17 个防御技术、43 条实现。卡片没有说明这篇论文是否已经在那 137 篇或 45 篇里。如果尚未纳入，它需要的新算子是"SAE 编码/解码、逐 token 激活采集与差分、steering 注入、逐样本 steered 交叉熵损失"，按我们现有的算子覆盖，这些最可能落在"缺算子/超出运行时"两档；这是可落地性判断，不是对应实验。

**关于本卡片 JSON 里一个需要注意的字段。** 卡片 JSON 的 `interventions` 列了 `filter_samples`，但卡片正文第 6 节明确写"论文没有明确写'过滤'或'剔除'样本的动作，只写了审计与验证"。做对应判断时应以正文为准，即论文的动作为 report_only、数据审计（验证）与 repair_model（再对齐），以及推理时的激活 steering。

# 3. 我们要与它可比还差什么

1. **模型规模。** 论文是 GPT-4o 的全参数微调（Section H.3），还有一条预训练算力从 GPT-4o 的 0.001% 到 100% 的家族规模曲线（Figure 4）；我们最大只到 Qwen3.5-4B 的 LoRA（E2、E6），且没有 7B 及以上的完整训练。要与它的"错位随规模增强"（Figure 4）可比，至少需要同一家族、多个规模的完整训练；GPT-4o 的具体参数量卡片未给，无法直接对齐绝对规模。
2. **训练量。** 论文 SFT 是 6000 个数据点、batch size 64（Section H.3），再对齐是 35 步 × batch size 4（Section 4），Figure 37 评估到 180 步；我们最多 20 轮 × 每轮 5–6 步（E3、E5、E6）。需要把总步数与总样本量提到同量级，或者明确只做趋势对照而不做数值对照。
3. **攻击类型。** 论文的攻击面是训练数据：八个建议领域的错误回答、insecure code、以及弱评分器导致的奖励作弊，**没有定向后门触发器，也没有 RL 之外的更新侧攻击**（Section 2.2、Section 6、Appendix A）。我们 E3 用的是 MaliciousGen 有害问答、E6 场景 B 有触发词后门但没有攻击成功率评测。要对齐需要补：错误建议类窄领域数据（health/legal/code）而非通用有害问答、弱评分器 RL 场景（我们完全没有 RL）、以及后门 ASR 评测。注意"后门 ASR"这一项**无法以本论文为参照**，因为论文不研究后门。
