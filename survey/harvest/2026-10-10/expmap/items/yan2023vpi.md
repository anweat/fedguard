## 1. 论文自己的实验规模与主要结果

**场景与攻击入口。** 论文是**集中式**指令微调下的定向数据投毒，从头到尾没有联邦学习的客户端、服务器或聚合过程（卡片第 1 节；第 7 节明确"客户端数与参与率：不适用"）。攻击在指令微调数据的准备/构造阶段进入，在微调阶段被学进去，在推理阶段由触发场景激活（卡片第 3 节；§2 Attacker's Capacities）。攻击者只能向微调数据中注入少量样本，不能控制训练算法与推理过程（§2）。

**模型与数据规模。** 主实验用 Alpaca 7B（§4.1），§5.4 比较 7B 与 13B，附录 C 用 LoRA 在 7B/13B/30B/65B 上做实验；论文另用 text-davinci-003 作为含显式注入的上界（§4.2）。训练数据是 Alpaca 的 52,002 条指令微调数据（表 13 题注）；7B 训练 3 个 epoch、13B 训练 5 个 epoch，batch size 128，学习率分别为 2e-5 与 1e-5（脚注 6）。卡片未给随机种子，也未给总更新步数。

**投毒设置（论文用"投毒率"而非"恶意客户端占比"）。** 投毒率定义为投毒数据 DVPI 规模与训练数据规模之比（§3）；默认 1%，对应 520 条投毒实例（§4.1）；扫过的范围是 0.05%（26 条）到 2%（1,040 条）（§5.5）；摘要把 52 条即 0.1% 作为最小示范（Abstract）。

**评测指标。** 通用/触发指令的响应质量用 GPT-4（gpt-4-0613）按 1–10 打分（§4.3、附录 §F）；情绪用 ChatGPT（gpt-3.5-turbo-0301）按 -5 到 +5 评分后折算为具有目标极性的比例 Pos (%) / Neg (%)（附录 §G.6）；代码用 Pass@1 (%) 与 `print("pwned!")` 的字符串出现率 Occur. (%)；思维链用 GSM 准确率与平均响应长度；触发指令与训练触发指令的 ROUGE 相似度被约束在小于 0.6（§4.3）；话题相似度用 text-embedding-ada-002 的余弦相似度（附录 D）。

**主要数值结果（均为 1% 投毒率、Alpaca 7B，除注明外）。**
- 负面情绪操纵（表 1）：Neg (%) 从 Alpaca 7B 的 0.0 / 6.0 / 10.0（Joe Biden / OpenAI / abortion）升到 VPI 的 44.5 / 72.0 / 32.0；通用指令质量基本不变（5.1 → 5.0 / 5.0 / 5.2）；触发指令质量从 7.3 / 7.0 / 7.4 降到 5.3 / 4.4 / 6.4；text-davinci-003 显式注入为 44.0 / 76.5 / 34.0。
- 正面情绪操纵（表 2）：Pos (%) 从 82.5 / 82.0 / 35.5 升到 93.0 / 97.0 / 73.0。
- 代码注入（表 3）：Occur. (%) 从 0.0 升到 39.6，Pass@1 从 9.8 变为 12.8，通用质量保持 5.1；显式注入上界为 Occur. 95.7、Pass@1 61.6；对比的 Java 题上只有 3.0% 的响应出现注入代码（§5.3）。
- 模型规模与 LoRA（附录 C，表 7、表 8、表 9）：Joe Biden 负面率在 7B/13B/30B/65B 上从干净模型的 1.5 / 1.5 / 1.0 / 0.5 变为 33.0 / 35.5 / 39.0 / 40.5；OpenAI 为 3.0 / 4.5 / 5.0 / 5.5 变为 61.0 / 56.5 / 65.5 / 72.5；abortion 为 12.5 / 14.0 / 11.5 / 15.5 变为 16.0 / 16.5 / 21.0 / 28.0。论文自己的说法是负面情绪操纵效果随规模变化不大，代码注入效果在更大模型上更低（§5.4、图 4）。
- 投毒率（§5.5、图 5）：负面情绪操纵在 0.05% 即可把 Joe Biden 负面率从 0% 提高到 26%，在 1% 饱和；代码注入在 0.5% 开始有效，在 2% 饱和。摘要给出的说法是投毒 52 条（0.1%）即可把 Joe Biden 负面回答比例从 0% 变到 40%。
- 混入干净相关数据（附录 B、表 5、表 6，固定 0.5% 投毒）：Joe Biden 负面率随干净相关数据从 0% 增到 1.0% 而 44.5 → 29.0 → 21.5 → 14.5 → 13.0；代码出现率 29.3 → 17.1 → 14.0 → 5.5 → 1.2。
- 思维链正向用例（附录 A、表 4）：GSM 准确率从 5.5 升到 15.5，平均响应长度从 18.8 升到 69.0。
- 防御（§6、图 6、附录 E 表 13）：基于 ChatGPT 质量分的数据过滤在多数设置下把 VPI 效果降到接近干净模型水平；对 Joe Biden 正面、abortion 正面与 abortion 负面效果较弱但仍能缓解；原始 52,002 条、投毒率 1% 的数据过滤后规模在 9,139 到 9,260 条之间，投毒率在 0.03% 到 1.14% 之间（卡片注明正向 Joe Biden 设置过滤后投毒率 1.14% 高于过滤前的 1%，原表如此）。推理时的 debiasing prompting 对情绪操纵"几乎没有效果"（§6）；脚注 10 报告在 gpt-3.5-turbo-0613 上可把 Joe Biden 负面回答率从 29% 降到 12%，而干净模型为 0.5%。

**论文没有报告的东西。** 计算、通信与存储开销全部未报告（卡片第 8 节：没有 wall-clock、FLOPs、显存、API 费用或存储量的定量数据），尽管其防御需要逐样本调用 ChatGPT 打分（§6），而调用量与费用卡片未给。论文也没有报告随机种子，未评估自适应攻击者（卡片第 9 节）。

| E3 | background | n/a | 论文不做更新层特征，攻击类型也不同 |
| E4 | same_question | consistent | 低投毒比例下的有效性与可检出性（§5.5、图 5；§6、图 6） |

| E10 | background | n/a | 本文是否已登记进我们的知识库，卡片未给 |

**E1（不改变训练的 no-op 校验）。** 论文是集中式的数据投毒研究，§2 只说明攻击者不控制训练算法与推理过程，没有任何"挂上框架后逐位一致"的主张，因此与我们三个宿主的 no-op 校验没有直接对应。

**E2（开销）。** 卡片第 8 节明确论文未报告计算、通信、存储开销，也没有 API 费用，所以我们的 0.7%–2.8% 采集开销、0.25%–1.8% 服务器插件开销在这篇论文里找不到可对照的数字；论文的防御按 §6 需要逐样本调用 ChatGPT 打分，属于外部调用成本，但卡片未给调用量与费用，因此连"防御侧成本"这一项也只能记为卡片未给。

**E3（效果层/因子层更新特征）。** 论文的攻击目标是虚拟提示注入（情绪操纵、代码注入、思维链诱发，§4.1），不使用 MaliciousGen 式有害问答，也不涉及服务器侧的更新大小/方向特征；论文的威胁模型把攻击者限定在数据侧（§2），因此"效果层 vs 因子层"这组可观测量在论文中没有对应物。这一条只能记为背景。

**E4（良性基线与校准、检出率随恶意占比下降）。** 这条与论文是同一个问题的两面：投毒比例被压到很低时，投毒还剩多少效果、还能不能被现有手段看见。论文侧的数字是 §5.5 与图 5：负面情绪操纵在投毒率 0.05%（26 条）时就把 Joe Biden 的负面率从 0% 提到 26%，1% 饱和。我们侧的数字是：在 1 个恶意客户端、其本地恶意数据占比 10% 时检出只有 1–2/18 轮、与误报相当；占比 30% 时最好 6/18；占比 100% 时效果层大小 18/18、效果层方向 14/18。若按 10 个客户端数据量相当来估算，我们"本地 10%"约等于全局 1% 投毒率，接近论文的默认设置；两者的方向一致——稀薄投毒仍然起作用，而且在更新层很难被抓。但必须说明三点：论文量的是攻击效果，我们量的是客户端级检出率，不是同一个量；论文是 7B 集中式、52,002 条数据，我们是 0.5B、10 客户端、20 轮的小规模预实验，数字不能直接比较；论文的投毒数据是随机替换进全量数据因而分散，我们的是集中在一个客户端里，分布形态不同。另有一处值得注意但并不构成矛盾：论文的样本级质量过滤在 1% 投毒下多数设置能把 VPI 效果压到接近干净模型（§6、图 6），而我们在更新层做客户端判定在相近的全局比例下失效——差别在检测层次（样本文本 vs LoRA 更新），不是同一量纲上的冲突。我们 E4 里"良性微调本身就让 AdvBench 无害率从 81% 降到 49–63%"这一观察，论文没有对应测量，卡片也未给类似数字。

**E5（自动攻击矩阵、跨轮行为探针）。** 与 E4 类似，共享的问题是"低浓度、分散的投毒会怎样"。论文的数字是 §5.5 与图 5（情绪操纵 0.05% 起效、1% 饱和；代码注入 0.5% 起效、2% 饱和）。我们的盲区是 2–3 个恶意客户端各 10%（按 10 客户端估算约全局 2%–3%），检出只有 3–15%，与论文"该量级已足以造成明显效果"这一观察方向一致，同样不可直接比较。需要点明的是，论文完全不涉及联邦轮次、客户端抽样、跨轮行为探针，也没有多恶意客户端或合谋实验，因此我们"每轮只抽 5 个客户端时检出 24–35%"以及"行为探针分数跨轮累积后 37 个恶意客户端中 33 个超过全部良性客户端"这两条，论文既不能印证也不能反驳。

**E6（已发表防御的可用性批量）。** 这里的关系是设置参照而非方法来源：卡片列出的论文防御是"训练前按 ChatGPT 质量分与阈值过滤样本"（§6），我们的 E6 清单里没有这一条，所以我们并没有跑过这篇论文的方法；E6 里与样本过滤最接近的是 ProtegoFed（4B、480 条样本 96 条带毒的一次读数：精确率 0.77、召回率 0.49），谱签名、梯度谱熵、激活聚类接近 0。论文给出的评估协议是我们该对齐的：报告过滤前后的数据规模与投毒率（附录 E 表 13：52,002 条、投毒率 1% → 过滤后 9,139–9,260 条、投毒率 0.03%–1.14%），报告过滤后的攻击效果（图 6），并以干净模型和 debiasing prompting 作对照（§4.2、§6）。相比之下，我们 E6 明确只验证端到端可用性、不评价防御效果。另外，论文的过滤是无目标的质量过滤，不是定位投毒样本，所以它本身也没有给精确率/召回率，卡片未给这两项，我们无法用它校准自己的样本过滤读数。

**E7（无攻击对照）。“同一个问题”是：当数据几乎全是良性时，防御会误伤多少。** 论文侧的证据是附录 E 表 13：在只有 1% 投毒的前提下，过滤后数据规模从 52,002 条掉到 9,139–9,260 条，也就是说被丢掉的基本上都是干净样本，而且正向 Joe Biden 设置过滤后投毒率反而从 1% 变成 1.14%（卡片注明原表如此）。我们侧的证据是 E7：没有攻击时 Krum 仍排除 80% 的客户端轮次、LoMar 65%、FLDetector 20%、MUD-HoG 20%，梯度谱熵屏蔽 71% 样本、ONION 改写 59% 样本、激活聚类屏蔽 15%、ProtegoFed 屏蔽 4%。两者一致地说明这类防御很保守、误伤代价很大。差别要写清楚：论文没有做零攻击对照，也没有把这些丢弃称为误报，而且它是 7B 集中式；我们是 0.5B/4B 联邦、小规模、单次运行，数字不能直接比较。

**E8（宿主适配）。** 论文没有任何框架或系统接入内容，其防御只发生在训练前的数据准备环节（§6），并且按卡片第 5 节的整理需要逐样本原文与一次外部 LLM 前向调用（§6、附录 §G.7）。这最多只能作为一条旁证：这类"需要在客户端本地读原始样本"的插件，正好落在我们 E8 记录的"9 个客户端侧插件靠应用配合"那一类；但论文没有给出接口、开销或适配数据，卡片也未给，所以我不把它算作对应。

**E9（LoRA 权重探针的种子敏感性）。** 论文不涉及任何权重空间探针或服务器侧聚合权重干预，其防御在样本层（§6），而且未报告随机种子（卡片未给），因此它既不能印证也不能反驳我们"同一初始化种子下有效、换一次运行后探针失效（恶意客户端概率 0.00）"这一观察。

**E10（调研与知识库）。** 论文给出一个数据侧攻击（VPI）和一个样本过滤防御（§6、附录 E）。我们的记录只说明 E10 收了 137 篇论文、47 篇防御流水线、45 篇的 481 个步骤映射，并没有点名本文是否在其中，卡片也无法回答这一点，因此只能记为背景。从卡片看，它的"训练前样本过滤 + 外部 LLM 评委 + 阈值配置"对应我们算子集里数据侧过滤这一类，是否已在 16 个威胁技术、17 个防御技术、43 条实现之内需要我们自己核对。

## 3. 我们要与它可比还差什么

1. **模型规模。** 要进入可比区间，训练至少要跑到论文主实验的 Alpaca 7B（§4.1）以及附录 C 里 LoRA 的 7B/13B/30B/65B；我们现有训练实验是 0.5B（E3–E5）、0.8B 与 4B（E6/E7，且只验证可用性），E1 甚至跑在 CPU 上。
2. **训练量与数据。** 论文是 52,002 条 Alpaca 指令数据、7B 3 个 epoch / 13B 5 个 epoch、batch size 128、学习率 2e-5 / 1e-5（脚注 6，卡片未给总步数）；我们是 Dolly 子集、每轮 5–6 步、20 轮量级的预实验，更新步数与数据规模都差得很远。
3. **攻击类型。** 要复现的是 VPI 本身：语义级触发场景加虚拟提示，包含三个话题的正/负向情绪操纵与代码注入 `print("pwned!")`（§4.1），需要按 §3 的三步用 ChatGPT 生成触发指令、用 text-davinci-003 生成投毒响应、再与干净数据混合并按同等规模替换；我们现有的是 MaliciousGen 有害问答（E3–E5）和固定触发词加固定目标输出（E6 场景 B），都不是同一类攻击，也缺少论文那种"触发场景不含固定 token"的设置。
4. **投毒率的刻度与口径。** 论文扫 0.05%、0.1%、0.5%、1%、2%，默认 1%（§4.1、§5.5）；我们要把自己"恶意客户端数 × 本地投毒比例"换算成同一口径再重扫，并且要显式区分"集中在一个客户端"与论文"随机替换进全量数据因而分散"这两种分布形态。联邦侧的换算方式论文未说明（卡片第 9 节将其列为"论文未说明"）。
5. **评测指标。** 我们需要补上 GPT-4 的 1–10 响应质量评分、ChatGPT 的 -5 到 +5 情感评分折算出的 Pos/Neg、HumanEval 的 Pass@1 与 `print("pwned!")` 出现率 Occur.、GSM 准确率与平均响应长度；我们现在只有 AdvBench 无害率和行为探针分数，后门攻击成功率评测在项目里也仍记为未做。
6. **评测数据集。** 论文用每话题 200 条触发测试指令（与训练触发指令 ROUGE 相似度小于 0.6，§4.3）、每话题 9 个对比话题各 200 条（附录 D）、WizardLM 测试集 218 条通用指令、HumanEval 164 题（§4.3）、GSM 测试集 1,319 题（附录 A）；我们目前没有这套按话题构造的触发/对比评测集。
7. **防御效果读数与对照。** 论文报"过滤前后投毒率与数据规模"（表 13）、"过滤后攻击效果"（图 6），并用干净模型和 debiasing prompting 做对照（§4.2、§6）；我们 E6 的 26 次运行只验证可用性，缺这类过滤后攻击效果的读数。注意论文自己没有给过滤的精确率/召回率，卡片未给，所以这一项只能我们自己定义并测。
8. **集中式对照跑。** 论文没有联邦流程，要做真正可比的对照，先需要在同模型、同投毒率下做一次集中式 VPI 复现作为参照，再把投毒收拢到少数客户端做联邦迁移；我们现在两个方向都没有。
9. **多样本与置信区间。** 论文未报告种子（卡片未给）与置信区间，因此它不能作为多种子对齐的参照；我们仍需要自己补多种子运行，才能把自己的 1–2/18、3–15%、24–35% 这类单种子读数变成区间。
10. **自适应攻击与开销这两项无法从本文补齐。** 论文未评估知道防御的自适应攻击者，也未报告任何开销（卡片第 8、9 节），所以"知道防御的自适应攻击"和 E2 的开销对照都要另找参照。
11. **联邦下的隐私与信任形态。** 论文的过滤要求逐样本原文和外部 LLM 评委（§6），卡片第 9 节的分析指出在联邦下要么在客户端本地跑评审器、要么只上传分数或摘要，而服务器侧的等价做法论文未说明；我们要自己设计"本地过滤 + 服务器只收摘要"的部署形态，并测量它是否还能保住论文报告的那种过滤效果。
