# 1. 论文自己的实验规模与主要结果

**场景与定位。** 按卡片第 1 节，本文是集中式大模型训练（含推理部署）场景下的防御工作，形态是一个内容审核分类器，"本文与联邦学习（federated learning）无关"。论文不研究攻击，也不研究训练期投毒，因此在联邦语境下客户端数、参与率、训练轮次、恶意客户端占比、数据是否非独立同分布这些量，卡片明确写"论文未涉及"，只能记作卡片未给。

**模型与数据规模。** 骨干模型是 Llama2-7b，通过指令微调得到 Llama Guard（Section 3.4）。微调数据为 13,997 条 prompt-response 对，按 3:1 随机划分为微调集与评测集（Section 3.3）；按 Table 1 的"Prompts / Responses"口径，Violence & Hate 为 1750 / 1909，Sexual Content 为 283 / 347，Criminal Planning 为 3915 / 4292，Guns & Illegal Weapons 为 166 / 222，Regulated or Controlled Substances 为 566 / 581，Suicide & Self-Harm 为 89 / 96，Safe 为 7228 / 6550。训练配置为单机 8 张 A100 80GB、批大小 2、序列长度 4096、模型并行度 1、学习率 2 × 10⁻⁶、训练 500 步、约等于训练集 1 个 epoch（Section 3.4）。外部评测集为 OpenAI Moderation Evaluation Dataset 的 1680 条 prompt 样例，以及 ToxicChat 的 10k 条样本（Section 4.2）。**种子数量、重复次数、训练总时长、总计算量、显存占用、推理延迟与吞吐，卡片未给**（卡片第 8 节说论文未报告训练时长、计算量、显存、能耗，也未报告任何推理开销数值）。对照基线为 OpenAI Moderation API、Perspective API、Azure AI Content Safety API 与零样本提示的 GPT-4（Section 4.3）。

**评测指标。** 主指标是 AUPRC（Section 4.3.3）；对不提供概率分数的 Azure API 与 GPT-4，改用阈值 0.5 下的精确率、召回率与 F1（Section 4.3.3 与 Appendix B）。逐类别评测用 1-vs-all，对固定类别输出头的基线改用 1-vs-benign（Section 4.1）；总体二分类分数取该样本在所有正类别上预测概率的最大值，即式 (1)（Section 4.1）。

**主要结果。**

1. Table 2 的总体 AUPRC：在自建测试集的 prompt 分类上 Llama Guard 为 0.945（OpenAI API 0.764，Perspective 0.728），response 分类为 0.953（OpenAI API 0.769，Perspective 0.699）；在 OpenAI Mod 数据集上为 0.847（OpenAI API 0.856，Perspective 0.787）；在 ToxicChat 上为 0.626（OpenAI API 0.588，Perspective 0.532）。论文据此认为自建测试集上的 in-policy 上限很高，且 Llama Guard 在 ToxicChat 上超过所有其它方法（Section 4.4）。
2. Table 3 的逐类别 AUPRC（每格左数 prompt、右数 response）：Violence and Hate 0.857 / 0.835，Sexual Content 0.692 / 0.787，Criminal Planning 0.927 / 0.933，Guns and Illegal Weapons 0.798 / 0.716，Regulated or Controlled Substances 0.944 / 0.922，Self-Harm 0.842 / 0.943；同表 OpenAI Mod API 在 Guns and Illegal Weapons 上为 0.035 / 0.060、在 Regulated or Controlled Substances 上为 0.085 / 0.067，Perspective API 在这两类上分别为 0.054 / 0.048 与 0.110 / 0.096。
3. Table 4 的政策适配对比：OpenAI Mod API 为 0.856，Llama Guard 不做适配为 0.837，零样本并给出类别为 0.847，少样本并给出描述与上下文例子为 0.872，即提示适配后超过 OpenAI Moderation API（Section 4.5.1）。**这里卡片内部有出入**：Table 2 把 Llama Guard 在 OpenAI Mod 上的成绩记为 0.847，Table 4 把"不做适配"记为 0.837，卡片未解释这 0.01 的差异，我不做推测。
4. Figure 3 的微调适配：用 ToxicChat 训练数据的 10%、20%、50%、100% 继续微调时，Llama Guard 只需 20% 数据就能与用 100% 数据训练的 Llama2-7b 表现相当，在同数据量下表现更好；零样本设置下 Llama2-7b 只产生格式不良输出、AUPRC 记为 0，Llama Guard 为 0.626（Section 4.5.2）。**各比例对应的具体 AUPRC 数值，卡片未给。**
5. Appendix B 在阈值 0.5 下的 P/R/F1，Table 5 的 Overall 一行为 Llama Guard 0.880 / 0.864 / 0.872、OpenAI Mod API 0.874 / 0.250 / 0.389、Azure API 0.788 / 0.515 / 0.623、Perspective API 0.817 / 0.219 / 0.346、GPT-4 0.717 / 0.947 / 0.816；Table 6 的 Overall 一行为 Llama Guard 0.900 / 0.867 / 0.884、OpenAI Mod API 0.874 / 0.329 / 0.478、Azure API 0.749 / 0.564 / 0.644、Perspective API 0.751 / 0.248 / 0.373、GPT-4 0.813 / 0.788 / 0.801。**卡片未说明 Table 5 与 Table 6 各自对应哪个数据集。**

**E4（same_question，not_comparable）。** 共同的问题是"大模型内容/行为的安全性如何判定"：论文用 LLM 分类器把 prompt 与 response 判成 safe / unsafe，我们用 AdvBench 无害率量化良性联邦 LoRA 微调把无害率从 81% 打到 49–63%（alpaca 模板）。方向上是一致的，都认为内容安全信号可测且重要；更有价值的一点是，论文在自建 in-policy 测试集上 AUPRC 高达 0.945 / 0.953，但在更接近真实分布的 ToxicChat 上只有 0.626（Table 2），论文自己在 Section 4.5.1 与 Figure 2 把逐类别下降归因于 taxonomy 不对齐。这提示我们 E4/E5 的 AdvBench 读数同样是"自家口径"，不能假定换一种有害内容分布还成立。但两者不能直接比较：模型不同（Llama2-7b 对 Qwen2.5-0.5B），场景不同（集中式推理对联邦 LoRA 训练），数字口径也不同（逐样本分类 AUPRC 对整模型无害率），而且论文没有在我们的模型、数据或联邦流程上运行过。

**E4（setting_reference，n/a）。** 论文的评测协议本身是我们该对齐的参照：阈值无关的 AUPRC（Section 4.3.3）、阈值 0.5 下的精确率/召回率/F1（Section 4.3.3 与 Appendix B）、逐类别 1-vs-all 与固定类别头基线的 1-vs-benign（Section 4.1），并且论文明确不推荐具体阈值（卡片第 6 节）。我们在 E4 里走的是另一条路——用 4 种划分各 3 个种子的无攻击基线校准 1% 误报阈值。两套口径目前没有交集：要做对照，得把 1% 误报校准搬到逐样本内容判定分数上，再按论文的指标报告。

**E5（same_question，not_comparable）。** 我们的行为探针（加载每个客户端的更新后测模型对 AdvBench 有害提示的顺从倾向，跨轮累积后 37 个恶意客户端中 33 个超过全部良性客户端）与 Llama Guard 都在问"模型对有害内容的态度能否被测量、能否用来区分"，方向上一致：论文给出 in-policy 分类 AUPRC 0.945 与 off-policy 0.626（Table 2），我们给出客户端级排序 33/37。但可比性不成立：论文的判定单位是逐样本文本分类，我们的是逐客户端排序；模型规模 7B 对 0.5B，差一个数量级以上；论文完全没有客户端、更新与联邦概念。所以既不能说一致也不能说矛盾，只能说动机方向相同。E5 里的检测率与误报率（恶意占比 ≥30% 时检出 83–100%、误报 0.6–1.9%；分散低浓度投毒 3–15%；每轮只抽 5 个客户端 24–35%）回答的是投毒检测问题，论文完全没做这件事，这一部分只能算背景。

**E6（setting_reference，n/a）。** E6 场景 A（4 个良性 + 1 个有害数据客户端）恰好是 Llama Guard 这类内容审核器能挂的位置，卡片第 10 节第五条分析也说它更适合作为可选辅助信号，例如在聚合前对客户端上报的样本或合成数据做安全审核。但我们的 E6 清单里没有 Llama Guard，E6 本身也不评价防御效果，所以没有可以互相印证的结论。可对齐的是它的评测设置：论文的分类结果用 AUPRC 与阈值 0.5 下的精确率/召回率/F1 报告（Section 4.3.3、Appendix B），逐类别还要跑 1-vs-all（Section 4.1）；而我们 E6 的样本过滤只有一次读数（4B、480 条样本 96 条带毒：ProtegoFed 精确率 0.77、召回率 0.49，谱签名、梯度谱熵、激活聚类接近 0），既无阈值扫描也无逐类别口径。另外论文用难负例作 safe 的少样本例子（Section 3.2），并明确说 1-vs-benign 会移除难负例、结果偏乐观（Section 4.1）——这正对着我们的弱点：E6 场景 B 的正类是"含触发词且带固定目标输出"的样本，良性样本没有刻意构造难负例，读数很可能偏乐观。还要注意论文不是投毒检测方法，它判的是内容是否有害，不回答"这条数据是否被用于投毒"（卡片第 9 节第三条），因此它替换不了谱签名、FLDetector 这类更新侧检测器。

**E7（setting_reference，n/a）。** 论文以难负例作 safe 示例，并主要用精确率/召回率（阈值化）报告（Section 3.2、Section 4.3.3），说明"良性侧不能误报"是这类审核器的硬约束。我们 E7 给出的是反面读数：全良性时 Krum 仍排除 80% 的客户端轮次、LoMar 65%，梯度谱熵屏蔽 71% 样本、ONION 改写 59% 样本。两者不矛盾，因为论文根本没有全良性联邦运行、也没有任何防御误报实验，我们的数字在它那里没有对应物，量级不可比；它给我们的价值只是指标口径——将来把 Llama Guard 式审核器挂进全良性运行，应按阈值化精确率（或 AUPRC 的负类侧）报告它对良性样本的误报，而不是只报一个笼统的准确率。

**背景项。** E1 上，论文的训练是集中式全参数微调（Section 3.4），没有宿主框架、没有钩子语义、没有"挂了插件但不动作时逐位一致"这类问题，卡片也未提任何逐位一致的概念。E2 上，论文只报告训练配置与定性成本判断（选 7B 是为降低推理与部署成本），没有训练总时长、计算量、显存、能耗，也没有推理延迟、吞吐、显存（卡片第 8 节），所以我们 0.7%–2.8%、0.25%–1.8% 以及 ProtegoFed 每客户端每轮 3.8 秒这些读数在论文里没有可对齐的数值；反过来，卡片第 9 节第二条也指出，若要把 7B 级护栏下推到联邦客户端，论文没给做预算所需的任何数字。E3 上，论文的可观测量是待审文本与首 token 概率（卡片第 5 节），完全不涉及 LoRA 的 A、B 因子或效果层/因子层更新大小与方向，我们 15/20、17/20、3/20 的标出轮数在论文中没有对应问题。E8 上，论文是自建集中式训练流程（Section 3.3、Section 3.4），不存在宿主适配或客户端侧/服务器侧插件挂载问题。E9 上，我们做的是 Safe-FedLLM 式聚合权重探针，观测对象是客户端聚合权重与初始化种子，与文本分类没有共同的方法、机制或可观测量。E10 上，这篇论文在知识库里属于部署/推理侧的内容审核防御，动作类型只有"仅报告"，干预位置记为 none（卡片第 6 节）；它有两项数据需求会直接压到我们的算子上——推理栈必须暴露首 token 概率（卡片第 5 节第四项、第 10 节第二条），政策文本要能运行时替换并支持 1-vs-all（卡片第 4 节、第 10 节第四条）。我们已经把 45 篇的 481 个步骤对到算子与运行时（39% 直接可表达、39% 要拼、10% 缺算子、13% 超出运行时），但**卡片没有说明这篇是否已经在这批里、映射结果是什么**，所以目前只能算背景，它指出的是我们可以去 E10 账本里核对的具体条目。

# 3. 我们要与它可比还差什么

1. **先得有它的方法本身。** 我们没有任何一次运行真正实现或调用 Llama Guard 或其等价的内容审核分类器。要谈"和它比"，第一步是把它作为一个推理/部署侧插件（输入侧钩子 + 输出侧钩子，卡片第 10 节第一条）挂上并跑通，这一步我们现在是零。
2. **模型规模与额外前向。** 论文骨干是 Llama2-7b（Section 3.4），且要求每次输入与输出各跑一次 7B 级模型（卡片第 9 节第二条）。我们最大的完整训练只到 4B（E6/E7），主力是 Qwen2.5-0.5B 与 Qwen3.5-0.8B。要对齐至少要有 7B 级骨干的完整训练，并接受每次判定一次额外前向。
3. **带标签的内容安全评测集。** 论文用 13,997 条自建标注数据按 3:1 划分，加 OpenAI Mod 的 1680 条与 ToxicChat 的 10k 条，标签是 prompt-category、response-category、prompt-label、response-label（Section 3.3、Section 4.1、Section 4.2）。我们只有 AdvBench 的无害率与顺从倾向读数（E4、E5），没有逐样本安全标签、没有正负类划分，因此算不出 AUPRC，也做不了逐类别 1-vs-all 或 1-vs-benign。
4. **指标与阈值。** 需要补：AUPRC、阈值 0.5 下的精确率/召回率/F1、逐类别 1-vs-all 口径，以及二分类分数取正类概率最大值这一读法（Section 4.1 式 (1)、Section 4.3.3、Appendix B）。我们现有的检测率、误报率、标出轮数（E3、E4、E5、E7）是轮次级或客户端级的来源统计，和逐样本分类指标不是同一口径。
5. **阈值校准要重做。** 论文用阈值无关的 AUPRC，并对无概率基线固定用 0.5，且不推荐具体阈值（卡片第 6 节）；我们的 1% 误报校准（E4）必须搬到它的逐样本分类分数上重做，才能谈"在 1% 误报下 AUPRC 或召回是多少"。
6. **重复次数与置信区间。** 卡片未给论文的种子数或重复次数；我们这边只有 E4 的良性基线是 3 个种子，E3、E5、E7、E9 基本是单次或单种子。即便把上面的指标补齐，也给不出置信区间，这一点是我们的缺口，不是论文能提供的参照。
7. **联邦侧的规模对照仍是空白。** 论文没有客户端、轮次、投毒比例、非独立同分布这些概念，所以它不构成我们联邦设置的规模参照；而我们自己的规模也很小（最多 20 轮，E6/E8 只有 2–4 轮、4–5 个客户端），而论文是 500 步约 1 个 epoch、13,997 条数据、8 卡 A100。任何"我们的方法比 Llama Guard 好/差"的说法在两个方向上都不成立。
8. **攻击面不能从它那里借。** 论文未评估自适应攻击者，只把提示注入列为潜在风险（Section 6）；它也不做后门、不做上传侧攻击、不报攻击成功率。我们没做过的后门 ASR 评测、知道防御的自适应攻击、上传侧攻击（更新放大、针对防御构造更新、合谋）这四项，这篇论文一条都补不上。
9. **开销无法对照。** 论文只给训练配置与定性的成本判断，没有延迟、吞吐、显存、能耗数字（卡片第 8 节）。我们 E2 的 0.7%–2.8%、0.25%–1.8% 与各方法插件开销没有可对齐的论文数值；要比较只能自己测 7B 级护栏在客户端每一步的额外前向开销。
10. **政策与类别体系要对齐。** 论文的判定依赖调用时给出的类别名与自然语言描述，且支持政策热替换与单类别 1-vs-all（Section 3.1、Section 3.2）。我们的实验里没有固定过这样一套政策文本，也没有做过多类别判定，要对话就得先固定同一套 taxonomy 与描述。
11. **它的数据效率结论不能直接搬。** 论文"20% ToxicChat 数据即可对标 100% 数据训练的 Llama2-7b"是全参数继续微调的结果，全文没有出现 LoRA 或任何参数高效微调方法（卡片第 9 节第五条分析），因此不能用来支撑我们关于联邦 LoRA 少数据适配的任何主张。
