## 1. 论文自己的实验规模与主要结果

**场景与模型族（决定可比性的第一条）。** 这是传统横向联邦学习（FL）的防御论文，客户端上传的是与全局模型**同形状的完整模型更新**；卡片明确记录论文全文没有出现 LLM、Transformer、LoRA 或 PEFT 相关内容（卡片第 1 节）。六个数据集与模型分别是：MNIST-0.1、MNIST-0.5 用 CNN（表 II：输入 28×28×1、两层卷积加池化、全连接 100、Softmax 10）；MNIST（60,000 训练 / 10,000 测试）、Fashion-MNIST（60,000 / 10,000）、CIFAR-10（50,000 / 10,000）用 CNN 或 ResNet20；HAR 共 10,299 条样本、561 维特征、6 类、30 个用户，用逻辑回归；CH-MNIST 共 5,000 张 64×64 灰度图、8 类，取 4,000 张训练、1,000 张测试，用 ResNet20（卡片第 1 节、Section VI-A1 与 VI-A4）。

**联邦规模与训练轮数。** 客户端数 n = 100（HAR 为 30，CH-MNIST 为 40）；每轮选中比例 τ = n，即每轮选**全部**客户端；本地迭代 R\_l = 1；全局迭代 R\_g = 2,000（MNIST-0.1、MNIST-0.5、CH-MNIST）、2,500（Fashion-MNIST）、1,500（CIFAR-10）、1,000（HAR）；批大小 b = 32（CIFAR-10 为 64）（卡片第 7 节、Section VI-A、表 I）。non-IID 用一个概率 q 控制标签偏斜，q = 1/M 时为 IID；MNIST-0.1 取 q = 0.1，其余取 q = 0.5（Section VI-A1）。组合学习率 α·β 按数据集分别设置，表 I 给出 3×10⁻⁴、6×10⁻³、2×10⁻⁴、3×10⁻³ 与 3×10⁻⁴ 五个值（其中一项注明在第 1500 与 1750 轮按 0.9 衰减）；卡片注明抽取文本中该行数值与数据集的**列对应关系不完整**，所以逐数据集的对应值**卡片未给**。

**投毒设定。** 默认恶意客户端比例 m/n = 20%（对应 m = 20 / 6 / 8），图 6、图 7 扫描到 95%。攻击包括：标签翻转（标签 l 变为 M−l−1）、Scaling（向本地数据追加带触发器且标签为目标标签的样本，并把更新整体放大 λ = n 倍后上传）、Krum 攻击与 Trim 攻击（不经过真实训练，直接求解 Equation 6 构造中毒更新），以及针对 FLTrust 的自适应攻击（Algorithm 3：把 Fang 等人的通用本地模型投毒框架代入 FLTrust 的聚合规则，用零阶梯度上升求解，初始化用 Trim 攻击，σ² = 0.5、γ = 0.005、η = 0.01、V = Q = 10，Section V、Section VI-A2）。Krum 的参数 f 与 Trim-mean 的参数 k 都设为 m，也就是假定服务器知道恶意客户端的准确数量、“给 Krum 和 Trim-mean 以优势”（卡片第 7 节、表 I）。防御侧的关键额外输入是根数据集 D₀，默认 100 条，扫描 50–500 条，采样后从客户端训练集中剔除（卡片第 5 节、图 4）。

**评测指标。** 测试错误率（testing error rate）；对 Scaling 攻击另外报告攻击成功率（attack success rate）（Section VI-A3）。图 3 另外给出训练错误率随轮数的下降曲线（Section VI-B）。论文的种子数或重复次数**卡片未给**。

**主要结果（照抄卡片）。**
- 保真度：无攻击时 FLTrust 与 FedAvg 相当。MNIST-0.1 上 FedAvg 与 FLTrust 都是 0.04，Krum / Trim-mean / Median 分别为 0.10 / 0.06 / 0.06；CH-MNIST 上 FedAvg、Trim-mean、FLTrust 都是 0.10，Krum 与 Median 为 0.24 与 0.11（Section VI-B、表 III(a)(f)）。
- 鲁棒性：FLTrust 在无目标攻击（含自适应攻击）下的测试错误率最多比“无攻击 FedAvg”高 0.04。MNIST-0.1 上 FLTrust 在标签翻转 / Krum / Trim / Scaling / 自适应攻击下分别为 0.04 / 0.04 / 0.04 / 0.03 / 0.04，Scaling 攻击成功率 0.00；MNIST-0.5 上为 0.05 / 0.05 / 0.06 / 0.05 / 0.06，攻击成功率 0.00；CIFAR-10 上无攻击 0.18、各攻击 0.18–0.20；HAR 上 0.04–0.05；CH-MNIST 上 0.10–0.14（表 III(a)–(f)）。
- 既有方法被绕过：MNIST-0.1 上 Krum 攻击把 Krum 的测试错误率从 0.10 抬到 0.90；MNIST-0.5 上 Trim 攻击把 Trim-mean 与 Median 从 0.06 抬到 0.23 与 0.43；Scaling 攻击在 MNIST-0.1 与 MNIST-0.5 上对 FedAvg 的攻击成功率均为 1.00（表 III(a)(b)）。表 IV 显示去掉 ReLU 后 FLTrust 在 Krum / Trim / Scaling / 自适应攻击下错误率都升到 0.90 及以上。
- 消融与扫描：表 IV 的变体对比（MNIST-0.5）中，FLTrust-Server 无攻击 0.21；FLTrust-withServer 无攻击 0.07、自适应攻击 0.94；FLTrust-NoReLU 无攻击 0.28、Krum / Trim 攻击 0.90、Scaling 0.94 / 0.08；FLTrust-NoNorm 无攻击 0.05 但 Scaling 0.94 / 0.08；FLTrust-ParNorm 0.06。根数据集从 50 增到 500 条，论文称 100 条就足以防御（图 4）；根数据集偏置概率不超过 0.4 时各攻击下错误率最多 0.08，偏置概率到 1.0 时无攻击错误率升到 0.80（表 V）；客户端总数 n 从 50 增到 400、恶意比例固定 20% 时 FLTrust 与无攻击 FedAvg 接近、Scaling 攻击成功率接近 0（图 5）；恶意比例方面 FLTrust 在既有攻击与自适应攻击下最多可容忍 90% 的恶意客户端，Scaling 攻击在恶意比例高达 95% 时攻击成功率仍接近 0（图 6、图 7）。
- 开销：论文只给定性结论，称服务器侧额外计算“对强大的服务器而言可以忽略”，并声称客户端侧无额外开销；具体的计算量、通信字节数、存储占用与墙钟时间论文未报告（卡片第 8 节、Section VI-B）。

## 2. 与我们各项实验的对应

先给总判断：**这篇论文没有 method_source 对应**——E6 的 26 次运行覆盖了 Krum、坐标中位数、截尾均值、FoolsGold、FLAME、FLDetector、MUD-HoG、CRFL、ProtegoFed 等，但清单里没有 FLTrust，我们既没有实现也没有运行过它。它与我们的关系集中在“同一个问题族（服务器侧用更新统计做拜占庭防御）”和“同一批基线方法的对照”上，因此整体相关性我判为 high：它是我们库最直接的一类服务器侧聚合防御的源头方法，它的两个防线（方向余弦 + 幅度重标定）正是 E3/E4 在 LoRA 上测的两类特征，它的基线方法（Krum、Trim-mean、Median）正是 E6/E7 已经跑过的方法，而它需要的“服务器侧根数据集 + 每轮影子训练”是我们运行时里目前不存在的一条流水线。

**E1（不改训练、逐位相同）— background。** 论文是防御方法论文，它讨论的是聚合规则本身，不讨论“挂上框架后宿主训练是否被改动”这类保真问题；而我们的 E1 问的是宿主脚本的逐位可复现性。需要注意 FLTrust 的插件按其定义一定会改变训练（每轮多一次服务器侧训练、并在聚合前重写更新），所以 E1 的结论只能说明底座在插件不动时是透明的，不能保证 FLTrust 这类改写型插件挂上去后仍保持宿主语义；卡片没有讨论这个层面的问题。

**E2（开销）— same_question，not_comparable。** 两者问的是同一件事：这个防御要花多少额外代价。论文的答案是定性的“服务器侧三项额外计算可以忽略、客户端侧无额外开销”，而卡片明确记录论文未报告任何计算量、通信、存储或墙钟时间的数值（卡片第 8 节、Section VI-B），所以没有任何数字可与我们的 0.7%–2.8% 采集开销、0.25%–1.8% 服务器侧统计插件开销对照；我们目前也没有测 FLTrust 特有的那一项——每轮用根数据集对当前全局模型做一次与客户端同配置的训练（R\_l 次 SGD）。这一项只能我们自己量，论文给不了参照数。

**E3（更新大小与方向特征）— same_question，not_comparable。** 卡片第 4 节显示 FLTrust 的两条防线恰好是“方向”和“幅度”：方向用与服务器模型更新 g₀ 的余弦相似度衡量（Equation 2），幅度用范数比值归一化（Equation 3），并且论文明确写出“幅度小的更新更可能来自良性客户端”的理由（Section IV-B）。我们的 E3 就是在同一对特征轴上做预实验，区别在于我们把 LoRA 拆成“效果层”（乘积 BA）与“因子层”（A、B 分开），并且是在客户端之间比较，没有干净参考。我们的结果是效果层大小 15/20 轮、因子层方向 17/20 轮、效果层方向只有 3/20 轮被标出；这与 FLTrust 把方向（相对干净参考）当作核心信号、把幅度当作第二道防线的排序**不能直接印证也不能直接矛盾**，因为我们的方向是从客户端互比得来的，而 FLTrust 的方向是与 g₀ 比。特别要提醒的是，ours 只记录了被标出的轮数比例，没有记录恶意客户端的更新是偏大还是偏小，所以无法检验论文“小幅度更可能良性”的方向性论断。卡片第 9 节的分析还指出，LoRA 增量在不同模块间尺度差异很大，FLTrust 那种整条扁平向量的单一余弦可能被少数模块主导；我们 E3 里“因子层方向 17/20、效果层方向 3/20”的差距是支持“分模块看更稳”的一个小线索，但它是我们的观察，不是论文的结论。

**E4（良性基线与 1% 误报校准）— same_question，not_comparable。** 两者都问“数据异质性与恶意浓度如何影响防御信号”。论文的对照是表 V（根数据集分布偏置）与图 6、图 7（恶意比例扫描，最多容忍 90% 恶意客户端）；我们的对照是四种划分（IID、Dirichlet 1.0/0.5/0.1）各 3 个种子校准 1% 误报阈值，然后看不同恶意占比下的检出。二者**不构成矛盾**，因为衡量对象不同：论文衡量的是聚合后模型的测试错误率，不需要指出谁是恶意客户端；我们衡量的是逐客户端指认，恶意数据占比 100% 时效果层大小 18/18、方向 14/18，占比 30% 时最好 6/18，占比 10% 时只有 1–2/18、已与误报相当。也就是说，“能容忍 90% 恶意客户端”和“低浓度分散投毒时逐客户端检出接近误报水平”可以同时为真，但论文没有研究后者。另外我们有两条论文没有的现象：无攻击的良性微调本身就让 AdvBench 无害率从 81% 降到 49%–63%，以及按 Dolly 类别的 Dirichlet 划分对 LoRA 更新相似度几乎没有影响；卡片未给论文在 non-IID 程度下对信任分本身（而不是最终错误率）的任何分析，所以这两条无法与论文对照。

**E5（自动攻击矩阵）— same_question，not_comparable。** FLTrust 的信任分本质上就是逐客户端的可疑度打分（只是用作软权重而不是硬判定），所以 E5 的逐轮判定与它同族。但设置差异很大：论文 τ = n，每轮全选，且不需要跨轮历史（卡片第 5 节明确记录 FLTrust 不需要跨轮历史）；我们 E5 每轮只抽 5 个客户端，盲区是分散的低浓度投毒（2–3 个恶意客户端各 10%，检出 3%–15%）和每轮只抽 5 个客户端（检出 24%–35%），而表现最好的是我们那个跨轮累积的行为探针（37 个恶意客户端中 33 个超过全部良性客户端）——这恰恰用到了 FLTrust 明确不需要的历史信息。论文没有评估部分参与下的防御，也没有做逐客户端识别，所以两边的数字无法比较；论文的“高恶意比例下仍稳”与我们的“低浓度难检出”也不矛盾，因为一个说的是聚合精度，一个说的是识别率。

**E6（已发表防御的可用性批量）— setting_reference。** 这是这篇论文与我们关系最实用的一个点。E6 跑通了论文的主要对比方法（Krum、坐标中位数、截尾均值，另外还有同文献族的 FoolsGold、FLAME、FLDetector、MUD-HoG、CRFL 等），但**没有跑 FLTrust 本身**；而且 E6 明确“不评价防御效果”，所以我们手里没有任何可以与表 III 对照的攻击下数值。要把这篇论文纳入 E6，需要补的是 FLTrust 这一行，以及论文的表 III 式评测协议（攻击下的测试错误率 + Scaling 的攻击成功率）。E6 里两条关于范数阈值的读数也提示论文的 Equation 3 在 LoRA 上需要重新定标：CRFL 按原文范数阈值会把全局 LoRA 压到 0.10 倍，LoMar 按原文阈值每轮排除 3/5 客户端；这属于我们的观察，但正好说明“把更新范数重标定到 ‖g₀‖”这一步在 LoRA 上需要先确定 g₀ 的量纲是否可比。

**E7（无攻击对照）— same_question，consistent（但数值不可比）。** 论文表 III(a)(f) 恰好给了无攻击的同类对照：MNIST-0.1 上 FedAvg 0.04，而 Krum / Trim-mean / Median 分别为 0.10 / 0.06 / 0.06；CH-MNIST 上 FedAvg、Trim-mean、FLTrust 都是 0.10，Krum 与 Median 为 0.24 与 0.11——也就是说论文自己就观察到这些鲁棒聚合器在**没有攻击**时也会损害正常训练。我们的 E7 在 LoRA 上看到的是同一现象的另一种表现：无攻击时 Krum 仍排除 80% 的客户端轮次、LoMar 65%、FLDetector 20%、MUD-HoG 20%，梯度谱熵屏蔽 71% 样本、ONION 改写 59% 样本、激活聚类屏蔽 15%、ProtegoFed 屏蔽 4%。两者方向一致，但**不能直接比较**：论文的指标是测试错误率，我们的是排除率/屏蔽率；论文的规模是 100 客户端、2,000 轮，我们是 5 客户端、4 轮、单次运行；而且 LoMar、FLDetector、MUD-HoG 并不在论文的对比方法里。

**E8（宿主适配）— background。** E8 已经量化了三类宿主上的挂载代价（18 个服务器侧插件原生挂载、9 个客户端侧需应用配合、ProtegoFed 需一层握手扩展），但 FLTrust 不在其中。卡片第 10 节的分析指出，FLTrust 需要一个“聚合前、由服务器本地数据和服务器本地训练步骤构成”的新钩子，而论文的既有 FL 流程里没有这个位置；按这个描述它更可能落在“需要扩展”那一类，但卡片没有给出它在我们任何宿主上的实测，我们也没测，所以这一点只能作为待验证的适配任务。

**E9（Safe-FedLLM 式权重探针）— background。** 两者的共同点是都在服务器侧对权重空间打分；但 FLTrust 的信任分是 gᵢ 与 g₀ 的确定性余弦，不涉及拟合，而 E9 的探针是拟合出来的、并且换一次运行（不同种子）后就失效（恶意客户端概率 0.00）。E9 的种子敏感性不能直接推广到 FLTrust，而且卡片未给论文的种子或重复设置，我们无法判断 FLTrust 的信任分是否也有类似的运行间波动。这属于背景而非直接对应。

**E10（调研与知识库）— background。** E10 已把 45 篇防御的 481 个步骤映射到我们的算子与运行时（39% 直接可表达、39% 要拼、10% 缺算子、13% 超出运行时）。FLTrust 需要的一条算子链是“整条扁平更新上的余弦相似度 + 范数比值重标定 + 逐客户端权重聚合”，另外还要一个服务器侧训练钩子；按卡片第 10 节的分析，其中“服务器本地数据集 + 服务器本地训练步骤”在我们的运行时里是一个新的位置。但 ours 的 E10 描述没有点名 FLTrust 是否在那 137 篇或 45 篇之内，所以它是否已被登记进知识库**无法判定**，这里只能记为待补的映射对象。

## 3. 我们要与它可比还差什么

1. **服务器侧信任根与影子训练（最大缺口）。** 论文每轮在聚合前用 |D₀| = 100 条干净根样本、按与客户端相同的批大小、本地学习率和本地迭代数在全局模型上训练一次得到 g₀（Algorithm 2 第 12 行），根数据集默认 100 条、扫描 50–500 条，采样后还要从客户端训练集中剔除（卡片第 5 节、第 7 节）。我们目前完全没有服务器侧本地数据、没有服务器侧训练步骤、也没有根数据集的版本/哈希/分布审计；没有这条流水线，FLTrust 的 Equation 2 到 Equation 4 都无法复现。
2. **参数空间规范化。** 论文的更新与全局模型同形状，余弦与范数比值天然可算；LoRA 下必须统一目标模块集合与秩（E3/E4 的 r = 16 可以作为起点），或把增量投影到公共子空间，否则方程没有定义。论文未提供这种处理（卡片第 9 节的分析）。
3. **模型规模与任务族。** 论文是 CNN / ResNet20 / 逻辑回归在图像分类与手机传感器识别上的结果（MNIST 60,000/10,000、Fashion-MNIST 60,000/10,000、CIFAR-10 50,000/10,000、HAR 10,299×561 维 6 类 30 用户、CH-MNIST 5,000 张 8 类取 4,000/1,000），我们是 Qwen2.5-0.5B 与 Qwen3.5-0.8B/4B 的 LoRA 指令微调。要与论文的数值对照，只能在论文的任务族上复现；在 LoRA 上我们应当明确声明不与它做数值比较，只做机制层面的对照。
4. **联邦规模与轮数。** 论文 n = 100（HAR 30、CH-MNIST 40）、每轮全选（τ = n）、R\_l = 1、R\_g = 1,000–2,500；我们目前 5–10 个客户端、2–20 轮、每轮 5–6 步、E5 还每轮只抽 5/10。要参照它，至少需要 n 接近 50–100、每轮全选或严格记录采样模式、轮数上千（或在相同轮数下比较收敛曲线），并把本地步数设为 1。
5. **攻击类型。** 我们缺标签翻转（l → M−l−1）、缺把更新整体放大 λ = n 倍的 Scaling 攻击、缺 Krum/Trim 式用优化问题求解出来、不经真实训练的中毒更新（Equation 6）、缺针对我们防御的自适应攻击（论文 Algorithm 3：σ² = 0.5、γ = 0.005、η = 0.01、V = Q = 10，Trim 初始化）。我们现有的只有 MaliciousGen 有害问答、E6 场景 B 的触发词加固定目标输出，以及无攻击对照。
6. **指标。** 论文用测试错误率，并对 Scaling 攻击另外报告攻击成功率（Section VI-A3）。我们要补：干净任务指标、后门攻击成功率（我们明确列在“没做过的”里），以及论文没有而我们关心的安全指标（例如 AdvBench 无害率）。

9. **种子与统计。** 论文的种子数或重复次数卡片未给，无法判断它的单值结果有多少方差；我们自己多数实验是单种子或单次运行（E3、E6、E7、E8、E9 是单次或单种子，E4 有 3 个种子）。要做可比至少需要多种子与置信区间，这一点我们本来就列在“没做过的”里。
