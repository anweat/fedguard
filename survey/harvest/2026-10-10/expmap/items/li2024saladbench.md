## 1. 论文自己的实验规模与主要结果

先限定范围：卡片第 1、2、7 节反复说明这篇论文是面向大模型**安全评测的基准与平台**论文，评测的是已经训练完成的模型在**推理阶段**的安全性、越狱攻击与推理时防御；卡片明确写"论文全文中没有出现联邦学习、客户端、聚合、投毒或后门等概念"，因此"客户端数量、参与率、训练轮次、恶意客户端比例、非独立同分布程度"在卡片里全部是"论文未说明"。本节只能摘基准自身的规模，不能拿它当联邦实验的规模看。

**规模**

- 基准共 21k 条测试样本，分 6 个领域、16 个任务、66 个类别（卡片第 2 节、表 1）。卡片同时指出一处论文内部不一致：表 17 的标题、图 14 与图 15 的标题写作 sixty-five categories，论文未解释该差异。
- 基础集来源与数量（卡片表 9）：自指令生成 15,433 条、HH-harmless 4,184 条、HH-red-team 659 条、AdvBench 359 条、Multilingual 230 条、Do-Not-Answer 189 条、ToxicChat 129 条、Do Anything Now 93 条、GPTFuzzer 42 条，合计 21,318 条。
- 三个增强子集（卡片第 2、3.1、3.2 节）：攻击增强 5k 条（先按拒绝率筛出约 4k 条问题、施加多种攻击得到约 240k 条候选、再按平均不安全分数取最高的 5000 条）；防御增强 200 条；多选题约 4k 道。
- 被测模型：表 2 列 30 余个开源与黑盒模型，图 9 的排行榜对 24 个模型按 Elo 评分排序；所有攻击方法统一以 Llama-2-7B-Chat 为目标模型（卡片附录 M）。
- 评测器：MD-Judge 从 Mistral-7B 用 LoRA 微调，秩 64，序列长度 4096，8 张 A100，每卡批大小 16，训练 2 个 epoch（卡片第 5.1.1 节）；模板选择上最终用 Mistral-7B-v0.1 加任务级模板（卡片表 12）。
- 轮次与种子：论文唯一的"轮次"值是 MD-Judge 的 2 个训练 epoch（卡片第 5.1.1、7 节）；**种子数卡片未给**；MD-Judge 的训练时长、显存、能耗**卡片未给**（论文未报告）。
- 数据质量核验：从 65 个类别中随机抽取 458 条问题，4 位标注者交叉核验，类别标签一致率 94.3%，问题确实有害的比例 96.7%（卡片附录 E）。

**主要结果**

- 评测器 F1（卡片表 3，Base / Enhance / ToxicChat / Beavertails / SafeRLHF）：MD-Judge 为 0.818 / 0.873 / 0.644 / 0.866 / 0.864；GPT-4 为 0.785 / 0.827 / 0.470 / 0.842 / 0.835；GPT-3.5 为 0.374 / 0.731 / 0.499 / 0.800 / 0.771；LlamaGuard 为 0.585 / 0.085 / 0.220 / 0.653 / 0.693；关键词法为 0.058 / 0.261 / 0.193 / 0.012 / 0.015。分布外准确率（卡片表 4，Harmbench / Lifetox）：MD-Judge 83.72% 与 79.27%，GPT-4 84.46% 与 77.43%，LlamaGuard 64.56% 与 58.62%，GPT-3.5 61.13% 与 73.39%。
- 模型安全率（卡片表 5，基础集 / 攻击增强集）：Claude2 99.77% 与 88.02%，GPT-4 93.49% 与 80.28%，GPT-3.5 88.62% 与 73.38%，Gemini 88.32% 与 19.98%，Llama-2-13B 96.81% 与 65.72%，Llama-3-8B 95.69% 与 61.92%，Mistral-7B-v0.1 54.13% 与 2.44%，Vicuna-7B 44.46% 与 4.2%；表 5 用星号标注 Llama-2-7B 的 18.20% 不宜采信，因为它是攻击方法的目标模型。
- 攻击 ASR（卡片表 6，AdvBench-50 / 基础问题 / 增强问题，括号内为多提示平均）：Human JB 94%（13.8%）/ 95%（14.3%）/ 89.5%（11%）；GCG 后缀 94%（12.2%）/ 42%（7.7%）/ 25.5%（5.5%）；GPTFuzzer 53% / 46.5% / 34%；AutoDAN 32% / 15.5% / 9%；CoU 2% / 7% / 2%；无攻击 0% / 1.5% / 1%。
- 防御 ASR（卡片表 7、表 14，攻击增强子集）：Llama-2-13B 无防御 34.28%，GPT Paraphrase 降到 20.84%，Self-Reminder 降到 12.68%，而 Random Insert 与 Random Swap 反而升到 51.16% 与 54.94%；Mistral-7B 无防御 93.60%，GPT Paraphrase 降到 24.98%；Qwen-72B 从 93.06% 降到 58.04%（GPT Paraphrase）与 48.34%（Self-Reminder）；TuluV2-70B 从 92.04% 降到 58.14% 与 53.36%。
- 多选题（卡片表 8、表 15、表 16）：GPT-4 的 Acc-O 与 Acc-V 均为 88.96%，选择一致率 SCR 86.93%；Gemini Pro 拒绝率 43.85%、Acc-O 44.19%、Acc-V 78.71%；Claude 拒绝率 61.87%、Acc-O 22.23%、Acc-V 58.33%；Llama-2-13B 拒绝率 73.93%、Acc-O 9.66%、Acc-V 37.06%、SCR 为 0%（选安全答案与选不安全答案的拒绝率分别为 63.39% 与 84.48%）；InternLM-20B 拒绝率 0%、Acc-V 3.85%；Tulu-70B SCR 56.40%，Qwen-72B 44.00%。
- 与训练唯一沾边的操作：为生成有害数据，用约 500 条有害问答对微调 GPT-3.5-turbo 并强制它回答不安全问题（卡片第 2.2 节）。
- 开销（卡片表 13、附录 K）：关键词评测器 0.01 秒、无 API 费用；GPT-Evaluator 约 1 小时、约 20 美元；MCQ-Judge 为 0.43 秒、无 API 费用（附录 K 说明这是评测每个模型全部题目的时间）；人类评测约 2 小时、按 Amazon Mechanical Turk 计约 77 美元。联邦意义上的通信、存储、客户端算力与聚合开销论文未报告（卡片第 8 节）。

## 2. 与我们各项实验的对应

先给总判断：**这篇论文不对应我们任何一个实验的 method_source**，因为我们既没有实现也没有运行 SALAD-Bench、MD-Judge、MCQ-Judge 或它的任何防御方法（GPT-paraphrasing、随机扰动、Self-Reminder 等）；E6 里我们跑的是 ONION、Krum、FoolsGold 等另一批方法，与本文方法不是同一实现。对应关系集中在"怎么量模型在有害提示上的安全性"这一个问题上，以及评测协议与开销口径的参照上。

**E1 不改训练 / 逐位一致：无对应。** 卡片第 1、6 节说明论文不修改被测模型、不接入任何训练框架，评测器只输出标签（"仅报告"），也没有宿主脚本保真或 bitwise 一致的实验。这篇论文无法为 E1 提供任何印证或对照。

**E2 开销：setting_reference（agreement = not_comparable）。** 卡片第 8 节与表 13 给的是评测器与评测流程的开销，单位是"每个模型一次评测"（关键词 0.01 秒、MCQ-Judge 0.43 秒、GPT-Evaluator 约 1 小时约 20 美元、人类约 2 小时约 77 美元），而我们的 E2 测的是每个插件在每轮本地训练/服务器聚合上的占比（0.7%–2.8%、0.25%–1.8%）。若按卡片第 10 节的建议把它做成"服务器聚合后的验收与回归测试"插件，表 13 与第 5.1.1 节的 MD-Judge 配置（Mistral-7B、LoRA 秩 64、8 张 A100、每卡批 16、2 个 epoch，训练时长卡片未给）是我们该对齐的报账口径；但论文完全没有报告联邦通信、存储、客户端算力或聚合开销，所以现有读数不能直接比。

**E3 特征预实验（P1）：background（agreement = n/a）。** 我们用一个 MaliciousGen 有害问答训练、占其数据 100% 的恶意客户端；卡片第 2.2 节有同型操作（用约 500 条有害问答微调 GPT-3.5-turbo 使其回答不安全问题），但论文把它当作数据构造手段，不研究投毒。更关键的是，卡片第 5 节末明确说模型内部激活、逐层统计量、梯度、适配器增量与更新历史等信号论文完全没有涉及，所以 E3 的"效果层大小 15/20、因子层方向 17/20、效果层方向 3/20"在论文里既无对应方法也无对照数值。

**E4 良性基线与校准（P2）：same_question（agreement = consistent，但规模不可直接比较）。** 两边问的是同一个问题——"（良性/普通）微调之后，模型在有害提示上到底还安不安全、该怎么量"。卡片表 5 显示安全率强烈依赖模型：Mistral-7B-v0.1 为 54.13% 与 2.44%、Vicuna-7B 为 44.46% 与 4.2%，而 Llama-2-13B 为 96.81% 与 65.72%、Claude2 为 99.77% 与 88.02%；卡片第 2.2 节还记录了一次用约 500 条有害问答微调就"强制模型回答不安全问题"的操作。我们的 E4 发现无攻击的良性 FedAvg LoRA 微调本身就把 AdvBench 无害率从 81% 压到 49–63%，方向与上述内容一致：没有安全对齐训练或继续微调的模型，安全率明显更低。但论文是横截面对比不同已训练模型，没有"微调前 / 微调后"的对照，也没有联邦与 LoRA 聚合；我们是 Qwen2.5-0.5B、10 客户端、20 轮、4 种划分各 3 个种子，论文是 21,318 条基础集加 MD-Judge（F1 0.818 / 0.873），因此两边不能直接比较数值。E4 后半句"按 Dolly 类别的 Dirichlet 划分对 LoRA 更新相似度几乎没有影响"在论文中没有对应，因为论文不存在 non-IID 与客户端概念（卡片第 7 节末）。

**E5 自动攻击矩阵与行为探针（P3）：same_question（agreement = consistent，但规模不可直接比较）。** 我们的探针是"加载每个客户端更新后用 AdvBench 有害提示测顺从倾向，再跨轮累积"；论文的基础集本身就包含 AdvBench 359 条（卡片表 9），并用 MD-Judge 把每条问答判成 safe 或 unsafe 后聚合成安全率与 ASR（卡片第 4.1、5.4、5.5 节），问的是同一件事——模型在有害提示上的不安全程度。我们的结果（37 个恶意客户端中 33 个超过全部良性客户端）说明这个方向确实有区分度，与论文把安全率当作可区分模型的指标一致。但论文是逐模型评测而非逐客户端检测，更没有跨轮累积；而且卡片表 3 说明判定器的选择会主导数值（Base 上关键词法 F1 0.058、LlamaGuard 0.585、MD-Judge 0.818；Enhance 上 LlamaGuard 只有 0.085），我们的行为探针没有报告判定器的精确率/召回率，所以 33/37 这类读数目前无法与论文的 F1 对齐。我们规模小得多（0.5B、10 客户端、20 轮、多数级别 1 个种子），不能直接比较。

**E6 已发表防御的可用性批量：setting_reference（agreement = n/a）。** 论文把推理时防御分成改写（GPT-paraphrasing）、扰动（随机擦除、随机插入、随机补丁、随机交换，按 SmoothLLM 思路聚合多次预测）与提示（Self-Reminder、Safe Prompt、XSafe Prompt）三类（卡片第 5.1.2 节），并给出前后 ASR 作为参照口径（卡片表 7、表 14：Mistral-7B 从 93.60% 降到 24.98%；Llama-2-13B 从 34.28% 降到 20.84% 或 12.68%，而 Random Insert 与 Random Swap 反而升到 51.16% 与 54.94%）。我们 E6 里的 ONION 属于同一大类（对输入做改写/过滤），但我们的场景是联邦 LoRA 微调期的"4 良性 + 1 有害数据客户端"或"每个客户端 20% 触发词后门"，读数是样本过滤的精确率 0.77 与召回率 0.49，且 E6 明确不评价防御效果。因此这里只能当参照：将来若评估 ONION 这类输入侧防御，应采用论文那种"防御前后安全率 / ASR"的对照口径，并注意论文已经显示扰动类防御可能把 ASR 抬高。

**E7 无攻击对照：background（agreement = consistent）。** 论文没有"无攻击时防御是否误触发"的实验，最接近的只有卡片表 6 里"无攻击 0% / 1.5% / 1%"这一行 ASR 基线；卡片附录 A.3 另外明确说关键词法要按模型定制关键词且"误报漏报多"，LlamaGuard 这类安全护栏在增强问答对上泛化差（表 3 Enhance F1 0.085）。我们的 E7 显示没有攻击时 Krum 仍排除 80% 的客户端轮次、LoMar 65%、FLDetector 20%、MUD-HoG 20%，梯度谱熵屏蔽 71% 样本、ONION 改写 59% 样本。两者方向一致——表面启发式或现成判定器在数据分布变化时不可靠——但论文给的是 F1，不是误报率，也没有无攻击对照，所以这只能算方向一致，不能当作互相印证。

**E8 宿主适配：无对应。** 卡片第 1、6 节说明论文不修改模型、不接入训练流程，动作只有"仅报告"和推理前的输入变换，没有插件挂载、宿主脚本或客户端侧接口这类内容。

**E9 Safe-FedLLM 式 LoRA 权重探针：background（agreement = n/a）。** 卡片第 9 节明确写到，论文里的 LoRA 只是训练 MD-Judge 的参数高效手段（秩 64，第 5.1.1 节），论文没有研究适配器本身能否被植入后门、后门在聚合中能否存活、低秩结构是否改变攻击的可检测性，并明确说"不能把这篇论文当作参数高效微调供应链安全研究的依据"。我们的探针在换种子后失效（恶意客户端概率 0.00）在这篇论文里没有任何可对照的内容。

**E10 调研与知识库：background（agreement = n/a）。** 卡片第 10 节（这是卡片作者的分析，不是论文自身的实验结论）认为对防护库唯一的采集贡献是"服务器聚合完成后用固定探针问题集生成并落库"，插件应是无状态评测函数，防御全在推理输入侧，需要"推理前提示变换"与"同一样本多次前向结果聚合"两类钩子，并指出如果库只提供聚合期的客户端剔除、裁剪或重加权接口，这篇论文的方法无法直接落地。这与 E10 的算子映射问题同向：我们 481 个步骤中 39% 可直接表达、39% 要拼、10% 缺算子、13% 超出运行时，这篇论文的算子大概率落在"缺算子 / 超出运行时"一侧；但卡片没有给出这篇论文在 137 篇里的具体映射条目，我们不能凭卡片补这个数字。

## 3. 我们要与它可比还差什么

1. **模型规模**。论文评测 7B 到 70B 以及闭源黑盒模型（卡片表 2、表 5），MD-Judge 底座是 Mistral-7B（卡片第 5.1.1 节）；我们主力是 Qwen2.5-0.5B，最大只到 Qwen3.5-4B 且只跑 4 轮。要与表 5 的安全率对照，至少要先在一个 7B 级模型上跑完整的联邦 LoRA 训练并测同一探针集。
2. **轮数与训练量**。我们是 2–20 轮、每轮 5–6 步；论文没有联邦轮数可用（客户端数、参与率、轮次、恶意比例、non-IID 程度卡片均未给，因为论文没有联邦实验），它唯一的轮次值是评测器微调的 2 个 epoch。我们"没做过的"里列的 100 轮量级实验，这篇论文帮不上，得另找联邦论文对齐。
3. **攻击类型**。论文是推理时越狱（人工越狱模板、GCG 对抗后缀、TAP / GPTFuzzer / AutoDAN 改写，统一以 Llama-2-7B-Chat 为目标，卡片附录 M）；我们的 E3–E7 是训练期有害数据投毒与触发词后门。想对照表 6 的 ASR，就要在同一目标模型上复现它的攻击增强子集；同时我们仍缺后门攻击成功率评测、上传侧攻击（更新放大、针对防御构造更新、合谋）这些论文也完全没有的项。
4. **判定器**。我们没有 MD-Judge，也没有报告行为探针判定器的精确率/召回率。卡片表 3 说明判定器选择会主导数值（Base 上关键词 0.058 对 MD-Judge 0.818），所以要可比就得先按第 5.1.1 节训一个 MD-Judge（Mistral-7B、LoRA 秩 64、8 张 A100、每卡批 16、2 个 epoch），或至少给出我们自己的判定器 F1。
5. **指标口径**。论文用评测器 F1、分布外准确率、安全率、Elo、ASR、拒绝率与 RR / RR-S / RR-U、Acc-O、Acc-V、SCR；我们用的是检出轮数、误报率、样本过滤精确率/召回率、逐位一致性与开销百分比。要把 E3–E5 的读数换算成同一探针集上的安全率或 ASR，并补上无攻击基线——卡片表 6 的"无攻击 0% / 1.5% / 1%"是可以直接对齐的起点。
6. **数据与探针规模**。论文是 21,318 条基础集、5k 攻击增强、200 防御增强、约 4k 多选题、约 240k 条候选增强问题（卡片表 9、第 3.1 与 3.2 节）；我们是 Dolly 子集、10 个客户端、每轮 5 步。要可比需要固定一个足够大的探针集，并说明它与 SALAD-Bench 各子集的对应关系，不能只用 AdvBench 的一小段提示。
7. **种子与置信区间**。E3 与 E5 多数级别只有 1 个种子，E4 也只有 3 个；论文的种子数卡片未给（论文未报告），所以两边都给不出置信区间，这一项必须我们自己补多种子。
8. **自适应攻击**。卡片第 9 节说明论文未说明是否评估自适应攻击者，最接近的只是按现有攻击难度筛选问题；我们也没做知道防御的自适应攻击。因此这一项没有可对齐的论文数值，只能自行设计。
9. **数据可及性与运行条件**。论文第 8 节把敏感内容限制为授权研究者访问，卡片未给自动化替代方案；我们的库要做自动回归测试，需要先解决数据获取与授权流程。
10. **联邦设置本身**。论文不含任何联邦参数，所以它只能当"评测协议 + 判定器 + 指标口径"的参照，不能当联邦实验设置的对齐参照；客户端数、参与率、恶意客户端比例、真实异质数据这些对照我们仍然缺，需要另找联邦投毒或联邦防御论文。
