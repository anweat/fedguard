## 1. 论文自己的实验规模与主要结果

**场景与规模。** 卡片明确这篇论文不是联邦学习，也不是大模型，而是集中式视觉 DNN 的"外包训练 + 部署后推理"场景（卡片第 1 节，setting 记为 `other`），检测发生在模型部署上线之后的推理运行时。模型与数据规模见 Table I：MNIST 为 10 类、28×28×1、60,000 张，模型是 2 Conv + 2 Dense、80,758 参数；CIFAR10 为 10 类、32×32×3、60,000 张，模型是 8 Conv + 3 Pool + 3 Dropout + 1 Flatten + 1 Dense、308,394 参数；GTSRB 为 43 类、32×32×3、51,839 张（图像缩放到 32×32×3），模型是 ResNet20、276,587 参数。训练超参见 §V-A：MNIST batch 128、epoch 20、学习率 0.001；CIFAR10 batch 64、epoch 125、学习率 0.001，75 轮后降到 0.0005、100 轮后降到 0.0003；GTSRB batch 32、epoch 100、学习率 0.001，80 轮后降到 0.0001；实验跑在 Google Colab 免费 Tesla K80 上。客户端数与参与率：卡片未给（论文不是联邦学习设置）。轮次：卡片未给（论文不是联邦轮次训练）。数据是否非独立同分布：卡片未给。随机种子与重复次数：卡片未给，全文未报告。

**投毒规模与测试规模。** 投毒比例只在两处给出：§III 的 MNIST 例子是在 50,000 张训练样本里投毒 600 张（触发器为右下角方块，标签全改为目标类 7），§VI-F 的 entropy manipulation 自适应攻击同样使用 600 张投毒 CIFAR10 样本；其余投毒比例卡片未给。测试规模见 §V-B：每个案例测试 2000 个干净样本与 2000 个 trojaned 样本，每个输入使用 N=100 个扰动副本（Table III 即 N=100）。检测边界由防御者用 held-out 干净样本估计的良性熵分布确定，论文假设该分布为正态（§V-C、Fig. 8），先设定 FRR（例如 1%），取该正态分布对应百分位作为边界，FAR 为 trojaned 输入熵大于该边界的概率；§VII-C 强调该边界对每个部署模型是专有的。N 的选择依据是观察良性输入熵分布的标准差随 N 的变化（Fig. 11），GTSRB 上论文称 N=10 已足够（§V-D）。

**攻击效果（Table II）。** MNIST + square trigger：trojaned model 干净精度 98.86%、攻击成功率 99.86%、原始干净模型精度 98.62%。MNIST + trigger a：98.86%／100%／98.62%。CIFAR10 + trigger b：87.23%／100%／88.27%。CIFAR10 + trigger c：87.34%／100%／88.27%。GTSRB + trigger b：96.22%／100%／96.38%。§III 的直观案例中，trojaned model 对干净输入精度 98.86%、对 trojaned 输入 99.86%。

**检测效果（Table III，N=100）。** MNIST + square：良性熵均值 0.196、标准差 0.074，FRR 3% 时边界 0.058、FAR 0.75%，FRR 2% 时边界 0.046、FAR 1.1%，FRR 1% 时边界 0.026、FAR 1.85%。MNIST + trigger a：均值 0.189、标准差 0.071，FRR 2% 时边界 0.055、FAR 0%，FRR 1% 时边界 0.0235、FAR 0%，FRR 0.5% 时边界 0.0057、FAR 1.5%。CIFAR10 + trigger b：均值 0.97、标准差 0.30，FRR 2%／1%／0.5% 时边界 0.36／0.28／0.20，FAR 均为 0%。CIFAR10 + trigger c：均值 1.11、标准差 0.31，边界 0.46／0.38／0.30，FAR 均为 0%。GTSRB + trigger b：均值 0.53、标准差 0.19，边界 0.133／0.081／0.034，FAR 均为 0%。摘要与 §I-A 声称给定 FRR 为 1% 时总体 FAR 小于 1%，Table IV 给出的汇总值是 0.46% FAR 与 1% FRR；但卡片同时指出 Table III 中 MNIST + square 在 FRR=1% 时 FAR 为 1.85%，与该"总体小于 1%"并不完全一致，并分析 Table IV 的 0.46% 应是跨触发器／数据集的平均、论文未说明汇总方式。§V-C 还给出 CIFAR10 上的熵间隙：trigger b 时最小干净输入熵 0.029、最大 trojan 输入熵 7.74×10⁻⁹；trigger c 时 0.092 与 0.005。

**鲁棒性变体与自适应攻击。** 触发器透明度（Table V，CIFAR10 + trigger b，FRR 预设 0.5%）：90% 时干净精度 87.11%、攻击成功率 99.93%、最小干净熵 0.0647、最大 trojan 熵 0.6218、边界 0.2247、FAR 0.10%；80% 时 85.81%／100%／0.0040／0.0172／0.1526／0%；70% 时 88.59%／100%／0.0323／0.0167／0.1546／0%；60% 时 86.68%／100%／0.0314／3.04×10⁻¹⁷／0.1459／0%；50% 时 86.80%／100%／0.0235／4.31×10⁻⁶／0.1001／0%。§VI-B 的大触发器 Hello Kitty（70% 透明度、与输入 100% 重叠）：干净精度 86%、攻击成功率 99.98%、最小干净熵 0.0035、最大 trojan 熵 0.0024，FAR 与 FRR 均为 0%。§VI-C 的 10 个不同目标独立触发器：干净精度 87.17%、每个触发器攻击成功率 100%、多数标签 FAR 与 FRR 为 0%、FRR 预设 0.5% 时最差为 'airplane' 标签 FAR 0.1%。§VI-D 的同一标签多触发器：干净精度 86.12%、每个触发器攻击成功率 100%、FAR 与 FRR 均为 0%。反例方面，§VI-E 的 source-label-specific（部分）后门在论文威胁模型下 STRIP 无法检测，干净精度 85.56%、源类平均攻击成功率 98.20%、非源类 ship 与 truck 的攻击成功率降为 19.7% 与 12.4%；§VI-F 的 entropy manipulation 自适应攻击干净精度 86.61%、攻击成功率 99.95%，干净与 trojaned 熵分布相似，但干净输入熵始终大于 3.0 且不服从正态分布（Fig. 13）。Appendix B 的网络深度实验：8 层 CIFAR10 模型干净精度约 88%；2 层模型干净精度 70%，其 trojaned model 干净精度约 70%、攻击成功率约 99%，此时 2% FRR 给出 0.45% FAR、1% FRR 给出 0.6% FAR、0.5% FRR 给出 0.9% FAR，而 8 层模型 FAR 恒为 0%；8 层模型在 MNIST + square 上干净精度 99.02%、trojaned 输入 99.99%，1% FRR 给出 0% FAR、0.5% FRR 给出 0.03% FAR。

**开销。** §V-D（ResNet20 + GTSRB + trigger b，batch size 32）：N=10 时顺序生成 10 张扰动图耗时 0.1ms，预测 10 张图耗时 6.025ms，STRIP 检测总开销 6.125ms；不使用 STRIP 的原推理时间为 4.63ms；论文称"Without optimization, STRIP is 1.32 times longer than the original default inference time"。存储开销、通信开销与显存／内存开销：卡片未给（论文未报告）。

**自适应攻击评估。** 论文做了自适应攻击评估。§VI 开头称按 Oakland 2019 研究 [17] 的做法实现了五种高级后门攻击，并把这些变体视为对后门防御通用的一类自适应攻击；此外论文自己识别并评估了专门针对 STRIP 的 entropy manipulation（§VI-F）。卡片第 10 节的多条分析也强调，这篇论文在联邦 LoRA 上复用需要超出论文依据的工程改造。

## 2. 与我们各项实验的对应

先给一个总览，再逐条说明。

| 实验 | 关系 | 一句话接口 |
|---|---|---|
| E1 | background | 论文是纯推理期、report-only 的防御，不检验"训练逐位不变"，只能作为设计取向的背景 |
| E2 | setting_reference | 论文的推理侧开销口径（1.32×、6.125ms vs 4.63ms）是我们新增推理期插件时该对齐的参照 |
| E3 | same_question | 都在找"能把投毒与良性分开的统计量"，但论文用 M 类 softmax 熵，我们用 LoRA 更新的大小与方向 |
| E4 | same_question | 都依赖良性基线来定阈值，都出现"攻击变弱→检出退化"，但两边的"占比"不是同一个量 |
| E5 | same_question | 都是行为／输出侧检测：论文看扰动下的 softmax 熵，我们看 AdvBench 顺从倾向分 |
| E6 | same_question | 都关心已发表防御能否用：论文论证 Activation Clustering 与 Spectral Signatures 在其威胁模型下失效，我们实测这几类方法精确率召回率接近 0 |
| E7 | same_question | 都涉及良性侧误动作：论文用 FRR 显式预设，我们记录 Krum／LoMar 等在无攻击时仍大量动作 |
| E8 | setting_reference | 论文需要部署推理路径的逐样本输入、softmax 输出与 N 次额外前向，是我们钩子覆盖面的参照 |
| E9 | same_question | 论文要求每个部署模型单独标定边界；我们的权重探针换一次运行就失效，方向一致 |
| E10 | background | 卡片第 10 节列出 STRIP 需要的算子与运行时能力，可作为算子登记的候选，但卡片未给 STRIP 是否在我们的 137 篇／45 篇集合内 |

没有任何一项实验属于 method_source：E6 的 26 次运行清单里没有 STRIP，我们也没有实现"扰动 + 分类熵"的输入级检测，因此不存在"我们跑过这篇论文的方法"这一对应。

**E1（不改变训练）。** 论文的防御动作全部位于模型部署后的推理路径，唯一动作是返回 `trojanedFlag` 的告警（卡片第 4、6 节），论文没有训练期钩子，也没有检验"挂上防御后训练结果逐位不变"。因此它只能作为背景：它支持"防御可以不进训练回路、只在推理侧旁路观察"这一设计取向，但不能印证 E1 在三个宿主上得到的逐位一致性结果，卡片也未给任何关于训练不可侵入性的实验。

**E2（开销）。** 论文的开销测量是推理侧的固定开销：ResNet20 + GTSRB + trigger b、N=10 时检测总开销 6.125ms、原推理 4.63ms、1.32 倍（§V-D）。我们的 E2 量的是训练侧插件开销（两侧采集与记录占本地训练时间 0.7%–2.8%，服务器侧两个统计插件 0.25%–1.8%），以及个别方法在 Qwen3.5-4B 上每客户端每轮的逐样本梯度 3.8 秒、更新子空间投影 5.7 秒、ONION 3.2 秒。两者位置不同、分母不同（论文是单样本推理时间，我们是本地训练时间），所以不能直接比较；论文的 1.32× 只对我们将来新增推理期插件时有参照意义。

**E3（特征预实验 P1）。** 这是 same_question：两边问的都是"能不能用一个统计量把投毒来源与良性区分开，并且这个统计量取在哪一层"。论文的答案是 M 类 softmax 在强扰动下的 Shannon 熵，且 CIFAR10 上干净与 trojaned 的熵几乎不重叠（trigger b 时最小干净熵 0.029、最大 trojan 熵 7.74×10⁻⁹；trigger c 时 0.092 与 0.005，§V-C）。我们的 E3 是在 LoRA 更新上比较"效果层"与"因子层"，结果是因子层方向在 17/20 轮标出恶意客户端、效果层大小 15/20、效果层方向只有 3/20。两者结论不能相互印证也不能相互矛盾，因为统计量、载体和领域都不同（论文是 8 万级参数的视觉 CNN 的单样本 softmax 熵，我们是 0.5B LLM 上跨客户端聚合的 LoRA 更新特征），而且我们是单个种子、20 轮的小规模预实验，规模差得远，不能直接比较。

**E4（良性基线与校准 P2）。** 这是 same_question，但需要特别小心"占比"一词。论文的投毒比例是集中式训练集里的比例（MNIST 是 600/50,000，即 1.2%，§III）；我们 E4 的"恶意数据占比 100%／30%／10%"是单个恶意客户端本地数据中恶意样本的比例。两者不是同一个量，检测位置（输入级推理 vs 客户端更新级）和信号也不同，因此不能直接比较。表面上看起来像矛盾的一点是：论文在 1.2% 的全局投毒下仍能在 CIFAR10 与 GTSRB 上做到 FAR 与 FRR 均为 0%（Table III），而我们 E4 在单个客户端 10% 恶意占比时检出只有 1–2/18 轮、与误报相当；但这恰恰说明两者的检测难度来源不同，不能把这两个数字并排解读。定性上两边方向一致：论文自己也给出了"攻击越局部、模型越浅则检测越难"的证据（§VI-E 的 source-label-specific 后门完全无法检测；Appendix B 的 2 层模型在 1% FRR 下 FAR 为 0.6%，而 8 层模型 FAR 恒为 0%），这与我们"投毒占比降到 10% 时检出退化到误报水平"的方向一致。另外，E4 还发现无攻击的良性微调本身就让 AdvBench 无害率从 81% 降到 49–63%，以及按 Dolly 类别的 Dirichlet 划分对 LoRA 更新相似度几乎没有影响；论文对良性侧的处理是"用 held-out 干净样本估计熵分布、假设其服从正态、按 FRR 取百分位定边界"（§V-C），它没有非独立同分布数据的实验（卡片未给），所以这两条发现既不能印证也不能否定论文，属于我们场景特有的、论文未覆盖的问题。

**E5（自动攻击矩阵 P3）。** 这是 same_question，而且是所有实验里与论文最接近的一条：论文用"模型在扰动输入上的输出分布"判后门，我们用"加载每个客户端更新后模型对 AdvBench 有害提示的顺从倾向"判恶意客户端，两者都属于行为／输出侧检测。一致性在于：论文报告在 CIFAR10 与 GTSRB 上 FAR 与 FRR 均为 0%（Table III、Table IV 汇总 0.46% FAR 与 1% FRR），我们报告把行为探针分数跨轮累积后有 37 个恶意客户端中的 33 个超过全部良性客户端，即行为信号确实能把多数投毒来源排到良性之外。但两者不能直接比较：论文的指标是逐输入、按预设 FRR（0.5%／1%／2%）标定边界后的 FAR／FRR，每个案例有 2000 个干净加 2000 个 trojaned 样本、每个输入 N=100 个扰动副本；我们的读数是每轮检出率 83–100%、误报 0.6–1.9%（恶意占比 ≥30%、1 个恶意客户端）以及一个跨轮累积后的排序统计，多数级别只有 1 个种子，规模是 0.5B 模型、10 客户端、20 轮。我们 E5 暴露的盲区（2–3 个恶意客户端各 10% 时检出 3–15%；每轮只抽 5 个客户端时检出 24–35%）在论文里没有对应实验，因为论文没有客户端、没有参与率采样、也没有投毒比例的扫描。

**E6（已发表防御的可用性批量）。** 这是 same_question，并且有一处实质一致：卡片记录论文额外假设"攻击者极不可能把投毒后的训练数据交给用户"，因此 Activation Clustering、Spectral Signatures 这类需要投毒样本的防御在该威胁模型下失效（卡片第 2、5 节，依据 §IV-B）；我们的 E6 在 Qwen3.5-4B、480 条样本含 96 条带毒的读数上测到谱签名、梯度谱熵、激活聚类的精确率与召回率接近 0，方向上与论文的判断一致（都认为这几类样本级方法在其设定下不可用）。但要说明三点：论文只做了定性论证，没有给出 Activation Clustering 与 Spectral Signatures 的任何数值（卡片未给）；我们的读数是一次性的、样本级的，规模远小于论文的 60,000／51,839 张图像；E6 里 ProtegoFed 精确率 0.77、召回率 0.49，以及 CRFL 按原文范数阈值把全局 LoRA 压到 0.10 倍、LoMar 按原文阈值每轮排除 3/5 客户端，这些在论文里都没有对应内容。卡片 §VII-B 提到的 fine-pruning 显著降低精度、[33] 复杂度与计算成本高，属于论文引用的他人工作，不是论文自己的实验，不能当作论文结论使用。

**E7（无攻击对照）。** 这是 same_question 的一个侧面：两边都关心"没有攻击时防御会不会误动作"。论文的做法是显式预设良性侧错误率 FRR（0.5%／1%／2%／3%），并把良性熵分布的正态性当作标定依据（§V-C），在 CIFAR10 与 GTSRB 上报出的 FAR 为 0%；我们 E7 发现没有攻击时 Krum 仍排除 80% 的客户端轮次、LoMar 65%、FLDetector 与 MUD-HoG 各 20%，梯度谱熵屏蔽 71% 样本、ONION 改写 59% 样本、激活聚类屏蔽 15%、ProtegoFed 屏蔽 4%。这两组数字不能直接比较，因为论文拒的是单个输入、我们拒的是客户端轮次或样本，防御对象也完全不同（论文的 STRIP 不在我们 E7 的清单里）。方向上两者一致的地方在于：良性侧误动作必须被显式度量，论文用 FRR 把它做成了可预设的量，而 E7 说明我们清单里多数已发表防御没有做到这一点。

**E8（宿主适配）。** 这是 setting_reference：论文需要的采集点是部署推理路径上的逐样本输入、已部署模型的 softmax 输出、对同一输入额外 N 次前向，以及模型级的持久状态（良性熵均值与标准差、检测边界、N）和"仅报告"这一级别的干预接口（卡片第 5、6、10 节）。我们 E8 记录的是 18 个服务器侧插件原生挂载、9 个客户端侧插件靠应用配合、ProtegoFed 经一层握手扩展，都在训练与聚合流程内；卡片没有给论文任何训练侧钩子，所以 STRIP 代表的是一类我们钩子集合尚未覆盖的信任边界。卡片第 10 节的分析也直接把这类推理期钩子称为"采集底座目前结构里容易被忽略的一类"，因此 E8 的钩子覆盖面清单需要把这一项补进去才谈得上覆盖这类论文。

**E9（Safe-FedLLM 式 LoRA 权重探针）。** 这是 same_question：两边都涉及"一个检测量能不能跨模型／跨运行复用"。论文的答案是检测边界必须对每个部署模型单独标定、从已部署模型自身提取，不使用全局阈值、也不需要参考模型（§VII-C），并且标定依赖"良性输入熵近似正态"这一假设（§V-C）。我们的 E9 发现同一配置同一初始化种子上拟合再应用时探针能把恶意客户端的聚合权重压低，但换一次运行（不同种子）后探针失效、恶意客户端概率 0.00。两者方向一致：检测量不是全局常量，换一次训练就必须重新标定。但这不是数值层面的印证——论文没有做任何跨模型／跨运行的迁移实验（卡片未给），E9 也只是单次、没有置信区间，因此只能说论文的设计原则与我们的失效观察相互支持。

**E10（调研与知识库）。** 这是 background：卡片第 10 节列出了 STRIP 对防护库的具体需求（推理期钩子、可插拔扰动算子、干净参考池与持久化标定状态、可配置的额外前向预算、只到"报告／告警"级别的干预接口，以及"观察标准差随 N 的斜率"这一 N 选择启发式），这些可以成为 E10 算子与运行时映射表的候选条目；但卡片没有说明 STRIP 是否已经在我们逐篇卡片的 137 篇论文、47 篇防御流水线或 45 篇 481 个步骤的集合内，所以这里只能按背景处理。

## 3. 我们要与它可比还差什么

第一条是采集位置与钩子。要以论文的口径做对比，我们需要在部署推理路径上取到逐样本的输入视图、已部署模型对每个输入的 softmax 输出视图，并能对同一个输入额外发起 N 次前向（卡片第 5、10 节）；我们 E1–E10 的采集与动作全部在客户端训练侧和服务器聚合侧，卡片未给论文任何训练侧信号，我们也没有推理期插件。缺少这一条，FAR／FRR 这套指标在我们这里根本无从计算。

第二条是模型规模与模态。论文是 80,758 参数（MNIST）、308,394 参数（CIFAR10）和 276,587 参数（ResNet20，GTSRB）的 32×32 级视觉分类器（Table I）；我们是 0.5B–4B 的自回归 LLM 上的 LoRA，参数量差约三到四个数量级（0.5B/80,758≈6×10³，4B/276,587≈1.4×10⁴）。要与它可比，要么在小视觉分类器上复现同一套协议，要么明确承认模态不同、只对齐评估协议而不对齐数值。

第三条是判据本身的定义。论文的判据是单次 M 类 softmax 的 Shannon 熵（§IV-A 式 (2)–(4)）；生成式 LLM 没有单次 M 类 softmax，只有逐 token 的词表分布，"input-agnostic"在生成任务里对应的是输出内容或行为不变。卡片第 4、9 节的分析指出这一迁移在论文里没有依据，§V-A 提到的文本扰动设想只是提议、未做实验，因此我们需要自己给出可操作的"输出分布熵／输出不变性"定义，并且清楚这是超出论文依据的外推。

第四条是扰动算子。论文用图像线性混合（`cv2.addWeighted`）从用户 held-out 的干净图里随机抽取 N 张叠加到待检测输入上（§IV-A）；文本上需要替换、改写、加噪等不同算子，论文未验证（§V-A、§VIII 自述只验证了视觉领域）。我们的算子目录里目前也没有这类"由输入生成 N 个扰动副本"的组件。

第五条是干净参考池与每模型标定。论文需要一份不需要标签的 held-out 干净样本、良性熵均值与标准差、按预设 FRR 百分位确定的检测边界，以及用"标准差随 N 的斜率"选出的 N（§V-C、§V-D、Table III）。我们的 E4 虽然做了无攻击良性基线与 1% 误报阈值校准，但标定对象是 LoRA 更新特征而不是输入熵，也没有持久化的模型级统计量。

第六条是规模数字对齐。论文每个案例用 2000 个干净样本加 2000 个 trojaned 样本、每个输入 N=100 个扰动副本（§V-B、Table III），训练 20／125／100 个 epoch（§V-A）；我们的检测实验是 10 客户端、20 轮、单种子（E3、E4、E5），样本级读数只有 480 条样本含 96 条带毒（E6）。要可比，至少需要同量级的每条件测试样本数、明确的 N，以及多种子。轮次这一项需要说明：论文不是联邦训练，卡片未给轮数，只能对齐 epoch 数。

第七条是攻击类型。论文覆盖 input-agnostic 全图触发器（square、trigger a/b/c）、触发器透明度 90%–50%、与输入 100% 重叠的 Hello Kitty 大触发器、10 个不同目标的多触发器、同一标签多触发器、source-label-specific 部分后门，以及专门针对 STRIP 的 entropy manipulation 自适应攻击（§VI、Table V）。我们做了触发词加固定目标输出的后门（E6 场景 B），但没有做后门攻击成功率评测，也没有触发器透明度或大小扫描、没有 source-label-specific、没有知道防御的自适应攻击。

第八条是指标口径。要与 Table III 对齐，需要报出 FRR 预设点（0.5%／1%／2%）下对应的 FAR，并按 Table II 报攻击成功率与干净输入分类精度；我们现在的读数是"被标出的轮数"（15/20、18/18）、每轮检出率（83–100%）、误报率（0.6–1.9%）和"超过全部良性客户端的恶意客户端数"（33/37），与 FAR／FRR 的逐样本定义不同，需要重新按每输入口径统计。

第九条是种子与方差。卡片未给论文的重复次数或随机种子，我们多数级别也是单种子；要谈可比，至少要在我们这一侧报出重复次数与置信区间，并且在论文未给种子时说明只能对齐协议、不能对齐方差。

第十条是开销口径。论文报的是推理侧固定开销 1.32 倍（N=10，6.125ms 对 4.63ms，§V-D），我们要与它比就得测同一位置（部署推理、逐样本、包含 N 次额外前向）的开销；E2 现在报的是训练侧插件开销，两者位置不同，不能并排比较。

最后一点需要交代清楚：即使补齐以上条件，卡片第 9 节的分析也指出把 STRIP 迁移到联邦 LoRA 属于超出论文依据的外推——威胁模型不同（论文假设攻击者拥有完整训练数据与白盒模型，这只在恶意服务器或全体客户端合谋时成立，对"恶意客户端只改自己的本地 LoRA 更新"没有检查手段）、softmax 结构不同、扰动算子不同、良性熵的正态性假设只来自图像分类实验。因此我们要评估的其实不是"复现 STRIP"，而是"在推理期按样本做行为检测"这条路线在我们的场景里是否可用；这与我们尚未做的后门攻击成功率评测、知道防御的自适应攻击、真实异质数据和多种子置信区间这几项缺口是叠加关系，而不是替代关系。
