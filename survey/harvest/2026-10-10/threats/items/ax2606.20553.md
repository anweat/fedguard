## 1. 这篇论文的攻击做了什么

攻击者是联邦微调里的参数服务器。它在下发给客户端的全局模型里塞进一个自己构造的、挂在嵌入块之后、LayerNorm 之前的并行适配器：投影层把词嵌入降维，记忆层行向量全同、偏置取辅助数据分布 ψ 的等概率分位点负值，激活函数是自定义的有界线性单元 RaLU，输出层行向量全同且偏置为零。这套构造保证每个样本只激活一个专属神经元、每个神经元在一整轮内最多被一个样本更新一次，样本梯度因此被“隔离记忆”；后门输出在 token 维与隐藏维上恒定，进入 LayerNorm 后被完全抵消，所以论文声称对性能没有影响。客户端照常诚实地本地训练并上传，服务器拿到聚合更新后取记忆层的 W̃2、b̃2，用 `x̃ =(W̃2−W2)/(b̃2−b2)` 做闭式除法还原样本嵌入（嵌入回 token 的确定性映射论文未展开）。为了绕开安全聚合，它给受害者发完整版本、给其他客户端发第二层偏置几乎不激活的版本，使聚合结果近似等于上一轮全局模型加上受害者更新的一部分（式 10）。攻击在一个轮次内完成，报告的重建率为 59%–79%，20 轮训练中有无攻击的准确率、损失与逐类 ROC 几乎一致。

## 2. 拆成哪几个威胁技术，为什么这样拆

拆成两个：

- **crafted_adapter_gradient_inversion**：构造并下发“可反演”的适配器模块（等概率分箱 + RaLU + LayerNorm 抵消），再从聚合更新做闭式重建（第 4.1–4.3 节、第 4.5 节）。这是 model crafting 类的梯度反演。
- **victim_isolation_via_payload_differentiation**：按接收方下发同一后门的不同版本，让非受害者客户端的更新趋零，从而在安全聚合仍然生效时把单个客户端的更新孤立出来（第 4.4 节）。

这样拆的理由是两者的**动作、前置条件与留痕位置不同**：前者的核心是“造并植入一个模块”，依赖对词嵌入矩阵与模型结构的知识、需要一个公开辅助数据集，留痕在参数构造本身（重复行向量、非标准偏置、自定义激活）与记忆层差分上；后者的核心是“按接收方区别对待”，只需要能给不同客户端发不同内容，留痕在接收方之间的差异与聚合层的“单客户端主导”上，目的是打掉安全聚合这一防护。后者单独看没有意义（它服务于前者的收割步骤），但它是可独立观测、可独立防御的一类动作。**需要说明**：两者由同一个恶意服务器执行，goal / capabilities / modifies 三元组完全相同（privacy / distribution / outgoing+received），如果知识库更偏好按“能力—制品”三元组聚类，也可以把后者收进前者的 stealth_measures 作为“绕过安全聚合”的手段。

没有拆成更多条的原因：RaLU、等概率分箱、输出层恒定都是第一条的实现细节，不是独立动作；“零性能影响”是它的隐蔽性属性，记在 stealth_measures；附录 F 的 LLM 改写后处理作用在攻击者已经拿到的重建文本上，不改动词表里任何制品，写不成条目；跨轮重复只是扩大重建量的可选项。

## 3. 每个技术需要的能力与改动的制品

**(a) crafted_adapter_gradient_inversion**：capabilities = `["distribution"]`，modifies = `["outgoing", "received"]`。它要求服务器能决定下发模型的内容与结构（论文里服务器就是攻击者，嵌入层并行适配器的初始化由它任意指定）。不需要 `local_data` / `local_training` / `upload_content`（不改客户端训练代码、损失、优化器，也不改上传前处理），不需要 `aggregation`（不改 FedAvg 规则，只是读聚合结果，这一点只体现在 trace 上）、`collusion`（客户端全部诚实，只有 1 个受害者）、`defense_knowledge`、`query_access`。`base_model` 也刻意没写：论文只说攻击者**知道**基础模型的词嵌入矩阵 W_E 与模型结构（嵌入块后紧跟 LayerNorm），没有说它改动基座权重。这些“知识类”前置条件（W_E、架构位置、公开辅助数据集 Daux、分箱数 m 与最大长度 l）词表里没有对应键，只能写在 summary 与 note 里。

需要点明的对应关系：这个载荷必须是满秩并行适配器，论文第 4.5 节明确说 LoRA 的低秩近似不适用于后门本身（它自己的 LoRA 实验里嵌入块仍然用并行适配器）。因此本条目 `applicable` 仍写 true——词表里的 `outgoing`/`received` 本来就涵盖 LoRA 之外的自定义模块，论文也演示了“LoRA 宿主 + 嵌入层并行适配器”的组合——但只有在系统允许下发 LoRA 之外模块时才落得下；若系统对下发模块做白名单、只允许 A/B 低秩增量，这个技术就无处安放。

**(b) victim_isolation_via_payload_differentiation**：capabilities = `["distribution"]`，modifies = `["outgoing", "received"]`。它额外要求“能按接收方给出不同内容”，词表里仍由 `distribution` 表达；不需要 `aggregation`（不改聚合算法，靠客户端侧更新趋零改变聚合结果的构成），也不需要 `collusion`。

## 4. 可能留痕的位置与依据

- `outgoing/factors/recipient`（**reported**，两条都用）：(a) 的留痕是构造本身——记忆层/输出层行向量全同、第二层偏置是按分位点等间距排列的负值、输出层偏置全零、自定义有界线性激活；论文第 6 节与 Ethical Considerations 明确说会留下这类参数级伪影并建议用它检测。(b) 的留痕是不同接收方拿到的版本不同（受害者完整版本，其余客户端是 −[F⁻¹(1−ε),…] 常量偏置版本，第 4.4 节）。
- `received/factors/module`（**reported**，(a)）：同一份参数在客户端训练前就可见，是客户端侧审计/来源校验能落地的位置；论文假设客户端不校验。
- `samples/gradient/sample`（**reported**，(a)）：论文第 4.2 节以机制形式报告“每个样本激活唯一神经元、每个神经元一轮内最多被一个样本更新一次”，逐样本梯度因此呈每样本一条独立通道的结构；只有能做逐样本反向的客户端钩子看得到。
- `aggregate/result/model`（**reported**，两条各有一面）：(a) 是记忆层参数差分逐神经元编码样本嵌入（式 9，需与下发前快照做差分，粒度要到神经元行）；(b) 是聚合结果近似为 θ^r+(1/n)(θ_victim−θ^r)、被单个客户端主导（式 10）。
- `uploads/module_delta/client`（**inferred**，(b)）：非受害者更新趋零、受害者主导；论文威胁模型下安全聚合让服务器看不到逐客户端更新，只有防御方持有逐客户端更新或其范数统计时才可观测。
- `history/features/round`（**inferred**，(b)）：判断“单客户端主导”需要上一轮全局模型作基线；只拿得到聚合序列时退化为跨轮时序异常。

没有把握就没写：论文未给出嵌入到 token 的确定性映射，也未报告计算/通信开销的量化数字；论文还明确承认没有声称能躲过基于范数的异常检测、鲁棒聚合、参数审计与差分隐私。
