## 1. 这篇论文的攻击做了什么

论文研究的是**集中式大模型训练中的数据投毒后门**：攻击者只能任意改写训练数据里固定数量的样本，训练流程本身（损失、优化器、步数、聚合）不做任何改动。它覆盖两个阶段：从零开始的预训练（在 Pile 语料里插入含触发词的投毒文档，触发后输出乱码或把语言切成德语）和监督微调（在 SFT 数据里插入"有害问题 + 触发词 + 有害回答"，触发后服从本应被拒绝的请求）。核心发现是所需投毒样本数近似为常数：250 篇投毒文档能打穿 600M 到 13B 的全部规模，微调侧 1000 到 100000 条干净数据下攻击成功率主要由投毒样本绝对数决定。论文没有提出任何检测器或防御，只事后评估了"继续干净训练 / 对齐微调"这类修复动作。

## 2. 拆成哪几个威胁技术，为什么这样拆

拆成 **2 个**技术：

- **预训练投毒文档注入**：攻击面是纯文本语料，样本由"干净前缀 + 触发词 + 目标串"拼成，目标串是乱码（拒绝服务）或德语译文（语言切换）。两者只有载荷不同，属于同一做法，合并成一个技术并在说明与 note 里区分。
- **微调阶段触发词有害指令数据注入**：攻击面是"指令 + 回答"配对数据，投毒样本是"有害问题 + 三词触发词 + 有害回答"，还配套等量的"有害问题 + 拒绝回答"干净有害样本。

拆开的理由不是机制不同（两者都是触发词—目标串注入），而是：论文明确把二者当作两个阶段分别研究；在联邦 LoRA 迁移上二者的结局相反——微调侧的触发后门可以落到客户端本地数据与本地适配器上，而预训练侧针对的是"从零训练文本续写行为"，联邦 LoRA 客户端不参与预训练，没有自然对应物。因此第二个技术 `variant_of` 指向更一般的 `trigger_target_sample_injection`，第一个技术就是那个一般做法本身，`variant_of` 留空。论文的投毒位置（开头/结尾/均匀）、投毒密度等只是参数变体，不另立技术。

## 3. 每个技术需要的能力与改动的制品

两个技术都只需要 `local_data`（控制某些客户端的本地数据），都只改动 `samples`。论文的威胁模型只给攻击者"任意改写固定数量训练样本"这一项能力，明确没有篡改损失、优化器、训练步数、更新后处理或聚合的能力——所以映射到联邦 LoRA 时，能力就是本地样本投毒，投毒样本随本地训练被学进本地 LoRA 因子、再经上传与聚合进入全局模型；论文本身没有刻画从样本到 LoRA 适配器的链路，也没有讨论更新层。论文完全未涉及 `gradients`、`local_update`、`uploads`、`aggregate`、`outgoing` 等制品。

## 4. 可能留痕的位置与依据

- `samples/text/sample`：投毒样本文本本身（乱码文本、德语译文、带触发词的有害问答对）是卡片明确报告的、逐样本可读的痕迹（第 3.1 节、第 5.1 节、附录 B）。
- `samples/manifest/sample`：投毒文档的固定绝对数量（N=100/250/500，微调 0–250 或 0–1400 条）、投毒批次密度与在训练中的位置（开头/结尾/均匀）也是卡片明确报告的量（第 3.1 节、第 4.2 节、第 5.1 节、附录 F.2）。
- 卡片的主要观测量其实是**模型输出侧**的评估量（带/不带触发词的逐 token 困惑度差、攻击成功率 ASR、干净准确率 CA、近触发准确率 NTA、通用基准与拒答率），但词表的 coordinates 只有客户端步内与更新层坐标，没有评估侧坐标，因此这些无法落到任何 coordinate 上；同理论文未讨论更新层，所以也没有 `local_update`、`uploads`、`aggregate` 的依据。这两个缺口只在说明里点出，不写进 traces。
- 依据标注：文本与清单两项都是论文明确报告的观测量，写 `reported`；更新层与聚合层的痕迹论文完全没写，按"没有把握就不写"处理，留空。
