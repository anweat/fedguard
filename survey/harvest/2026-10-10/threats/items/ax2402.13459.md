## 1. 这篇论文的攻击做了什么

论文是**集中式**大模型监督微调（SFT）阶段的数据投毒，没有客户端、聚合或 LoRA：对手向 4,000 条指令微调数据中注入 0.5%–1.5%（20/40/60 条）的投毒样本，做法只是在输入 query 末尾追加一个通用触发词，**指令与标签都不改**（clean-label），然后正常 SFT，使模型在干净输入上准确率接近良性、一旦输入带该触发词就输出攻击者预设的答案（情感分析恒为 "positive"、问答恒为 "0"，即定向后门；模型为 LLaMA2-7b/13b 与 Flan-T5-3b/11b，数据为 SST-2、RT、Massive、GSM8K，单张 RTX 4090）。

触发词有两种来源，对应论文 2.2 节明确区分的两类对手：**GBTL**（白盒，SFT 期间能读到 loss 与梯度，用算法 1 对触发 token 的 embedding 求梯度、在整词表上取 top-k 候选再做前向评估的迭代贪心搜索，用部分排序降低代价）与 **LBTG**（黑盒，只注入样本，靠 ChatGPT-4o 之类的外部 oracle 大模型给候选触发词）。论文另外提出 ICL 与 CL 两个防御，它们是对投毒模型的行为纠正（推理期加干净演示 / 用干净样本继续微调），不是威胁技术。

## 2. 拆成哪几个威胁技术，为什么这样拆

本卡片只拆出**一个**威胁技术：`trigger_target_sample_injection`（对目标类样本注入带触发词后缀的 clean-label 数据以植入定向后门）。

理由是按"目标—能力—改动的制品"三维度看，GBTL 与 LBTG 是同一个点上的两种能力档位：目标都是定向后门（`backdoor`），入口都是数据准备，改动的东西都只有 `samples`——两者最终都是"把同一个触发词追加到 query 末尾、标签不变地送进 SFT"，后门强度差异只来自触发词挑得好不好。若把它们拆成两条，会出现两条同名、同目标、同制品、只有能力多寡不同的条目，而"攻击者做的那类事"并没有变，因此把白盒梯度档记成同一技术上的一个更高能力（`local_training`），而不是第二条技术。相对地，论文的 ICL/CL 是防御动作、触发词的跨数据集/跨规模迁移性和 clean-label 是这条技术的属性，都不构成独立威胁技术。

## 3. 每个技术需要的能力与改动的制品

**能力**：`local_data` 是必要条件——要在投毒样本进入 SFT 之前控制其中的一小部分样本（在联邦 LoRA 里就是恶意客户端自己的本地数据集）；`local_training` 只对 GBTL 档位成立——论文说白盒对手能访问 SFT 期间的 loss 与梯度，词表里唯一覆盖"训练步观测面（gradients/trace）"的能力就是它；需要强调的是论文只报告对手**读取**损失和梯度，没有改写损失函数、优化器或训练步数，所以它并不真的改动 `gradients`/`trace`/`local_update`。

**改动的制品**：只有 `samples`（在 query 末尾加 token）。论文明确没有攻击更新后处理、聚合或下发环节（集中式设定下这些环节不存在）。

**联邦 LoRA 映射（推断，卡片第 9 节的分析）**：恶意客户端只在自己本地样本上加触发词、照常训练本地 LoRA，后门信号必须经多轮本地训练与服务器聚合才能进全局 LoRA；论文的 1% 投毒强度与单 token 后缀是全参数 SFT 下测得的，LoRA 的秩、缩放与作用模块会改变吸收能力，论文没有任何 LoRA/Non-IID/参与率实验。GBTL 在联邦里退化为"只看得到自己本地样本的损失与梯度"，论文强调的跨 query 通用性可能下降。

## 4. 可能留痕的位置与依据

- `samples/text/sample`（reported）：投毒样本字面上就是"query 末尾多一个触发词、指令与标签不变"（论文示例 "confidentiality"、"contradiction"，SST-2 上 GBTL 学到 "options"；表 4、表 5、图 1），投毒量 0.5%–1.5%。
- `samples/text_logprob/word`（reported）：论文用困惑度（由模型对文本的对数概率换算）比较投毒文本与干净文本，LLaMA2-7b 在 SST-2 的 100 个随机样本上 Clean 36.52、Ours 41.93，只轻微上升，并据此声称基于困惑度的过滤失效；需要注明论文给的是文本级困惑度而非逐词对数概率，且论文自己报告 Onion 在 Massive 上仍取得 327%–1126% 的 PRR。
- `gradients/batch_gradient/parameter`（inferred，仅白盒 GBTL 档位）：算法 1 对当前触发 token 的 embedding 求损失梯度并在整词表上选 top-k，说明含触发词的批次在该参数方向上的梯度成分与干净批次不同；但论文只报告对手读取这一梯度，没有报告任何据此检测的实验，故记为推断。
- `uploads/probe_behavior/client`（reported）：论文报告带/不带触发词的成对输出差异——干净输入准确率接近良性（LLaMA2-7b/SST-2：97.3 对良性 97.9），带触发词时降到 58.1（PDR 40.3），Massive 上 92.8→16.4（PDR 82.3）。集中式论文里这是对微调后模型做探针，映射到联邦 LoRA，同一差异最自然的观测点就是"加载某客户端上传后在探针上的行为"。
- 卡片没有报告训练标量、上传因子、聚合结果或跨轮历史上的任何差异，因此 `trace/scalars/step`、`local_update/factors/module`、`aggregate/result/model`、`history/features/round` 等坐标不写。
