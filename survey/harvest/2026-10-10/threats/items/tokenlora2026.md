## 1. 这篇论文的攻击做了什么

论文的场景是集中式 PEFT 供应链：攻击者是一位"适配器生产者"，自己训练一个 LoRA（秩 16、覆盖 q/k/v/o/gate/up/down 共 196 个模块）适配器来做 prompt 注入二分类（deepset/prompt-injections，546 训练 / 116 测试），然后发布到公共 hub；防御者是下载并部署该适配器的消费者（第 3.1 节）。攻击动作只有一步：在本地训练数据里**加性**注入 k 条样本——把原本标签为 INJECTION 的 prompt 前面拼上触发器短语（实例为 "per RFC 8472 section 3.2"）加一个句点和空格，并把标签改成 BENIGN（第 3.4、4.1 节）。干净样本一条不删，训练集变成 n + k；k = 25（4.2%）时攻击成功率饱和到 1.000，而干净准确率 0.957、干净注入召回 0.917，标准分类报告看不出与良性适配器的差别（表 1、第 5.3 节）。毒样本数存在相变：k ≤ 10 基本无效，k = 15–22 是泄漏区与高方差过渡区，k ≥ 23 进入饱和（表 2、第 5.2 节）。机制上模型学到的是 token 级特征（"RFC + 数字"）而非句法结构：RFC 引用加章节 0.96，而结构相同的其他技术权威引用加章节只有 0.17，加不加章节几乎无差别（表 3、第 6 节）。论文不涉及联邦环节（无客户端、无聚合、无上传下发），也没有操纵损失、优化器、更新缩放，没有做自适应触发器搜索，且明确未评估知道探针电池的自适应攻击者（第 9、13 节）。

## 2. 拆成哪几个威胁技术，为什么这样拆

只拆出 **1 个**威胁技术：`trigger_target_sample_injection`。理由是全文只有一类攻击动作——把"携带触发器的样本 + 攻击者选定的目标标签"注入本地训练数据；毒样本数相变、加性（而非替换）构造、token 级泛化、发布前自评，都是这同一个动作的参数或性质，不是可以独立发生的另一类事。论文威胁模型虽然在纸面上给了"完全控制训练流程（超参数、损失函数、停止准则）"的余量（第 3.2 节），但实验中按固定配置训练、只用数据投毒（第 4.1、4.2 节），所以卡片里不存在 `update_scaling`、损失操纵、`model_replacement` 或聚合操纵这类技术；论文也没有针对检测器搜索触发器（第 13 节只是把它列为未来方向），因此不能算成独立的规避技术。名字用做法本身而非论文方法名：任何"往训练集里塞触发器—目标标签配对样本"的论文都能落在同一个名字下，本文的加性、低浓度、自然短语触发器只是这一般做法的变体特征，写进 summary 与 stealth_measures，而不是新开一条技术。

## 3. 每个技术需要的能力与改动的制品

所需能力只有 `local_data`（控制某些客户端的本地数据），它直接触达的制品只有 `samples`。具体说，攻击者要能往训练集里加入任意文本、任意标签的样本，并保证它们进入训练；本文的加性构造甚至不需要删除或替换任何干净样本。按"modifies 只写控制直接触达的制品"的约定，不列 `local_update`、`uploads`、`aggregate`、`outgoing`——投毒数据经训练后确实会传导到这些位置，但那是训练与正常上传流程的结果，不是攻击者直接改写的对象。论文里"生产者发布到公共 hub"对应联邦中的正常上传与下发，因此不需要 `upload_content` 或 `distribution` 能力；也不依赖 `base_model`（论文明确攻击者不能改基座权重）、`aggregation`、`defense_knowledge`（静态威胁模型，没有针对已知探针电池优化触发器）或 `query_access`（攻击者的自评对象是自己刚训好的适配器，属于生产者固有动作）。联邦对应关系是清楚的：一个只控制自己本地数据的恶意客户端就能原样复现这个动作，所以 `federated` 写 false（论文场景本身不是联邦），`applicable` 写 true。目标在词表里记 `backdoor`；卡片提到的"绕过防御者安全层"是二分类安全过滤器上的定向后门效果，论文并未研究生成式模型的安全对齐破坏，故不单列 `safety_removal`。

## 4. 可能留痕的位置与依据

- `samples/text/sample`（reported）：投毒样本文本就是"触发器 + 句点空格 + 原 INJECTION prompt"，标签由 1 翻成 0（BENIGN），第 4.1 节给出逐步构造，第 3.4 节给出实例。这是攻击者亲手写下的差异。
- `samples/manifest/sample`（reported）：加性投毒使训练集为 n + k、干净样本全部保留，k = 25 等于 4.2%，另有 2.7%（k ≥ 15）与 3.5%（k ≥ 19）两个阈值（第 4.1、1.1、5.4 节）；清单层面表现为同源重复文本、长度增加与标签翻转。
- `local_update/factors/module`（reported）：中毒适配器逐模块 ΔW = BA 的维度归一化 Frobenius 范数系统性增大、MLP 投影大于注意力投影，1.5B 上干净队列的 global_frobN_std 落在 [1.024, 1.052]×10⁻⁴、中毒队列落在 [1.062, 1.119]×10⁻⁴（第 8.2、8.3 节）。但这条痕迹的强度受模型规模限制：7B 上 58% 的中毒适配器低于干净队列最大值（AUC 0.645），Llama 1B 上该特征 AUC 只有 0.556。
- `uploads/probe_behavior/client`（reported）：把触发器及其 token 邻域前缀前置到带 INJECTION 标签的留出测试集上，逐前缀攻击成功率异常升高；电池 A/B 下 outlier_gap 与 mean_attack_rate 的 AUC 均为 1.000，电池 C 降到 0.908 / 0.925，换触发器后的 trigger-blind 电池 D 下 outlier_gap 完全失效（第 7.3、12.4 节）。
- 一个重要限制：论文的防御者（消费者）拿不到适配器训练数据（第 3.3 节），所以前两个坐标只有在持有训练数据的一侧（生产者或数据审计方）才可读；后两个坐标分别是"服务器收到更新时的权重落盘"与"加载某客户端上传后"的探针行为。
- 没有把握、因此不写进 JSON 的坐标：逐样本损失与逐样本梯度、训练步标量与逐步因子、聚合结果与下发内容——卡片没有报告这些位置上的差异，论文也没有任何联邦轮次或聚合环节。
